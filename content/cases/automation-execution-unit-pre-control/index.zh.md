## 机器人已经就绪，为什么仍然不能进入抓取阶段？

> 应用层级：自动化执行单元层  
> 代表对象：视觉识别输送线机器人单元

**建议引用：**

全野南政 / Nansei Zenno，  
《自动化执行单元前置判定案例：机器人已经就绪，为什么仍然不能进入抓取阶段》，  
公开案例，Public Case Version 1.6，2026-10-01，  
https://zennns.com/zh/cases/automation-execution-unit-pre-control/

在视觉识别输送线机器人单元中，机器人就绪、视觉识别结果、安全许可、正常投放位接收状态都可能已经成立，但机器人仍然没有开始抓取。

这些状态分别来自不同设备或系统。单独看各项状态都没有明显异常时，仍需以同一个目标状态入口为基准，判断**当前这一时刻是否满足进入抓取阶段的要求**。

本案例以“进入抓取阶段”为目标状态入口（Target State Entry），按照统一九步工程顺序，说明 PCN 如何取得相关状态，并连接 CAE-SDB 判定、控制仲裁、多路径控制、后续状态迁移和状态迁移判定履历。

1. 当前状态
2. 目标状态 / 目标状态入口
3. PCN：相关状态获取与 C / A / E 状态映射
4. S / D / B 判定与 CAE-SDB 判定结果 + T
5. 控制仲裁
6. 多路径控制
7. 当前入口控制结果
8. 后续目标状态入口与执行结果
9. 状态迁移判定履历

## 案例对象

本案例以视觉识别输送线机器人单元为代表对象，并设定 PCN 由 PLC 内的控制逻辑实现。

单元由输送带、工件检测、视觉识别系统、机器人、夹爪 / 真空末端执行机构、安全系统、正常投放位、回流路径和上位系统构成。

与“进入抓取阶段”直接有关的状态，分别来自视觉、机器人、安全、输送、下游和上位系统。

![视觉识别输送线机器人单元前置控制示意图](/images/tpca/06-pcn-pick-flow.png)

图：PCN 在机器人进入抓取阶段前，取得与当前目标状态入口有关的多源状态，并根据判定结果形成控制路径。

以下时间和值用于说明公开案例中的一次示例运行关系，不代表特定真实项目参数。

---

# 1. 当前状态 / 当前阶段

当前工件已经完成视觉识别，但机器人尚未执行抓取。

当前状态为“识别完成 / 等待抓取”。

此时已经确认工件存在、视觉识别结果正常、机器人就绪成立，机器人动作尚未开始。

工件已经进入本次抓取流程，视觉系统也已经生成与当前工件对应的识别结果。

系统接下来需要判断是否允许进入“抓取阶段”。

---

# 2. 目标状态 / 目标状态入口

本次目标状态为“抓取阶段”。

对应的目标状态入口为“进入抓取阶段”。

PCN 设置在当前状态与这一目标状态入口之间。

机器人真正开始动作之前，PCN 需要完成本次入口所需的状态获取、状态映射、判定与控制。

![PCN 在目标阶段入口前的位置关系图](/images/tpca/07-pcn-position-before-target-stage.png)

图：PCN 在抓取动作开始之前，对“进入抓取阶段”这一目标状态入口进行前置判定。

---

# 3. PCN：相关状态获取与 C / A / E 状态映射

PCN 取得与“进入抓取阶段”直接相关的状态，并根据这些状态在本次状态迁移中的工程作用进行 C / A / E 状态映射。

| 代表状态 | 状态映射 |
|---|---|
| 工件存在、位置、姿态、视觉识别结果 | C：条件状态 |
| 安全许可、区域许可、上位系统许可 | A：许可状态 |
| 机器人就绪、机器人路径、夹爪 / 真空状态、正常投放位接收状态 | E：执行链状态 |

本次示例中，视觉识别结果属于 C，安全许可属于 A，机器人就绪和正常投放位接收状态属于 E 的相关状态。

机器人就绪成立，只能说明当前抓取执行链中的一个相关状态已经满足。

系统还需要确认视觉结果是否对应当前工件、是否仍然有效，必要许可是否成立，以及抓取以后执行链是否能够继续。

回流、异常分流等路径的可用状态，用于后续控制路径选择，不直接代替当前抓取入口中的 E 判定。

---

# 4. S / D / B 判定与 CAE-SDB 判定结果

本次示例的当前判定时刻为 10:32:21.850。

机器人就绪、安全许可、正常投放位接收状态均已成立，视觉识别结果也为“正常”。

视觉识别结果的生成时刻为 10:32:14.200，本次示例设定的有效时间窗口为 5.0 s。

从识别结果生成到当前判定时刻，已经经过 7.650 s，超过有效时间窗口。

因此，视觉识别结果的状态值虽然仍然是“正常”，但已经不能继续作为当前抓取入口的有效判定依据。

视觉结果在当前入口中映射为 C，本次问题发生在动态时序有效性，因此形成 CAE-SDB 判定结果：

`C-D`

判定内容为：视觉识别结果已经超过有效时间，当前不能继续作为“进入抓取阶段”的有效判定依据。

这里需要区分两件事：

**状态值正常**，与**该状态当前仍可作为判定依据**，属于两个不同的工程判断。

本次状态值、生成时刻、判定时刻和 `C-D` 判定结果，与时间信息 T 关联保存。

本案例只展开与当前问题直接有关的判定关系，不逐项展开全部 CAE-SDB 坐标。

完整 C / A / E 与 S / D / B 双轴关系可参见：

[为什么是 CAE-SDB？——状态变量域与判定性质的双轴结构](/zh/notes/why-cae-sdb/)

---

# 5. 控制仲裁

当前抓取入口已经形成 `C-D` 判定结果。

与此同时，关键安全许可成立，机器人就绪成立，正常投放位接收状态满足当前入口要求，回流路径也处于可用状态。

当前抓取动作所依赖的视觉识别结果已经失去时序有效性，因此不能继续作为抓取位置和姿态的有效依据。

基于当前全部判定结果，控制仲裁确定：

- 当前抓取入口不允许进入；
- 后续控制优先选择回流路径。

控制仲裁负责在多个状态和判定结果同时存在时，确定当前入口最终应采用的控制方向。

---

# 6. 多路径控制

根据控制仲裁结果，本次多路径控制选择“回流”作为后续候选路径。

这里的“回流”表示：当前抓取入口已经确定下一候选控制方向，系统准备转向另一条状态迁移路径。

此时尚未完成“进入回流路径”的前置判定，因此不能直接视为已经允许进入回流路径。

---

# 7. 当前入口控制结果

当前目标状态入口为“进入抓取阶段”。

该入口的控制结果为“不进入”。

因此，本周期机器人不会使用已经失效的视觉识别结果执行抓取。

系统同时确定新的候选目标状态：

- 目标状态：回流状态
- 目标状态入口：进入回流路径

到这里，当前“抓取入口 PCN”的责任范围完成。

---

# 8. 后续目标状态入口与执行结果

系统准备进入回流路径后，判定对象发生变化。

新的目标状态为“回流状态”，新的目标状态入口为“进入回流路径”。

对应 PCN 需要根据回流入口自身定义的相关状态和进入条件重新执行前置判定。

例如，回流入口可能需要确认：

- 回流输送带就绪状态；
- 回流路径可用状态；
- 区域许可；
- 工件当前位置；
- 回流下游承接状态。

这些状态不会因为抓取入口已经选择“回流”而自动成立。

只有当新的回流入口判定允许进入以后，系统才实际执行回流，并记录执行结果“工件已进入回流路径”。

本案例到这里停止，不继续展开回流入口的完整状态配置、CAE-SDB 判定和控制规则。

---

# 9. 状态迁移判定履历

本次抓取入口可以形成如下 PCN Trace（状态迁移判定履历）：

| 项目 | 记录内容 |
|---|---|
| 履历 ID | PCN-PICK-XXXX |
| PCN | 抓取入口 PCN |
| 当前状态 | 识别完成 / 等待抓取 |
| 目标状态 | 抓取阶段 |
| 目标状态入口 | 进入抓取阶段 |
| 判定时刻 | 10:32:21.850 |
| 机器人就绪 | 成立 |
| 安全许可 | 成立 |
| 正常投放位接收状态 | 成立 |
| 视觉识别结果 | 正常 |
| 视觉结果生成时刻 | 10:32:14.200 |
| CAE-SDB 判定结果 | C-D |
| 判定内容 | 视觉结果超过 5.0 s 有效时间窗口 |
| 控制仲裁结果 | 当前抓取入口不允许进入 |
| 多路径控制 | 选择回流作为后续候选路径 |
| 当前入口控制结果 | 当前抓取入口不进入 |
| 后续目标状态 | 回流状态 |
| 后续目标状态入口 | 进入回流路径 |
| 时间信息 | T |

这条履历记录的是一次明确目标状态入口中的状态、判定、控制和后续入口关系。

系统随后进入“回流路径”判定时，由回流入口对应的 PCN 形成新的状态迁移判定履历。

## 案例总结

本次示例中，机器人就绪、安全许可和正常投放位接收状态均已成立，视觉识别结果也为正常。

但视觉识别结果已经经过 7.650 s，超过本次示例设定的 5.0 s 有效时间窗口。

以“进入抓取阶段”这一目标状态入口为基准进行判定后，可以确认视觉结果已经失去动态时序有效性，因此形成 `C-D`。

当前抓取入口不允许进入，后续候选路径选择为回流。系统随后将“进入回流路径”作为新的目标状态入口，由对应 PCN 重新判定。

### 本次判定中明确的工程信息

| 原有现场能够确认 | 本次判定进一步明确 |
|---|---|
| 机器人已经就绪 | 机器人就绪属于当前抓取执行链中的相关状态之一，不能单独代表入口成立 |
| 视觉系统已经输出正常结果 | 当前结果虽然正常，但已经超过本次入口允许的有效时间 |
| 安全许可成立 | 关键 A 已成立，但不能替代 C 和 E 的判定 |
| 正常投放位可以接收 | 当前执行链相关状态满足本次入口要求 |
| 抓取动作没有开始 | 当前入口形成 `C-D` |
| 现场需要继续判断为什么不能抓取 | 问题已经定位到视觉结果的动态时序有效性 |
| 下一步需要决定如何处理 | 控制仲裁选择回流作为后续候选路径 |
| 回流路径可以使用 | 仍需在新的“进入回流路径”入口重新判定 |
| 不同系统分别保存状态或日志 | 当前状态、时间、判定、控制和后续目标状态入口可以关联到同一 PCN Trace |

本次案例完整展示了一个目标状态入口从状态获取、结构化判定、控制仲裁、多路径选择，到后续入口和状态迁移判定履历形成的工程过程。
