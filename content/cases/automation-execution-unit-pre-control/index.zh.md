## 为什么机器人已经就绪，仍不足以进入抓取阶段

> 应用层级：自动化执行单元层  
> 代表对象：视觉识别输送线机器人单元

**建议引用：**

```text
全野南政 / Nansei Zenno，《自动化执行单元前置判定案例：为什么机器人已经就绪，仍不足以进入抓取阶段》，公开案例，Public Case Version 1.5，2026-09-20，https://zennns.com/zh/cases/automation-execution-unit-pre-control/
```

视觉识别输送线机器人单元中，可能出现这样的现场状态：

机器人已经就绪，视觉系统也已经输出识别结果，安全系统没有明显异常，但抓取动作仍然没有开始。

机器人就绪只能说明机器人本体处于所定义的准备状态。真正进入抓取阶段，还要看当前工件条件、关键许可和抓取后的执行链是否满足当前入口要求。

本案例重点验证的不是“机器人是否就绪”这一单一状态，而是：

> **能否围绕“进入抓取阶段”这一明确目标状态入口，把分散在视觉、机器人、安全、输送和下游系统中的状态进一步组织为明确的 CAE-SDB 判定结果，并继续连接控制路径、后续状态迁移和状态迁移判定履历。**

本案例按照统一九步工程顺序展开：

```text
1. 当前状态
2. 目标状态 / 目标状态入口
3. PCN：相关状态获取 + C / A / E 状态映射
4. S / D / B 判定 → CAE-SDB 结果 + T
5. 控制仲裁
6. 多路径控制
7. 当前入口控制结果
8. 后续目标状态入口与执行结果
9. 状态迁移判定履历
```

## 案例对象

本案例以视觉识别输送线机器人单元为代表对象，并假设 PCN 由 PLC 内的控制逻辑实现。

与本次抓取入口有关的主要系统包括视觉系统、机器人控制器、安全系统、输送带、正常投放位和上位系统。

![视觉识别输送线机器人单元前置控制示意图](/images/tpca/06-pcn-pick-flow.png)

图：PCN 在机器人进入抓取阶段前取得与当前目标状态入口有关的多源状态，并根据判定结果形成控制路径。

---

# 1. 当前状态 / 当前阶段

现在现场是什么状态？

```text
当前状态：
识别完成 / 等待抓取
```

工件已经进入本次抓取流程，视觉识别结果已经生成，机器人尚未开始抓取。

这就是本次状态迁移的起点。

---

# 2. 目标状态 / 目标状态入口

这次准备进入哪里？

```text
目标状态：
抓取阶段

目标状态入口：
进入抓取阶段
```

PCN 位于当前状态与目标状态入口之间：

```text
当前状态［识别完成 / 等待抓取］
    ↓
PCN［进入抓取阶段前的判定］
    ↓
目标状态入口［进入抓取阶段］
    ↓
目标状态［抓取阶段］
```

![PCN 在目标阶段入口前的位置关系图](/images/tpca/07-pcn-position-before-target-stage.png)

图：PCN 在抓取动作真正开始之前，对“进入抓取阶段”这一目标状态入口进行前置判定。

---

# 3. PCN：相关状态获取与 C / A / E 状态映射

本次入口最关键的状态分别是什么？

PCN 取得与“进入抓取阶段”直接相关的状态，并按照其在本次目标状态入口中的作用进行 C / A / E 状态映射。

| 代表状态 | 状态映射 |
|---|---|
| 工件存在、位置、姿态、视觉识别结果 | C：条件状态 |
| 安全许可、区域许可、上位系统许可 | A：许可状态 |
| 机器人就绪、机器人路径、夹爪 / 真空状态、正常投放位接收状态 | E：执行链状态 |

本案例重点使用以下状态：

```text
视觉结果 → C
安全许可 → A
机器人就绪 → E 的相关输入
正常投放位接收状态 → E
```

机器人就绪并不单独代表整个执行链已经成立。

回流、异常分流等候选路径的可用状态属于后续控制选择信息，不作为当前抓取入口 E 的直接替代。

---

# 4. S / D / B 判定与 CAE-SDB 结果

本次实际出现了什么判定问题？

本案例假设：

```text
机器人就绪：
成立

安全许可：
成立

正常投放位接收状态：
满足当前入口要求

视觉结果：
已经超过有效时间
```

视觉结果属于 C，当前问题发生在其动态时序有效性，因此形成：

```text
CAE-SDB 结果：
C-D

视觉结果已经失效，
不能继续作为本次抓取入口的有效判定依据
```

时间信息 T 与本次状态及判定结果关联保存。

本案例不展开完整 9 个 CAE-SDB 坐标。C / A / E 与 S / D / B 的完整关系可参见：

[为什么是 CAE-SDB？——状态变量域与判定性质的双轴结构](/zh/notes/why-cae-sdb/)

---

# 5. 控制仲裁

多个结果一起出现时，最终优先处理什么？

本次控制仲裁的主要输入为：

```text
CAE-SDB 结果：
C-D

关键安全许可：
成立

当前抓取阶段所需执行链：
满足当前入口要求

回流路径：
可用
```

由于视觉结果已经失效，当前抓取入口不能继续按原识别结果进入抓取。

控制仲裁结果为：

```text
当前抓取入口不允许进入
优先选择回流路径
```

---

# 6. 多路径控制

选择了什么路径？

根据控制仲裁结果，本次形成：

```text
多路径控制：
回流
```

回流表示系统选择该路径作为后续候选控制路径。

---

# 7. 当前入口控制结果

本次入口到底进不进？

```text
当前入口控制结果：
当前抓取入口不进入
```

本次“进入抓取阶段”的目标状态入口未被允许。

同时已经确定：

```text
后续候选目标状态：
回流状态

后续候选目标状态入口：
进入回流路径
```

---

# 8. 后续目标状态入口与执行结果

实际执行以后发生了什么？

回流路径被选中后，系统准备进入新的状态迁移：

```text
目标状态：
回流状态

目标状态入口：
进入回流路径
```

回流入口由对应 PCN 按自身进入要求重新进行前置判定。

```text
当前抓取入口不进入
    ↓
多路径控制：回流
    ↓
目标状态入口［进入回流路径］
    ↓
回流入口对应 PCN
    ↓
若允许进入
    ↓
执行回流
    ↓
执行结果［工件已进入回流路径］
```

本公开案例不展开回流入口的具体状态配置和判定规则。

---

# 9. 状态迁移判定履历

这次状态迁移最终记录成什么？

本次抓取入口可以形成如下履历：

```text
PCN：
抓取入口 PCN

当前状态：
识别完成 / 等待抓取

目标状态：
抓取阶段

目标状态入口：
进入抓取阶段

主要状态：
  机器人就绪 = 成立
  安全许可 = 成立
  视觉结果 = 已过期

CAE-SDB 结果：
C-D

控制仲裁结果：
当前抓取入口不允许进入

多路径控制：
回流

当前入口控制结果：
当前抓取入口不进入

后续目标状态入口：
进入回流路径

时间信息：
T

履历 ID：
PCN-PICK-XXXX
```

当系统继续进入“回流路径”判定时，由回流入口对应 PCN 形成新的履历。

关于状态迁移判定履历的详细说明可参见：

[为什么状态迁移判定履历是一种新的工程数据？](/zh/notes/why-pcn-trace-is-engineering-data/)

## 案例总结

本案例中，机器人已经就绪，安全许可和正常投放位接收状态也满足当前入口要求。

如果只看机器人就绪状态，现场很容易得到：

> **“机器人已经准备好，但为什么仍然不抓取？”**

围绕“进入抓取阶段”这一目标状态入口重新组织后，本次问题被进一步明确为：

```text
目标状态入口：
进入抓取阶段

CAE-SDB 结果：
C-D

具体问题：
视觉结果已经超过有效时间，
不能继续作为当前抓取入口的有效判定依据
```

### 本案例带来的工程信息差异

| 原有现场能够确认 | 通过本案例进一步明确 |
|---|---|
| 机器人已经就绪 | 机器人就绪只是当前抓取入口中的一个相关状态，不能单独代表入口成立 |
| 视觉系统已经输出识别结果 | 当前真正需要确认的是该视觉结果是否仍属于本次工件、当前周期并保持有效 |
| 安全许可成立 | 关键 A 已成立，但这不能替代 C 和 E 的判定 |
| 正常投放位可以接收 | 当前抓取阶段所需 E 的一部分已经具备 |
| 抓取动作仍然没有开始 | CAE-SDB 结果为 **C-D：视觉结果已经超过有效时间** |
| 现场只能看到“机器人不动作” | 问题被进一步定位到“当前抓取入口所依赖的视觉条件已经失去动态时序有效性” |
| 工程师需要继续人工判断为什么不能抓 | 当前入口为什么不能进入已经被结构化说明 |
| 需要人工决定下一步怎么处理 | 控制路径明确为“回流” |
| 回流路径可用 | “选择回流”只表示确定了后续候选路径，不代表回流入口已经获得进入许可 |
| 各系统分别保存自己的状态和日志 | 本次状态、判定、控制以及后续目标状态入口被组织到同一次状态迁移判定履历中 |

由此，原本笼统的：

> **“机器人已经就绪，但抓取动作没有开始”**

被进一步转换为：

> **“当前抓取入口依赖的哪一个状态已经失效、为什么不能进入、系统选择了什么后续路径，以及下一步进入哪个新的状态迁移入口”。**

因此，本案例展示的主要工程效果是：

- 将机器人就绪、视觉结果、安全许可和下游承接状态组织到同一次目标状态入口；
- 将“机器人已经就绪但仍不动作”进一步定位到明确的 CAE-SDB 判定问题；
- 将设备就绪状态与当前入口成立条件区分开来；
- 将判定结果直接连接到当前入口控制结果和后续控制路径；
- 将当前抓取入口与后续回流入口明确分离；
- 将本次状态、判定、控制和后续状态迁移关系形成统一的状态迁移判定履历。

本案例的效果不是增加更多机器人、视觉或安全状态，而是：

> **把原本分散在多个系统中的状态，进一步组织成“当前入口为什么不能成立、哪一类状态发生了什么问题、应该选择什么控制路径，以及后续进入哪个新的状态迁移入口”的完整工程关系。**
