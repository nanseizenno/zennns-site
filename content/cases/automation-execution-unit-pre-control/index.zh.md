## 为什么 Robot Ready 不代表可以进入抓取阶段

> 应用层级：自动化执行单元层

## 1. 现场问题

视觉系统已经输出 OK。

机器人显示 Ready。

安全系统没有明显异常。

PLC 侧也没有直接阻断。

但机器人仍然没有进入抓取阶段。

继续排查后，可能发现：

- 视觉结果虽然曾经有效，但已经超时；
- 工件已经接近或离开可抓取区域；
- 区域许可尚未成立；
- 正常投放位暂时无法承接；
- 返回路径不可用；
- 异常分流路径没有准备好；
- 结果回写链路无法继续。

表面上看到的是：

> **Robot Ready，为什么还是不抓？**

真正的问题是：

> **Robot Ready 只说明机器人本体具备一定的运行能力，并不能证明“进入抓取阶段”这一次状态迁移已经成立。**

机器人准备进入的不是一个孤立动作，而是一条后续仍需继续接续的物理执行链。

因此，PLC / PCN 需要在抓取阶段真正进入之前，对与本次状态迁移相关的条件、许可和执行链进行统一判断。

---

## 2. 案例对象与 PCN 位置

本案例以视觉识别输送线机器人单元为代表例。

工件由主输送带连续进入。

视觉系统完成识别后，可以提供：

- 工件存在状态；
- 位置；
- 姿态；
- 识别置信度；
- 异常判定；
- 结果时间信息；
- 工件跟踪信息。

PLC / PCN 在机器人进入抓取阶段之前，读取与本次状态迁移有关的多源状态。

当前阶段：

```text
机器人等待
+
工件进入识别与抓取区域
+
视觉结果已经生成
```

目标阶段：

```text
机器人进入抓取阶段
```

PCN 位置：

```text
当前阶段
→ PCN
→ 目标抓取阶段
```

![视觉识别输送线机器人单元前置控制示意图](/images/tpca/06-pcn-pick-flow.png)

图：PLC / PCN 在机器人进入抓取阶段前，汇总视觉系统、机器人控制器、安全系统、主输送带、正常投放位、返回路径、异常分流路径和上位系统等状态，完成前置判定并形成对应控制路径。

![PCN 在目标阶段入口前的位置关系图](/images/tpca/07-pcn-position-before-target-stage.png)

图：PCN 部署在当前阶段与目标阶段之间，在抓取动作真正启动之前完成判定。

PCN 的位置决定了它处理的是：

> **是否进入目标物理执行阶段。**

而不是动作失败以后再解释为什么失败。

## 3. 多源状态信号与 C / A / E 状态映射

PLC / PCN 不只读取一个 Ready 信号。

它读取的是与“进入抓取阶段”直接相关的多源状态。

| 信号来源 | 代表性状态 |
|---|---|
| 视觉系统 | 工件存在、位置、姿态、识别置信度、异常判定、结果时间、结果有效状态、工件跟踪信息 |
| 主输送带 | 运行状态、速度、位置、工件是否处于抓取区域 |
| 返回输送带 | 运行状态、可接收状态、返回路径是否可用 |
| 异常输送带 | 运行状态、可接收状态、异常分流路径是否可用 |
| 正常投放位 | 是否空位、是否可承接、前一件处理是否完成 |
| 机器人控制器 | 自动模式、Ready、当前位置、路径可达、程序状态、动作完成、夹爪 / 真空状态、报警状态 |
| 安全系统 | 安全门、光栅、急停、安全回路、区域进入许可 |
| 上位系统 / HMI | 工单、生产许可、异常品处理许可、人工确认、结果记录或回写要求 |

这些状态进入 PCN 后，根据本次目标状态进行 C / A / E 映射。

| 变量域 | 判定问题 | 本案例中的代表项 |
|---|---|---|
| C：Condition | 工件是否构成当前可抓取对象 | 工件存在、位置合格、姿态合格、视觉结果有效、置信度满足、工件跟踪关系正确 |
| A：Authority | 系统是否允许进入抓取阶段 | 安全许可、区域许可、PLC 放行、上位许可、必要人工确认 |
| E：Execution Chain | 进入抓取阶段以后，执行链是否能够继续接续 | 机器人路径可达、夹爪可用、正常投放位可承接、返回路径可用、异常分流路径可用、结果回写链路可用 |

因此：

```text
Robot Ready
≠
进入抓取阶段的完整条件已经成立
```

例如：

机器人 Ready，但视觉结果已经失效，C 不成立。

机器人 Ready，但区域许可未成立，A 不成立。

机器人 Ready，但正常投放位和替代路径都无法承接，E 不成立。

Robot Ready 只是与本次状态迁移有关的一个输入。

## 4. S / D / B 判定

完成 C / A / E 状态映射以后，PCN 进一步从 S / D / B 三类性质进行判定。

| 判定性质 | 判定问题 | 本案例中的代表项 |
|---|---|---|
| S：Structure | 本次判定所需要的信号、接口、映射关系、许可来源和执行链边界是否已经定义、接入并可观测 | 视觉接口、坐标映射、安全许可来源、返回路径、异常分流路径、结果回写接口 |
| D：Dynamics | 当前状态是否仍然有效、同步并可用于本次判定 | 视觉结果未刷新、位置追踪不同步、许可撤销、机器人状态延迟、下游状态冲突 |
| B：Boundary | 当前状态是否进入预设控制边界 | 结果有效时间、识别置信度、位置或姿态偏差、等待时间、重试次数、补偿范围 |

例如：

视觉结果接口和坐标映射都存在，但结果已经超过有效时间。

这时问题不在结构缺失，而在动态时序有效性。

再例如：

工件仍然可以识别，但位置已经接近可抓取边界。

此时可以进入相应控制边界判断，并决定继续抓取、重新定位、回流或进入其他处理路径。

## 5. CAE-SDB 判定结果、控制仲裁与多路径控制

PCN 对 C / A / E 状态进行 S / D / B 判定后，可以形成一个或多个 CAE-SDB 判定结果。

代表性结果包括：

| 判定结果 | 本案例中的代表性问题 |
|---|---|
| C-S | 视觉接口未接入；坐标映射未建立；工件跟踪关系未定义 |
| C-D | 视觉结果未刷新；工件位置与输送带追踪不同步；识别结果发生冲突 |
| C-B | 识别结果接近有效时间边界；位置或姿态接近允许边界 |
| A-S | 安全许可、区域许可或上位许可来源未定义或不可观测 |
| A-D | 许可反复撤销、延迟、未刷新或处于切换状态 |
| A-B | 许可等待进入预设控制边界 |
| E-S | 正常投放、返回、异常分流或结果回写链路未完整定义 |
| E-D | 下游状态未刷新；机器人动作反馈超时；返回路径状态冲突 |
| E-B | 下游等待、缓冲能力或备用路径进入预设控制边界 |

同一次状态迁移中可以同时出现多个判定结果。

这些结果进入控制仲裁以后，再形成最终多路径控制。

本案例中的代表性控制路径可以包括：

- 允许进入抓取阶段；
- 等待；
- 重识别；
- 重采样；
- 重定位；
- 回流；
- 异常分流；
- 下游协调；
- 人工确认；
- 禁止进入；
- 安全相关控制；
- 增强记录。

因此，系统不再只有：

```text
抓取 OK
抓取 NG
```

而是可以根据当前状态进入不同处理路径。

## 6. 一个典型判定过程

以“视觉曾经 OK、Robot Ready，但机器人没有抓取”为例。

当前阶段：

```text
识别完成 / 等待抓取
```

目标阶段：

```text
进入抓取阶段
```

当前状态：

```text
机器人 Ready：成立
安全许可：成立
视觉结果：已超过当前有效时间
返回路径：可用
```

PCN 可以形成：

```text
C-D：
视觉结果当前已失效

A：
关键许可成立

E：
返回路径可接续
```

控制仲裁后，本次抓取不放行。

最终控制路径：

```text
不进入抓取
→ 工件回流
→ 重新识别
```

PCN Trace 可以记录：

```text
当前阶段：识别完成 / 等待抓取
目标阶段：进入抓取阶段

主要判定：
C-D：视觉结果已失效

控制结果：
回流再识别

执行结果：
工件进入返回路径

Trace ID：
PCN-PICK-XXXX
```

另一个场景中，如果关键安全许可未成立，则即使 C 和 E 均满足，也不能进入抓取阶段。

这时 PCN 记录的是另外一种状态迁移结果，而不是简单写成同一个“抓取 NG”。

## 7. PCN Trace 与工程复盘

PCN 在形成控制路径的同时，可以记录本次状态迁移的判定履历。

公开层面的代表性内容包括：

- 当前阶段；
- 目标阶段；
- 关键输入状态；
- 输入时间信息；
- C / A / E 状态映射；
- S / D / B 判定；
- CAE-SDB 判定结果；
- 控制仲裁结果；
- 多路径控制结果；
- 执行结果；
- Trace ID。

这些记录可以用于：

- HMI 结构化显示；
- 现场问题复盘；
- 高频状态迁移问题统计；
- 改善前后比较；
- 同类自动化单元复用；
- 项目交接与新人培训。

记录的重点不是增加更多原始日志，而是保存：

> **为什么本次没有进入抓取阶段，以及系统最终进入了哪一条控制路径。**

## 8. 案例意义与公开边界

本案例说明：

> **自动化执行单元进入目标物理执行阶段之前，不能只依赖单体 Ready 判断。**

在视觉识别输送线机器人单元中，Robot Ready 只说明机器人本体具备一定的运行能力。

系统能否进入抓取阶段，还需要综合：

- 工件条件；
- 识别结果；
- 关键许可；
- 机器人本体与末端执行机构；
- 正常投放路径；
- 返回路径；
- 异常分流路径；
- 下游承接；
- 结果回写。

TPCA / PCN 将这些原本分散在 PLC 程序、视觉接口、机器人控制器、安全系统、下游设备和上位系统中的状态，围绕“进入抓取阶段”这一明确入口组织起来。

其工程链为：

```text
当前阶段
→ 目标阶段
→ PCN
→ C/A/E 状态映射
→ S/D/B 判定
→ CAE-SDB 判定结果
→ 控制仲裁
→ 多路径控制
→ PCN Trace
```

本文为公开说明案例。

公开内容用于说明：

- PCN 的部署位置；
- 多源状态；
- C / A / E 状态映射；
- S / D / B 判定；
- CAE-SDB 判定结果；
- 控制仲裁；
- 代表性多路径控制；
- PCN Trace 的基本作用。

具体阈值、等待窗口、重试次数、完整控制优先级、内部配置结构、接口参数、运行生命周期和详细 Trace 结构，应根据实际设备、安全要求和工程实现另行确定。
