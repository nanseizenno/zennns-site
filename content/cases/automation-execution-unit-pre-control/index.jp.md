## なぜ Robot Ready はピック工程へ進入できることを意味しないのか

> 適用レベル：自動化実行ユニット層  
> 代表対象：画像認識コンベヤロボットユニット

## 1. 現場問題

画像認識コンベヤロボットユニットでは、次のような現象が発生することがある。

- 画像認識システムはすでに OK を出力している；
- ロボットは Ready を表示している；
- 安全システムに明確な異常はない；
- PLC 側では直接的な阻止条件が成立していない；
- それでもロボットはピック工程へ進入しない。

さらに確認すると、次のような状態が見つかることがある。

- 画像認識結果は一度有効だったが、現在はすでにタイムアウトしている；
- ワークがピック可能領域の境界付近、または領域外へ移動している；
- エリア許可がまだ成立していない；
- 正常投入先が一時的に受入できない；
- 戻り経路が使用できない；
- 異常分流経路の準備が完了していない；
- 結果書戻し経路が継続できない。

表面的な現象は、次のようにまとめられる。

> **Robot Ready なのに、なぜピック工程へ進入しないのか？**

重要なのは、次の点である。

> **Robot Ready は、ロボット本体が局所的な運転条件を満たしていることを示すにすぎず、「ピック工程へ進入する」という Target State Entry が成立していることを証明するものではない。**

ロボットがピック工程へ進入した後も、後続の物理実行チェーンは継続して接続される必要がある。

したがって、PLC / PCN は、実際にピック工程へ進入する前に、本状態遷移に関係する条件、許可、実行チェーン状態を統一的に判定する必要がある。

## 2. 事例対象と PCN の位置

本事例では、画像認識コンベヤロボットユニットを代表対象とする。

ワークはメインコンベヤから連続的に搬送され、画像認識システムによる認識後、次の情報を取得できる。

- ワーク存在状態；
- 位置；
- 姿勢；
- 認識信頼度；
- 異常判定；
- 結果の時間情報；
- ワーク追跡情報。

PLC / PCN は、ロボットがピック工程へ進入する前に、本状態遷移に関係する複数ソース状態を取得する。

現在段階：

```text
ロボット待機
+
ワークが認識・ピック領域へ進入
+
画像認識結果が生成済み
```

目標段階：

```text
ロボットがピック工程へ進入
```

PCN の位置：

```text
現在段階 → PCN → 目標ピック工程
```

![画像認識コンベヤロボットユニット前制御概念図](/images/tpca/06-pcn-pick-flow.png)

図：PLC / PCN は、ロボットがピック工程へ進入する前に、画像認識システム、ロボットコントローラ、安全システム、メインコンベヤ、正常投入先、戻り経路、異常分流経路、上位システムなどの状態を集約し、前判定を行って対応する制御経路を形成する。

![PCN の Target State Entry 前における位置関係図](/images/tpca/07-pcn-position-before-target-stage.png)

図：PCN は現在段階と目標段階の間に位置し、実際のピック動作が開始される前に前判定を完了する。

本事例における PCN の役割は、

> **「ピック工程へ進入する」という明確な Target State Entry に対する前判定である。**

ピック工程へ進入した後に運転状態が変化した場合、システムは新しい Current State を形成し、後続の Target State を対象として新たな状態遷移判定を行う。

したがって、TPCA / PCN が対象とするのは、すべての運転プロセスを一つのノードへ圧縮することではなく、それぞれの明確な Target State Entry を対象として独立した判定を行うことである。

PCN のエンジニアリング上の位置については、以下を参照。

[なぜ PCN は TPCA の最小エンジニアリングノードなのか？](/ja/notes/pcn-minimum-engineering-unit/)

## 3. 複数ソース状態信号と C / A / E 状態マッピング

PLC / PCN は、単一の Ready 信号を最終判断の根拠とせず、「ピック工程へ進入する」ことに直接関係する複数ソース状態を取得する。

| 信号源 | 代表的な状態 |
|---|---|
| 画像認識システム | ワーク存在、位置、姿勢、認識信頼度、異常判定、結果時刻、結果有効状態、ワーク追跡情報 |
| メインコンベヤ | 運転状態、速度、位置、ワークがピック領域内にあるか |
| 戻りコンベヤ | 運転状態、受入可能状態、戻り経路が使用可能か |
| 異常分流コンベヤ | 運転状態、受入可能状態、異常分流経路が使用可能か |
| 正常投入先 | 空きがあるか、受入可能か、前ワークの処理が完了しているか |
| ロボットコントローラ | 自動モード、Ready、現在位置、経路到達可能、プログラム状態、動作完了、グリッパ / 真空状態、アラーム状態 |
| 安全システム | 安全扉、ライトカーテン、非常停止、安全回路、エリア進入許可 |
| 上位システム / HMI | 作業指示、製造許可、異常品処理許可、人による確認、結果記録または書戻し要求 |

これらの状態は PCN に入力された後、本 Target State Entry における役割に基づいて C / A / E へマッピングされる。

| 変数領域 | 判定する問題 | 本事例における代表項目 |
|---|---|---|
| C：Condition | ワークが現在ピック可能な対象として成立しているか | ワーク存在、位置適合、姿勢適合、画像認識結果有効、信頼度条件成立、ワーク追跡関係が正しい |
| A：Authority | システムとしてピック工程への進入が許可されているか | 安全許可、エリア許可、PLC からの許可、上位許可、必要な人による確認 |
| E：Execution Chain | ピック工程へ進入した後、実行チェーンが継続できるか | ロボット経路到達可能、グリッパ使用可能、正常投入先受入可能、戻り経路使用可能、異常分流経路使用可能、結果書戻し経路使用可能 |

したがって、

```text
Robot Ready ≠ ピック工程への進入条件が完全に成立
```

である。

たとえば、

- Robot Ready が成立していても、画像認識結果が失効していれば、C に関係する条件は成立しない；
- Robot Ready が成立していても、エリア許可が成立していなければ、A は成立しない；
- Robot Ready が成立していても、正常投入先および代替経路のいずれも受入できなければ、E は成立しない。

Robot Ready は、本状態遷移に関係する一つの入力状態にすぎない。

---

## 4. S / D / B 判定

C / A / E 状態マッピングを完了した後、PCN はさらに S / D / B の 3 つの判定性質から分析する。

| 判定性質 | 判定する問題 | 本事例における代表項目 |
|---|---|---|
| S：Structure | 本判定に必要な信号、インターフェース、マッピング関係、許可元、実行チェーン境界が定義・接続され、観測可能になっているか | 画像認識インターフェース、座標マッピング、安全許可元、戻り経路、異常分流経路、結果書戻しインターフェース |
| D：Dynamics | 現在状態が今も有効で、同期され、本判定に適用可能か | 画像認識結果未更新、位置追跡非同期、許可取消、ロボット状態遅延、下流状態競合 |
| B：Boundary | 現在状態が事前に定義された制御境界に入っているか | 結果有効時間、認識信頼度、位置または姿勢偏差、待ち時間、リトライ回数、補正範囲 |

たとえば、画像認識結果のインターフェースと座標マッピングがともに確立されていても、認識結果が有効時間を超えている場合がある。

この場合、問題は構造完全性ではなく、動的時系列有効性に属する。

また、ワークは引き続き認識可能であっても、その位置がピック可能範囲の事前定義された境界に近づいている場合がある。

この場合は対応する Boundary 判定を形成する必要があり、その後にピックを継続するか、再位置決めするか、回流させるか、その他の処理経路へ進めるかは、完全な判定結果と Arbitration に基づいて決定する。

---

## 5. CAE-SDB Result、時間情報 T、Arbitration、Multipath Control

PCN は C / A / E 状態に対して S / D / B 判定を行った後、1 つまたは複数の CAE-SDB Result を形成し、本状態および判定に対応する時間情報 T を保持する。

代表的な結果を以下に示す。

| 判定結果 | 本事例における代表的な問題 |
|---|---|
| C-S | 画像認識インターフェース未接続；座標マッピング未設定；ワーク追跡関係未定義 |
| C-D | 画像認識結果未更新；ワーク位置とコンベヤ追跡が非同期；認識結果が競合 |
| C-B | 認識結果が有効時間境界に接近；位置または姿勢が許容境界に接近 |
| A-S | 安全許可、エリア許可、上位許可の取得元が未定義または観測不能 |
| A-D | 許可が繰り返し取消される、遅延する、未更新、または切替中 |
| A-B | 許可待ちが事前定義された制御境界に到達 |
| E-S | 正常投入、戻り、異常分流、結果書戻し経路が完全に定義されていない |
| E-D | 下流状態未更新；ロボット動作フィードバックタイムアウト；戻り経路状態が競合 |
| E-B | 下流待ち、バッファ能力、代替経路が事前定義された制御境界に到達 |

同一の状態遷移において、複数の判定結果が同時に形成されることがある。

基本的な制御チェーンは、次のように表せる。

```text
CAE-SDB Result + T → Arbitration → Multipath Control
```

これらの結果に対して Arbitration を行った後、最終的な Multipath Control を形成する。

本事例における代表的な制御経路には、次のようなものがある。

- ピック工程への進入許可；
- 待機；
- 再認識；
- 再サンプリング；
- 再位置決め；
- 回流；
- 異常分流；
- 下流調整；
- 人による確認；
- 進入禁止；
- 安全関連制御；
- 強化記録。

これらの名称は、それぞれ異なるエンジニアリング用途の制御経路を表す。

TPCA の状態遷移視点では、最終的にはすべて、

> **Current State から、新しい Target State または目標実行経路へ進む**

ことに対応する。

したがって、システムの処理結果は、

```text
ピック OK
ピック NG
```

だけに限定されず、Current State と判定結果に応じて異なる制御経路へ進むことができる。

## 6. 代表的な判定プロセス

「画像認識結果は一度有効で、Robot Ready も成立しているが、ロボットがピック工程へ進入していない」ケースを例とする。

現在段階：

```text
認識完了 / ピック待ち
```

目標段階：

```text
ピック工程へ進入
```

現在状態：

```text
Robot Ready：成立
安全許可：成立
画像認識結果：現在の有効時間を超過
戻り経路：使用可能
```

PCN は、次のような結果を形成できる。

```text
C-D：
画像認識結果が現在は失効

A：
重要許可が成立

E：
戻り経路が継続可能
```

同時に、本状態および判定に対応する時間情報 T を保持する。

Arbitration の結果、本ピック動作は許可されない。

代表的な制御経路は、次の通りである。

```text
ピック工程へ進入しない → ワークを回流 → 再認識
```

ここでいう「回流」と「再認識」は、いずれも後続の新しい Target State または目標実行経路であり、システムが以前の状態インスタンスへ戻ることを意味しない。

PCN Trace には、たとえば次の内容を記録できる。

```text
現在段階：認識完了 / ピック待ち
目標段階：ピック工程へ進入

時間情報：
T

主要判定：
C-D：画像認識結果が失効

制御結果：
回流後に再認識

実行結果：
ワークが戻り経路へ進入

Trace ID：
PCN-PICK-XXXX
```

重要な安全許可が成立していない場合は、C と E がともに成立していても、ピック工程へ進入してはならない。

この場合は、別の状態遷移判定結果として扱われ、「ピック NG」に一括して記録するものではない。

## 7. PCN Trace とエンジニアリング振り返り

PCN は制御経路を形成すると同時に、本状態遷移に関する判定履歴を記録できる。

公開レベルでの代表的な記録内容には、次のものが含まれる。

- 現在段階；
- 目標段階；
- 主要入力状態；
- 時間情報 T；
- C / A / E 状態マッピング；
- S / D / B 判定；
- CAE-SDB Result；
- Arbitration Result；
- Multipath Control Result；
- 実行結果；
- Trace ID。

これらの記録は、次の用途に利用できる。

- HMI での構造化表示；
- 現場問題の振り返り；
- 頻発する状態遷移問題の集計；
- 改善前後比較；
- 同種自動化ユニットへの再利用；
- プロジェクト引継ぎと新人教育。

記録の重点は、単純に生ログの量を増やすことではなく、

> **今回なぜピック工程へ進入しなかったのか、そしてシステムが最終的にどの Target State または制御経路へ進んだのか**

を保存することである。

時間情報 T は、エンジニアリング上の状態内容が同じであっても、異なる時間位置で発生した状態インスタンスを区別するためにも使用できる。

## 8. 事例の意味と公開範囲

本事例が示しているのは、次の点である。

> **自動化実行ユニットが目標物理実行段階へ進入する前に、単体の Ready だけを根拠として Target State Entry の成立を判断することはできない。**

画像認識コンベヤロボットユニットでは、Robot Ready は、ロボット本体が局所的な運転条件を満たしていることを示すにすぎない。

システムがピック工程へ進入できるかどうかは、さらに次の要素に依存する。

- ワーク条件；
- 画像認識結果；
- 重要許可；
- ロボット本体とエンドエフェクタ；
- 正常投入経路；
- 戻り経路；
- 異常分流経路；
- 下流受入；
- 結果書戻し。

TPCA / PCN は、従来 PLC プログラム、画像認識インターフェース、ロボットコントローラ、安全システム、下流設備、上位システムなどに分散していた状態を、「ピック工程へ進入する」という明確な Target State Entry を中心として整理する。

そのエンジニアリングチェーンは、次の通りである。

```text
現在段階
→ 目標段階
→ PCN
→ C / A / E 状態マッピング
→ S / D / B 判定
→ CAE-SDB Result + T
→ Arbitration
→ Multipath Control
→ PCN Trace
```

ピック工程へ進入した後に運転状態が変化した場合、システムは新しい Current State を形成し、新しい Target State を対象として次の状態遷移判定を行う。

したがって、回流、戻り、再認識、異常分流、人による確認、安全関連経路などは、現場における既存のエンジニアリング名称をそのまま使用できるが、TPCA の状態遷移視点では、いずれも新しい Target State または目標実行経路として扱われる。

本稿は公開説明用の事例である。

公開内容は、次の事項を説明することを目的としている。

- PCN のエンジニアリング上の位置；
- 複数ソース状態；
- C / A / E 状態マッピング；
- S / D / B 判定；
- CAE-SDB Result；
- 時間情報 T；
- Arbitration；
- 代表的な Multipath Control；
- PCN Trace の基本的な役割。

具体的なしきい値、待機ウィンドウ、リトライ回数、完全な制御優先度、内部設定構造、インターフェースパラメータ、ランタイムライフサイクル、詳細な Trace 構造については、実際の設備、安全要求、具体的なエンジニアリング実装に応じて別途決定する必要がある。
