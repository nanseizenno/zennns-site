## なぜ Robot Ready だけではピックアップ段階へ移行できることを意味しないのか

> 適用レベル：自動化実行ユニット層  
> 代表対象：画像認識搬送ラインのロボットユニット

## 1. 現場の問題

画像認識システムはすでに OK を出力している。

ロボットは Ready を表示している。

安全システムにも明確な異常はない。

PLC 側にも直接的な阻害条件はない。

それでも、ロボットはピックアップ段階へ入らない。

さらに確認すると、次のような状態が見つかる場合がある。

- 画像認識結果は一度有効だったが、すでにタイムアウトしている；
- ワークがピックアップ可能領域の境界に近づいている、またはすでに外れている；
- エリア許可がまだ成立していない；
- 正常品投入位置が一時的に受け入れできない；
- 回流経路が使用できない；
- 異常分流経路の準備が完了していない；
- 結果書戻しチェーンを継続できない。

表面的には、次のように見える。

> **Robot Ready なのに、なぜまだピックアップしないのか？**

本質的な問題は、次にある。

> **Robot Ready はロボット本体が一定の運転能力を持つことを示すだけであり、「ピックアップ段階へ入る」という今回の状態遷移が成立していることを意味しない。**

ロボットがこれから入ろうとしているのは、孤立した一つの動作ではなく、その後も継続する必要がある物理実行チェーンである。

そのため PLC / PCN は、ピックアップ段階へ実際に入る前に、今回の Target State Entry に関係する条件、許可、実行チェーンを統合して判定する必要がある。

## 2. 事例対象と PCN の位置

本事例では、画像認識搬送ラインのロボットユニットを代表例とする。

ワークは主搬送コンベヤから連続的に流入する。

画像認識システムは認識完了後、次のような状態を提供できる。

- ワーク存在状態；
- 位置；
- 姿勢；
- 認識信頼度；
- 異常判定；
- 結果時刻情報；
- ワーク追跡情報。

PLC / PCN は、ロボットがピックアップ段階へ入る前に、今回の状態遷移に関係する複数ソース状態信号を取得する。

Current State：

```text
ロボット待機
+
ワークが認識・ピックアップ領域へ進入
+
画像認識結果が生成済み
```

Target State：

```text
ロボットがピックアップ段階へ入る
```

PCN の位置：

```text
Current State
→ PCN
→ Target State
```

![画像認識搬送ラインのロボットユニット前制御概念図](/images/tpca/06-pcn-pick-flow.png)

図：PLC / PCN は、ロボットがピックアップ段階へ入る前に、画像認識システム、ロボットコントローラ、安全システム、主搬送コンベヤ、正常品投入位置、回流経路、異常分流経路、上位システムなどの複数ソース状態信号を集約し、前置判定を行って対応する制御経路を形成する。

![Target State 入口前に配置される PCN の位置関係](/images/tpca/07-pcn-position-before-target-stage.png)

図：PCN は Current State と Target State の間に配置され、実際にピックアップ動作を開始する前に判定を完了する。

PCN の位置によって、扱う対象が決まる。

> **Target State へ入るかどうかを判定する。**

動作失敗後に、その理由を説明することが主目的ではない。

PCN のエンジニアリング上の位置については、以下を参照。

[なぜ PCN は TPCA の最小エンジニアリングノードなのか？](/jp/notes/pcn-minimum-engineering-unit/)

## 3. 複数ソース状態信号と C / A / E 状態マッピング

PLC / PCN は、一つの Ready 信号だけを取得するのではない。

「ピックアップ段階へ入る」という Target State Entry に直接関係する複数ソース状態信号を取得する。

| 信号源 | 代表的な状態 |
|---|---|
| 画像認識システム | ワーク存在、位置、姿勢、認識信頼度、異常判定、結果時刻、結果有効状態、ワーク追跡情報 |
| 主搬送コンベヤ | 運転状態、速度、位置、ワークがピックアップ領域にあるか |
| 回流搬送コンベヤ | 運転状態、受入可否、回流経路が使用可能か |
| 異常品排出コンベヤ | 運転状態、受入可否、異常分流経路が使用可能か |
| 正常品投入位置 | 空き状態、受入可否、前ワークの処理完了状態 |
| ロボットコントローラ | 自動モード、Ready、現在位置、経路到達可否、プログラム状態、動作完了、グリッパ / 真空状態、アラーム状態 |
| 安全システム | 安全扉、ライトカーテン、非常停止、安全回路、エリア進入許可 |
| 上位システム / HMI | 作業指示、生産許可、異常品処理許可、手動確認、結果記録または書戻し要求 |

これらの状態は PCN に入力された後、今回の Target State を基準として C / A / E 状態マッピングを行う。

| 状態変数領域 | 判定する問題 | 本事例における代表項目 |
|---|---|---|
| C：Condition / 条件状態 | ワークが現在のピックアップ対象として成立しているか | ワーク存在、位置合格、姿勢合格、画像認識結果有効、認識信頼度条件成立、ワーク追跡関係が正しい |
| A：Authority / 許可状態 | システムがピックアップ段階への進入を許可しているか | 安全許可、エリア許可、PLC 放行、上位許可、必要な手動確認 |
| E：Execution Chain / 実行チェーン状態 | ピックアップ段階へ入った後、実行チェーンが継続可能か | ロボット経路到達可、グリッパ使用可、正常品投入位置が受入可、回流経路が使用可、異常分流経路が使用可、結果書戻しチェーンが使用可 |

したがって：

```text
Robot Ready
≠
Target State へ入るための条件・許可・実行チェーンが成立している
```

例えば：

ロボットが Ready でも、画像認識結果がすでに失効していれば、C は成立しない。

ロボットが Ready でも、エリア許可が成立していなければ、A は成立しない。

ロボットが Ready でも、正常品投入位置と代替経路のいずれも受け入れできなければ、E は成立しない。

Robot Ready は、今回の Target State Entry に関係する一つの入力にすぎない。

---

## 4. S / D / B 判定

C / A / E 状態マッピングの後、PCN はさらに S / D / B の三つの判定性質から評価する。

| 判定性質 | 判定する問題 | 本事例における代表項目 |
|---|---|---|
| S：Structure / 構造完全性 | 今回の判定に必要な信号、インターフェース、マッピング関係、許可元、実行チェーン境界が定義・接続され、観測可能になっているか | 画像認識インターフェース、座標マッピング、安全許可元、回流経路、異常分流経路、結果書戻しインターフェース |
| D：Dynamics / 動的時系列有効性 | 関連状態が現在も有効で、同期・安定しており、今回の Target State Entry の判定根拠として使用できるか | 画像認識結果が未更新、位置追跡が非同期、許可が撤回、ロボット状態が遅延、下流状態が競合 |
| B：Boundary / 制御境界 | 関連状態が事前に定義された制御境界に到達しているか | 結果有効時間、認識信頼度、位置・姿勢偏差、待機時間、再試行回数、補正範囲 |

例えば：

画像認識インターフェースと座標マッピングは存在するが、結果がすでに有効時間を超えている。

この場合、問題は Structure ではなく Dynamics にある。

また例えば：

ワークは引き続き認識可能だが、位置がピックアップ可能境界に近づいている。

この場合は Boundary の判定対象となり、最終的な制御経路は CAE-SDB Result 全体を基に Arbitration を行った後に決定する。

---

## 5. CAE-SDB Result、Arbitration、Multipath Control

PCN は C / A / E の状態変数を S / D / B の判定性質から評価し、一つまたは複数の CAE-SDB Result を形成する。

代表的な結果は次の通りである。

| CAE-SDB Result | 本事例における代表的な問題 |
|---|---|
| C-S | 画像認識インターフェースが未接続；座標マッピングが未構築；ワーク追跡関係が未定義 |
| C-D | 画像認識結果が未更新；ワーク位置とコンベヤ追跡が非同期；認識結果に競合が発生 |
| C-B | 認識結果が有効時間境界に接近；位置または姿勢が許容境界に接近 |
| A-S | 安全許可、エリア許可、上位許可の発生源が未定義または観測不能 |
| A-D | 許可が反復して撤回、遅延、未更新、または切替中 |
| A-B | 許可待機が事前定義された制御境界に到達 |
| E-S | 正常投入、回流、異常分流、結果書戻しチェーンが完全に定義されていない |
| E-D | 下流状態が未更新；ロボット動作フィードバックがタイムアウト；回流経路状態が競合 |
| E-B | 下流待機、バッファ能力、代替経路が事前定義された制御境界に到達 |

同一の状態遷移では、複数の CAE-SDB Result が同時に成立する場合がある。

これらはそのまま最終制御指令にはならない。

```text
CAE-SDB Result
→ Arbitration
→ Multipath Control
```

Arbitration では、完全な CAE-SDB Result と事前定義された制御制約に基づいて制御優先関係を処理し、最終的な制御方向を決定する。

その後、Multipath Control によって実際の制御経路へ変換する。

本事例における代表的な制御経路には、次のようなものがある。

- 進入許可；
- 待機；
- 再認識；
- 再サンプリング；
- 再位置決め；
- 回流；
- 異常分流；
- 下流調整；
- 手動確認；
- 進入禁止；
- 安全ロック；
- 強化記録。

したがって、システムは次の二値だけで処理する必要はない。

```text
ピックアップ OK
ピックアップ NG
```

Target State Entry 前の状態に応じて、異なる制御経路へ進むことができる。

## 6. 代表的な判定プロセス

「画像認識は一度 OK、Robot Ready だが、ロボットがピックアップしない」場面を例にする。

Current State：

```text
認識完了 / ピックアップ待機
```

Target State：

```text
ピックアップ段階
```

現在状態：

```text
Robot Ready：成立
安全許可：成立
画像認識結果：現在の有効時間を超過
回流経路：使用可能
```

PCN は、例えば次の CAE-SDB Result を形成できる。

```text
C-D：
画像認識結果が今回の Target State Entry の有効な判定根拠として使用できない

A：
重要許可成立

E：
回流経路は継続可能
```

Arbitration の結果、今回のピックアップは許可されない。

Multipath Control：

```text
ピックアップ段階へ進入しない
→ 回流
→ 再認識
```

PCN Trace には、例えば次を記録できる。

```text
Current State：
認識完了 / ピックアップ待機

Target State：
ピックアップ段階

CAE-SDB Result：
C-D

Arbitration Result：
今回のピックアップを許可しない

Multipath Control：
回流 / 再認識

実行結果：
ワークは回流経路へ進入

Trace ID：
PCN-PICK-XXXX
```

別の場面で重要な A 許可が成立していない場合は、C と E がいずれも成立していても Target State への進入は許可されない。

この場合、PCN は別の状態遷移判定履歴として記録し、すべてを同じ「ピックアップ NG」として扱わない。

## 7. PCN Trace / 状態遷移判定履歴とエンジニアリング上の振り返り

PCN は Multipath Control を形成すると同時に、今回の Target State Entry に関する判定履歴を PCN Trace として記録できる。

公開範囲での代表的な記録項目は次の通りである。

- Current State；
- Target State；
- 主要入力状態；
- 入力時刻情報；
- C / A / E Mapping；
- S / D / B Evaluation；
- CAE-SDB Result；
- Arbitration Result；
- Multipath Control；
- 実行結果；
- Trace ID。

これらの記録は、次の用途に利用できる。

- HMI における構造化表示；
- 現場問題の振り返り；
- 高頻度の状態遷移問題の集計；
- 改善前後の比較；
- 類似自動化ユニットへの再利用；
- プロジェクト引継ぎ、新任者教育。

記録の重点は、単純にログ項目を増やすことではない。

> **今回どの Target State へ入ろうとしていたのか、なぜその判定になったのか、最終的にどの制御経路を選択したのかを一回の状態遷移判定履歴として残すことである。**

## 8. 本事例の意味と公開範囲

本事例が示すのは、次の点である。

> **自動化実行ユニットが Target State となる目標物理実行段階へ入る前の判定は、単体の Ready だけに依存することはできない。**

画像認識搬送ラインのロボットユニットにおいて、Robot Ready が示すのは、ロボット本体が一定の運転能力を持つことにすぎない。

システムがピックアップ段階へ進めるかどうかは、さらに次を統合して確認する必要がある。

- ワーク条件；
- 認識結果；
- 重要許可；
- ロボット本体とエンドエフェクタ；
- 正常投入経路；
- 回流経路；
- 異常分流経路；
- 下流受入；
- 結果書戻し。

TPCA / PCN は、従来 PLC プログラム、画像認識インターフェース、ロボットコントローラ、安全システム、下流設備、上位システムに分散していた状態を、「ピックアップ段階」という明確な Target State Entry を基準として整理する。

そのエンジニアリングチェーンは次の通りである。

```text
Current State
→ Target State
→ PCN
→ C / A / E Mapping
→ S / D / B Evaluation
→ CAE-SDB Result
→ Arbitration
→ Multipath Control
→ PCN Trace
```

本稿は公開説明用の事例である。

公開内容は、次の事項を説明するためのものである。

- PCN の配置位置；
- 複数ソース状態信号；
- C / A / E 状態マッピング；
- S / D / B 判定；
- CAE-SDB Result；
- Arbitration；
- 代表的な Multipath Control；
- PCN Trace の基本的な役割。

具体的な閾値、待機ウィンドウ、再試行回数、完全な Arbitration ロジック、制御優先度、内部設定構造、インターフェースパラメータ、PCN Runtime の内部ライフサイクル、詳細な PCN Trace データ構造については、実際の設備、安全要求、エンジニアリング実装に応じて別途設計するものであり、本稿では公開しない。
