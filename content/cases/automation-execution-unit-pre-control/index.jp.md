## ロボットが Ready でも、なぜ把持段階へ進入できないのか

> 適用階層：自動化実行ユニット層  
> 代表対象：視覚認識搬送ラインのロボットユニット

**推奨引用：**

```text
全野南政 / Nansei Zenno，
『自動化実行ユニット前判定事例：ロボットが Ready でも、なぜ把持段階へ進入できないのか』，
公開事例，Public Case Version 1.5，
2026-09-20，
https://zennns.com/jp/cases/automation-execution-unit-pre-control/
```

視覚認識を用いた搬送ラインのロボットユニットでは、次のような状態が発生することがある。

ロボットは Ready であり、画像認識システムも認識結果を出力している。安全システムにも明確な異常はない。それでも、把持動作が開始されない。

Robot Ready は、ロボット本体が定義された準備状態にあることを示している。しかし、実際に把持段階へ進入するためには、現在のワーク条件、重要な許可、さらに把持後の実行チェーンが、現在の入口に対する要求を満たしている必要がある。

本事例で確認するのは、単一の「Robot Ready」という状態ではない。

> **「把持段階への進入」という明確な目標状態入口を基準として、画像認識、ロボット、安全システム、搬送設備、下流設備に分散している状態を CAE-SDB 判定結果として構造化し、その結果を制御経路、後続状態遷移、状態遷移判定履歴まで連続して接続できるか。**

という工程関係である。

本事例は、統一した9ステップの工程順序に沿って説明する。

```text
1. 現在状態
2. 目標状態 / 目標状態入口
3. PCN：関連状態取得 + C / A / E 状態マッピング
4. S / D / B 判定 → CAE-SDB Result + T
5. 制御優先度調停
6. 複数経路制御
7. 現在の入口に対する制御結果
8. 後続の目標状態入口と実行結果
9. 状態遷移判定履歴
```

基礎概念については、以下を参照できる。

- [中核概念](/jp/concepts/)
- [TPCA / PCN 状態遷移前制御アーキテクチャ｜ホワイトペーパー](/jp/whitepaper/)

## 事例対象

本事例では、視覚認識を用いた搬送ラインのロボットユニットを代表対象とし、PCN は PLC 内の制御ロジックとして実装されているものとする。

今回の把持入口に関係する主なシステムは、画像認識システム、ロボットコントローラ、安全システム、搬送コンベヤ、正常品搬送先、上位システムである。

![視覚認識搬送ラインのロボットユニット前制御イメージ](/images/tpca/06-pcn-pick-flow.png)

図：PCN は、ロボットが把持段階へ進入する前に、現在の目標状態入口に関連する複数システムの状態を取得し、判定結果に基づいて制御経路を形成する。

---

# 1. 現在状態 / 現在段階

現在、現場はどの状態にあるか。

```text
現在状態：
認識完了 / 把持待ち
```

ワークは今回の把持フローに入り、画像認識結果も生成されているが、ロボットによる把持はまだ開始されていない。

これが、今回の状態遷移の起点となる。

---

# 2. 目標状態 / 目標状態入口

今回、どの状態へ進もうとしているか。

```text
目標状態：
把持段階

目標状態入口：
把持段階への進入
```

PCN は、現在状態と目標状態入口の間に配置される。

```text
現在状態［認識完了 / 把持待ち］
    ↓
PCN［把持段階への進入前判定］
    ↓
目標状態入口［把持段階への進入］
    ↓
目標状態［把持段階］
```

![目標段階入口前における PCN の位置関係](/images/tpca/07-pcn-position-before-target-stage.png)

図：PCN は、把持動作が実際に開始される前に、「把持段階への進入」という目標状態入口について前制御判定を行う。

---

# 3. PCN：関連状態取得と C / A / E 状態マッピング

今回の入口に対して、どの状態が重要になるか。

PCN は、「把持段階への進入」に直接関係する状態を取得し、それぞれが今回の目標状態入口で担う役割に基づいて C / A / E へマッピングする。

| 代表状態 | 状態マッピング |
|---|---|
| ワーク存在、位置、姿勢、画像認識結果 | C：条件状態 |
| 安全許可、区域許可、上位システム許可 | A：許可状態 |
| Robot Ready、ロボット経路、グリッパ / 真空状態、正常品搬送先の受入状態 | E：実行チェーン状態 |

本事例では、主に次の状態を使用する。

```text
画像認識結果 → C
安全許可 → A
Robot Ready → E の関連入力
正常品搬送先の受入状態 → E
```

Robot Ready だけで、実行チェーン全体が成立していると判断することはできない。

また、戻し搬送や異常品排出など、代替候補となる経路の利用可否は後続の制御選択に用いる情報であり、現在の把持入口における E の成立を直接示すものではない。

---

# 4. S / D / B 判定と CAE-SDB Result

今回、実際にどのような判定問題が発生したか。

本事例では、次の状態を仮定する。

```text
Robot Ready：
成立

安全許可：
成立

正常品搬送先の受入状態：
現在の目標状態入口に必要な条件を満たす

画像認識結果：
有効時間を超過
```

画像認識結果は C にマッピングされる。

今回の問題は、その画像認識結果の動的時系列有効性にあるため、次の CAE-SDB Result が形成される。

```text
CAE-SDB Result：
C-D

画像認識結果が失効しており、
今回の把持入口に対する有効な判定根拠として
継続使用できない
```

時間情報 T は、今回の状態および判定結果と関連付けて保持する。

本事例では、9つの CAE-SDB 座標すべてを展開しない。

C / A / E と S / D / B の全体関係については、以下を参照できる。

[なぜ CAE-SDB なのか？——目標状態入口前の二軸構造化分析法](/jp/notes/why-cae-sdb/)

---

# 5. 制御優先度調停

複数の状態や判定結果が存在する場合、何を優先して処理するか。

今回の制御優先度調停における主な入力は、次のとおりである。

```text
CAE-SDB Result：
C-D

重要な安全許可：
成立

現在の把持段階に必要な実行チェーン：
現在の目標状態入口に必要な条件を満たす

戻し搬送経路：
利用可能
```

画像認識結果はすでに失効しているため、現在の把持入口から、元の認識結果を使用したまま把持段階へ進入することはできない。

したがって、今回の制御優先度調停結果は次のようになる。

```text
現在の把持入口：
進入不可

優先制御経路：
戻し搬送
```

---

# 6. 複数経路制御

どの制御経路が選択されたか。

制御優先度調停の結果に基づき、今回の複数経路制御は次のとおりとなる。

```text
複数経路制御：
戻し搬送
```

ここでいう戻し搬送は、現在の把持入口へは進入せず、ワークを別の搬送処理へ移すために選択された後続制御経路を表す。

---

# 7. 現在の入口に対する制御結果

今回の把持入口へ進入するか。

```text
現在の入口に対する制御結果：
現在の把持入口には進入しない
```

今回の「把持段階への進入」という目標状態入口は許可されなかった。

同時に、後続処理として次の候補が確定する。

```text
次の目標状態：
戻し搬送段階

次の目標状態入口：
戻し搬送経路への進入
```

---

# 8. 後続の目標状態入口と実行結果

選択された経路を実行すると、その後どうなるか。

戻し搬送が選択されると、システムは「戻し搬送段階への移行」という新たな状態遷移へ進む。

```text
目標状態：
戻し搬送段階

目標状態入口：
戻し搬送経路への進入
```

この戻し搬送入口では、対応する PCN が、当該入口に定義された進入条件に基づいて改めて前制御判定を行う。

```text
現在の把持入口には進入しない
    ↓
複数経路制御：戻し搬送
    ↓
目標状態入口［戻し搬送経路への進入］
    ↓
戻し搬送入口に対応する PCN
    ↓
進入が許可された場合
    ↓
戻し搬送を実行
    ↓
実行結果［ワークが戻し搬送経路へ移行］
```

本公開事例では、戻し搬送入口に対する具体的な状態設定および判定規則までは扱わない。

---

# 9. 状態遷移判定履歴

今回の状態遷移は、最終的にどのような履歴として記録されるか。

今回の把持入口については、次のような PCN Trace を形成できる。

```text
【PCN】 把持入口 PCN
【現在状態】 認識完了 / 把持待ち
【目標状態】 把持段階
【目標状態入口】 把持段階への進入

【主要状態】
Robot Ready = 成立
安全許可 = 成立
画像認識結果 = 有効時間を超過

【CAE-SDB Result】 C-D
【判定内容】 画像認識結果が失効しており、現在の把持入口に対する有効な判定根拠として使用できない

【制御優先度調停結果】 現在の把持入口への進入不可
【複数経路制御】 戻し搬送
【現在の入口に対する制御結果】 現在の把持入口には進入しない

【次の目標状態】 戻し搬送段階
【次の目標状態入口】 戻し搬送経路への進入

【時間情報】 T
【履歴 ID】 PCN-PICK-XXXX
```

その後「戻し搬送経路への進入」を判定する場合は、戻し搬送入口を担当する PCN が新たな状態遷移判定履歴を形成する。

PCN Trace の詳細については、以下を参照できる。

[なぜ PCN Trace は新しいエンジニアリングデータなのか？](/jp/notes/why-pcn-trace-is-engineering-data/)

## 事例まとめ

本事例では、Robot Ready、安全許可、正常品搬送先の受入状態は、いずれも現在の目標状態入口に必要な条件を満たしている。

Robot Ready だけを確認すると、現場では次の疑問が残る。

> **「ロボットは Ready なのに、なぜ把持しないのか。」**

これを「把持段階への進入」という目標状態入口を基準として整理すると、今回の状態遷移は次のように明確化される。

```text
目標状態入口：
把持段階への進入

CAE-SDB Result：
C-D

具体的な問題：
画像認識結果が有効時間を超過しており、
現在の把持入口に対する有効な判定根拠として使用できない
```

### 本事例によって明確になる工程情報

| 従来の現場情報から確認できること | 本事例によってさらに明確になること |
|---|---|
| Robot Ready が成立している | Robot Ready は現在の把持入口に関係する一つの状態であり、それだけでは当該入口への進入条件成立を意味しない |
| 画像認識システムが認識結果を出力している | その画像認識結果が現在のワーク、現在の周期に対応し、現在も有効であるかを確認する必要がある |
| 安全許可が成立している | 重要な A は成立しているが、それによって C や E の判定が代替されるわけではない |
| 正常品搬送先が受入可能である | 現在の把持段階に必要な E の一部が成立している |
| 把持動作が開始されない | CAE-SDB Result は **C-D：画像認識結果の有効時間超過** である |
| 現場では「ロボットが動かない」としか見えない | 問題を「現在の把持入口が依存する画像認識条件の動的時系列有効性が失われている」と特定できる |
| エンジニアが追加調査しなければ、把持できない理由が分からない | 現在の入口へ進入できない理由を構造化して説明できる |
| 次にどう処理するかを人が判断する必要がある | 制御経路として「戻し搬送」が選択されたことを明示できる |
| 戻し搬送経路が利用可能である | 「戻し搬送を選択した」ことは次の制御経路が決まったことを意味するが、戻し搬送入口への進入が許可されたことを意味しない |
| 各システムが個別に状態やログを保存している | 今回の状態、判定、制御、後続の目標状態入口を一回の状態遷移判定履歴として関連付けられる |

これにより、従来の、

> **「ロボットは Ready だが、把持動作が始まらない。」**

という現象は、

> **「現在の把持入口に必要などの状態が失効したのか、なぜ現在の入口へ進入できないのか、どの後続制御経路が選択されたのか、次にどの新しい状態遷移入口へ進むのか。」**

という工程関係へ展開できる。

本事例で示した主な工程上の意味は、次のとおりである。

Robot Ready、画像認識結果、安全許可、下流受入状態を、一回の目標状態入口に対する関連状態として整理できる。

「ロボットは Ready だが動かない」という現象を、明確な CAE-SDB 判定問題へ展開できる。

設備の Ready 状態と、現在の目標状態入口が成立しているかどうかを分離して扱える。

判定結果を、現在の入口に対する制御結果と後続の制御経路へ直接接続できる。

現在の把持入口と、その後に続く戻し搬送入口を、それぞれ独立した目標状態入口として明確に区別できる。

さらに、今回の状態、判定、制御、後続状態遷移の関係を、一つの状態遷移判定履歴として記録できる。

本事例で追加される価値は、ロボット、画像認識、安全システムの状態数を増やすことではない。

> **複数システムに分散していた状態を、「現在の入口がなぜ成立しないのか」「どの機能役割にどの判定問題が生じたのか」「どの制御経路を選択したのか」「次にどの新しい状態遷移入口へ進むのか」という一連の工程関係として組織化することにある。**
