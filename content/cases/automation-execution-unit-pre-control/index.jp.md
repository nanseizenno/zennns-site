## 1. 現場で発生する問題

画像認識コンベヤロボットユニットでは、次のような状態であっても、ロボットがピックアップ段階へ進まないことがある。

- 画像認識システムが OK を出力している。
- ロボットが Ready 状態である。
- 安全システムに明確な異常がない。
- PLC 側で直接的な阻止条件が成立していない。
- それでもロボットがピックアップ段階へ進まない。

このような場合、関連状態を確認すると、次のような要因が存在することがある。

- 画像認識結果は一度有効であったが、現在は有効時間を超えている。
- ワークがピック可能領域の境界付近、または領域外へ移動している。
- エリア許可が成立していない。
- 正常投入先が一時的に受入不能である。
- 戻り経路が使用できない。
- 異常分流経路の準備が完了していない。
- 結果書戻し経路を継続できない。

表面的には、次の問題として現れる。

> **Robot Ready なのに、なぜピックアップ段階へ進まないのか。**

ここで重要なのは、Robot Ready が示す範囲である。

> **Robot Ready は、ロボット本体が局所的な運転可能条件を満たしていることを示す状態の一つであり、「ピックアップ段階へ進む」という Target State Entry が成立したことを意味するものではない。**

ピックアップ段階へ進んだ後も、ロボット動作、エンドエフェクタ、投入先、戻り経路、異常分流経路、結果書戻しなど、後続の実行チェーンが継続可能である必要がある。

このため PLC / PCN は、ピックアップ段階へ実際に進む前に、本状態遷移に関係する条件、許可、実行チェーン状態を同一の Target State Entry に対して判定する。

## 2. 事例対象と PCN の位置

本事例では、画像認識コンベヤロボットユニットを代表対象とする。

ワークはメインコンベヤによって連続搬送される。画像認識システムは認識処理後、代表的に次の情報を出力する。

- ワーク存在
- 位置
- 姿勢
- 認識信頼度
- 異常判定
- 結果の時間情報
- ワーク追跡情報

PLC / PCN は、ロボットがピックアップ段階へ進む前に、本状態遷移に関係する複数ソース状態を取得する。

Current State に相当する状態：

```text
ロボット待機
+
ワークが認識・ピック領域内に存在
+
画像認識結果が生成済み
```

Target State：

```text
ロボットがピックアップ段階へ進む
```

PCN の位置：

```text
Current State → PCN → Target State
```

![画像認識コンベヤロボットユニット前制御概念図](/images/tpca/06-pcn-pick-flow.png)

図：PLC / PCN は、ロボットがピックアップ段階へ進む前に、画像認識システム、ロボットコントローラ、安全システム、メインコンベヤ、正常投入先、戻り経路、異常分流経路、上位システムなどの状態を取得し、前置判定を行ったうえで対応する制御経路を形成する。

![Target State Entry 前における PCN の位置関係](/images/tpca/07-pcn-position-before-target-stage.png)

図：PCN は Current State と Target State の間に位置し、ピックアップ動作を開始する前に Target State Entry に対する前置判定を行う。

本事例における PCN の対象は、

> **「ピックアップ段階へ進む」という明確な Target State Entry**

である。

Target State へ進んだ後に運転状態が変化した場合、その時点の状態が新しい Current State となり、後続の Target State に対して新たな状態遷移判定を行う。

したがって、TPCA / PCN は運転プロセス全体を一つの判定ノードで処理するものではない。明確に定義された各 Target State Entry を、それぞれ独立した判定対象として扱う。

PCN のエンジニアリング上の位置については、以下を参照。

[なぜ PCN は TPCA の最小エンジニアリングノードなのか？](/ja/notes/pcn-minimum-engineering-unit/)

## 3. 複数ソース状態信号と C / A / E 状態マッピング

PLC / PCN は、単一の Ready 信号だけを最終判断の根拠とはしない。

「ピックアップ段階へ進む」という Target State Entry に直接関係する状態を複数の情報源から取得し、そのエンジニアリング上の役割に基づいて C / A / E へマッピングする。

| 信号源 | 代表的な状態 |
|---|---|
| 画像認識システム | ワーク存在、位置、姿勢、認識信頼度、異常判定、結果時刻、結果有効状態、ワーク追跡情報 |
| メインコンベヤ | 運転状態、速度、位置、ワークのピック領域内存在 |
| 戻りコンベヤ | 運転状態、受入可能状態、戻り経路の使用可否 |
| 異常分流コンベヤ | 運転状態、受入可能状態、異常分流経路の使用可否 |
| 正常投入先 | 空き状態、受入可能状態、前ワーク処理完了状態 |
| ロボットコントローラ | 自動モード、Ready、現在位置、経路到達可否、プログラム状態、動作完了、グリッパ / 真空状態、アラーム状態 |
| 安全システム | 安全扉、ライトカーテン、非常停止、安全回路、エリア進入許可 |
| 上位システム / HMI | 作業指示、生産許可、異常品処理許可、人による確認、結果記録または書戻し要求 |

これらの状態は、信号の取得元ではなく、本 Target State Entry における役割に基づいて C / A / E へマッピングする。

| 状態変数領域 | 判定内容 | 本事例における代表項目 |
|---|---|---|
| C：Condition | ピックアップ対象として必要な事実条件が成立しているか | ワーク存在、位置適合、姿勢適合、画像認識結果有効、信頼度条件成立、ワーク追跡関係が正しい |
| A：Authority | システムとしてピックアップ段階への進入が許可されているか | 安全許可、エリア許可、PLC 側進入許可、上位許可、必要な人による確認 |
| E：Execution Chain | ピックアップ段階へ進んだ後、必要な実行チェーンを継続できるか | ロボット経路到達可能、エンドエフェクタ使用可能、投入先受入可能、必要な戻り・異常分流経路使用可能、結果書戻し可能 |

したがって、次の二つは同義ではない。

```text
Robot Ready ≠ ピックアップ段階への進入条件成立
```

例えば、

- Robot Ready が成立していても、画像認識結果が失効していれば、C に関係する条件は成立しない。
- Robot Ready が成立していても、必要なエリア許可が成立していなければ、A は成立しない。
- Robot Ready が成立していても、ピックアップ後に必要となる投入先または関連実行経路を継続できなければ、E は成立しない。

Robot Ready は、本状態遷移に関係する複数の入力状態の一つである。

## 4. S / D / B 判定

C / A / E 状態マッピング後、PCN は各状態変数を S / D / B の判定性質から評価する。

| 判定性質 | 判定内容 | 本事例における代表項目 |
|---|---|---|
| S：Structure | 判定に必要な信号、インターフェース、マッピング関係、許可元、経路、実行チェーン境界が定義・接続され、観測可能であるか | 画像認識インターフェース、座標マッピング、安全許可元、戻り経路、異常分流経路、結果書戻しインターフェース |
| D：Dynamics | 関連状態が現在も有効で、同期・安定しており、本判定の根拠として使用可能であるか | 画像認識結果未更新、位置追跡非同期、許可取消、ロボット状態遅延、下流状態競合 |
| B：Boundary | 関連状態が事前に定義された制御境界に到達しているか | 結果有効時間、認識信頼度、位置・姿勢偏差、待ち時間、リトライ回数、補正範囲 |

例えば、画像認識インターフェースと座標マッピングが正しく構成されていても、認識結果が有効時間を超えている場合がある。

この場合、必要な構造自体は成立しているため S の問題ではなく、現在の判定根拠として使用できるかという D：Dynamics の問題として扱う。

また、ワークの位置がピック可能範囲の事前定義境界に接近している場合は、B：Boundary に関する判定が必要となる。

この境界判定だけで最終的な制御経路を決定するわけではない。ピックアップを継続するか、再位置決めするか、回流させるか、その他の経路へ移行するかは、完全な CAE-SDB Result に対する Arbitration の結果によって決定する。

## 5. CAE-SDB Result、時間情報 T、Arbitration、Multipath Control

PCN は、C / A / E 状態に対して S / D / B 判定を行い、1 つまたは複数の CAE-SDB Result を形成する。

同時に、本状態および判定に対応する時間情報 T を保持する。

代表的な判定結果を以下に示す。

| 判定結果 | 本事例における代表的な状態 |
|---|---|
| C-S | 画像認識インターフェース未接続、座標マッピング未設定、ワーク追跡関係未定義 |
| C-D | 画像認識結果未更新、ワーク位置とコンベヤ追跡が非同期、認識結果競合 |
| C-B | 認識結果が有効時間境界に接近、位置または姿勢が許容境界に接近 |
| A-S | 安全許可、エリア許可、上位許可の取得元が未定義または観測不能 |
| A-D | 許可の取消、遅延、未更新、切替中 |
| A-B | 許可待ちが事前定義された制御境界に到達 |
| E-S | 正常投入、戻り、異常分流、結果書戻しに必要な経路またはインターフェースが未定義 |
| E-D | 下流状態未更新、ロボット動作フィードバックタイムアウト、戻り経路状態競合 |
| E-B | 下流待ち、バッファ能力、代替経路に関する状態が事前定義された制御境界に到達 |

同一の Target State Entry に対する判定で、複数の CAE-SDB Result が同時に成立する場合がある。

基本的な制御チェーンは次のとおりである。

```text
CAE-SDB Result + T → Arbitration → Multipath Control
```

Arbitration は、完全な判定結果と事前に定義された制御制約に基づいて制御上の優先関係を処理する。

その結果として、Multipath Control が最終的なエンジニアリング制御出力を形成する。

本事例における代表的な制御経路には、次のようなものがある。

- ピックアップ段階への進入許可
- 待機
- 再認識
- 再サンプリング
- 再位置決め
- 回流
- 異常分流
- 下流調整
- 人による確認
- 進入禁止
- 安全ロック
- 強化記録

これらは、それぞれ異なるエンジニアリング上の制御経路を示す。

TPCA の状態遷移視点では、いずれも最終的には、

> **Current State から、新しい Target State または目標実行経路へ進む**

ことに対応する。

したがって、システムの判定結果を単純な二値結果だけに圧縮する必要はない。

```text
ピック OK
ピック NG
```

ではなく、Current State と判定結果に応じて、事前に定義された複数の制御経路から適切な経路を選択できる。

## 6. 代表的な判定プロセス

「画像認識結果は一度有効であり、Robot Ready も成立しているが、ロボットがピックアップ段階へ進まない」場合を例とする。

Current State：

```text
認識完了 / ピック待ち
```

Target State：

```text
ピックアップ段階
```

主要入力状態：

```text
Robot Ready：成立
安全許可：成立
画像認識結果：有効時間超過
戻り経路：使用可能
```

このとき PCN は、例えば次の状態を確認する。

```text
CAE-SDB Result：
C-D
画像認識結果が現在の判定根拠として失効

A 関連状態：
重要許可が成立

E 関連状態：
戻り経路が使用可能
```

本状態と判定には、対応する時間情報 T を保持する。

Arbitration の結果、今回の Target State Entry に対してピックアップ段階への進入を許可しないと判断した場合、Multipath Control は例えば次の経路を出力する。

```text
ピックアップ段階へ進入しない
→ ワークを回流
→ 再認識
```

ここで「回流」および「再認識」は、いずれも後続の新しい Target State または目標実行経路である。

過去の状態インスタンスへ戻ることを意味しない。

PCN Trace には、例えば次の内容を記録する。

```text
Current State： 認識完了 / ピック待ち

Target State： ピックアップ段階

時間情報： T

CAE-SDB Result： C-D

判定内容： 画像認識結果が失効

Arbitration Result： ピックアップ段階への進入を許可しない

Multipath Control： 回流 → 再認識

実行結果： ワークが戻り経路へ進入

Trace ID： PCN-PICK-XXXX
```

また、重要な安全許可が成立していない場合は、C および E に関係する状態が成立していても、Target State へ進入してはならない。

この場合も、単純に「ピック NG」として扱うのではなく、本 Target State Entry に対する構造化判定結果として記録する。

## 7. PCN Trace とエンジニアリングレビュー

PCN は Multipath Control を形成すると同時に、本状態遷移に関する判定履歴を PCN Trace として記録できる。

公開レベルでの代表的な記録項目は次のとおりである。

- Current State
- Target State
- 主要入力状態
- 時間情報 T
- C / A / E 状態マッピング
- S / D / B 判定
- CAE-SDB Result
- Arbitration Result
- Multipath Control
- 実行結果
- Trace ID

これらの記録は、例えば次の用途に利用できる。

- HMI における構造化表示
- 現場で発生した状態遷移問題の解析
- 頻発する判定結果の集計
- 改善前後の比較
- 同種自動化ユニットへの設計展開
- プロジェクト引継ぎおよび教育

PCN Trace の目的は、単純に生ログの項目数を増やすことではない。

記録すべき中心情報は、

> **なぜ今回の Target State Entry が成立しなかったのか。また、その結果としてシステムがどの Target State または制御経路へ進んだのか。**

という状態遷移判定の履歴である。

時間情報 T を保持することで、エンジニアリング上の状態内容が同一であっても、異なる時間位置で生成された状態インスタンスを区別できる。

## 8. 本事例の位置付けと公開範囲

本事例が示す要点は、次のとおりである。

> **自動化実行ユニットが目標物理実行段階へ進む前に、単体の Ready だけを根拠として Target State Entry の成立を判断することはできない。**

画像認識コンベヤロボットユニットでは、Robot Ready はロボット本体が局所的な運転可能条件を満たしていることを示す状態の一つである。

ピックアップ段階へ進むためには、さらに次の状態を確認する必要がある。

- ワーク条件
- 画像認識結果
- 重要許可
- ロボット本体およびエンドエフェクタ
- 正常投入経路
- 戻り経路
- 異常分流経路
- 下流受入
- 結果書戻し

TPCA / PCN は、従来 PLC プログラム、画像認識インターフェース、ロボットコントローラ、安全システム、下流設備、上位システムなどに分散していた関連状態を、「ピックアップ段階へ進む」という一つの明確な Target State Entry を中心として整理する。

基本的なエンジニアリングチェーンは次のとおりである。

```text
Current State
→ Target State
→ PCN
→ C / A / E 状態マッピング
→ S / D / B 判定
→ CAE-SDB Result + T
→ Arbitration
→ Multipath Control
→ PCN Trace
```

Target State へ進んだ後に運転状態が変化した場合、その状態が新しい Current State となり、新しい Target State に対して次の状態遷移判定を行う。

したがって、回流、戻り、再認識、異常分流、人による確認、安全ロックなどは、現場で使用する既存のエンジニアリング名称を維持できる。一方、TPCA の状態遷移視点では、これらはいずれも新しい Target State または目標実行経路として扱う。

なお、PCN は安全 PLC、安全リレー、ハードウェア安全回路などの安全制御機能を代替するものではない。本事例における安全許可は、既存の安全制御システムから取得する A：Authority に関係する状態として扱う。

本稿は公開説明用の事例である。

公開範囲は次のとおりである。

- PCN のエンジニアリング上の位置
- 複数ソース状態
- C / A / E 状態マッピング
- S / D / B 判定
- CAE-SDB Result
- 時間情報 T
- Arbitration
