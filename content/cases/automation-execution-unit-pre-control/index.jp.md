## なぜ Robot Ready だけではピックアップ段階へ移行できることを意味しないのか

> 適用レベル：自動化実行ユニット層  
> 代表対象：画像認識搬送ラインのロボットユニット  
> バージョン：Public Case Version 1.1

## 1. 現場の問題

画像認識システムはすでに OK を出力している。

ロボットは Ready を表示している。

安全システムにも明確な異常はない。

PLC 側にも直接的な阻害条件はない。

それでも、ロボットはピックアップ段階へ入らない。

さらに確認すると、次のような状態が見つかる場合がある。

- 画像認識結果は一度有効だったが、すでにタイムアウトしている；
- ワークがピックアップ可能領域の境界に近づいている、またはすでに外れている；
- エリア許可がまだ成立していない；
- 正常品投入位置が一時的に受け入れできない；
- リターン経路が使用できない；
- 異常分流経路の準備が完了していない；
- 結果書戻しチェーンを継続できない。

表面的には、次のように見える。

> **Robot Ready なのに、なぜまだピックアップしないのか？**

本質的な問題は、次にある。

> **Robot Ready はロボット本体が一定の運転能力を持つことを示すだけであり、「ピックアップ段階へ入る」という今回の状態遷移が成立していることを証明するものではない。**

ロボットがこれから入ろうとしているのは、孤立した一つの動作ではなく、その後も継続する必要がある物理実行チェーンである。

そのため PLC / PCN は、実際にピックアップ段階へ入る前に、今回の状態遷移に関係する条件、許可、実行チェーンを統合して判定する必要がある。

## 2. 事例対象と PCN の位置

本事例では、画像認識搬送ラインのロボットユニットを代表例とする。

ワークは主搬送コンベヤから連続的に流入する。

画像認識システムは認識完了後、次のような状態を提供できる。

- ワーク存在状態；
- 位置；
- 姿勢；
- 認識信頼度；
- 異常判定；
- 結果時刻情報；
- ワーク追跡情報。

PLC / PCN は、ロボットがピックアップ段階へ入る前に、今回の状態遷移に関係する複数ソース状態を取得する。

現在段階：

```text
ロボット待機
+
ワークが認識・ピックアップ領域へ進入
+
画像認識結果が生成済み
```

目標段階：

```text
ロボットがピックアップ段階へ進入
```

PCN の位置：

```text
現在段階
→ PCN
→ 目標ピックアップ段階
```

![画像認識搬送ラインのロボットユニット前制御概念図](/images/tpca/06-pcn-pick-flow.png)

図：PLC / PCN は、ロボットがピックアップ段階へ入る前に、画像認識システム、ロボットコントローラ、安全システム、主搬送コンベヤ、正常品投入位置、リターン経路、異常分流経路、上位システムなどの状態を集約し、前置判定を行って対応する制御経路を形成する。

![Target Stage 入口前に配置される PCN の位置関係](/images/tpca/07-pcn-position-before-target-stage.png)

図：PCN は現在段階と目標段階の間に配置され、実際にピックアップ動作を開始する前に判定を完了する。

PCN の位置によって、扱う対象が決まる。

> **Target State に入るかどうかを判定する。**

動作失敗後に、その理由を説明することが主目的ではない。

PCN のエンジニアリング上の位置については、以下を参照。

## 3. 複数ソース状態信号と C / A / E 状態マッピング

PLC / PCN は、一つの Ready 信号だけを取得するのではない。

「ピックアップ段階へ入る」ことに直接関係する複数ソース状態を取得する。

| 信号源 | 代表的な状態 |
|---|---|
| 画像認識システム | ワーク存在、位置、姿勢、認識信頼度、異常判定、結果時刻、結果有効状態、ワーク追跡情報 |
| 主搬送コンベヤ | 運転状態、速度、位置、ワークがピックアップ領域にあるか |
| リターン搬送コンベヤ | 運転状態、受入可否、リターン経路が使用可能か |
| 異常品排出コンベヤ | 運転状態、受入可否、異常分流経路が使用可能か |
| 正常品投入位置 | 空き状態、受入可否、前ワークの処理完了状態 |
| ロボットコントローラ | 自動モード、Ready、現在位置、経路到達可否、プログラム状態、動作完了、グリッパ / 真空状態、アラーム状態 |
| 安全システム | 安全扉、ライトカーテン、非常停止、安全回路、エリア進入許可 |
| 上位システム / HMI | 作業指示、生産許可、異常品処理許可、手動確認、結果記録または書戻し要求 |

これらの状態は PCN に入力された後、今回の Target State を基準として C / A / E にマッピングされる。

| 状態変数領域 | 判定する問題 | 本事例における代表項目 |
|---|---|---|
| C：Condition | ワークが現在のピックアップ対象として成立しているか | ワーク存在、位置合格、姿勢合格、画像認識結果有効、認識信頼度条件成立、ワーク追跡関係が正しい |
| A：Authority | システムがピックアップ段階への進入を許可しているか | 安全許可、エリア許可、PLC 放行、上位許可、必要な手動確認 |
| E：Execution Chain | ピックアップ段階へ入った後、実行チェーンが継続可能か | ロボット経路到達可、グリッパ使用可、正常品投入位置が受入可、リターン経路が使用可、異常分流経路が使用可、結果書戻しチェーンが使用可 |

したがって：

```text
Robot Ready
≠
ピックアップ段階へ入るための完全な条件が成立している
```

例えば：

ロボットが Ready でも、画像認識結果がすでに失効していれば、C は成立しない。

ロボットが Ready でも、エリア許可が成立していなければ、A は成立しない。

ロボットが Ready でも、正常品投入位置と代替経路のいずれも受け入れできなければ、E は成立しない。

Robot Ready は、今回の状態遷移に関係する一つの入力にすぎない。

---

## 4. S / D / B 判定

C / A / E 状態マッピングの後、PCN はさらに S / D / B の三つの判定性質から評価する。

| 判定性質 | 判定する問題 | 本事例における代表項目 |
|---|---|---|
| S：Structure | 今回の判定に必要な信号、インターフェース、マッピング関係、許可元、実行チェーン境界が定義・接続され、観測可能になっているか | 画像認識インターフェース、座標マッピング、安全許可元、リターン経路、異常分流経路、結果書戻しインターフェース |
| D：Dynamics | 現在状態が引き続き有効で、同期しており、今回の判定に使用できるか | 画像認識結果が未更新、位置追跡が非同期、許可が撤回、ロボット状態が遅延、下流状態が競合 |
| B：Boundary | 現在状態が事前定義された制御境界に入っているか | 結果有効時間、認識信頼度、位置・姿勢偏差、待機時間、再試行回数、補正範囲 |

例えば：

画像認識結果インターフェースと座標マッピングは存在するが、結果がすでに有効時間を超えている。

この場合、問題は構造欠落ではなく、動的時系列有効性にある。

また例えば：

ワークは引き続き認識可能だが、位置がピックアップ可能境界に近づいている。

この場合は対応する制御境界判定へ入り、継続ピックアップ、再位置決め、リターン、その他の処理経路のどれへ進むかを決定する。

## 5. CAE-SDB Result、Arbitration、Multipath Control

PCN は C / A / E の状態を S / D / B から判定した後、一つまたは複数の CAE-SDB Result を形成する。

代表的な結果は次の通りである。

| 判定結果 | 本事例における代表的な問題 |
|---|---|
| C-S | 画像認識インターフェースが未接続；座標マッピングが未構築；ワーク追跡関係が未定義 |
| C-D | 画像認識結果が未更新；ワーク位置とコンベヤ追跡が非同期；認識結果に競合が発生 |
| C-B | 認識結果が有効時間境界に接近；位置または姿勢が許容境界に接近 |
| A-S | 安全許可、エリア許可、上位許可の発生源が未定義または観測不能 |
| A-D | 許可が反復して撤回、遅延、未更新、または切替中 |
| A-B | 許可待機が事前定義された制御境界に到達 |
| E-S | 正常投入、リターン、異常分流、結果書戻しチェーンが完全に定義されていない |
| E-D | 下流状態が未更新；ロボット動作フィードバックがタイムアウト；リターン経路状態が競合 |
| E-B | 下流待機、バッファ能力、代替経路が事前定義された制御境界に入る |

同一の状態遷移では、複数の判定結果が同時に存在する場合がある。

これらの結果は Arbitration に入力され、その後に最終的な Multipath Control を形成する。

本事例における代表的な制御経路には、次のようなものがある。

- ピックアップ段階への進入許可；
- 待機；
- 再認識；
- 再取得；
- 再位置決め；
- リターン；
- 異常分流；
- 下流調整；
- 手動確認；
- 進入禁止；
- 安全関連制御；
- 強化記録。

したがって、システムは次の二値だけで処理する必要はない。

```text
ピックアップ OK
ピックアップ NG
```

現在状態に応じて、異なる処理経路へ進むことができる。

## 6. 代表的な判定プロセス

「画像認識は一度 OK、Robot Ready だが、ロボットがピックアップしない」場面を例にする。

現在段階：

```text
認識完了 / ピックアップ待機
```

目標段階：

```text
ピックアップ段階へ進入
```

現在状態：

```text
Robot Ready：成立
安全許可：成立
画像認識結果：現在の有効時間を超過
リターン経路：使用可能
```

PCN は、例えば次を形成できる。

```text
C-D：
画像認識結果が現在失効している

A：
重要許可成立

E：
リターン経路は継続可能
```

Arbitration の結果、今回のピックアップは許可されない。

最終的な制御経路：

```text
ピックアップ段階へ進入しない
→ ワークをリターン
→ 再認識
```

PCN Trace には、例えば次を記録できる。

```text
現在段階：認識完了 / ピックアップ待機
目標段階：ピックアップ段階へ進入

主要判定：
C-D：画像認識結果が失効

制御結果：
リターン再認識

実行結果：
ワークはリターン経路へ進入

Trace ID：
PCN-PICK-XXXX
```

別の場面で重要な安全許可が成立していない場合は、C と E がいずれも成立していても、ピックアップ段階へ進入させることはできない。

この場合、PCN は異なる状態遷移結果として記録し、すべてを同じ「ピックアップ NG」として扱わない。

## 7. PCN Trace とエンジニアリング上の振り返り

PCN は制御経路を形成すると同時に、今回の状態遷移に関する判定履歴を記録できる。

公開範囲での代表的な記録項目は次の通りである。

- 現在段階；
- 目標段階；
- 主要入力状態；
- 入力時刻情報；
- C / A / E 状態マッピング；
- S / D / B 判定；
- CAE-SDB Result；
- Arbitration Result；
- Multipath Control Result；
- 実行結果；
- Trace ID。

これらの記録は、次の用途に利用できる。

- HMI における構造化表示；
- 現場問題の振り返り；
- 高頻度の状態遷移問題の集計；
- 改善前後の比較；
- 類似自動化ユニットへの再利用；
- プロジェクト引継ぎ、新任者教育。

記録の重点は、さらに多くの原始ログを追加することではない。

> **なぜ今回ピックアップ段階へ入らなかったのか、そして最終的にどの制御経路へ進んだのかを残すことである。**

## 8. 本事例の意味と公開範囲

本事例が示すのは、次の点である。

> **自動化実行ユニットが目標物理実行段階へ入る前の判定は、単体の Ready だけに依存することはできない。**

画像認識搬送ラインのロボットユニットにおいて、Robot Ready が示すのは、ロボット本体が一定の運転能力を持つことにすぎない。

システムがピックアップ段階へ進めるかどうかは、さらに次を統合して確認する必要がある。

- ワーク条件；
- 認識結果；
- 重要許可；
- ロボット本体とエンドエフェクタ；
- 正常投入経路；
- リターン経路；
- 異常分流経路；
- 下流受入；
- 結果書戻し。

TPCA / PCN は、従来 PLC プログラム、画像認識インターフェース、ロボットコントローラ、安全システム、下流設備、上位システムに分散していた状態を、「ピックアップ段階へ入る」という明確な入口を基準として整理する。

そのエンジニアリングチェーンは次の通りである。

```text
現在段階
→ 目標段階
→ PCN
→ C / A / E 状態マッピング
→ S / D / B 判定
→ CAE-SDB Result
→ Arbitration
→ Multipath Control
→ PCN Trace
```

本稿は公開説明用の事例である。

公開内容は、次の事項を説明するためのものである。

- PCN の配置位置；
- 複数ソース状態；
- C / A / E 状態マッピング；
- S / D / B 判定；
- CAE-SDB Result；
- Arbitration；
- 代表的な Multipath Control；
- PCN Trace の基本的な役割。

具体的な閾値、待機ウィンドウ、再試行回数、完全な制御優先度、内部設定構造、インターフェースパラメータ、Runtime Lifecycle、詳細な Trace 構造については、実際の設備、安全要求、エンジニアリング実装に応じて別途設計するものであり、本稿では公開しない。
