## 1. 現場で発生する問題

製造 DX プロジェクトでは、通常、すでに多くの生産データや運転データを取得できる。

MES は作業指示、ロット、計画、生産実績を記録できる。品質システムは検査結果、品質判定、品質承認状態を記録できる。PLC や設備制御システムは、自動モード、設備 Ready、アラーム、Interlock、動作状態を提供できる。人員システムは、本人確認や権限を管理できる。保全システムは、修理、点検、復旧状態を記録できる。さらに、下流設備、搬送システム、バッファエリアからも、受入、占有、運転状態などを取得できる。

しかし、現場では依然として次のような問題が発生することがある。

- 前工程は完了しているが、次工程を開始できない。
- MES 上では作業指示が有効で、設備も Ready であるにもかかわらず、対象製品または対象ロットを次の段階へ進められない。
- 品質結果は生成されているが、対象ロットに対する正式な品質承認が成立しているかを直ちに確認できない。
- 検査結果が NG であっても、手直し、回流、廃棄処理、隔離など、どの後続工程へ進めるかを別途判断する必要がある。
- 保全作業は完了しているが、設備を生産へ再投入できるかをさらに確認する必要がある。
- 作業指示は切り替わっているが、PLC レシピ、材料、品質結果、トレーサビリティ情報が完全には同期していない。
- 下流は受入可能と表示されているが、その状態が現在も有効かを直ちに確認できない。
- 複数システムに状態記録が存在していても、対象をどの後続工程へ進めるべきかを判断するために、プログラム、状態、履歴を複数システムにまたがって確認する必要がある。

多くの場合、問題はデータ不足ではない。

> **対象がどの Current State からどの Target State へ進むのか、またその Target State Entry に必要な条件、許可、実行チェーンが、同一の Target State Entry を中心として統一的に設計されていないこと**

が問題となる。

例えば、

```text
MES 作業指示 = 有効
品質結果 = 合格
設備 = Ready
オペレータ = 確認済み
下流 = 受入可能
```

という状態が個別に成立していても、それだけで、

```text
対象を次工程へ進める
```

と判断することはできない。

さらに、少なくとも次の事項を確認する必要がある。

- 品質結果が対象ロットに対応しているか。
- 必要な品質承認が成立しているか。
- 作業指示、レシピ、材料、設備モードが一致しているか。
- 保全解除が成立しているか。
- 人による確認を行った者が必要な権限を持っているか。
- 下流状態が現在も有効か。
- Target State へ進んだ後も、実行チェーン全体を継続できるか。
- 本判定結果を追跡可能な状態遷移履歴として記録できるか。

したがって、本事例では、

> **明確な生産 Target State Entry を中心として、複数システムに分散している状態を、判定・制御・記録が可能な生産状態遷移の設計構造として整理すること**

を対象とする。

## 2. 事例の位置付けと PCN の位置

本事例では、生産プロセスにおける複数システム横断の状態遷移を対象とする。

ある生産段階が完了した後、対象は複数の後続工程へ進む可能性がある。

```text
前工程完了 → 次工程

検査完了 → 手直し工程

検査完了 → 回流工程

検査完了 → 廃棄処理工程

検査完了 → 隔離工程

保全完了 → 自動生産へ再投入
```

これらはいずれも、明確な生産状態遷移である。

手直し、回流、廃棄処理、隔離、再投入などの名称は、現場で使用されている工程上の意味をそのまま維持する。

TPCA の状態遷移視点では、これらはいずれも、

```text
Current State → New Target State / Target Path
```

として扱う。

後続で、過去と同一または類似した状態内容が再び現れた場合でも、それは新しい状態インスタンスである。

TPCA / PCN が対象とするのは、

> **Current State から Target State、目標実行経路、または目標生産段階へ進む前に、必要な条件、許可、実行チェーンが成立しているか**

という判定である。

PCN は、明確な Target State Entry の前に配置する。

基本的な処理の流れは次のとおりである。

```text
Current State
→ Target State
→ PCN
→ 複数ソース状態信号
→ C / A / E 状態マッピング
→ S / D / B 判定
→ CAE-SDB Result + T
→ Arbitration
→ Multipath Control
→ PCN Trace
```

例えば、Current State が「検査完了」である場合、後続の Target State として、次工程、手直し工程、回流工程、廃棄処理工程、隔離工程などを設定できる。

PCN は、対象製品または対象ロット、Target State、関連する複数ソース状態に基づいて判定を行い、対応する生産経路の制御結果を形成する。

PCN の具体的な実装は、MES、製造実行ミドルウェア、産業用エッジシステム、PLC / HMI 協調モジュール、その他のソフトウェアコンポーネントとして実現できる。

本事例では、具体的な実装プラットフォームを限定しない。

## 3. 複数ソース状態信号と C / A / E 状態マッピング

代表的な状態を以下に示す。

| 情報源 | 代表的な状態 |
|---|---|
| MES | 作業指示状態、ロット番号、製品型式、生産許可、レシピ番号 |
| 品質システム | 検査完了、品質結果、品質承認、手直し判定、廃棄判定、隔離状態 |
| PLC / 設備 | 自動モード、設備 Ready、現在工程段階、レシピ読込み、動作完了、設備アラーム |
| 保全システム | 点検完了、修理完了、保全解除、再投入許可 |
| 人員 / 権限システム | オペレータ本人確認、資格、権限、人による確認 |
| 材料 / トレーサビリティシステム | 材料 ID、ロット関連付け、トレーサビリティ識別子、前工程結果との関連付け |
| 下流 / 搬送システム | 下流受入可能状態、バッファ容量、搬送可否、引渡し許可 |
| データインターフェース | 状態更新時刻、状態バージョン、シーケンス情報、書き戻し完了、インターフェース利用可否、同期完了 |

これらの状態は、情報源ではなく、本 Target State Entry における判定上の役割に基づいて C / A / E へマッピングする。

| 状態変数領域 | 判定内容 | 本事例における代表項目 |
|---|---|---|
| C：Condition | Target State へ進むために必要な事実条件が成立しているか | 作業指示有効、対象ロット一致、前工程完了、品質結果あり、材料・レシピ一致、トレーサビリティ関係有効 |
| A：Authority | システムとして Target State への進入が許可されているか | 品質承認、生産許可、保全解除、人員権限、人による確認、特別承認 |
| E：Execution Chain | Target State へ進んだ後、実行チェーンを継続できるか | 設備が実行可能、下流が受入可能、搬送が実行可能、バッファが利用可能、手直し・回流・廃棄処理・隔離経路が利用可能、結果アップロードおよびトレーサビリティ書き戻しが可能 |

C / A / E は、システムの情報源によって分類するものではない。

同一システムが C、A、E に関係する複数の状態を同時に提供する場合もある。また、同じ状態であっても、Target State Entry が変われば、その判定上の役割が変わる場合がある。

### 品質結果と品質承認

例えば、

```text
品質結果 = 合格
```

であり、Target State が「次工程」である場合、この品質結果は C における事実条件として扱うことができる。

一方、

```text
品質承認 = 承認済み
```

は、正式な進入許可が成立していることを示すため、A に属する。

したがって、

> **品質結果が合格であることと、品質承認が成立していることは同じではない。**

### 品質 NG と Target State

例えば、

```text
品質結果 = NG
```

であっても、その意味は Target State によって異なる。

Target State が「次の正常生産工程」である場合、品質 NG は関連する C 条件が成立していないことを示し得る。

一方、Target State が「手直し工程」である場合、品質 NG は手直し工程へ進むために必要な C 条件の一つとなり得る。

回流、廃棄処理、隔離についても同様であり、それぞれの Target State を中心として C / A / E を構成する。

したがって、

> **状態の意味は、Current State、Target State、具体的な Target State Entry との関係によって決まり、状態値だけを切り離して判断することはできない。**

### 設備 Ready と Execution Chain

設備 Ready は、設備本体が局所的に運転可能な状態であることを示すにすぎない。

下流が受入不能、搬送が利用不能、バッファが満杯、手直し工程へ接続不能、廃棄処理工程が利用不能、隔離場所が利用不能、結果書き戻しが継続不能である場合、E：Execution Chain が成立しているとは判断できない。

## 4. S / D / B 判定

C / A / E 状態マッピング後、PCN は各状態変数を S / D / B の判定性質から評価する。

| 判定性質 | 判定内容 | 本事例における代表項目 |
|---|---|---|
| S：Structure | 必要な信号、インターフェース、マッピング関係、許可元、実行チェーン境界が定義・接続され、観測可能であるか | ロットと品質結果のマッピング、品質承認元、保全解除元、手直し / 回流 / 廃棄処理 / 隔離工程インターフェース |
| D：Dynamics | 現在状態が現在も有効で、同期され、タイムアウト・取消・競合が発生していないか | 作業指示切替、レシピ同期、許可取消、状態未更新、状態失効、バージョン不一致、インターフェース遅延 |
| B：Boundary | 現在状態が事前に定義された制御境界に到達しているか | 待ち時間、同期時間、人による確認の有効期限、バッファ容量、リトライ上限、手直し回数 |

### 状態値が所定の値であることと、現在も有効であることは同じではない

製造 DX では、複数ソース状態を異なるシステムから取得するため、取得周期、更新時刻、状態保持方式は必ずしも一致しない。

したがって、PCN は単に、

```text
品質結果 = 合格
下流 = 受入可能
保全解除 = 成立
人による確認 = 完了
```

という値を読み取るだけでは不十分である。

さらに、それらが**対象および本 Target State Entry に対して現在も有効な状態であるか**を確認する必要がある。

例えば、

```text
品質結果 = 合格
```

であっても、その結果が対象製品または対象ロットに対応しており、状態バージョン、更新時刻、有効範囲が本状態遷移の要求を満たしていることを確認できて初めて、現在の C 条件に対する有効な判定根拠として使用できる。

同様に、

```text
下流受入可能 = 成立
```

であっても、その値が長時間更新されていない、または下流側の状態切替前に生成されたものである場合、現在値が所定の値を示していても、E：Execution Chain が現在も有効であるとは判断できない。

したがって、製造 DX では、

```text
状態値が所定値 ≠ 状態が現在も有効
```

を区別する必要がある。

PCN による判定では、現在値だけでなく、対象との関連付け、更新時刻、更新状態、状態バージョン、シーケンス情報、必要な有効時間範囲などを組み合わせて現在の有効性を判断する。

これは、すべてのシステムに同一の Timestamp や更新周期を要求するものではない。

MES、品質システム、PLC、保全システム、人員システム、下流システムは、それぞれ異なる更新方式を使用できる。

技術上必要なのは、

> **本 Target State Entry に関係する状態が、現在有効であるかを判断するために十分な時間的意味を持つこと**

である。

この時間的意味は、システム特性に応じて、状態更新時刻、バージョン番号、シーケンス情報、ロット番号、イベント識別子、更新状態、その他の追跡可能な情報によって与えることができる。

これらは D：Dynamics の動的時系列有効性判定に使用する。

本事例では、各状態および CAE-SDB Result とともに、対応する時間情報 **T** を保持する。

T は Timestamp、更新時刻、イベント時刻などで表すことができ、本状態および判定の時間位置を示し、状態間の前後関係、継続時間、動的時系列有効性判定、PCN Trace の形成に利用する。

具体的な有効時間、更新周期、同期ウィンドウ、失効条件は、実際の生産システム、工程要求、制御要求に応じて設計する。

### C-S

品質結果は存在しているが、

```text
品質結果 ↔ 対象ロット
```

の明確な関連付けが定義されていない場合、C 領域における構造完全性の問題となる。

### C-D

MES は新しい作業指示へ切り替わっているが、PLC が前のレシピを保持している場合や、品質結果が前ロットに属している場合がある。

また、状態値自体は存在していても、本 Target State Entry で許容される有効範囲を超えている、または複数システム間で状態バージョンやシーケンス関係が一致していない場合もある。

この場合、必要な情報は存在しているが、現在の判定根拠として使用するための動的時系列有効性を満たしていない。

### A-S

Target State への進入に品質承認、保全解除、特定人員による確認が必要であるにもかかわらず、その許可元がシステム上で明確に定義されていない場合、A 領域における構造完全性の問題となる。

### A-D

品質許可は一度成立したが、その後取り消された場合や、保全解除状態が変化したにもかかわらず関連システムに旧状態が残っている場合がある。

また、人による確認、生産許可、その他の認可状態が有効範囲を超えているにもかかわらず、システムが以前の許可状態を保持している場合もある。

この場合、許可元は存在するが、現在の許可状態を判定根拠として使用するための動的時系列有効性を満たしていない。

### E-S

手直し、回流、廃棄処理、隔離、下流受入、結果書き戻しなどの実行経路は存在していても、それらに必要な信号、インターフェース、役割、実行チェーン境界が十分に定義されていない場合がある。

この場合、E 領域における構造完全性の問題となる。

### E-D

下流は受入可能と表示されているが、長時間更新されていない場合がある。また、手直し設備、搬送システム、廃棄処理設備、隔離エリア、結果書き戻しインターフェースが、切替中、遅延、閉塞などの状態にある場合もある。

ある状態値が正常を示していても、その更新時刻、状態バージョン、シーケンス関係、関連コンテキストから、本 Target State Entry に現在も適用可能であることを確認できない場合、その Execution Chain が現在有効であるとは判断できない。

この場合、実行チェーンの構造は定義されているが、現在の状態で継続可能であることを確認できない。

### B に関する判定

生産プロセスでは、さらに次のような状態が発生することがある。

- 状態同期待ちが事前設定時間に到達する。
- 人による確認が有効期限に到達する。
- 再読込みまたはリトライが事前設定回数に到達する。
- 下流バッファが容量境界に接近する。
- 作業指示切替が長時間安定しない。
- 許可状態が再確認条件に到達する。
- 手直し回数が事前に定義された制御境界に到達する。

これらの判定は CAE-SDB Result を形成し、Arbitration へ入力する。

## 5. 生産状態遷移と Multipath Control

同一の Current State から、複数の候補 Target State または生産経路へ分岐する場合がある。

例えば、検査工程完了後、対象の状態に応じて次の工程へ進むことができる。

```text
次工程
手直し工程
回流工程
廃棄処理工程
隔離工程
```

各候補 Target State に対して、PCN は対応する C / A / E を構成し、S / D / B 判定を行う。

### 次工程へ進む場合

```text
Current State：前工程完了

Target State：次工程
```

代表的な関連状態：

```text
作業指示有効
品質結果合格
品質承認成立
設備実行可能
下流受入可能
トレーサビリティ関係有効
```

Target State Entry への進入条件が成立したと判定された場合、

```text
CAE-SDB Result + T
→ Arbitration
→ Multipath Control
→ 進入許可
```

となり、対象製品または対象ロットは次工程へ進む。

### 品質承認状態が同期していない場合

```text
Current State：前工程完了

Target State：次工程

品質結果：合格
```

ここで、

```text
品質承認状態：未同期
下流状態：更新遅延
```

である場合、例えば、

```text
A-D + E-D
```

という CAE-SDB Result を形成し得る。

その後、

```text
CAE-SDB Result + T
→ Arbitration
→ Multipath Control
→ 待機 / 状態再同期 / 再確認
```

となり、対象製品または対象ロットは一時的に Target State へ進まない。

関連状態が更新された後、PCN は再度判定を行う。

### 手直し工程へ進む場合

```text
Current State：検査完了

品質結果：NG

Target State：手直し工程
```

PCN は、例えば次の内容を判定する。

```text
C：
対象製品、対象ロット、品質結果、手直し条件が成立しているか

A：
手直し許可、品質許可、人員権限が成立しているか

E：
手直し設備、搬送、バッファ、トレーサビリティ、結果書き戻しが利用可能か
```

Target State Entry への進入条件が成立したと判定された場合、

```text
CAE-SDB Result + T
→ Arbitration
→ Multipath Control
→ 手直し工程へ進入
```

となる。

### 回流または廃棄処理工程へ進む場合

回流、廃棄処理などの経路も、それぞれの Target State Entry を中心として判定する。

例えば、

```text
Current State：検査完了

Target State：廃棄処理工程
```

の場合、PCN は次の内容を判定する。

```text
C：
廃棄判定、製品 ID、ロット情報が成立しているか

A：
廃棄処理許可が成立しているか

E：
廃棄搬送、回収、数量計上、トレーサビリティ、結果書き戻しが利用可能か
```

Target State Entry への進入条件が成立したと判定された場合、

```text
→ Multipath Control
→ 廃棄処理工程へ進入
```

となる。

手直し、回流、廃棄処理、隔離は、いずれも生産プロセス上の Target State または目標実行経路として扱う。

TPCA の状態遷移視点では、これらはすべて Current State から新しい Target State または目標実行経路へ進むことを意味し、過去の状態インスタンスへ戻ることを意味しない。

## 6. 代表的な CAE-SDB Result、時間情報 T、制御経路、PCN Trace

本事例で想定される代表的な CAE-SDB Result を以下に示す。

| 判定座標 | 本事例における代表状態 |
|---|---|
| C-S | 対象ロットと品質結果、作業指示、レシピの対応関係が明確に定義されていない |
| C-D | 作業指示、ロット、レシピ、品質結果の切替が非同期、状態失効、バージョン不一致 |
| C-B | C：Condition に関係する状態が事前定義された再確認条件または制御境界に到達 |
| A-S | 品質承認、保全解除、人による確認などの許可元が明確に定義されていない |
| A-D | 許可取消、遅延、未更新、有効範囲超過、複数システム間状態非同期 |
| A-B | 許可待ち、確認有効期限、人による確認が制御境界に到達 |
| E-S | 下流受入、手直し、回流、廃棄処理、隔離、結果書き戻しに必要な経路が明確に定義されていない |
| E-D | 下流、搬送、手直し設備、廃棄処理、バッファ、インターフェース、書き戻し状態が現在有効でない、または継続可能であることを確認できない |
| E-B | バッファ容量、待ち時間、手直し回数、Execution Chain に関係する状態が事前定義された制御境界に到達 |

各 CAE-SDB Result とともに、対応する時間情報 T を保持する。

CAE-SDB Result は Arbitration を経て Multipath Control を形成する。

代表的な制御出力には、次のようなものがある。

- 進入許可
- 待機
- 再読込み
- 再照合
- 再確認
- 状態再同期
- 手直し
- 回流
- 廃棄処理
- 異常分流
- 下流調整
- リソース解放
- 縮退実行
- 代替経路
- 進入禁止
- 安全ロック
- 人による確認
- 隔離
- 強化記録

例えば、

```text
CAE-SDB Result： C-D

判定内容： 作業指示は切り替わっているが、PLC レシピが未同期

Multipath Control： 再読込み / 同期待ち
```

また、

```text
CAE-SDB Result：
C-D

判定内容：
品質結果は合格だが、前ロットに属している、
または本 Target State Entry に対する有効範囲を超えている

Multipath Control：
再読込み / 再照合 / Target State へ一時的に進入しない
```

あるいは、

```text
CAE-SDB Result：
A-D

判定内容：
品質承認が取り消された、有効範囲を超えている、
または複数システム間で状態が同期していない

Multipath Control：
待機 / 再確認 / Target State へ一時的に進入しない
```

さらに、

```text
CAE-SDB Result：
E-D

判定内容：
下流状態が未更新で、現在受入可能か確認できない

Multipath Control：
更新待ち / 状態再同期
```

また、

```text
Target State：手直し工程

CAE-SDB Result：
E-S

判定内容：
手直しに必要な Execution Chain が明確に定義されていない

Multipath Control：
手直し工程へ一時的に進入しない
→ 人による確認 / 技術確認
```

一方、

```text
Target State：廃棄処理工程

C / A / E：必要条件が成立

Multipath Control：廃棄処理工程への進入許可
```

となる。

1 回の PCN 判定では、対応する PCN Trace を同時に形成する。

代表的な記録項目は次のとおりである。

```text
Current State
Target State
主要入力状態
時間情報 T
C / A / E 状態マッピング
S / D / B 判定
CAE-SDB Result
Arbitration Result
Multipath Control
実行結果
Trace ID
```

必要に応じて、主要入力状態には次の情報を関連付けることができる。

```text
対象 / ロット情報
状態更新時刻
状態バージョン / シーケンス情報
関連イベントまたはトレーサビリティ識別子
```

これらの情報は、本判定がどの有効状態とコンテキストを根拠としたかを明確にするために使用する。

例えば、

```text
Current State：前工程完了

Target State：次工程

時間情報：T

CAE-SDB Result：A-D + E-D

判定内容：品質承認状態の再確認が必要。下流受入状態が適時更新されていない

Arbitration Result：Target State への即時進入を許可しない

Multipath Control：状態再同期 / 再確認

実行結果：Target State へは一時的に未進入
```

また、

```text
Current State：検査完了

Target State：手直し工程

時間情報：T

品質結果：NG

Multipath Control：手直し工程への進入許可

実行結果：対象製品または対象ロットが手直し工程へ進入
```

となる。

PCN Trace が記録する中心情報は、

> **今回どの Target State へ進もうとしていたのか、どの現在有効な状態を根拠に判定したのか、なぜその判定結果となったのか、そして最終的にどの生産経路へ進んだのか。**

という状態遷移判定履歴である。

## 7. 履歴分析、AI 補助分析、製造 DX における価値

複数の PCN を継続運用すると、PCN Trace が蓄積される。

製造 DX では、設備効率、生産実績、品質結果、停止、アラーム、エネルギー消費、物流などの分析に加えて、状態遷移判定履歴を用いた次のような分析が可能になる。

- どの Target State が頻繁に成立しないか。
- どの C 条件が長期的に状態遷移を阻害しているか。
- どの A 許可が生産許可のボトルネックとなっているか。
- どの E：Execution Chain が頻繁に継続不能となっているか。
- どの手直し、回流、廃棄処理経路が高頻度で使用されているか。
- どの S：Structure に関係する問題が繰り返し発生しているか。
- どの D：Dynamics に関係する問題が継続して発生しているか。
- どの B：Boundary が頻繁に到達しているか。
- どの制御経路が高頻度で使用されているか。
- どの技術改善後に、同一判定結果が減少したか。

例えば、A-S が高頻度で発生している場合、許可元、責任分界、システムインターフェースの定義を見直す必要がある可能性がある。

C-D、A-D、E-D が高頻度で発生している場合は、作業指示切替、状態更新、状態有効性、バージョン関係、インターフェース遅延、複数システム間同期を重点的に確認できる。

複数システムが同一の状態遷移判定に関与する場合、特に重要なのは、

> **各システム内の状態が個別には正しくても、それらが同一の Target State Entry 判定に対して同時に有効であるとは限らない。**

という点である。

例えば、MES、品質システム、PLC、下流システムが、それぞれ妥当な状態値を保持していても、それらが異なる対象、異なるロット、異なる状態バージョン、異なる更新時間範囲に属している場合、単純に組み合わせて一つの有効な状態遷移判定根拠とすることはできない。

手直し経路が長期的に高頻度で使用されている場合は、製品、設備、工程、品質履歴と組み合わせて発生条件を分析できる。

特定の B 判定が頻繁に成立する場合は、現在の状態遷移条件、確認方式、制御境界が適切かを再検討できる。

したがって、PCN Trace は事後追跡だけでなく、生産状態遷移設計を見直すためのデータソースとしても利用できる。

手直し、回流、再投入などについても、PCN Trace は、状態内容が同じであっても、発生時間や遷移履歴が異なる状態インスタンスを区別できる。

### AI 補助分析

本事例では、AI は現場における確定的制御を担当せず、PCN Trace の補助分析に使用する。

AI の分析対象は、単独の設備状態、アラーム、生産結果、時系列データだけではなく、具体的な Target State Entry と結び付いた PCN Trace である。

PCN Trace は、

```text
Current State
Target State
主要入力状態
時間情報 T
C / A / E 状態マッピング
S / D / B 判定
CAE-SDB Result
Arbitration Result
Multipath Control
実行結果
```

を、同一の状態遷移判定履歴として整理する。

そのため AI は、

```text
状態値そのものが異常
```

である場合と、

```text
状態値は正常だが、
失効、未更新、非同期、または本 Target State Entry に適用できない
```

場合を区別して分析できる。

ここで重要なのは、データ量を増やすことではなく、**状態遷移コンテキストと判定意味を付加すること**である。

従来の MES / SCADA データは、設備状態、アラーム、イベント、生産結果などを中心として記録する。

PCN Trace はさらに、

> **システムがその時点でどの Target State へ進もうとしていたのか、どの状態を根拠として判定したのか、なぜその制御経路を選択したのか、そして最終的に状態遷移がどのように実行されたのか**

を記録する。

したがって、

> **PCN Trace は単なる状態履歴ではなく、状態遷移判定履歴である。**

これにより、AI 分析は単純な状態相関分析から、状態遷移条件、動的時系列有効性、制御経路を対象とした履歴比較へ展開できる。

基本的な位置付けは次のとおりである。

```text
PCN Trace
→ 履歴集約
→ AI 補助分析
→ 改善候補
→ エンジニア確認
→ 限定試行
→ 効果確認
→ 状態遷移設計更新
```

AI は、例えば次の作業を補助できる。

- 同種の PCN Trace の集約
- 高頻度の C / A / E と S / D / B の組合せの抽出
- 異なる Target State における繰返し問題の比較
- 状態値異常と動的時系列有効性問題の区別
- 手直し、回流、廃棄処理などの経路利用傾向の分析
- 改善前後の判定結果比較
- 確認項目候補や技術レポートの生成

例えば、長期間の PCN Trace に次の結果が繰り返し記録されている場合、

```text
Target State：次工程

CAE-SDB Result：A-D

関連状態：品質承認状態が非同期

Multipath Control：待機 / 再確認
```

AI は、例えば次のような改善候補を提示できる。

> 作業指示切替時に品質承認状態の非同期が繰り返し発生しているため、品質システムと MES 間の承認状態同期処理を優先的に確認する。

この出力は、技術分析上の改善候補である。

AI は、次の責務を負わない。

- PCN の変更
- CAE-SDB ルールの変更
- 制御境界の変更
- Arbitration を迂回した現場制御の出力
- 技術変更の自動承認

最終的な状態定義、許可関係、制御境界、PCN ルール変更、限定試行、効果確認、正式採用については、企業既存の技術変更管理プロセスに従って確認する。

この枠組みにおける製造 DX の重点は、単に「より多くのデータをシステムへ接続すること」ではない。

> **データ、設備、人員、品質、権限、生産プロセス間の状態遷移条件を明示化・構造化し、追跡可能な履歴を形成すること**

にある。

## 8. 公開範囲

本稿は、製造 DX 状態遷移条件設計・履歴分析に関する公開説明事例である。

本稿で公開する内容は、次の事項に限る。

- Current State / Target State
- 生産状態遷移における PCN の位置
- 代表的な複数ソース状態
- C / A / E 状態マッピング
- S / D / B 判定
- CAE-SDB Result
- 時間情報 T
- 代表的な Arbitration と Multipath Control
- PCN Trace と履歴分析の価値

本稿における時間情報 T および状態の動的時系列有効性に関する内容は、技術判定の原則を説明するためのものである。

具体的な状態有効時間、更新周期、同期ウィンドウ、バージョンルール、失効条件、リトライ回数、関連制御パラメータは、実際の生産システム、工程要求、プラットフォームアーキテクチャ、制御要求に応じて設計する必要があり、本稿では公開しない。

具体的な実装は、プラットフォームアーキテクチャ、現場設備、品質要求、安全要求、権限体系、納入仕様を踏まえて設計する。

PCN は、安全 PLC、安全リレー、ハードウェア安全回路、企業既存の強制安全制御メカニズムを置き換えるものではない。
