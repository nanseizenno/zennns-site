# 自動加工が完了していても、なぜ手作業セルで組立を開始できないのか

> 適用階層：製造プロセス / システム横断状態遷移  
> 代表対象：部品の自動加工 → 手作業セルでの組立

**推奨引用：**

```text
全野南政 / Nansei Zenno，
『製造DXにおける状態遷移条件設計・履歴分析事例：自動加工が完了していても、なぜ手作業セルで組立を開始できないのか』，
公開事例，Public Case Version 1.5，
2026-09-20，
https://zennns.com/jp/cases/production-dx-state-transition/
```

製造現場では、次のような工程構成が一般的に存在する。

```text
自動加工設備
    ↓
部品加工完了
    ↓
搬送 / 部品供給
    ↓
手作業セルでの組立
```

自動加工が完了しているからといって、次工程を直ちに開始できるとは限らない。

手作業セルで組立を開始するためには、品質判定、工程移行許可、必要部品の供給状態、作業者資格、セル設備、治具・締結工具、組立後の検査、完成品搬出、実績データの書戻しなど、複数の状態が関係する。

本事例が対象とする工程問題は、次の問いである。

> **自動加工は完了しているのに、なぜ現在の部品は手作業セルで組立を開始できないのか。**

本事例で確認するのは、「自動加工が完了した」という単一の状態ではない。

> **明確な目標状態入口を基準として、設備、MES、品質システム、作業者資格、部品供給、後工程に分散している状態を同一の判定に関連付け、どの状態が現在の入口成立を阻害しているのか、どのような処理が必要なのか、処理後にどのように再判定するのかを明確にできるか。**

という工程関係を扱う。

本事例は、統一した9ステップの工程順序に沿って説明する。

```text
1. 現在状態
2. 目標状態 / 目標状態入口
3. PCN：関連状態取得 + C / A / E 状態マッピング
4. S / D / B 判定 → CAE-SDB Result + T
5. 制御優先度調停
6. 複数経路制御
7. 現在の入口に対する制御結果
8. 後続の目標状態入口と実行結果
9. 状態遷移判定履歴
```

基礎概念については、以下を参照できる。

- [中核概念](/jp/concepts/)
- [TPCA / PCN 状態遷移前制御アーキテクチャ｜ホワイトペーパー](/jp/whitepaper/)

## 事例対象

本事例では、自動加工設備で対象部品の加工が完了し、搬送後に作業者が担当する手作業セルで組立を開始する工程を対象とする。

今回の状態遷移に関係する主な対象は、次のとおりである。

- MES
- 自動加工設備 / PLC
- 品質管理システム
- 部品搬送・供給システム
- 作業者認証・資格管理システム
- 手作業セル設備
- 治具・締結工具
- 組立後検査
- 完成品搬出
- 生産実績データの書戻し

この工程は、自動設備、情報システム、人、部品、工具、後工程をまたいで成立する。

そのため、製造DXにおける代表的なシステム横断状態遷移の一つとして扱うことができる。

---

# 1. 現在状態

現在、現場はどの状態にあるか。

```text
現在状態：

自動加工完了
/
手作業セルでの組立待ち
```

この時点では、次の状態が確認されている。

```text
加工完了：
成立

部品番号：
読取済み

対象ロット：
確定済み

品質測定：
完了

部品搬送：
完了
```

これが、今回の状態遷移の起点となる。

---

# 2. 目標状態 / 目標状態入口

今回、どの状態へ進もうとしているか。

```text
目標状態：
対象部品の手作業セル組立実行中

目標状態入口：
対象部品の手作業セル組立開始
```

PCN は、現在状態と目標状態入口の間に配置される。

```text
現在状態
［自動加工完了 / 組立待ち］
        ↓
PCN
［組立開始前判定］
        ↓
目標状態入口
［対象部品の手作業セル組立開始］
        ↓
目標状態
［対象部品の組立実行中］
```

今回確認するのは、次の工程関係である。

> **現在の加工済み部品について、現在の作業者が、現在の手作業セルで組立を開始できるか。また、組立開始後に必要な実行チェーンを継続できるか。**

---

# 3. PCN：関連状態取得と C / A / E 状態マッピング

今回の目標状態入口に対して、どの状態が重要になるか。

PCN は、組立開始に直接関係する状態を取得し、それぞれが今回の目標状態入口で担う工程上の役割に基づいて C / A / E へマッピングする。

| 代表状態 | 状態マッピング |
|---|---|
| 加工完了、部品番号、ロット、品質判定結果、必要部品 | C：条件状態 |
| 工程移行許可、生産許可、作業者資格、対象製品の作業権限 | A：許可状態 |
| セル設備準備状態、治具、締結工具、組立後検査、完成品搬出、実績データ書戻し | E：実行チェーン状態 |

本事例では、主に次の状態を使用する。

```text
加工完了 → C

品質判定結果 → C

工程移行許可 → A

作業者資格 → A

セル設備準備完了 → E の関連状態

後工程検査 / 実績データ書戻し → E
```

ここでは、品質に関する二つの状態を区別する必要がある。

```text
品質判定結果 = 合格

→ 現在の部品が
   定義された品質条件を満たしている

→ C
```

一方、

```text
工程移行許可 = 成立

→ 現在の部品を
   次工程へ進めることが許可されている

→ A
```

という関係になる。

同様に、セル設備が準備完了であっても、現在の作業者が当該製品の組立作業を行う資格を有しているとは限らない。

---

# 4. S / D / B 判定と CAE-SDB Result

今回、どのような判定問題が発生したか。

本事例では、次の状態を仮定する。

```text
加工完了：
成立

品質判定結果：
合格

工程移行許可：
成立

必要部品：
揃っている

セル設備：
準備完了

作業者ログイン：
有効

対象製品の作業資格：
登録済みだが、有効期限を超過
```

作業者資格は、今回の目標状態入口において A：Authority に対応する。

資格情報そのものは存在しているが、現在の資格有効期限が許容範囲を超えている。

したがって、問題は許可状態の制御境界にあり、次の CAE-SDB Result が形成される。

```text
CAE-SDB Result：

A-B


判定内容：

現在の作業者資格が有効期限を超過しており、
今回の組立開始入口に定義された
許可条件を満たしていない
```

時間情報 T は、今回の状態および判定結果と関連付けて保持する。

本事例では、9つの CAE-SDB 座標すべてを展開しない。

C / A / E と S / D / B の全体関係については、以下を参照できる。

[なぜ CAE-SDB なのか？——目標状態入口前の二軸構造化分析法](/jp/notes/why-cae-sdb/)

---

# 5. 制御優先度調停

複数の判定結果が存在する場合、何を優先して処理するか。

今回の制御優先度調停における主な入力は、次のとおりである。

```text
C 関連状態：
現在の入口要求を満たす

E 関連状態：
現在の入口要求を満たす

工程移行許可：
成立

作業者資格：
A-B

資格有効期限：
超過
```

作業者資格は、今回の組立開始入口における重要な A である。

そのため、加工完了、品質合格、設備準備完了といった他の状態が成立していても、現在の作業者資格が有効でなければ組立開始は許可されない。

今回の制御優先度調停結果は、次のとおりである。

```text
制御優先度調停結果：

現在の組立開始を保留

作業者資格の確認・是正を優先
```

---

# 6. 複数経路制御

どの制御処理が選択されたか。

今回の制御優先度調停結果から、次の処理を選択する。

```text
複数経路制御：

有効な作業資格を持つ作業者を確認し、
必要に応じて作業者を変更する
```

この処理は、現在の組立開始入口に対して行う是正処理である。

---

# 7. 現在の入口に対する制御結果

今回、組立を開始するか。

```text
現在の入口に対する制御結果：

現在の手作業セル組立は開始しない
```

今回の「対象部品の手作業セル組立開始」という目標状態入口は許可されない。

その理由は、加工未完了でも、設備未準備でもない。

> **重要な許可状態 A である作業者資格が、現在の入口要求を満たしていないためである。**

---

# 8. 制御経路の実行 / 後続の目標状態入口と実行結果

選択された処理を実行した後、何が起きるか。

今回の処理は、次のように進む。

```text
現在の組立開始を保留
    ↓
作業者資格を再確認
    ↓
有効な資格を持つ作業者へ変更
    ↓
最新の資格状態を取得
    ↓
実行結果
```

処理完了後、次の状態になったと仮定する。

```text
作業者ログイン：
有効

対象製品の作業資格：
有効
```

この場合、実行結果は次のように整理できる。

```text
実行結果：

有効な作業資格を持つ作業者への変更が完了し、
現在の作業資格が有効であることを確認
```

ただし、この時点で確定したのは、新しい運転状態である。

その後、再び次の目標状態入口が要求された場合、

```text
目標状態入口：

対象部品の手作業セル組立開始
```

更新された状態に基づいて、PCN が改めて前制御判定を行う。

また、後続制御として別の作業セル、リワーク工程、隔離工程など、別の目標状態が選択された場合は、新たな目標状態入口を設定し、その入口を担当する PCN が前制御判定を行う。

---

# 9. 状態遷移判定履歴

今回の状態遷移は、どのような履歴として記録されるか。

今回の組立開始入口については、次のような PCN Trace を形成できる。

```text
【PCN】
手作業セル組立開始入口 PCN

【現在状態】
自動加工完了 / 手作業セル組立待ち

【目標状態】
対象部品の手作業セル組立実行中

【目標状態入口】
対象部品の手作業セル組立開始


【主要状態】

加工完了 = 成立

品質判定結果 = 合格

工程移行許可 = 成立

必要部品 = 揃っている

セル設備 = 準備完了

作業者ログイン = 有効

対象製品の作業資格 = 有効期限超過


【CAE-SDB Result】

A-B


【判定内容】

現在の作業者資格が有効期限を超過しており、
今回の組立開始入口に定義された
許可条件を満たしていない


【制御優先度調停結果】

現在の組立開始を保留

作業者資格の確認・是正を優先


【複数経路制御】

有効な作業資格を持つ作業者を確認し、
必要に応じて作業者を変更


【現在の入口に対する制御結果】

現在の手作業セル組立は開始しない


【実行結果】

有効な作業資格を持つ作業者への変更が完了

現在の作業資格が有効であることを確認


【時間情報】

T


【履歴 ID】

PCN-CELL-XXXX
```

作業者変更後に、同じ目標状態入口が再度要求された場合は、更新後の状態を使用して新たな前制御判定を行い、新しい PCN Trace を形成する。

前回の履歴は上書きしない。

## 事例まとめ

本事例では、自動加工完了、品質判定合格、工程移行許可成立、必要部品供給完了、セル設備準備完了という状態が成立している。

それでも、作業者資格が有効期限を超過しているため、組立開始は許可されない。

加工完了や設備準備完了だけを確認すると、現場では次の疑問が残る。

> **「前工程は完了していて、設備も準備できているのに、なぜ組立を開始できないのか。」**

これを「対象部品の手作業セル組立開始」という目標状態入口を基準として整理すると、今回の問題は次のように明確化される。

```text
目標状態入口：

対象部品の手作業セル組立開始


CAE-SDB Result：

A-B


具体的な問題：

現在の作業者資格が有効期限を超過しており、
今回の組立開始入口に定義された
許可条件を満たしていない
```

### 本事例によって明確になる工程情報

| 従来の現場情報から確認できること | 本事例によってさらに明確になること |
|---|---|
| 自動加工が完了している | 判定対象は「手作業セル組立開始」という明確な目標状態入口である |
| 品質判定結果が合格している | 品質判定結果は C として、対象部品が品質条件を満たしていることを示す |
| 工程移行許可が成立している | 工程移行許可は A として、対象部品が次工程へ進む許可を持つことを示す |
| 必要部品が揃っている | 部品供給条件は現在の組立開始入口を満たしている |
| セル設備が準備完了である | 設備準備完了は E に関係する状態であり、それだけでは入口成立を意味しない |
| 作業者がログインしている | ログイン状態と、対象製品に対する作業資格の有効性は別の状態である |
| 組立が開始されない | CAE-SDB Result は **A-B：作業者資格の有効期限超過** である |
| 複数システムを確認しなければ原因が分からない | 問題を「重要な許可状態が現在の入口条件を満たしていない」と特定できる |
| 次の対応を人が判断する必要がある | 「有効資格を持つ作業者の確認・変更」という処理方向を明示できる |
| 作業者変更後に状態だけが更新される | 新しい運転事実として扱い、同じ組立開始入口について改めて判定する |
| 各システムが個別に状態やログを保持している | 状態、判定、制御、実行結果を一回の状態遷移判定履歴として関連付けられる |

これにより、従来の、

> **「自動加工は完了しているが、次工程が開始されない。」**

という現象は、

> **「現在の目標状態入口を阻害している状態は何か、その状態はどの工程上の役割に属するか、どの処理を行い、その後どのように再判定するか。」**

という工程関係へ展開できる。

本事例で示した主な工程上の意味は、次のとおりである。

自動加工、品質、部品供給、作業者資格、セル設備、後工程状態を、一回の目標状態入口へ関連付けることができる。

「自動加工は完了しているが組立を開始できない」という現象を、明確な重要許可問題へ展開できる。

品質条件と工程移行許可、設備準備状態と作業者資格など、それぞれ異なる工程上の役割を分離して扱える。

重要な A を独立した必要条件として、目標状態入口の進入可否に反映できる。

判定結果を、処理内容、実行結果、更新後の再判定へ連続して接続できる。

さらに、その一連の状態、判定、制御、実行結果を、一回の状態遷移判定履歴として記録できる。

本事例で追加される価値は、設備や情報システムから取得する状態数を増やすことではない。

> **複数の設備・システム・人に分散していた状態を、「現在の入口がなぜ成立しないのか」「どの工程上の役割に問題があるのか」「どのように処理するのか」「処理後にどのように再判定するのか」という一連の工程関係として組織化することにある。**
