## 1. 現場で発生する問題

生産 DX では、多くの生産情報や運転情報を取得できるようになっている。

MES は作業指示、ロット、計画、生産実績などを記録する。品質システムは検査結果、品質判定、品質承認などを記録する。PLC や設備制御システムからは、自動モード、設備 Ready、アラーム、インターロック、動作状態などを取得できる。

また、人員管理システムでは担当者の識別情報や権限、保全システムでは修理、点検、復旧状態を管理できる。下流設備、搬送システム、バッファからも、受入、占有、運転状態などを取得できる。

それでも現場では、次のような状況が発生することがある。

* 前工程は完了しているが、次工程が開始されない。
* MES 上では作業指示が有効で、設備も Ready であるが、対象製品またはロットが次の段階へ進まない。
* 品質結果は取得済みであるが、対象ロットの工程移行に必要な品質承認を確認できない。
* 検査結果が NG となった後、手直し、工程戻し、廃棄処理、隔離のどの工程へ進めるかを確認する必要がある。
* 保全作業は完了しているが、設備を生産へ再投入するための復旧状態を確認する必要がある。
* 作業指示は切り替わっているが、PLC のレシピ、材料、品質結果、トレーサビリティ情報の同期が完了していない。
* 下流設備は受入可能状態を保持しているが、その状態が今回の判定に使用できる状態かを確認する必要がある。
* 各システムに状態記録が存在していても、対象製品またはロットを次にどの工程へ進めるかについて、複数システムの状態と履歴を照合する必要がある。

このような場面では、次に進もうとしている Target State を明確にし、その Target State Entry に必要な条件状態、許可状態、実行チェーン状態を同じ判定対象として整理する必要がある。

例えば、各システムから次の状態が得られているとする。

```text
MES 作業指示 = 有効
品質結果 = 合格
設備 = Ready
担当者確認 = 完了
下流 = 受入可能
```

この場合も、Target State Entry の判定では、さらに次の状態関係を確認する。

* 品質結果が現在の製品またはロットに対応しているか。
* 工程移行に必要な品質承認が成立しているか。
* 作業指示、レシピ、材料、設備モードが対応しているか。
* 保全復旧に必要な許可が成立しているか。
* 手動確認を行った担当者が必要な権限を持っているか。
* 下流の受入状態が今回の判定に使用できる状態か。
* Target State へ入った後の実行チェーンを継続できるか。
* 今回の判定内容と制御結果を PCN Trace として記録できるか。

本事例では、

> **明確な生産上の Target State Entry を中心として、異なるシステムに分散した状態を判定・制御・記録できる状態遷移構造として整理する。**

## 2. 事例の位置付けと PCN の配置位置

本事例では、生産プロセスにおけるシステム間状態遷移を対象とする。

ある生産段階が完了した後、対象製品またはロットは、判定結果に応じて異なる後続工程へ進む場合がある。

例えば、次のような状態遷移がある。

```text
前工程完了 → 次生産工程

検査完了 → 手直し工程

検査完了 → 工程戻し

検査完了 → 廃棄処理工程

検査完了 → 隔離工程

保全完了 → 自動生産へ再投入
```

手直し、工程戻し、廃棄処理、隔離、再投入は、それぞれ現場で定義された生産上の経路として扱う。

TPCA / PCN では、各経路を次の関係で扱う。

```text
Current State → New Target State / Target Path
```

同じ工程状態が後から再び発生した場合も、その時点で新しい状態インスタンスが形成される。

PCN は、Current State から明確な Target State へ入る Target State Entry の前に配置する。

基本的な処理関係は次の通りである。

```text
Current State
→ Target State
→ PCN
→ 複数ソース状態
→ C / A / E Mapping
→ S / D / B Evaluation
→ CAE-SDB Result + T
→ Arbitration
→ Multipath Control
→ PCN Trace
```

例えば Current State が「検査完了」の場合、候補となる Target State には、次生産工程、手直し工程、工程戻し、廃棄処理工程、隔離工程などがある。

PCN は、対象製品またはロット、Target State、および今回の状態遷移に関係する複数ソース状態を用いて判定し、次に進む生産経路を形成する。

PCN の実装は、MES、製造実行用ミドルウェア、産業用エッジシステム、PLC / HMI 連携モジュール、その他のソフトウェアコンポーネントなどで構成できる。

## 3. 複数ソース状態と C / A / E 状態マッピング

代表的な状態を次に示す。

| 情報源               | 代表的な状態                                       |
| ----------------- | -------------------------------------------- |
| MES               | 作業指示状態、ロット番号、製品型式、生産許可、レシピ番号                 |
| 品質システム            | 検査完了、品質結果、品質承認、手直し判定、廃棄判定、隔離状態               |
| PLC / 設備          | 自動モード、設備 Ready、現在工程、レシピ読込み、動作完了、設備アラーム       |
| 保全システム            | 点検完了、修理完了、復旧状態、生産再投入許可                       |
| 人員 / 権限システム       | 担当者 ID、資格、権限、手動確認                            |
| 材料 / トレーサビリティシステム | 材料識別、ロット関連付け、トレーサビリティ ID、前工程結果との関連付け         |
| 下流 / 搬送システム       | 下流受入状態、バッファ容量、搬送可能状態、引渡し許可                   |
| データインターフェース       | 状態更新時刻、状態バージョン、シーケンス情報、書戻し完了、インターフェース状態、同期完了 |

これらの状態は、今回の Target State Entry における機能役割に基づいて C / A / E へマッピングする。

```text
C：必要な条件が揃っているか。
A：進入が許可されているか。
E：進入後の実行チェーンが継続できるか。
```

| 状態変数領域                       | 判定対象                                | 本事例における代表的な状態                                                         |
| ---------------------------- | ----------------------------------- | --------------------------------------------------------------------- |
| C：Condition / 条件状態           | Target State へ入るために必要な事実条件が成立しているか  | 作業指示状態、ロット状態、前工程完了状態、品質結果、材料状態、レシピ状態、トレーサビリティ関係                       |
| A：Authority / 許可状態           | Target State への進入が許可されているか          | 品質承認、生産許可、保全復旧許可、担当者権限、手動確認、特別承認                                      |
| E：Execution Chain / 実行チェーン状態 | Target State へ入った後に後続の実行チェーンを継続できるか | 設備実行状態、下流受入状態、搬送状態、バッファ状態、手直し / 工程戻し / 廃棄処理 / 隔離経路、結果送信、トレーサビリティ書戻し状態 |

関連状態は、今回の Target State Entry における役割に基づいて C / A / E へマッピングし、その後に必要な S / D / B 判定を行う。

### 品質結果と品質承認

例えば、

```text
品質結果 = 合格
```

という状態があり、Target State が「次生産工程」である場合、この品質結果は C に関係する事実条件として扱うことができる。

一方、

```text
品質承認 = 承認済み
```

は、次工程への移行に必要な A の許可状態として扱う。

したがって、今回の Target State Entry では次のように整理する。

```text
品質結果 → C
品質承認 → A
```

### 品質 NG と Target State

次の状態を考える。

```text
品質結果 = NG
```

この状態の C における役割は、Target State によって変わる。

Target State が「次の正常生産工程」の場合、品質 NG は、その工程へ入るために必要な C の判定に使用される。

Target State が「手直し工程」の場合は、品質 NG を手直し工程へ入るための C の一つとして使用できる。

工程戻し、廃棄処理、隔離についても、それぞれの Target State Entry に必要な C / A / E を設定する。

このように、同じ状態であっても、Current State、Target State、Target State Entry に応じて状態マッピングを行う。

### 設備 Ready と実行チェーン

設備 Ready は、設備本体の運転準備状態として、今回の Target State Entry に関係する入力状態の一つとなる。

E では、設備状態とともに、下流受入、搬送、バッファ、手直し工程、工程戻し、廃棄処理、隔離位置、結果書戻しなど、Target State へ入った後の実行チェーンに関係する状態を確認する。

## 4. S / D / B 判定

C / A / E 状態マッピングの後、PCN は関連状態に対して必要な S / D / B 判定を行う。

```text
S：判定に必要な構造が成立しているか。
D：現在の状態を本判定の根拠として使用できるか。
B：現在の状態が事前定義された制御境界に到達しているか。
```

| 判定性質                  | 判定対象                                                          | 本事例における代表項目                                                    |
| --------------------- | ------------------------------------------------------------- | -------------------------------------------------------------- |
| S：Structure / 構造完全性   | 必要な対象、信号、インターフェース、マッピング関係、許可元、経路、役割、実行チェーン境界が定義・接続され、観測可能であるか | ロットと品質結果のマッピング、品質承認元、保全復旧許可元、手直し / 工程戻し / 廃棄処理 / 隔離工程のインターフェース |
| D：Dynamics / 動的時系列有効性 | 関連状態が現在も有効で、同期・安定し、今回の判定に使用できるか                               | 作業指示切替、レシピ同期、許可取消、状態未更新、状態有効期限、バージョン不一致、インターフェース遅延             |
| B：Boundary / 制御境界     | 関連状態と事前定義された制御境界との関係                                          | 待機時間、同期時間、手動確認有効期間、バッファ容量、再試行回数、手直し回数                          |

### 状態値と現在の有効性

生産 DX では、MES、品質システム、PLC、保全システム、人員システム、下流システムなど、複数の情報源から状態を取得する。

各システムでは、更新タイミングや状態保持方法が異なる。

例えば、

```text
品質結果 = 合格
```

という状態については、現在の製品またはロットとの対応関係、および今回の Target State Entry に使用する対象、バージョン、時間情報を確認する。

同様に、

```text
下流受入可能 = TRUE
```

という状態についても、更新時刻や状態切替との前後関係を確認し、今回の E の判定に使用する。

状態値と、その状態を現在の Target State Entry に使用できるかという動的時系列有効性は、それぞれ個別に判定する。

D では、例えば次の情報を使用できる。

* 更新時刻
* バージョン番号
* シーケンス情報
* ロット番号
* イベント ID
* 更新状態

CAE-SDB Result には、対応する時間情報 T を保持する。

時間情報 T は、状態の前後関係、D 判定、および PCN Trace に使用する。

### C-S

品質結果は取得されているが、次の関連付けに必要な構造が定義されていない場合を考える。

```text
品質結果 ↔ 現在ロット
```

この場合、該当する S 判定から C-S を形成できる。

### C-D

MES が新しい作業指示へ切り替わった後も PLC が前のレシピを保持している場合や、現在参照している品質結果が前ロットに対応している場合、C に関係する状態の動的時系列有効性を確認する。

また、状態の有効時間、バージョン、シーケンス関係が今回の Target State Entry と一致しているかを判定する。

該当する D 判定結果から C-D を形成できる。

### A-S

Target State への進入に品質承認、保全復旧許可、特定担当者による確認などが必要であり、その許可元が定義または接続されていない場合、A-S を形成できる。

### A-D

品質承認の取消、保全復旧状態の変更、手動確認の有効期限超過、生産許可の更新遅延などについて、A の動的時系列有効性を判定する。

該当する D 判定結果から A-D を形成できる。

### E-S

手直し、工程戻し、廃棄処理、隔離、下流受入、結果書戻しなどについて、必要な信号、インターフェース、役割、実行チェーン境界が定義または接続されているかを判定する。

必要な構造が不足している場合、E-S を形成できる。

### E-D

下流受入状態、手直し設備、搬送システム、廃棄処理設備、隔離エリア、結果書戻しインターフェースなどについて、更新時刻、状態バージョン、シーケンス関係、切替状態を確認する。

今回の Target State Entry に対する動的時系列有効性の判定結果から E-D を形成できる。

### B に関する判定

代表的な Boundary 判定には、次のようなものがある。

* 状態同期待ち時間が事前定義された時間に到達した。
* 手動確認が事前定義された有効期間に到達した。
* 再試行回数が事前定義された上限に到達した。
* 下流バッファが事前定義された容量境界に到達した。
* 作業指示切替後の安定確認時間が事前定義された境界に到達した。
* 手直し回数が事前定義された上限に到達した。

これらの S / D / B 判定結果を C / A / E の状態変数領域と組み合わせ、CAE-SDB Result を形成する。

## 5. 生産状態遷移と Multipath Control

同じ Current State から、複数の Target State または生産経路が候補となる場合がある。

例えば検査工程完了後には、次のような Target State を設定できる。

```text
次生産工程
手直し工程
工程戻し
廃棄処理工程
隔離工程
```

各 Target State Entry に対して、PCN はそれぞれ必要な C / A / E を設定し、S / D / B 判定を行う。

### 次生産工程へ進む場合

```text
Current State：前工程完了

Target State：次生産工程
```

関連する状態には、例えば次のものがある。

```text
作業指示が有効
品質結果が合格
品質承認が成立
設備が実行可能
下流が受入可能
トレーサビリティ関係が有効
```

必要な判定結果を Arbitration で処理し、次生産工程への進入許可を Multipath Control として形成する。

```text
CAE-SDB Result + T
→ Arbitration
→ Multipath Control
→ 次生産工程への進入許可
```

### 品質承認状態の同期が完了していない場合

```text
Current State：前工程完了

Target State：次生産工程

品質結果：合格
```

次の状態が確認された場合を考える。

```text
品質承認状態が未同期
下流状態が未更新
```

対応する D 判定によって、例えば次の CAE-SDB Result を形成できる。

```text
A-D + E-D
```

その後、Arbitration を経て、今回の Target State Entry に対応する Multipath Control を形成する。

```text
CAE-SDB Result + T
→ Arbitration
→ 待機 / 状態再同期 / 再確認
```

### 手直し工程へ進む場合

```text
Current State：検査完了

品質結果：NG

Target State：手直し工程
```

PCN は、今回の Target State Entry に対して、例えば次の状態を判定する。

```text
C：対象製品、ロット、品質結果、手直し条件

A：手直し許可、品質承認、担当者権限

E：手直し設備、搬送、バッファ、トレーサビリティ、結果書戻し
```

必要な CAE-SDB Result と時間情報 T を Arbitration で処理し、手直し工程への進入を Multipath Control として形成する。

```text
CAE-SDB Result + T
→ Arbitration
→ Multipath Control
→ 手直し工程へ進入
```

### 工程戻しまたは廃棄処理工程へ進む場合

工程戻しや廃棄処理についても、それぞれの Target State Entry に対して C / A / E と S / D / B を設定する。

例えば、

```text
Current State：検査完了

Target State：廃棄処理工程
```

の場合、PCN は次の状態を判定する。

```text
C：廃棄判定、製品識別、ロット情報

A：廃棄処理許可

E：廃棄品搬送、回収、数量記録、トレーサビリティ、結果書戻し
```

Arbitration の結果に基づいて、廃棄処理工程への進入を Multipath Control として形成する。

```text
→ Multipath Control
→ 廃棄処理工程へ進入
```

手直し、工程戻し、廃棄処理、隔離は、それぞれ生産プロセス上の Target State または目標実行経路として扱う。

これらの経路へ進んだ後は、その時点で新しい状態インスタンスが形成される。

---

## 6. 代表的な判定、時間情報 T、Multipath Control、PCN Trace

本事例で形成される代表的な CAE-SDB Result を次に示す。

| CAE-SDB Result | 本事例における代表的な状態                                                                          |
| -------------- | -------------------------------------------------------------------------------------- |
| C-S            | 現在ロットと品質結果、作業指示、レシピとの関係が十分に定義されていない                                                    |
| C-D            | 作業指示、ロット、レシピ、品質結果の切替が同期していない、状態が有効時間を超えている、またはバージョンが一致していない                            |
| C-B            | 条件状態が事前定義された値または時間の制御境界に到達している                                                         |
| A-S            | 品質承認、保全復旧許可、担当者確認などの許可元が十分に定義されていない                                                    |
| A-D            | 許可取消、更新遅延、未更新、有効期間超過、システム間状態の非同期が発生している                                                |
| A-B            | 許可待機時間、確認有効期間、権限範囲が事前定義された制御境界に到達している                                                  |
| E-S            | 下流受入、手直し、工程戻し、廃棄処理、隔離、結果書戻しの実行チェーン構造が十分に定義されていない                                       |
| E-D            | 下流、搬送、手直し設備、廃棄処理、バッファ、インターフェース、書戻しなどの状態について、今回の Target State Entry に対する動的時系列有効性を確認できない |
| E-B            | バッファ容量、待機時間、手直し回数、その他の実行チェーン状態が事前定義された制御境界に到達している                                      |

各 CAE-SDB Result には、対応する時間情報 T を保持する。

CAE-SDB Result と時間情報 T は Arbitration に入力され、今回の Target State Entry に対する Multipath Control を形成する。

代表的な制御出力には、次のようなものがある。

* 進入許可
* 待機
* 再読込み
* 再照合
* 再確認
* 状態再同期
* 手直し
* 工程戻し
* 廃棄処理
* 異常経路への分岐
* 下流調整
* 資源解放
* 縮退実行
* 代替経路
* 進入禁止
* 安全ロック
* 手動確認
* 隔離
* 強化記録

代表的な判定例を次に示す。

```text
C-D：
作業指示は切り替わっているが、PLC のレシピがまだ同期していない

A-D：
品質承認が取り消されている、またはシステム間で同期していない

E-D：
下流状態が更新されておらず、今回の Target State Entry に使用する状態を確認できない

E-S：
手直し工程の実行チェーンに必要な構造が十分に定義されていない
```

PCN は、今回の判定と制御結果を PCN Trace として記録する。

代表的な記録内容は次の通りである。

```text
Current State
Target State
主要な入力状態
時間情報 T
C / A / E Mapping
S / D / B Evaluation
CAE-SDB Result
Arbitration Result
Multipath Control
実行結果
Trace ID
```

必要に応じて、主要な入力状態に次の情報を関連付ける。

```text
対象 / ロット情報
状態更新時刻
状態バージョン / シーケンス情報
関連イベント / トレーサビリティ ID
```

これらの情報により、今回の Target State Entry で使用した状態とその判定時点を記録できる。

例えば、次のような PCN Trace を形成できる。

```text
Current State：前工程完了

Target State：次生産工程

時間情報：T

CAE-SDB Result：A-D + E-D

判定内容：品質承認状態の再確認が必要 / 下流受入状態が未更新

Multipath Control：状態再同期 / 再確認

実行結果：次生産工程への進入を保留
```

別の例を次に示す。

```text
Current State：検査完了

Target State：手直し工程

時間情報：T

品質結果：NG

Multipath Control：手直し工程への進入許可

実行結果：対象製品が手直し工程へ進入
```

PCN Trace は、

> **今回どの Target State へ進もうとしていたか、どの状態を判定に使用したか、どの CAE-SDB Result と Arbitration Result が形成され、最終的にどの生産経路へ進んだか**

を一連の状態遷移判定履歴として記録する。

## 7. 履歴レビュー、AI 支援分析、生産 DX への活用

複数の PCN を継続運用すると、PCN Trace が蓄積される。

生産 DX では、設備効率、生産実績、品質結果、停止、アラーム、エネルギー、物流などに加え、Target State Entry に関する判定履歴を分析対象とすることができる。

例えば、次のような項目を確認できる。

* どの Target State Entry で進入保留や経路変更が多く発生しているか。
* どの C 条件が状態遷移時の制約として繰り返し現れているか。
* どの A 許可が生産進行時のボトルネックとなっているか。
* どの E 実行チェーンで継続性に関する問題が多く発生しているか。
* 手直し、工程戻し、廃棄処理などの経路がどの程度使用されているか。
* どの S に関する構造上の問題が繰り返し発生しているか。
* どの D に関する動的時系列有効性の問題が継続しているか。
* どの状態が制御境界に頻繁に到達しているか。
* どの Multipath Control が頻繁に選択されているか。
* エンジニアリング改善後に、同じ CAE-SDB Result の発生頻度がどのように変化したか。

例えば A-S が継続して高頻度で発生している場合、許可元、責任範囲、システムインターフェースなどを改善対象として確認できる。

C-D、A-D、E-D が継続して多い場合は、作業指示切替、状態更新、状態有効期間、バージョン関係、インターフェース遅延、システム間同期などを確認対象とすることができる。

複数のシステムが一つの Target State Entry に関係する場合は、それぞれの状態について、対象、ロット、状態バージョン、更新時刻などを同じ判定時点で照合する。

例えば MES、品質システム、PLC、下流システムがそれぞれ状態を保持している場合、PCN Trace にこれらの対象情報と時間情報を関連付けることで、同一の Target State Entry に使用した状態の組合せを確認できる。

手直し工程の使用頻度が高い場合は、製品、設備、工程、品質履歴と組み合わせて、手直し経路が選択された条件を分析できる。

B 判定が継続して高頻度で発生している場合は、現在の状態遷移条件、確認方法、制御境界などをレビュー対象とすることができる。

PCN Trace は、状態遷移条件や制御経路を継続的にレビューするためのデータとして利用できる。

手直し、工程戻し、再投入などによって同じ工程状態が再び現れる場合も、PCN Trace では、それぞれを異なる時間位置と遷移履歴を持つ状態インスタンスとして記録できる。

### AI 支援分析

PCN Trace は、一回の Target State Entry に関する次の情報を同じ判定履歴として保持する。

```text
Current State
Target State
主要な入力状態
時間情報 T
C / A / E Mapping
S / D / B Evaluation
CAE-SDB Result
Arbitration Result
Multipath Control
実行結果
```

この構造化された履歴を用いて、AI は例えば次の分析を支援できる。

* 同種の PCN Trace の集約
* 高頻度で発生する C / A / E と S / D / B の組合せの抽出
* Target State ごとの反復問題の比較
* 状態値と動的時系列有効性に関する問題の分類
* 手直し、工程戻し、廃棄処理などの経路利用状況の長期比較
* 改善前後における判定結果の比較
* 確認候補やエンジニアリングレポートの生成

例えば、長期間の PCN Trace で次の状態が繰り返し確認された場合を考える。

```text
Target State：次生産工程
CAE-SDB Result：A-D
関連状態：品質承認状態の非同期
```

この履歴を、品質システムと MES の品質承認状態同期を確認するための改善候補として利用できる。

生産 DX では、このような履歴を利用して、

> **状態遷移条件の設計、判定履歴の分析、エンジニアリング改善**

へ展開することができる。
