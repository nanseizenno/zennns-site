# 自动加工已经完成，为什么仍不能开始人工作业单元组装？

> 应用层级：制造流程 / 跨系统状态迁移  
> 代表对象：部件自动加工 → 人工作业单元组装

**建议引用：**

```text
全野南政 / Nansei Zenno，《制造 DX 状态迁移条件设计与履历分析案例：自动加工已经完成，为什么仍不能开始人工作业单元组装？》，公开案例，Public Case Version 1.5，2026-09-20，https://zennns.com/zh/cases/production-dx-state-transition/
```

制造现场中，经常存在这样的生产流程：

```text
自动加工设备
    ↓
部件加工完成
    ↓
搬送 / 供给
    ↓
人工作业单元组装
```

自动加工已经完成，并不代表下一工序已经可以开始。

进入人工作业单元组装，还可能涉及质量放行、必要零部件、作业人员资格、单元设备、治具工具以及组装后的检测、搬出和实绩回写。

本案例关注的问题是：

> **自动加工已经完成，为什么当前部件仍不能进入人工作业单元组装？**

本案例重点验证的不是“自动加工是否完成”这一单一状态，而是：

> **能否围绕一次明确的目标状态入口，把分散在设备、MES、质量系统、人员资格、部件供给和后续工序中的状态组织到同一次判定中，并进一步明确是哪一类状态阻止了当前入口成立、应该如何处理，以及处理后如何重新判定。**

本案例按照统一九步工程顺序展开：

```text
1. 当前状态
2. 目标状态 / 目标状态入口
3. PCN：相关状态获取 + C / A / E 状态映射
4. S / D / B 判定 → CAE-SDB 结果 + T
5. 控制仲裁
6. 多路径控制
7. 当前入口控制结果
8. 控制路径执行 / 后续目标状态入口与执行结果
9. 状态迁移判定履历
```

- [核心概念](/zh/concepts/)
- [TPCA / PCN 状态迁移前置控制架构｜白皮书](/zh/whitepaper/)

## 案例对象

本案例假设自动加工设备已经完成某个部件的加工，部件经过搬送后，准备进入由作业人员负责的人工作业单元进行组装。

与本次状态迁移有关的主要对象包括：

- MES；
- 自动加工设备 / PLC；
- 质量系统；
- 部件搬送与供给；
- 作业人员认证与资格管理；
- 人工作业单元设备；
- 治具与紧固工具；
- 组装后检测；
- 完成品搬出与生产实绩回写。

这个场景同时跨越自动设备、信息系统、人员、物料、工具和后续工序，是制造 DX 中典型的跨系统状态迁移问题。

---

# 1. 当前状态

现在现场是什么状态？

```text
当前状态：
自动加工完成 / 等待人工作业单元组装
```

此时已经确认：

```text
加工完成：
成立

部件编号：
已读取

当前批次：
已确定

质量测量：
已完成

部件搬送：
已完成
```

这就是本次状态迁移的起点。

---

# 2. 目标状态 / 目标状态入口

这次准备进入哪里？

```text
目标状态：
对象部件处于人工作业单元组装中

目标状态入口：
开始对象部件的人工作业单元组装
```

PCN 位于当前状态与目标状态入口之间：

```text
当前状态
自动加工完成 / 等待组装
        ↓
PCN［组装开始前的判定］
        ↓
目标状态入口
开始对象部件的人工作业单元组装
        ↓
目标状态
对象部件处于组装中
```

本次需要判断的是：

> **当前加工完成的部件，能否由当前作业人员，在当前人工作业单元中开始组装，并保证后续执行链能够继续接续。**

---

# 3. PCN：相关状态获取与 C / A / E 状态映射

本次入口最关键的状态分别是什么？

PCN 取得与组装开始直接相关的状态，并按照其在本次目标状态入口中的作用进行 C / A / E 状态映射。

| 代表状态 | 状态映射 |
|---|---|
| 加工完成、部件编号、批次、质量结果、必要零部件 | C：条件状态 |
| 质量放行、生产许可、作业人员资格、当前产品作业权限 | A：许可状态 |
| 单元设备就绪、治具、紧固工具、组装后检测、搬出和实绩回写 | E：执行链状态 |

本案例重点使用：

```text
加工完成 → C
质量结果 → C
质量放行 → A
作业人员资格 → A
单元设备就绪 → E 的相关状态
后续检测与实绩回写 → E
```

这里需要区分：

```text
质量结果合格
→ 表示当前部件满足质量条件
→ C
```

```text
质量放行成立
→ 表示当前部件被允许进入下一工序
→ A
```

同样，单元设备已经就绪，也不代表当前作业人员已经具备进入该组装作业的许可。

---

# 4. S / D / B 判定与 CAE-SDB 结果

本次实际出现了什么判定问题？

本案例假设：

```text
加工完成：
成立

质量结果：
合格

质量放行：
成立

必要零部件：
齐套

单元设备就绪：
成立

作业人员登录：
有效

当前产品作业资格：
已登记，但超过有效期
```

作业人员资格属于 A。

当前资格已经存在，但超过允许有效期，因此问题发生在许可状态的控制边界，形成：

```text
CAE-SDB 结果：
A-B

当前作业人员资格已经超过有效期，
不满足本次组装入口的许可边界
```

时间信息 T 与本次状态及判定结果关联保存。

本案例不展开完整 9 个 CAE-SDB 坐标。C / A / E 与 S / D / B 的完整关系可参见：

[为什么是 CAE-SDB？——状态变量域与判定性质的双轴结构](/zh/notes/why-cae-sdb/)

---

# 5. 控制仲裁

多个结果一起出现时，最终优先处理什么？

本次控制仲裁的主要输入为：

```text
C 相关状态：
满足当前入口要求

E 相关状态：
满足当前入口要求

质量放行：
成立

作业人员资格：
A-B
资格已经超过有效期
```

作业人员资格属于本次组装入口的关键 A。

因此，即使加工已经完成、质量结果合格、单元设备也已经就绪，当前入口仍不能允许进入。

控制仲裁结果为：

```text
暂缓当前组装开始
优先处理作业人员资格问题
```

---

# 6. 多路径控制

选择了什么路径？

本次形成：

```text
多路径控制：
确认并更换为具备有效资格的作业人员
```

该处理属于当前组装入口下的处理动作。

---

# 7. 当前入口控制结果

本次入口到底进不进？

```text
当前入口控制结果：
暂不开始当前人工作业单元组装
```

本次“开始对象部件的人工作业单元组装”的目标状态入口未被允许。

原因不是加工未完成，也不是设备未就绪，而是关键许可状态 A 当前不满足进入要求。

---

# 8. 控制路径执行 / 后续目标状态入口与执行结果

实际执行以后发生了什么？

本次处理过程为：

```text
当前组装开始暂缓
    ↓
重新确认作业人员资格
    ↓
更换为具备有效资格的作业人员
    ↓
重新取得当前资格状态
    ↓
执行结果
```

假设处理完成后：

```text
作业人员登录：
有效

当前产品作业资格：
有效
```

则形成：

```text
执行结果：
已完成具备有效资格的作业人员更换，
当前作业资格状态已确认有效
```

此时只是形成了新的运行事实。

后续再次请求：

```text
目标状态入口：
开始对象部件的人工作业单元组装
```

时，需要基于更新后的状态重新进行前置判定。

如果控制路径指向其他作业单元、返修或隔离等新的目标状态，则由新的目标状态入口对应 PCN 重新进行前置判定。

---

# 9. 状态迁移判定履历

这次状态迁移最终记录成什么？

本次组装开始入口可以形成如下履历：

```text
PCN：
人工作业单元组装开始入口 PCN

当前状态：
自动加工完成 / 等待人工作业单元组装

目标状态：
对象部件处于人工作业单元组装中

目标状态入口：
开始对象部件的人工作业单元组装

主要状态：
  加工完成 = 成立
  质量结果 = 合格
  质量放行 = 成立
  必要零部件 = 齐套
  单元设备就绪 = 成立
  作业人员登录 = 有效
  当前产品作业资格 = 已过期

CAE-SDB 结果：
A-B

控制仲裁结果：
暂缓当前组装开始，
优先处理作业人员资格问题

多路径控制：
确认并更换为具备有效资格的作业人员

当前入口控制结果：
暂不开始当前人工作业单元组装

执行结果：
已完成具备有效资格的作业人员更换，
当前作业资格状态已确认有效

时间信息：
T

履历 ID：
PCN-CELL-XXXX
```

作业人员更换完成后，后续再次请求同一目标状态入口时，将基于更新后的状态重新判定，并形成新的履历；前一次履历不被覆盖。

关于状态迁移判定履历的详细说明可参见：

[为什么状态迁移判定履历是一种新的工程数据？](/zh/notes/why-pcn-trace-is-engineering-data/)

## 案例总结

本案例中，自动加工已经完成，质量结果合格，质量放行成立，必要零部件齐套，单元设备也已经就绪。

如果只看自动加工完成和设备就绪状态，很容易得到：

> **“前工序已经完成，设备也准备好了，为什么组装还不能开始？”**

围绕“开始对象部件的人工作业单元组装”这一目标状态入口重新组织后，本次问题被进一步明确为：

```text
目标状态入口：
开始对象部件的人工作业单元组装

CAE-SDB 结果：
A-B

具体问题：
当前作业人员资格已经超过有效期，
不满足本次组装入口的许可边界
```

由此，原本笼统的“前工序已经完成但下一工序仍不能开始”被进一步定位为：

> **设备条件和执行链已经具备，但关键许可状态未满足当前入口要求。**

这一判定结果继续进入控制仲裁，并形成：

```text
当前组装入口：
暂不进入

多路径控制：
确认并更换为具备有效资格的作业人员
```

处理完成后，人员资格恢复有效，但原组装入口不会自动转为允许进入，而是基于更新后的状态重新进行前置判定。

因此，本案例展示的工程效果是：

- 将自动加工、质量、部件供给、人员资格、单元设备和后续处理状态组织到同一次目标状态入口；
- 将“自动加工已经完成但组装仍不能开始”进一步定位到明确的关键许可问题；
- 将质量条件与质量放行、设备就绪与人员资格等不同工程角色明确区分；
- 将关键 A 作为独立必要约束参与入口控制；
- 将判定结果直接连接到处理动作、执行结果和后续重新判定；
- 将本次状态、判定、控制和执行过程形成统一的状态迁移判定履历。

也就是说，原本只能观察到的：

> **“加工已经完成，但下一工序仍然没有开始”**

被进一步转换为：

> **“是哪一个跨系统状态阻止了当前入口、它属于什么工程角色、应该采取什么处理，以及处理后为什么仍需要重新判定”。**

这就是本案例所展示的主要工程效果。
