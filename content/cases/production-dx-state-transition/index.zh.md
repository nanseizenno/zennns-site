## 1. 现场问题

生产 DX 项目通常已经能够取得大量数据。

MES 可以记录工单、批次、计划和生产实绩；质量系统可以记录检测结果、质量判定和放行状态；PLC 与设备控制系统可以提供自动模式、设备就绪、报警、互锁和动作状态；人员系统可以管理身份与权限；保全系统可以记录维修、点检和复归；下游设备、搬送系统和缓存区也可以提供接收、占用和运行状态。

但现场仍然会出现：

* 前工序已经完成，下一工序迟迟没有开始；
* MES 显示工单有效，设备也已就绪，但当前产品或批次仍不能进入下一阶段；
* 质量结果已经产生，却不能确认当前批次是否已经正式放行；
* 检测结果为 NG，但返工、回流、废品处理或隔离工序是否可以接续仍需要进一步判断；
* 保全作业已经结束，但设备是否允许重新投入生产仍需要确认；
* 工单已经切换，但 PLC 配方、物料、质量结果和追溯信息没有完全同步；
* 下游显示可接收，但当前状态是否仍然有效无法立即确认；
* 多个系统都有状态记录，但当前对象究竟应该进入哪个后续生产工序，仍然依赖人工查程序、查系统和查履历。

问题并不一定是“没有数据”。

更常见的是：

> **当前状态准备进入哪个 Target State，进入前需要哪些条件、哪些许可、哪些执行链成立，以及最终应该进入哪条生产路径，没有被作为一个明确的工程对象统一设计。**

例如：

```text
MES 工单 = 有效
质量结果 = 合格
设备 = 就绪
操作人员 = 已确认
下游 = 可接收
```

这些局部状态同时存在，也不能直接推出：

```text
允许当前对象进入下一生产工序
```

还需要确认：

* 质量结果是否属于当前批次；
* 质量放行是否成立；
* 工单、配方、物料和设备模式是否一致；
* 保全解除是否成立；
* 人工确认是否具有相应权限；
* 下游状态是否仍然有效；
* 目标执行链是否能够接续；
* 本次判定结果是否能够形成可追溯的状态迁移履历。

本案例关注的是：

> **围绕明确的生产状态迁移入口，把分散在不同系统中的状态重新组织成可判定、可控制、可记录的生产工程状态迁移条件。**

## 2. 案例定位与 PCN 位置

本案例讨论生产工程中的状态迁移。

一个生产阶段完成以后，当前对象可能进入不同的后续工序，例如：

```text
前工序完成
→ 下一生产工序

检测完成
→ 返工工序

检测完成
→ 回流工序

检测完成
→ 废品处理工序

检测完成
→ 隔离工序

保全完成
→ 自动生产重新投入
```

这些都属于生产流程中的状态迁移。

TPCA / PCN 关注的是：

> **Current State 准备进入某个 Target State、目标执行路径或目标生产阶段之前，相关条件、许可和执行链是否成立。**

PCN 设置在明确的状态迁移入口之前。

基本工程链条为：

```text
Current State
→ Target State
→ 多源状态信号
→ C / A / E Mapping
→ S / D / B Evaluation
→ CAE-SDB Result
→ Arbitration
→ Multipath Control
→ PCN Trace
```

例如，当 Current State 为“检测完成”时，后续 Target State 可以是下一生产工序、返工工序、回流工序、废品处理工序或隔离工序。

PCN 根据当前对象、Target State 和相关多源状态进行前置判定，并输出对应的生产路径。

PCN 可以由 MES、制造执行中间层、工业边缘系统、PLC / HMI 协同模块或其他软件组件实现。

本案例不限定具体部署平台。

## 3. 多源状态信号与 C / A / E 映射

代表性状态如下。

| 来源        | 代表性状态                             |
| --------- | --------------------------------- |
| MES       | 工单状态、批次号、产品型号、生产许可、配方编号           |
| 质量系统      | 检测完成、质量结果、质量放行、返工判定、废品判定、隔离状态     |
| PLC / 设备  | 自动模式、设备就绪、当前工艺阶段、配方加载、动作完成、设备报警   |
| 保全系统      | 点检完成、维修完成、保全解除、重新投入许可             |
| 人员 / 权限系统 | 操作人员身份、资格、权限、人工确认                 |
| 物料 / 追溯系统 | 物料身份、批次关联、追溯 ID、前序结果关联            |
| 下游 / 搬送系统 | 下游可接收、缓存容量、搬送可用、交接许可              |
| 数据接口      | 状态更新时间、状态版本 / 序列信息、回写完成、接口可用、同步完成 |

这些状态根据本次 Target State 的要求映射到 C、A、E。

| 变量域               | 判定问题                        | 本案例代表项                                  |
| ----------------- | --------------------------- | --------------------------------------- |
| C：Condition       | 进入 Target State 所需的事实条件是否成立 | 工单有效、批次正确、前序完成、质量结果存在、物料与配方匹配、追溯关系有效    |
| A：Authority       | 系统是否允许进入 Target State       | 质量正式放行、生产许可、保全解除、人员权限、人工确认、特殊审批         |
| E：Execution Chain | 进入 Target State 后执行链是否能够接续  | 设备执行、下游承接、搬送、缓存、返工、回流、废品处理、隔离、结果上传、追溯回写 |

C / A / E 不是按照系统来源分类。

同一个系统可以同时提供 C、A、E 所需要的状态；同一个状态在不同 Target State 前，也可能承担不同工程作用。

### 质量结果与质量放行

例如：

```text
质量结果 = 合格
```

如果 Target State 是“进入下一生产工序”，该结果可以作为 C 中的事实条件。

而：

```text
质量放行 = 已批准
```

表示正式许可已经成立，属于 A。

因此：

> **质量结果成立，不等于质量放行已经成立。**

### 质量 NG 与 Target State

如果：

```text
质量结果 = NG
```

其工程意义仍然取决于 Target State。

当 Target State 是“下一正常生产工序”时，质量 NG 可能表示相关 C 条件不成立。

当 Target State 是“返工工序”时，质量 NG 反而可能成为返工工序所需的 C 条件之一。

同样，回流、废品处理和隔离也需要分别围绕对应 Target State 判断 C、A、E。

因此：

> **状态本身不能脱离 Current State 和 Target State 单独解释。**

### 设备就绪与 E

设备就绪只能说明本体设备具备局部运行条件。

如果下游无法承接、搬送不可用、缓存满载、返工工序无法接续、废品处理工序不可用、隔离位置不可用或结果回写链无法继续，则整个 E 执行链仍然不能认为已经成立。

## 4. S / D / B 性质判定

完成 C / A / E 映射后，PCN 进一步从 S、D、B 三类判定性质进行分析。

| 判定性质        | 判定问题                             | 本案例代表项                                          |
| ----------- | -------------------------------- | ----------------------------------------------- |
| S：Structure | 所需信号、接口、映射关系、许可来源和执行链边界是否已经定义并接入 | 批次与质量结果映射、质量放行来源、保全解除来源、返工 / 回流 / 废品处理 / 隔离工序接口 |
| D：Dynamics  | 当前状态是否有效、同步、未超时、未撤销、未冲突          | 工单切换、配方同步、许可撤销、状态未刷新、状态过期、版本不一致、接口延迟            |
| B：Boundary  | 当前状态是否已经进入预定义控制边界                | 等待时间、同步时间、人工确认有效期、缓存容量、重试上限、返工次数                |

### 状态值成立，不等于当前仍然有效

生产 DX 中，多源状态通常来自不同系统，各系统的采集周期、更新时间和状态保持方式并不一致。

因此，PCN 不能只读取：

```text
质量结果 = 合格
下游 = 可接收
保全解除 = 成立
人工确认 = 完成
```

还需要判断这些状态是否仍然属于**当前对象和本次 Target State Entry 的有效状态**。

例如：

```text
质量结果 = 合格
```

只有在确认该结果属于当前产品或批次，并且相关状态版本、更新时间及有效范围仍满足本次迁移要求时，才能继续作为当前 C 条件的有效依据。

同样：

```text
下游可接收 = True
```

如果该状态长时间未刷新，或者产生于下游状态切换之前，即使当前读取值仍然为 True，也不能直接认为 E 执行链当前仍然可以接续。

因此，生产 DX 中需要区分：

```text
状态值成立
≠
状态当前有效
```

PCN 对状态的判断不仅涉及当前值，还需要根据实际系统结合对象关联、更新时间、刷新状态、状态版本、序列信息以及必要的有效时间范围判断其当前有效性。

这里不要求所有系统使用完全相同的时间戳或刷新周期。

MES、质量系统、PLC、保全系统、人员系统和下游系统可以具有不同的数据更新机制。工程上需要保证的是：

> **与本次 Target State Entry 有关的状态，具备足以判断其当前有效性的时间语义。**

这种时间语义可以根据系统特点由状态更新时间、版本号、序列信息、批次号、事件 ID、刷新状态或其他可追溯信息提供。

相关内容属于 D：Dynamics 的动态时序有效性判定。

具体有效时间、刷新周期、同步窗口和失效条件，应根据实际生产系统、工艺要求和控制要求设定。

### C-S

质量结果已经存在，但没有建立：

```text
质量结果
↔ 当前批次
```

之间的明确关联。

此时属于条件结构不完整。

### C-D

MES 已经切换到新工单，但 PLC 仍处于上一配方，或者当前质量结果属于上一批次。

也可能出现相关状态值仍然存在，但已经超过本次 Target State Entry 所允许的有效范围，或者不同系统之间的状态版本、序列关系已经不一致。

此时条件信息存在，但当前状态不同步或动态有效性不足。

### A-S

进入 Target State 需要质量放行、保全解除或特定人员确认，但系统没有定义明确的许可来源。

此时属于许可结构问题。

### A-D

质量许可曾经成立，但随后被撤销；或者保全解除状态已经变化，而相关系统仍保留旧状态。

也可能出现人工确认、生产许可或其他授权状态已经超过有效范围，但系统仍保留原有成立值。

此时许可来源存在，但当前许可状态的动态有效性不足。

### E-S

返工、回流、废品处理、隔离、下游承接或结果回写等执行路径在生产流程中存在，但所需信号、接口、角色或执行链边界没有完整定义。

此时属于执行链结构问题。

### E-D

下游仍显示可接收，但状态长时间没有刷新；或者返工设备、搬送系统、废品处理设备、隔离区域、结果回写接口当前处于切换、延迟或阻塞状态。

即使某个状态值仍显示正常，如果其更新时间、状态版本、序列关系或相关上下文已经不能证明该状态仍适用于本次 Target State Entry，也不能直接认为执行链当前有效。

此时执行链已经定义，但当前不能确认其仍然可以稳定接续。

### B 相关判定

生产过程中还可能出现：

* 状态同步等待达到预设时间；
* 人工确认达到有效期限；
* 重读或重试达到预设次数；
* 下游缓存接近容量边界；
* 工单切换长时间未稳定；
* 某项许可达到重新确认条件；
* 返工次数达到预设控制边界。

这些判定共同形成 CAE-SDB Result，并继续进入 Arbitration。

## 5. 生产状态迁移与 Multipath Control

生产工程中的状态迁移本身就可能存在多条生产路径。

例如，检测工序完成以后，不同对象可以进入：

```text
下一生产工序
返工工序
回流工序
废品处理工序
隔离工序
```

PCN 在进入具体 Target State 前，对相应 C、A、E 进行判定。

### 进入下一生产工序

```text
Current State：
前工序完成

Target State：
下一生产工序
```

相关状态可能包括：

```text
工单有效
质量结果合格
质量放行成立
设备可执行
下游可承接
追溯关系有效
```

判定成立后：

```text
CAE-SDB Result
→ Arbitration
→ Multipath Control
→ 允许进入
```

当前对象进入下一生产工序。

### 质量放行状态不同步

```text
Current State：
前工序完成

Target State：
下一生产工序

质量结果：
合格
```

如果出现：

```text
质量放行状态未同步
下游状态未及时刷新
```

可能形成：

```text
A-D + E-D
```

随后：

```text
CAE-SDB Result
→ Arbitration
→ 等待 / 状态重新同步 / 重新确认
```

当前对象暂不进入 Target State。

状态刷新后，PCN 再次判定。

### 进入返工工序

```text
Current State：
检测完成

质量结果：
NG

Target State：
返工工序
```

PCN 判断：

```text
C：
当前产品、批次、质量结果、返工条件是否成立

A：
返工许可、质量许可、人员权限是否成立

E：
返工设备、搬送、缓存、追溯和结果回写是否能够接续
```

判定成立后：

```text
CAE-SDB Result
→ Arbitration
→ Multipath Control
→ 进入返工工序
```

### 进入回流或废品处理工序

同样可以围绕对应 Target State 进行判定。

例如：

```text
Current State：
检测完成

Target State：
废品处理工序
```

PCN 判断：

```text
C：
废品判定、产品身份、批次信息是否成立

A：
废品处理许可是否成立

E：
废品搬送、收集、计数、追溯和结果回写是否能够接续
```

判定成立后：

```text
→ Multipath Control
→ 进入废品处理工序
```

返工、回流、废品处理和隔离都是生产流程中的工序或执行路径。

## 6. 代表性判定、控制路径与 PCN Trace

本案例中的 CAE-SDB Result 可以形成如下代表性判定。

| 判定坐标 | 本案例代表性状态                                          |
| ---- | ------------------------------------------------- |
| C-S  | 当前批次与质量结果、工单或配方之间的关系未完整定义                         |
| C-D  | 工单、批次、配方或质量结果发生切换不同步、状态过期或版本不一致                   |
| C-B  | 条件状态达到预设重新确认或控制边界                                 |
| A-S  | 质量放行、保全解除、人员确认等许可来源未完整定义                          |
| A-D  | 许可撤销、延迟、未刷新、超过有效范围或跨系统状态不同步                       |
| A-B  | 许可等待、确认有效期或人工确认达到控制边界                             |
| E-S  | 下游承接、返工、回流、废品处理、隔离或结果回写链未完整定义                     |
| E-D  | 下游、搬送、返工设备、废品处理、缓存、接口或回写状态当前不可稳定接续，或相关状态已不能确认当前有效 |
| E-B  | 缓存容量、等待时间、返工次数或执行链状态达到预设控制边界                      |

CAE-SDB Result 经过 Arbitration 后形成 Multipath Control。

代表性输出包括：

* 允许进入；
* 等待；
* 重新读取；
* 重新核对；
* 重新确认；
* 状态重新同步；
* 返工；
* 回流；
* 废品处理；
* 异常分流；
* 下游协调；
* 资源释放；
* 降级执行；
* 备用路径；
* 禁止进入；
* 安全锁定；
* 人工确认；
* 隔离；
* 增强记录。

例如：

```text
C-D
工单已经切换，但 PLC 配方尚未同步
→ 重新读取 / 等待同步
```

```text
C-D
质量结果仍显示合格，但属于上一批次或已经超过本次迁移所允许的有效范围
→ 重新读取 / 重新核对 / 暂不进入 Target State
```

```text
A-D
质量放行发生撤销、超过有效范围或跨系统不同步
→ 等待 / 重新确认 / 暂不进入 Target State
```

```text
E-D
下游状态未刷新，无法确认是否能够承接
→ 等待刷新 / 状态重新同步
```

```text
Target State：
返工工序

E-S：
返工执行链没有完整定义
→ 暂不进入返工工序
→ 人工确认 / 工程确认
```

```text
Target State：
废品处理工序

C / A / E 均满足
→ 允许进入废品处理工序
```

一次 PCN 判定同时形成 PCN Trace。

代表性记录内容包括：

```text
Current State
Target State
关键输入状态
C / A / E Mapping
S / D / B Evaluation
CAE-SDB Result
Arbitration Result
Multipath Control
执行结果
Trace ID
```

必要时，关键输入状态还可以关联：

```text
对象 / 批次信息
状态更新时间
状态版本 / 序列信息
相关事件或追溯标识
```

用于说明本次判定实际采用的是哪一组有效状态。

例如：

```text
Current State：
前工序完成

Target State：
下一生产工序

CAE-SDB Result：
A-D + E-D

工程含义：
质量放行状态需要重新确认
下游接收状态未及时刷新

Multipath Control：
状态重新同步 / 重新确认

执行结果：
Target State 暂未进入
```

又例如：

```text
Current State：
检测完成

Target State：
返工工序

质量结果：
NG

Multipath Control：
允许进入返工工序

执行结果：
当前对象进入返工工序
```

PCN Trace 记录的是：

> **这一次准备进入哪个 Target State，基于哪些当前有效状态进行判定，为什么这样判定，最终进入了哪条生产路径。**

## 7. 履历复盘、AI 辅助分析与生产 DX 价值

当多个 PCN 长期运行以后，PCN Trace 会持续积累。

生产 DX 除了分析设备效率、生产实绩、质量结果、停机、报警、能耗和物流，还可以进一步分析：

* 哪些 Target State 经常不能成立；
* 哪些 C 条件长期成为状态迁移阻点；
* 哪些 A 许可长期成为生产放行瓶颈；
* 哪些 E 执行链经常不能接续；
* 哪些返工、回流或废品处理路径长期高频；
* 哪些 S 结构问题反复出现；
* 哪些 D 动态问题长期存在；
* 哪些 B 控制边界经常被触发；
* 哪些 Multipath Control 被频繁调用；
* 哪些工程改善以后，相同判定结果明显减少。

例如：

如果 A-S 长期高频出现，改善重点可能是重新整理许可来源、责任角色和系统接口。

如果 C-D、A-D、E-D 长期高频出现，则可以进一步检查工单切换、状态刷新、状态有效性、版本关系、接口延迟和跨系统同步机制。

特别是在多个系统共同参与一次状态迁移判定时，还需要关注：

> **跨系统状态都分别正确，不代表这些状态在同一次 Target State Entry 判定中仍然同时有效。**

例如 MES、质量系统、PLC 和下游系统可能分别保存着合理的状态值，但如果这些状态来自不同对象、不同批次、不同状态版本或不同更新时间窗口，则不能简单拼接为一次有效的状态迁移依据。

如果返工路径长期高频使用，可以结合产品、设备、工序和质量履历继续分析。

如果某些 B 判定长期频繁触发，则可以重新检查当前状态迁移条件、确认方式或控制边界是否合理。

PCN Trace 因此不仅用于事后追溯，也可以作为生产工程状态迁移设计复盘的数据来源。

### AI 辅助分析

AI 不直接参与现场控制，而是对 PCN Trace 进行辅助分析。

AI 的分析对象不再只是孤立的设备状态、报警、生产结果或时间序列，而是与一次具体 Target State Entry 绑定的 PCN Trace。

PCN Trace 将：

```text
Current State
Target State
关键输入状态及其时间语义
C / A / E Mapping
S / D / B Evaluation
CAE-SDB Result
Arbitration Result
Multipath Control
执行结果
```

组织在同一次状态迁移判定履历中。

因此，AI 可以进一步区分：

```text
状态值本身异常
```

与：

```text
状态值正常，但已经过期、未刷新、不同步或不再适用于本次状态迁移
```

之间的差异。

其价值不在于简单增加更多数据，而在于增加了**状态迁移上下文和判定语义**。

传统 MES / SCADA 数据通常以设备状态、报警、事件和生产结果为中心；PCN Trace 则进一步记录：

> **系统当时准备进入哪个 Target State、依据什么状态进行判定、为什么选择该控制路径，以及最终是否完成迁移。**

因此：

> **PCN Trace 不是单纯的状态历史，而是状态迁移判定历史。**

这使后续 AI 分析能够从单纯的状态相关性分析，进一步进入面向状态迁移条件、时序有效性和控制路径的履历比较。

基本位置为：

```text
PCN Trace
→ 履历聚合
→ AI 辅助分析
→ 改善候选
→ 工程师确认
→ 限定试行
→ 效果确认
→ 状态迁移设计更新
```

AI 可以辅助：

* 聚合同类 PCN Trace；
* 识别高频 C / A / E 与 S / D / B 组合；
* 比较不同 Target State 的重复问题；
* 区分状态值异常与状态时序有效性问题；
* 识别返工、回流、废品处理等路径的长期变化；
* 比较改善前后的判定结果；
* 生成候选检查点和工程报告。

例如，长期 PCN Trace 中反复出现：

```text
Target State：
下一生产工序

CAE-SDB Result：
A-D

相关状态：
质量放行状态不同步

Multipath Control：
等待 / 重新确认
```

AI 可以辅助生成候选提示：

> 工单切换阶段多次出现质量放行状态不同步，建议优先检查质量系统与 MES 之间的放行状态同步机制。

该结果只是工程分析候选。

AI 不直接：

* 修改 PCN；
* 修改 CAE-SDB 规则；
* 修改控制边界；
* 绕过 Arbitration 输出现场控制；
* 自动批准工程变更。

最终的状态定义、许可关系、控制边界、PCN 规则变更、限定试行、效果确认和正式采用，仍通过企业既有工程管理流程确认。

生产 DX 在这里处理的不只是“把更多数据接入系统”，而是：

> **把数据、设备、人员、质量、权限和生产流程之间的状态迁移条件显式化、结构化并留下履历。**

## 8. 公开边界

本文为生产 DX 状态迁移条件设计与履历分析的公开说明案例。

本文仅公开：

* Current State / Target State；
* PCN 在生产状态迁移中的位置；
* 代表性多源状态；
* C / A / E Mapping；
* S / D / B Evaluation；
* CAE-SDB Result；
* 代表性 Arbitration 与 Multipath Control；
* PCN Trace 与履历分析价值。

本文关于状态时间语义的内容仅说明工程判定原则。

具体状态有效时间、刷新周期、同步窗口、版本规则、失效条件、重试次数及相关控制参数，应根据实际生产系统、工艺要求、平台架构和控制要求设计，不在本文公开。

具体工程实现应结合平台架构、现场设备、质量要求、安全要求、权限体系和交付规范进行设计。

PCN 不替代安全 PLC、安全继电器、硬件安全回路及企业现有强制安全控制机制。
