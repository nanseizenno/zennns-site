## 1. 现场问题

生产 DX 项目通常已经能够获取大量生产与运行数据。

MES 可以记录工单、批次、计划和生产实绩；质量系统可以记录检测结果、质量判定和放行状态；PLC 与设备控制系统可以提供自动模式、设备就绪、报警、互锁和动作状态；人员系统可以管理身份与权限；保全系统可以记录维修、点检和复归；下游设备、搬送系统和缓存区也可以提供接收、占用和运行状态。

但现场仍可能出现：

- 前工序已经完成，但下一工序迟迟没有开始；
- MES 显示工单有效，设备也已就绪，但当前产品或批次仍不能进入下一阶段；
- 质量结果已经产生，却不能确认当前批次是否已经正式放行；
- 检测结果为 NG，但返工、回流、废品处理或隔离工序是否可以接续仍需要进一步判断；
- 保全作业已经结束，但设备是否允许重新投入生产仍需要确认；
- 工单已经切换，但 PLC 配方、物料、质量结果和追溯信息没有完全同步；
- 下游显示可接收，但当前状态是否仍然有效无法立即确认；
- 多个系统均有状态记录，但当前对象应进入哪个后续生产工序，仍然需要人工跨系统核对程序、状态和履历。

问题通常不在于数据缺失，而在于：

> **当前对象从何种状态进入何种目标状态，以及进入前所需的条件、许可和执行链，尚未围绕同一个目标状态入口形成统一的工程设计。**

例如：

```text
MES 工单 = 有效
质量结果 = 合格
设备 = 就绪
操作人员 = 已确认
下游 = 可接收
```

即使这些局部状态同时成立，也不能直接推出：

```text
允许当前对象进入下一生产工序
```

还需要进一步确认：

- 质量结果是否属于当前批次；
- 质量放行是否已经成立；
- 工单、配方、物料和设备模式是否一致；
- 保全解除是否已经成立；
- 人工确认是否具有相应权限；
- 下游状态是否仍然有效；
- 进入以后整个执行链是否能够继续接续；
- 本次判定结果是否能够形成可追溯的状态迁移履历。

本案例因此关注：

> **围绕明确的生产目标状态入口，将分散在不同系统中的状态组织为可判定、可控制、可记录的生产状态迁移工程结构。**

## 2. 案例定位与 PCN 位置

本案例以生产流程中的跨系统状态迁移为对象。

一个生产阶段完成以后，当前对象可能进入不同的后续工序，例如：

```text
前工序完成 → 下一生产工序

检测完成 → 返工工序

检测完成 → 回流工序

检测完成 → 废品处理工序

检测完成 → 隔离工序

保全完成 → 自动生产重新投入
```

上述路径均对应明确的生产状态迁移。

返工、回流、废品处理、隔离和重新投入等名称继续保留其现场工程含义。

从 TPCA 的状态迁移视角看，它们都表示：

```text
Current State → New Target State / Target Path
```

即使后续再次出现与历史状态相同或相似的工程状态内容，也属于新的状态实例。

TPCA / PCN 在此关注的是：

> **当前状态进入目标状态、目标执行路径或目标生产阶段之前，相关条件、许可和执行链是否已经成立。**

PCN 设置在明确的目标状态入口之前。

基本工程链条为：

```text
当前状态
→ 目标状态
→ PCN
→ 多源状态信号
→ C / A / E 迁移功能角色映射
→ S / D / B 状态判定
→ CAE-SDB Result + T
→ 控制仲裁
→ 多路径控制
→ PCN Trace
```

例如，当系统处于“检测完成”状态时，后续目标状态可以是下一生产工序、返工工序、回流工序、废品处理工序或隔离工序。

PCN 根据当前对象、目标状态和相关多源状态进行前置判定，并形成相应的生产路径控制结果。

PCN 的具体实现可以由 MES、制造执行中间层、工业边缘系统、PLC / HMI 协同模块或其他软件组件承担。

本案例不限定具体部署平台。

## 3. 多源状态信号与 C / A / E 迁移功能角色映射

代表性状态如下。

| 来源 | 代表性状态 |
|---|---|
| MES | 工单状态、批次号、产品型号、生产许可、配方编号 |
| 质量系统 | 检测完成、质量结果、质量放行、返工判定、废品判定、隔离状态 |
| PLC / 设备 | 自动模式、设备就绪、当前工艺阶段、配方加载、动作完成、设备报警 |
| 保全系统 | 点检完成、维修完成、保全解除、重新投入许可 |
| 人员 / 权限系统 | 操作人员身份、资格、权限、人工确认 |
| 物料 / 追溯系统 | 物料身份、批次关联、追溯标识、前序结果关联 |
| 下游 / 搬送系统 | 下游可接收、缓存容量、搬送可用、交接许可 |
| 数据接口 | 状态更新时间、状态版本、序列信息、回写完成、接口可用、同步完成 |

这些状态根据其在本次目标状态入口中的工程作用映射到 C / A / E。

```text
C：具不具备？
A：允不允许？
E：接不接得住？
```

| 迁移功能角色 | 基本问题 | 本案例代表性状态 |
|---|---|---|
| C：Condition | 进入目标状态所需的事实条件是否具备 | 工单状态、批次状态、前序完成状态、质量结果、物料状态、配方状态、追溯关系 |
| A：Authority | 系统是否被允许进入目标状态 | 质量放行、生产许可、保全解除、人员权限、人工确认、特殊审批 |
| E：Execution Chain | 进入目标状态后执行链是否能够接续 | 设备执行状态、下游承接状态、搬送状态、缓存状态、返工 / 回流 / 废品处理 / 隔离路径、结果上传与追溯回写状态 |

相关状态先按本次 Target State Entry 中的迁移功能角色进入 C / A / E，再进行 S / D / B 状态判定。

### 质量结果与质量放行

例如：

```text
质量结果 = 合格
```

如果目标状态是“进入下一生产工序”，该结果可以作为 C 中的事实条件。

而：

```text
质量放行 = 已批准
```

表示正式许可已经成立，属于 A。

因此：

```text
质量结果 → C
质量放行 → A
```

### 质量 NG 与目标状态

如果：

```text
质量结果 = NG
```

其工程意义仍取决于具体目标状态。

当目标状态是“下一正常生产工序”时，质量 NG 可能表示相关 C 条件不成立。

当目标状态是“返工工序”时，质量 NG 反而可能成为返工工序所需的 C 条件之一。

同样，回流、废品处理和隔离也需要分别围绕对应目标状态组织 C / A / E。

因此：

> **状态的工程含义不能脱离当前状态、目标状态和具体目标状态入口单独解释。**

### 设备就绪与执行链

设备就绪只能说明设备本体具备局部运行条件。

如果下游无法承接、搬送不可用、缓存满载、返工工序无法接续、废品处理工序不可用、隔离位置不可用或结果回写链路无法继续，则 E 执行链仍不能认为已经成立。

## 4. S / D / B 状态判定

完成 C / A / E 迁移功能角色映射后，PCN 进一步对相关状态进行 S / D / B 判定。

```text
S：结构建立了吗？
D：当前状态有效吗？
B：当前状态在界内吗？
```

| 判定性质 | 判定问题 | 本案例代表项 |
|---|---|---|
| S：Structure | 所需对象、信号、接口、映射关系、许可来源和执行链边界是否已经定义、接入并可观测 | 批次与质量结果映射、质量放行来源、保全解除来源、返工 / 回流 / 废品处理 / 隔离工序接口 |
| D：Dynamics | 当前状态是否仍然有效、同步并适用于本次判定 | 工单切换、配方同步、许可撤销、状态未刷新、状态过期、版本不一致、接口延迟 |
| B：Boundary | 当前有效状态是否处于预定义允许范围、限制值或边界内 | 等待时间上限、同步时间上限、人工确认有效期、缓存容量边界、重试次数上限、返工次数上限 |

### 状态值与当前有效性

生产 DX 中，多源状态来自 MES、质量、PLC、保全、人员和下游系统，各系统更新时间和状态保持方式不同。

例如：

```text
质量结果 = 合格
```

需要确认该结果是否属于当前产品或批次，并与本次 Target State Entry 的对象、版本和时间关系一致。

同样：

```text
下游可接收 = 成立
```

如果状态长期未刷新，或产生于下游状态切换之前，则不能直接作为当前 E 的有效依据。

因此：

```text
状态值成立 ≠ 状态当前有效
```

D 可以结合更新时间、版本号、序列信息、批次号、事件标识或刷新状态判断当前有效性。

每次 CAE-SDB Result 同时保留时间信息 T，用于标识本次状态与判定的时间位置，并支持动态时序判断与 PCN Trace。

### C-S

质量结果已经存在，但尚未建立：

```text
质量结果 ↔ 当前批次
```

之间的明确关联。

→ C-S

### C-D

MES 已经切换到新工单，但 PLC 仍处于上一配方，或者当前质量结果属于上一批次。

也可能出现相关状态值仍然存在，但已经超过本次目标状态进入所允许的有效范围，或者不同系统之间的状态版本、序列关系已经不一致。

→ C-D

### A-S

进入目标状态需要质量放行、保全解除或特定人员确认，但系统没有定义明确的许可来源。

→ A-S

### A-D

质量许可曾经成立，但随后被撤销；或者保全解除状态已经变化，而相关系统仍保留旧状态。

也可能出现人工确认、生产许可或其他授权状态已经超过有效范围，但系统仍保留原有成立值。

→ A-D

### E-S

返工、回流、废品处理、隔离、下游承接或结果回写等执行路径在生产流程中存在，但所需信号、接口、角色或执行链边界没有完整定义。

→ E-S

### E-D

下游仍显示可接收，但状态长时间没有刷新；或者返工设备、搬送系统、废品处理设备、隔离区域、结果回写接口当前处于切换、延迟或阻塞状态。

即使某个状态值仍显示正常，如果其更新时间、状态版本、序列关系或相关上下文已经不能证明该状态仍适用于本次目标状态进入，也不能直接认为执行链当前有效。

→ E-D

### B 相关判定

代表性 Boundary 判定包括：

- 状态同步等待超过预设时间；
- 人工确认超过有效期限；
- 重试次数达到或超过上限；
- 下游缓存达到容量边界；
- 工单切换稳定时间超过预设范围；
- 返工次数达到预设上限。

这些结果与 S / D 判定共同形成 CAE-SDB Result。

## 5. 生产状态迁移与多路径控制

同一当前状态可以对应多个候选目标状态或生产路径。

例如，检测工序完成以后，不同对象可以进入：

```text
下一生产工序
返工工序
回流工序
废品处理工序
隔离工序
```

每一候选目标状态进入前，PCN 分别组织相应的 C / A / E，并进行 S / D / B 状态判定。

### 进入下一生产工序

```text
当前状态： 前工序完成

目标状态： 下一生产工序
```

相关状态可能包括：

```text
工单有效
质量结果合格
质量放行成立
设备可执行
下游可承接
追溯关系有效
```

判定满足进入条件后：

```text
CAE-SDB Result + T → 控制仲裁 → 多路径控制 → 允许进入
```

当前对象随后进入下一生产工序。

### 质量放行状态不同步

```text
当前状态：前工序完成

目标状态：下一生产工序

质量结果：合格
```

如果出现：

```text
质量放行状态未同步
下游状态未及时刷新
```

可能形成：

```text
A-D + E-D
```

随后：

```text
CAE-SDB Result + T
→ 控制仲裁
→ 等待 / 状态重新同步 / 重新确认
```

### 进入返工工序

```text
当前状态：检测完成

质量结果：NG

目标状态：返工工序
```

PCN 判断：

```text
C：当前产品、批次、质量结果、返工条件是否成立

A：返工许可、质量许可、人员权限是否成立

E：返工设备、搬送、缓存、追溯和结果回写是否能够接续
```

判定满足进入条件后：

```text
CAE-SDB Result + T → 控制仲裁 → 多路径控制 → 进入返工工序
```

### 进入回流或废品处理工序

回流、废品处理等路径同样可以围绕各自目标状态入口进行判定。

例如：

```text
当前状态：检测完成

目标状态：废品处理工序
```

PCN 判断：

```text
C：废品判定、产品身份、批次信息是否成立

A：废品处理许可是否成立

E：废品搬送、收集、计数、追溯和结果回写是否能够接续
```

判定满足进入条件后：

```text
→ 多路径控制
→ 进入废品处理工序
```

返工、回流、废品处理和隔离均可作为生产流程中的目标工序或执行路径。

从 TPCA 的状态迁移视角看，这些路径都属于从当前状态进入新的目标状态或目标执行路径，不表示系统返回此前的状态实例。

## 6. 代表性判定、时间信息 T、控制路径与 PCN Trace

本案例可以形成如下代表性 CAE-SDB Result。

| 判定坐标 | 本案例代表性状态 |
|---|---|
| C-S | 当前批次与质量结果、工单或配方之间的关系未完整定义 |
| C-D | 工单、批次、配方或质量结果发生切换不同步、状态过期或版本不一致 |
| C-B | 条件状态的当前有效值超出预定义允许范围或时间边界 |
| A-S | 质量放行、保全解除、人员确认等许可来源未完整定义 |
| A-D | 许可撤销、延迟、未刷新、超过有效范围或跨系统状态不同步 |
| A-B | 许可等待时长、确认有效期或授权范围超出预定义边界 |
| E-S | 下游承接、返工、回流、废品处理、隔离或结果回写链未完整定义 |
| E-D | 下游、搬送、返工设备、废品处理、缓存、接口或回写状态当前不可稳定接续，或相关状态已不能确认当前有效 |
| E-B | 缓存容量、等待时长、返工次数或执行链状态超出预定义边界 |

每次 CAE-SDB Result同时保留对应的时间信息 T。

CAE-SDB Result经控制仲裁后形成多路径控制。

代表性控制输出包括：

- 允许进入；
- 等待；
- 重新读取；
- 重新核对；
- 重新确认；
- 状态重新同步；
- 返工；
- 回流；
- 废品处理；
- 异常分流；
- 下游协调；
- 资源释放；
- 降级执行；
- 备用路径；
- 禁止进入；
- 安全锁定；
- 人工确认；
- 隔离；
- 增强记录。

代表性判定示例：

```text
C-D：
工单已经切换，但 PLC 配方尚未同步

A-D：
质量放行状态发生撤销或跨系统不同步

E-D：
下游状态未刷新，无法确认当前承接能力

E-S：
返工执行链未完整定义
```

一次 PCN 判定同时形成相应的 PCN Trace。

代表性记录内容包括：

```text
当前状态
目标状态
关键输入状态
时间信息 T
C / A / E 迁移功能角色映射
S / D / B 状态判定
CAE-SDB Result
控制仲裁结果
多路径控制
执行结果
Trace ID
```

必要时，关键输入状态还可以关联：

```text
对象 / 批次信息
状态更新时间
状态版本 / 序列信息
相关事件或追溯标识
```

这些信息用于明确本次判定所依据的有效状态及其上下文。

例如：

```text
当前状态：前工序完成

目标状态：下一生产工序

时间信息：T

CAE-SDB Result：A-D + E-D

工程含义：质量放行状态需要重新确认 / 下游接收状态未及时刷新

多路径控制：状态重新同步 / 重新确认

执行结果：目标状态暂未进入
```

又例如：

```text
当前状态：检测完成

目标状态：返工工序

时间信息：T

质量结果：NG

多路径控制：允许进入返工工序

执行结果：当前对象进入返工工序
```

PCN Trace 重点记录：

> **本次准备进入哪个目标状态、依据哪些当前有效状态进行判定、为什么形成该判定，以及最终进入了哪一条生产路径。**

## 7. 履历复盘、AI 辅助分析与生产 DX 应用价值

多个 PCN 长期运行后，PCN Trace 会持续积累。

生产 DX 除了分析设备效率、生产实绩、质量结果、停机、报警、能耗和物流，还可以进一步分析：

- 哪些目标状态经常不能成立；
- 哪些 C 条件长期构成状态迁移阻点；
- 哪些 A 许可长期构成生产放行瓶颈；
- 哪些 E 执行链经常不能接续；
- 哪些返工、回流或废品处理路径长期高频；
- 哪些 S 结构问题反复出现；
- 哪些 D 动态问题长期存在；
- 哪些状态经常达到或超出预定义边界；
- 哪些控制路径被频繁调用；
- 哪些工程改善以后，相同判定结果明显减少。

例如，如果 A-S 长期高频出现，改善重点可能是重新梳理许可来源、责任角色和系统接口。

如果 C-D、A-D、E-D 长期高频出现，则可以进一步检查工单切换、状态刷新、状态有效性、版本关系、接口延迟和跨系统同步机制。

当多个系统共同参与一次状态迁移判定时，还需要关注：

> **不同系统中的状态分别正确，并不代表这些状态在同一次目标状态入口判定中仍然同时有效。**

例如 MES、质量系统、PLC 和下游系统可能分别保存着合理的状态值，但如果这些状态来自不同对象、不同批次、不同状态版本或不同更新时间窗口，则不能简单拼接为一次有效的状态迁移依据。

如果返工路径长期高频使用，可以结合产品、设备、工序和质量履历进一步分析其形成条件。

如果某些 B 判定长期频繁触发，则可以重新检查当前状态迁移条件、确认方式或控制边界是否合理。

因此，PCN Trace 不仅用于事后追溯，也可以作为生产状态迁移设计复盘的数据来源。

对于返工、回流、重新投入等路径，PCN Trace 还可以区分工程状态内容相同但发生时间和迁移历史不同的状态实例。

### AI 辅助分析

PCN Trace 将一次状态迁移中的：

```text
Current State
Target State
关键输入状态
时间信息 T
C / A / E 迁移功能角色映射
S / D / B 状态判定
CAE-SDB Result
控制仲裁结果
多路径控制
执行结果
```

组织为同一条判定履历。

在此基础上，AI 可用于：

- 聚合同类 PCN Trace；
- 识别高频 C / A / E 与 S / D / B 组合；
- 比较不同目标状态的重复问题；
- 区分状态值异常与动态时序有效性问题；
- 分析返工、回流、废品处理等路径的长期变化；
- 比较改善前后的判定结果；
- 生成候选检查点和工程报告。

例如长期 Trace 中反复出现：

```text
Target State：下一生产工序
CAE-SDB Result：A-D
相关状态：质量放行状态不同步
```

即可作为质量系统与 MES 放行状态同步机制的改善候选。

生产 DX 在此基础上从“数据采集与可视化”进一步进入：

> **状态迁移条件设计、判定履历分析与持续改善。**
