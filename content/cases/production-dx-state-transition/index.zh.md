# 自动加工已经完成，为什么仍不能开始人工作业单元组装？

> 应用层级：制造流程 / 跨系统状态迁移  
> 代表对象：部件自动加工 → 人工作业单元组装

**建议引用：**

```text
全野南政 / Nansei Zenno，《制造 DX 状态迁移条件设计与履历分析案例：自动加工已经完成，为什么仍不能开始人工作业单元组装？》，公开案例，Public Case Version 1.5，2026-09-20，https://zennns.com/zh/cases/production-dx-state-transition/
```

制造现场中，经常存在自动加工完成后转入人工作业单元组装的生产流程。

自动加工已经完成，并不代表下一工序已经可以开始。

进入人工作业单元组装，还可能涉及质量放行、必要零部件、作业人员资格、单元设备、治具工具，以及组装后的检测、搬出和实绩回写。

本案例关注的问题是：

> **自动加工已经完成，为什么当前部件仍不能进入人工作业单元组装？**

案例围绕“开始对象部件的人工作业单元组装”这一目标状态入口，说明如何把分散在设备、MES、质量系统、人员资格、部件供给和后续工序中的状态组织到同一次判定中，并继续连接控制仲裁、控制路径、执行结果和状态迁移判定履历。

案例按照统一九步工程顺序展开：

1. 当前状态
2. 目标状态 / 目标状态入口
3. PCN：相关状态获取与 C / A / E 状态映射
4. S / D / B 判定与 CAE-SDB 结果 + T
5. 控制仲裁
6. 多路径控制
7. 当前入口控制结果
8. 控制路径执行 / 后续目标状态入口与执行结果
9. 状态迁移判定履历

## 案例对象

本案例假设自动加工设备已经完成某个部件的加工，部件经过搬送后，准备进入由作业人员负责的人工作业单元进行组装。

与本次状态迁移有关的主要对象包括：

- MES；
- 自动加工设备 / PLC；
- 质量系统；
- 部件搬送与供给；
- 作业人员认证与资格管理；
- 人工作业单元设备；
- 治具与紧固工具；
- 组装后检测；
- 完成品搬出与生产实绩回写。

这个场景同时跨越自动设备、信息系统、人员、物料、工具和后续工序，是制造 DX 中典型的跨系统状态迁移问题。

---

# 1. 当前状态

当前现场状态为：

```text
自动加工完成 / 等待人工作业单元组装
```

此时已经确认：

```text
加工完成：成立

部件编号：已读取

当前批次：已确定

质量测量：已完成

部件搬送：已完成
```

这是本次状态迁移的起点。

---

# 2. 目标状态 / 目标状态入口

本次目标状态为：

```text
对象部件处于人工作业单元组装中
```

对应的目标状态入口为：

```text
开始对象部件的人工作业单元组装
```

PCN 设置在当前状态和这一目标状态入口之间，在组装开始前完成本次前置判定。

本次需要确认的是：

> **当前加工完成的部件，能否由当前作业人员在当前人工作业单元中开始组装，并保证后续执行链能够继续接续。**

---

# 3. PCN：相关状态获取与 C / A / E 状态映射

PCN 取得与组装开始直接相关的状态，并按照这些状态在当前目标状态入口中的工程作用进行 C / A / E 状态映射。

| 代表状态 | 状态映射 |
|---|---|
| 加工完成、部件编号、批次、质量结果、必要零部件 | C：条件状态 |
| 质量放行、生产许可、作业人员资格、当前产品作业权限 | A：许可状态 |
| 单元设备就绪、治具、紧固工具、组装后检测、搬出和实绩回写 | E：执行链状态 |

本案例重点使用：

- 加工完成：C
- 质量结果：C
- 质量放行：A
- 作业人员资格：A
- 单元设备就绪：E 的相关状态
- 后续检测与实绩回写：E

质量结果合格表示当前部件满足质量条件，属于 C。

质量放行成立表示当前部件被允许进入下一工序，属于 A。

同样，单元设备已经就绪，也不代表当前作业人员已经具备进入该组装作业的许可。

---

# 4. S / D / B 判定与 CAE-SDB 结果

本案例假设当前状态如下：

```text
加工完成：成立

质量结果：合格

质量放行：成立

必要零部件：齐套

单元设备就绪：成立

作业人员登录：有效

当前产品作业资格：已登记，但超过有效期
```

作业人员资格属于 A。

当前资格已经存在，但超过允许有效期，因此问题发生在许可状态的控制边界，形成：

```text
CAE-SDB 结果：
A-B

当前作业人员资格已经超过有效期，
不满足本次组装入口的许可边界
```

时间信息 T 与本次状态及判定结果关联保存。

本案例不展开完整 9 个 CAE-SDB 坐标。C / A / E 与 S / D / B 的完整关系可参见：

[为什么是 CAE-SDB？——状态变量域与判定性质的双轴结构](/zh/notes/why-cae-sdb/)

---

# 5. 控制仲裁

本次控制仲裁的主要输入为：

```text
C 相关状态：
  满足当前入口要求

E 相关状态：
  满足当前入口要求

质量放行：
  成立

作业人员资格：
  A-B
  资格已经超过有效期
```

作业人员资格属于本次组装入口的关键 A。

即使加工已经完成、质量结果合格、单元设备也已经就绪，当前入口仍不能允许进入。

控制仲裁结果为：

```text
暂缓当前组装开始
优先处理作业人员资格问题
```

---

# 6. 多路径控制

根据控制仲裁结果，本次选择：

```text
确认并更换为具备有效资格的作业人员
```

该处理属于当前组装入口下的处理动作。

---

# 7. 当前入口控制结果

本次“开始对象部件的人工作业单元组装”的目标状态入口不允许进入。

当前入口控制结果为：

```text
暂不开始当前人工作业单元组装
```

原因不是加工未完成，也不是设备未就绪，而是关键许可状态 A 当前不满足进入要求。

---

# 8. 控制路径执行 / 后续目标状态入口与执行结果

根据当前控制结果，现场重新确认作业人员资格，并更换为具备有效资格的作业人员。

假设处理完成后：

```text
作业人员登录：
  有效

当前产品作业资格：
  有效
```

则本次执行结果可以记录为：

```text
已完成具备有效资格的作业人员更换，
当前作业资格状态已确认有效
```

此时只是形成了新的运行事实。

后续再次请求“开始对象部件的人工作业单元组装”这一目标状态入口时，需要基于更新后的状态重新执行前置判定。

如果控制路径指向其他作业单元、返修或隔离等新的目标状态，则由对应目标状态入口的 PCN 单独进行前置判定。

---

# 9. 状态迁移判定履历

本次组装开始入口可以形成如下履历：

```text
PCN：
人工作业单元组装开始入口 PCN

当前状态：
自动加工完成 / 等待人工作业单元组装

目标状态：
对象部件处于人工作业单元组装中

目标状态入口：
开始对象部件的人工作业单元组装

主要状态：
  加工完成 = 成立
  质量结果 = 合格
  质量放行 = 成立
  必要零部件 = 齐套
  单元设备就绪 = 成立
  作业人员登录 = 有效
  当前产品作业资格 = 已过期

CAE-SDB 结果：
A-B

控制仲裁结果：
暂缓当前组装开始，
优先处理作业人员资格问题

多路径控制：
确认并更换为具备有效资格的作业人员

当前入口控制结果：
暂不开始当前人工作业单元组装

执行结果：
已完成具备有效资格的作业人员更换，
当前作业资格状态已确认有效

时间信息：
T

履历 ID：
PCN-CELL-XXXX
```

作业人员更换完成后，后续再次请求同一目标状态入口时，将基于更新后的状态重新判定，并形成新的履历；前一次履历不被覆盖。

关于状态迁移判定履历的详细说明可参见：

[为什么状态迁移判定履历是一种新的工程数据？](/zh/notes/why-pcn-trace-is-engineering-data/)

## 案例总结

本案例中，自动加工已经完成，质量结果合格，质量放行成立，必要零部件齐套，单元设备也已经就绪。

如果只看前工序完成和设备就绪状态，现场看到的是：

> **“前工序已经完成，设备也准备好了，为什么组装还不能开始？”**

围绕“开始对象部件的人工作业单元组装”这一目标状态入口检查后，可以明确：

```text
CAE-SDB 结果：
A-B

具体问题：
当前作业人员资格已经超过有效期，
不满足本次组装入口的许可边界
```

### 本案例带来的工程信息差异

| 原有现场能够确认 | 通过本案例进一步明确 |
|---|---|
| 自动加工已经完成 | 当前需要判定的是“开始人工作业单元组装”这一明确目标状态入口 |
| 质量结果合格 | 质量结果属于 C，表示当前部件满足质量条件 |
| 质量放行成立 | 质量放行属于 A，表示当前部件被允许进入下一工序 |
| 必要零部件已经齐套 | 物料条件满足当前组装入口要求 |
| 单元设备已经就绪 | 设备就绪只是 E 中的相关状态，不能单独代表入口成立 |
| 作业人员已经登录 | 登录状态不等于当前产品作业资格有效 |
| 组装仍然没有开始 | CAE-SDB 结果为 **A-B：当前作业人员资格已超过有效期** |
| 现场需要继续跨系统确认原因 | 问题已经定位到关键许可状态不满足当前入口要求 |
| 需要人工决定下一步如何处理 | 控制路径明确为“确认并更换为具备有效资格的作业人员” |
| 人员更换完成 | 形成新的运行事实，原组装入口仍需要重新判定 |
| 各系统分别保存自己的状态和日志 | 本次状态、判定、控制和执行结果被组织到同一次状态迁移判定履历中 |

本案例把“自动加工已经完成，但下一工序仍然没有开始”进一步定位为：当前组装入口中的关键许可 A 不满足要求，具体表现为作业人员资格超过有效期。

对应处理是确认并更换为具备有效资格的作业人员。人员更换完成后形成新的运行事实，但同一组装入口仍需要基于更新后的状态重新判定。

案例的重点不在增加更多状态数据，而在于把自动加工、质量、物料、人员资格、设备和后续处理状态放到同一个目标状态入口下进行判断，并明确当前入口为什么不能进入、应该如何处理，以及处理完成后如何继续判定。
