# 自动加工已经完成，为什么仍不能开始人工作业单元组装？

> 应用层级：制造流程 / 跨系统状态迁移  
> 代表对象：部件自动加工 → 人工作业单元组装

**建议引用：**

```text id="h76lj8"
全野南政 / Nansei Zenno，《制造 DX 状态迁移条件设计与履历分析案例：自动加工已经完成，为什么仍不能开始人工作业单元组装？》，公开案例，Public Case Version 1.5，2026-09-20，https://zennns.com/zh/cases/production-dx-state-transition/
```

制造现场中，从自动加工转入人工作业单元组装，往往不是单一设备内部的状态切换。

例如，某个部件已经完成自动加工，质量测量结果合格，部件也已经搬送到组装区域，单元设备处于就绪状态。

现场可能同时看到：

```text id="g3xswm"
加工完成：成立
质量结果：合格
质量放行：成立
必要零部件：齐套
单元设备就绪：成立
作业人员登录：有效
```

从设备和生产进度看，似乎已经具备开始组装的条件。

但组装仍然没有开始。

原因可能不在加工设备，也不在质量结果，而在另外一个系统中：**当前作业人员虽然已经登录，但对应产品的作业资格已经超过有效期。**

这类问题的特点是，状态分散在不同系统和责任对象中：

- 自动加工设备保存加工完成状态；
- MES 保存工单、产品和生产进度；
- 质量系统保存检测结果和放行状态；
- 物料系统确认零部件齐套；
- 人员系统保存作业资格；
- 单元设备提供就绪状态；
- 后续检测、搬出和实绩回写又属于其他执行链。

本案例围绕“开始对象部件的人工作业单元组装”这一 Target State Entry（目标状态入口），说明这些跨系统状态如何被放到同一次前置判定中。

案例按照统一九步工程顺序展开：

1. 当前状态
2. 目标状态 / 目标状态入口
3. PCN：相关状态获取与 C / A / E 状态映射
4. S / D / B 判定与 CAE-SDB 结果 + T
5. 控制仲裁
6. 多路径控制
7. 当前入口控制结果
8. 控制路径执行 / 后续目标状态入口与执行结果
9. 状态迁移判定履历

基础概念可参见：

- [核心概念](/zh/concepts/)
- [TPCA / PCN 状态迁移前置控制架构｜白皮书](/zh/whitepaper/)

## 案例对象

本案例假设自动加工设备已经完成某个部件的加工，部件经过搬送后，准备进入由作业人员负责的人工作业单元进行组装。

与本次状态迁移有关的主要对象包括：

- MES；
- 自动加工设备 / PLC；
- 质量系统；
- 部件搬送与供给；
- 作业人员认证与资格管理；
- 人工作业单元设备；
- 治具与紧固工具；
- 组装后检测；
- 完成品搬出；
- 生产实绩回写。

这个场景的关键不在于某一个设备能否动作，而在于**设备、信息系统、人员、物料和后续工序能否共同支持一次明确的组装开始入口。**

以下状态和时间关系用于说明公开案例中的示例运行关系，不代表特定真实项目参数或人员管理规则。

---

# 1. 当前状态

当前自动加工工序已经结束，部件已经搬送至人工作业单元附近。

当前状态为：

```text id="jyht6y"
自动加工完成 / 等待人工作业单元组装
```

此时多个系统分别提供以下状态：

```text id="ipjv7e"
加工完成：成立

部件编号：已读取
当前批次：已确定

质量测量：已完成
质量结果：合格
质量放行：成立

必要零部件：齐套

单元设备：就绪
```

从前工序和设备状态看，没有明显阻塞。

但系统仍未允许当前部件进入组装。

这构成本次需要解释的跨系统状态迁移问题。

---

# 2. 目标状态 / 目标状态入口

本次目标状态为：

```text id="s0xeql"
对象部件处于人工作业单元组装中
```

对应的 Target State Entry 为：

```text id="g985sf"
开始对象部件的人工作业单元组装
```

PCN 设置在“自动加工完成 / 等待组装”与这一入口之间。

这次前置判定需要回答的不只是“设备是不是 Ready”，而是：

> **当前部件、当前质量状态、当前物料、当前作业人员和当前单元设备，是否共同支持这一次组装开始。**

---

# 3. PCN：相关状态获取与 C / A / E 状态映射

PCN 从不同系统取得与本次组装入口直接相关的状态，并根据这些状态在当前迁移中的工程作用执行 C / A / E Mapping。

| 代表状态 | 状态映射 |
|---|---|
| 加工完成、部件编号、批次、质量结果、必要零部件 | C：条件状态 |
| 质量放行、生产许可、作业人员资格、当前产品作业权限 | A：许可状态 |
| 单元设备就绪、治具、紧固工具、组装后检测、搬出和实绩回写 | E：执行链状态 |

本案例重点使用：

```text id="oh0wzn"
加工完成 → C
质量结果 → C

质量放行 → A
作业人员资格 → A

单元设备就绪 → E 的相关状态
后续检测与实绩回写 → E
```

这里有两个容易混淆的状态。

第一：

```text id="zwem6x"
质量结果 = 合格
```

表示当前部件满足质量条件，因此属于 C。

第二：

```text id="0z3pbd"
质量放行 = 成立
```

表示当前部件已经获得进入下一工序的许可，因此属于 A。

两者不是同一个工程状态。

同样：

```text id="4vm9xq"
单元设备就绪 = 成立
```

只能说明执行链中的设备状态已经具备一定条件，并不能证明当前作业人员已经获得进入本次组装作业的许可。

---

# 4. S / D / B 判定与 CAE-SDB 结果

本次示例运行中，PCN 取得以下状态：

```text id="1z6zmh"
加工完成：成立
质量结果：合格
质量放行：成立
必要零部件：齐套
单元设备就绪：成立

作业人员登录：有效

当前产品作业资格：
已登记

资格允许有效期：
至 2026-09-29

当前判定日期：
2026-09-30
```

这里需要区分：

```text id="4jtzuu"
作业人员已登录
```

和：

```text id="8mkxx2"
当前产品作业资格仍然有效
```

前者说明人员身份已经被系统识别。

后者才决定当前人员是否满足本次组装入口的作业许可要求。

在本示例中，作业人员资格已经存在，但其有效期限为：

```text id="4zturm"
2026-09-29
```

当前判定日期为：

```text id="u7h1t8"
2026-09-30
```

因此，该资格已经超过预先定义的允许有效边界。

作业人员资格在当前入口中属于 A。

问题发生在许可状态的 Boundary（边界）判定，因此形成：

```text id="wuqxtr"
CAE-SDB Result：

A-B

当前作业人员资格已经超过有效期，
不满足本次组装入口的许可边界
```

这里不是“人员系统没有资格数据”，也不是“资格数据没有刷新”。

资格记录存在，状态也可以正常读取。

问题在于：

```text id="hnqnx5"
当前资格值已经落在允许边界之外
```

因此判定为 B，而不是 S 或 D。

时间信息 T 与本次资格状态、判定时间和 A-B 结果关联保存。

完整 C / A / E 与 S / D / B 关系可参见：

[为什么是 CAE-SDB？——状态变量域与判定性质的双轴结构](/zh/notes/why-cae-sdb/)

---

# 5. 控制仲裁

进入控制仲裁时，当前状态关系已经比较清楚：

```text id="mafav2"
C 相关状态：
满足当前入口要求

质量放行：
成立

E 相关状态：
满足当前入口要求

作业人员资格：
A-B
资格超过有效期
```

这意味着：

```text id="3hwnl0"
加工已经完成
质量没有问题
物料已经齐套
设备已经就绪
```

但本次 Target State Entry 仍然不能成立。

原因是作业人员资格属于当前组装入口的关键 A。

关键许可不满足时，不能由其他已经成立的 C 或 E 状态替代。

控制仲裁形成：

```text id="hio2un"
当前组装入口：
暂不允许进入

优先处理：
作业人员资格问题
```

---

# 6. 多路径控制

针对当前 A-B，本次形成的 Multipath Control（多路径控制）为：

```text id="wvndd1"
确认具备有效资格的作业人员

必要时更换当前作业人员
```

这里的处理不涉及修改加工结果，也不需要重新执行质量检测。

当前问题已经被定位到人员许可层。

因此控制范围可以集中在：

```text id="3equ01"
人员确认
资格确认
人员更换
```

而不需要重新检查所有已经成立的设备和质量状态。

---

# 7. 当前入口控制结果

当前 Target State Entry 为：

```text id="790ri8"
开始对象部件的人工作业单元组装
```

形成的控制结果为：

```text id="b903x5"
暂不进入
```

原因可以明确写成：

```text id="stg8kd"
关键许可 A 不成立

具体原因：
当前作业人员资格超过允许有效期
```

所以，组装没有开始，并不是因为：

- 自动加工失败；
- 质量结果不合格；
- 零部件没有齐套；
- 单元设备未就绪。

当前阻断点已经明确到人员资格许可。

---

# 8. 控制路径执行 / 后续目标状态入口与执行结果

根据当前控制结果，现场确认可执行该产品组装的作业人员。

处理前：

```text id="2vfob3"
当前人员：
已登录

当前产品作业资格：
已过期
```

处理后：

```text id="g4w592"
当前人员：
已更换

新作业人员登录：
有效

当前产品作业资格：
有效
```

本次控制处理可以形成如下执行结果：

```text id="6h8jab"
执行结果：

已完成具备有效资格的作业人员确认与更换
当前产品作业资格状态已恢复有效
```

这里需要注意，人员更换完成并不直接等于：

```text id="8myig8"
组装已经开始
```

它只形成了新的运行事实。

当系统再次请求：

```text id="a0t7q4"
开始对象部件的人工作业单元组装
```

同一个 Target State Entry 需要基于更新后的当前状态重新执行前置判定。

如果此时：

- 加工完成仍有效；
- 质量放行仍成立；
- 物料仍齐套；
- 新作业人员资格有效；
- 单元设备仍然就绪；
- 后续检测和实绩回写链仍可接续；

本次入口才可以重新形成允许进入的控制结果。

如果控制路径转向其他作业单元、返修、隔离等新的目标状态，则应建立新的 Target State Entry，由对应 PCN 独立执行前置判定。

---

# 9. 状态迁移判定履历

本次组装开始入口可以形成如下 PCN Trace：

```text id="yy215y"
履历 ID：
PCN-CELL-XXXX

PCN：
人工作业单元组装开始入口 PCN

当前状态：
自动加工完成 / 等待人工作业单元组装

目标状态：
对象部件处于人工作业单元组装中

目标状态入口：
开始对象部件的人工作业单元组装

主要状态：
  加工完成 = 成立
  质量结果 = 合格
  质量放行 = 成立
  必要零部件 = 齐套
  单元设备就绪 = 成立
  作业人员登录 = 有效
  当前产品作业资格 = 已过期

CAE-SDB Result：
A-B

判定内容：
当前作业人员资格超过允许有效期，
不满足本次组装入口许可边界

控制仲裁结果：
暂缓当前组装开始，
优先处理作业人员资格问题

多路径控制：
确认具备有效资格的作业人员
必要时更换当前作业人员

当前入口控制结果：
暂不开始当前人工作业单元组装

执行结果：
已完成具备有效资格的作业人员确认与更换，
当前产品作业资格状态已恢复有效

时间信息：
T
```

作业人员更换以后，前一次履历继续保留。

下一次再次请求同一 Target State Entry 时，会使用更新后的状态形成新的 PCN Trace。

也就是说：

```text id="dvx8uj"
第一次判定：
A-B
资格过期
→ 不进入

人员更换

第二次判定：
使用新的资格状态重新判断
```

两次状态迁移判定分别对应不同运行实例，前一次记录不会被新的结果覆盖。

关于 PCN Trace 的详细说明可参见：

[为什么状态迁移判定履历是一种新的工程数据？](/zh/notes/why-pcn-trace-is-engineering-data/)

## 案例总结

本次示例开始时，多个系统已经分别显示：

```text id="1fjnhl"
自动加工：完成
质量结果：合格
质量放行：成立
零部件：齐套
单元设备：就绪
作业人员：已登录
```

从生产进度画面看，很容易产生一个疑问：

> **前工序已经结束，设备也已经准备好，为什么组装还是不能开始？**

把这些状态放到：

```text id="2me2f4"
目标状态入口：
开始对象部件的人工作业单元组装
```

下面统一判定后，问题变得具体：

```text id="efklbq"
当前产品作业资格
        ↓
已超过允许有效期
        ↓
A-B
        ↓
关键许可不成立
        ↓
当前组装入口不进入
```

控制处理随后集中到人员许可问题：

```text id="3a3r8v"
确认资格
        ↓
更换具备有效资格的作业人员
        ↓
形成新的运行事实
        ↓
同一组装入口重新判定
```

### 本案例带来的工程信息差异

| 原有现场能够确认 | 通过本案例进一步明确 |
|---|---|
| 自动加工已经完成 | 当前真正需要判定的是“开始人工作业单元组装”这一 Target State Entry |
| 质量结果合格 | 质量结果属于 C，说明部件满足当前质量条件 |
| 质量放行成立 | 质量放行属于 A，表示部件已获得进入下一工序的许可 |
| 必要零部件齐套 | 当前物料条件满足组装入口要求 |
| 单元设备已经就绪 | 设备就绪只是 E 中的相关状态之一 |
| 作业人员已经登录 | 登录状态不能证明当前产品作业资格仍然有效 |
| 当前产品资格已经登记 | 资格记录存在，但已经超过允许有效边界 |
| 组装没有开始 | 当前入口形成 `A-B` |
| 工程师需要跨系统确认原因 | 阻断点已经定位到人员资格许可 |
| 下一步如何处理依赖人工经验 | 控制范围集中到资格确认和人员更换 |
| 人员更换完成 | 只形成新的状态事实，同一入口仍需重新判定 |
| 多个系统分别保存自己的记录 | 状态、判定、控制和执行结果进入同一次状态迁移判定履历 |

本案例最关键的信息不是“某一个系统报警”，而是：

> **加工、质量、物料和设备状态全部成立时，一个独立的关键许可 A 仍然可以阻止目标状态入口成立。**

这正是跨系统制造 DX 场景中容易被分散状态掩盖的问题。
