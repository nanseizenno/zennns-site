本ページでは、TPCA / PCN を異なるエンジニアリング対象に適用した公開事例を紹介する。

## 事例一覧

### [自動化実行ユニット前判定事例](/jp/cases/automation-execution-unit-pre-control/)

画像認識を用いたロボットユニットを例に、把持段階へ進入する前に関連状態を C / A / E へ整理し、S / D / B 判定、Arbitration（制御優先度調停）、Multipath Control（複数経路制御）、PCN Trace までの流れを示す。

### [MES / WCS 協調停滞診断モジュール事例](/jp/cases/collaborative-stagnation-diagnosis/)

MES / WCS の協調停滞を対象に、CAE-SDB 判定に加えて、群指標、群全体の停滞判定、停滞構造分類を扱う。

### [製造 DX 状態遷移条件設計・履歴分析事例](/jp/cases/production-dx-state-transition/)

自動加工工程からセル組立工程への移行を例に、品質、作業者資格、部品供給、セル設備などの状態を Target State Entry（目標状態入口）に対応付け、CAE-SDB Matrix（CAE-SDB マトリクス）を用いた判定と履歴分析を示す。

# 三つの事例から確認できる工学的価値

| 事例 | 従来の現場情報から<br>確認できること | TPCA / PCN により<br>さらに明確になること | 主な工学的価値 |
|---|---|---|---|
| 自動化実行ユニット | Robot Ready は成立しているが、<br>把持が開始されない | 「把持段階への進入」という<br>目標状態入口を明確化し、<br>`C-D：画像認識結果の動的時系列有効性喪失`<br>として整理 | 「設備は Ready だが動作しない」という現象を、<br>具体的な入口判定問題へ展開し、<br>後続の制御経路へ接続できる |
| MES / WCS 協調停滞 | タスクは存在し、実行主体もオンラインだが、<br>複数主体が継続して待機している | `A-D：資源ロック状態の非同期` を形成し、<br>群全体の停滞成立と<br>資源競合型の停滞構造を識別 | 分散した状態と群全体の現象を、<br>入口判定、停滞構造、<br>協調制御方向として整理できる |
| 製造DX | 自動加工完了、品質合格、<br>設備準備完了であるが、<br>組立が開始されない | `A-B：作業者資格の有効期限超過` を形成し、<br>重要な許可状態による<br>入口制約を明確化 | 設備、情報システム、人、許可にまたがる状態を<br>一回の入口判定に関連付け、<br>重要な許可制約を特定できる |

各事例の前後比較は、TPCA / PCN の適用によって、既存の状態情報からどのような状態遷移関係がさらに明確になるかを示している。

# 9ステップのエンジニアリング分析手順

各公開事例では、次の9ステップを共通の基本構成として使用する。

| 工程 | 概要 |
|---|---|
| **1. Current State（現在状態）** | 状態遷移の起点を明確にする。 |
| **2. Target State（目標状態） / Target State Entry（目標状態入口）** | 目標状態と目標状態入口を明確にする。 |
| **3. PCN：関連状態取得 + C / A / E 状態マッピング** | 関連状態を Condition（条件状態）、Authority（許可状態）、Execution Chain（実行チェーン状態）へ整理する。 |
| **4. S / D / B 判定 → CAE-SDB Matrix（CAE-SDB マトリクス） → CAE-SDB Result（CAE-SDB 判定結果） + T** | Structure（構造完全性）、Dynamics（動的時系列有効性）、Boundary（制御境界）の判定結果を構造化する。 |
| **5. Arbitration（制御優先度調停）** | 判定結果、重要な許可、制御制約の優先関係を整理する。 |
| **6. Multipath Control（複数経路制御）** | Target State Entry（目標状態入口）に対する制御出力を形成する。 |
| **7. Target State Entry（目標状態入口）に対する制御結果** | 進入許可、保留、進入禁止などの結果を明確にする。 |
| **8. 選択された制御経路の実行 → Execution Result（実行結果）** | 選択された制御を実行し、その結果を確認する。 |
| **9. PCN Trace** | 状態、判定、制御、実行結果を状態遷移判定履歴として記録する。 |

各適用事例では、この9ステップを共通の主工程として使用し、その内部に対象分野固有の分析を追加できる。

たとえば、MES / WCS 協調停滞診断では、第4ステップに群指標、群全体の停滞判定、停滞構造分類を加える。一方、9ステップ全体の工程順序は維持する。
