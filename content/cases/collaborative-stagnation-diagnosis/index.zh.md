## 为什么 MES 记录了状态，仍解释不了制造现场为什么停？

> 应用层级：群控协同层 / MES-WCS 协同停滞诊断  
> 代表对象：制造现场协同停滞诊断模块

**建议引用：**

全野南政 / Nansei Zenno，  
《MES / WCS 协同停滞诊断模块案例：为什么 MES 记录了状态，仍解释不了制造现场为什么停》，  
公开案例，Public Case Version 1.7，2026-10-01，  
https://zennns.com/zh/cases/collaborative-stagnation-diagnosis/

MES 和 WCS 通常已经掌握大量运行信息。

例如某一时刻，系统有 42 个活动任务，其中 17 个持续等待或未执行。执行主体在线，工位需求存在，部分路径仍可使用，共享资源处于部分占用状态，现场也没有出现足以直接解释整体停滞的重大单体设备报警。

但任务仍持续积压，多个主体长时间等待，整体协同执行能力下降。

当前需要判断的是：

> **为什么系统无法继续进入可持续协同执行状态？**

本案例以“进入可持续协同执行状态”为目标状态入口（Target State Entry），将 MES、WCS、执行主体、路径资源、许可和站点状态组织到同一次协同判定中。

本案例同时保留群控协同层自身的分析结果，用于判断群体停滞是否成立，以及当前停滞属于哪一种结构类型。CAE-SDB 判定和群控协同分析分别保持各自的工程语义。

案例按照统一九步工程顺序展开：

1. 当前状态
2. 目标状态 / 目标状态入口
3. PCN：相关状态获取与 C / A / E 状态映射
4. 前置判定与群控协同分析
5. 控制仲裁
6. 多路径控制
7. 当前入口控制结果
8. 控制路径执行 / 后续目标状态入口与执行结果
9. 状态迁移判定履历

## 案例对象

本案例对象为 MES / WCS 协同停滞诊断模块。

模块位于制造现场协同层，可汇总 MES 的任务与工位需求、WCS 的调度与搬送任务、AGV / AMR 或其他执行主体状态、路径和共享资源状态、区域及安全许可、站点承接状态、下游状态以及群体运行指标。

AGV / AMR 群控搬送属于代表场景之一。本案例关注更一般的制造现场协同问题：多个单体没有明显故障时，整体执行仍可能无法持续。

![MES / WCS 协同停滞诊断模块示意图](/images/tpca/08-mes-wcs-collaborative-stagnation-module.png)

图：协同停滞诊断模块汇总 MES、WCS、搬送主体、站点、路径资源、许可和下游状态，并将这些信息关联到同一次协同状态迁移中。

以下数量和状态组合用于说明公开案例中的一次示例运行关系，不代表特定真实项目数据。群体停滞阈值、持续时间窗口和完整结构分型规则不在本公开案例中展开。

---

# 1. 当前状态

当前系统仍有部分任务继续执行，因此整体状态可以定义为“协同执行持续受阻”。

在本次示例中，42 个活动任务中，25 个已经执行或正在推进，17 个持续等待或未执行。执行主体在线，工位需求存在，重大设备报警未发生，部分路径仍可使用。

与此同时，多个主体持续等待，一部分任务长时间未执行。

因此，当前能够确认的是：

**协同执行持续受阻。**

群体是否已经达到停滞条件，以及当前受阻主要属于哪一种结构，还需要继续判定。

---

# 2. 目标状态 / 目标状态入口

本案例关注系统级协同状态。

目标状态为“可持续协同执行状态”。

对应的目标状态入口为“进入可持续协同执行状态”。

这里的“可持续协同执行”，表示当前任务、执行主体、资源、许可、路径和站点关系能够支持系统整体继续推进。

PCN 设置在当前协同状态与这一目标状态入口之间。

后续状态映射、CAE-SDB 判定、群体停滞识别、结构分型和控制处理，都以这一协同入口为基准。

---

# 3. PCN：相关状态获取与 C / A / E 状态映射

PCN 从不同系统取得与当前协同入口直接相关的状态，并根据这些状态在本次状态迁移中的工程作用进行 C / A / E 状态映射。

| 代表状态 | 状态映射 |
|---|---|
| 任务状态、工位需求、目标站点信息 | C：条件状态 |
| 调度许可、资源锁、区域许可、安全许可 | A：许可状态 |
| 执行主体状态、路径状态、站点承接状态、下游状态 | E：执行链状态 |

本次示例中，任务存在属于 C；资源锁状态和安全许可属于 A；执行主体在线、路径可用状态和站点承接状态属于 E 的相关状态。

这里还需要区分两类信息。

第一类是与当前目标状态入口直接相关的状态，这些状态进入 CAE-SDB 判定。

第二类是由多个任务和执行主体汇总形成的群控协同指标，例如：

- 群体未执行比例；
- 群体辅助执行比例；
- 群体能源补给比例；
- 群体授权未成立比例。

这些群体指标用于停滞识别和结构分型，并单独保留其分析语义。

---

# 4. 前置判定与群控协同分析

本次示例中，任务存在，执行主体在线，安全许可成立，一部分路径仍可使用，工位也存在执行需求。

同时，资源锁状态在系统之间没有保持同步。

在当前协同入口中，资源锁属于 A：许可状态。

资源锁接口已经建立，因此结构本身存在。当前问题发生在运行过程中：资源锁状态不同步，无法继续作为当前入口的有效许可依据。

因此形成 CAE-SDB 判定结果：

`A-D`

判定内容为：资源锁状态在系统之间不同步，当前不能继续作为“进入可持续协同执行状态”的有效许可依据。

与此同时，群控协同层继续分析多个任务和执行主体的整体运行状态。

本次示例中：

- 群体未执行比例达到停滞识别条件；
- 群体辅助执行比例呈现资源竞争型特征；
- 群体能源补给比例未呈现能源偏在型特征；
- 群体授权未成立比例未形成分配约束型主导特征。

由此形成群控协同层分析结果：

- 群体停滞识别：成立；
- 停滞结构分型：资源竞争型。

因此，本次运行同时形成两类不同的工程结果：

| 分析层级 | 结果 |
|---|---|
| 目标状态入口层 | `A-D`：资源锁状态动态时序失效 |
| 群控协同层 | 群体停滞成立 / 资源竞争型 |

CAE-SDB 判定结果、群体停滞识别和结构分型分别保持独立工程语义，并共同进入后续控制仲裁。

具体群体比例阈值、持续时间窗口和完整分型规则属于内部工程实现范围，本公开案例不展开。

相关定义可参见：

- [为什么 MES / WCS 能记录，却不能解释停滞？](/zh/questions/why-mes-records-but-cannot-explain/)

---

# 5. 控制仲裁

进入控制仲裁时，当前系统已经形成以下主要结果：

- CAE-SDB 判定结果：`A-D`；
- 资源锁状态：不同步；
- 群体停滞识别：成立；
- 停滞结构分型：资源竞争型；
- 安全许可：成立。

当前首先需要处理已经确认的资源锁状态不一致。

同时，资源竞争型群体特征说明，受到影响的路径关系和任务分配也需要调整。

因此，控制仲裁确定：

- 优先处理资源锁状态不一致；
- 同时进行路径协调；
- 同时进行受影响任务重新分配。

---

# 6. 多路径控制

根据控制仲裁结果，本次协同入口形成以下多路径控制：

- 资源释放；
- 路径协调；
- 任务重新分配。

在协同层，多路径控制可以表现为结构化控制结果、协调请求或调度处理方向，并不要求由单一设备立即执行一个物理动作。

实际项目中，资源释放由哪个系统执行、任务由哪个调度系统重新分配、路径是否自动修改、哪些动作需要人工确认，由现有 MES、WCS、调度系统和现场控制系统的接口、职责与控制权限决定。

TPCA / PCN 在这里负责形成结构化判定和控制方向，并尊重既有系统的执行责任边界。

---

# 7. 当前入口控制结果

当前目标状态入口为“进入可持续协同执行状态”。

本次入口控制结果为“暂不进入”。

当前能够明确的原因包括：

- `A-D`：资源锁状态不同步；
- 群体停滞：成立；
- 停滞结构：资源竞争型。

系统需要先执行相应协调处理，再根据更新后的状态重新判断当前协同入口是否已经恢复到可以持续推进的条件。

---

# 8. 控制路径执行 / 后续目标状态入口与执行结果

由具备相应权限的既有系统执行协调处理。

处理过程中，资源锁状态重新同步，共享资源占用关系重新整理，受影响路径重新协调，相关任务完成重新分配。

本次示例中，处理完成后形成以下状态变化：

- 资源锁状态恢复一致；
- 关键路径恢复可用；
- 受影响任务重新分配完成；
- 持续等待或未执行任务下降；
- 群体未执行比例回到停滞识别条件以下。

这些变化构成本次控制处理的执行结果，并成为新的工程状态事实。

当前系统是否可以重新进入“可持续协同执行状态”，需要依据更新后的状态对同一个入口重新判定。

如果控制过程中选定了备用路径、回退路径、异常分流等新的目标状态或目标执行路径，则需要建立新的目标状态入口，并由对应 PCN 独立完成前置判定。

---

# 9. 状态迁移判定履历

本次协同入口可以形成如下 PCN Trace（状态迁移判定履历）：

| 项目 | 记录内容 |
|---|---|
| 履历 ID | PCN-COLLAB-XXXX |
| PCN | 协同执行入口 PCN |
| 当前状态 | 协同执行受阻 / 多主体持续等待 |
| 目标状态 | 可持续协同执行状态 |
| 目标状态入口 | 进入可持续协同执行状态 |
| 活动任务数 | 42 |
| 持续等待或未执行任务数 | 17 |
| 执行主体 | 在线 |
| 安全许可 | 成立 |
| 资源锁接口 | 已建立 |
| 资源锁状态 | 系统间不同步 |
| 可用路径 | 存在 |
| CAE-SDB 判定结果 | A-D |
| 判定内容 | 资源锁状态不同步，不能继续作为当前协同入口的有效许可依据 |
| 群体停滞识别 | 成立 |
| 停滞结构分型 | 资源竞争型 |
| 控制仲裁结果 | 优先处理资源锁不一致，同时进行路径协调和任务重新分配 |
| 多路径控制 | 资源释放、路径协调、任务重新分配 |
| 当前入口控制结果 | 暂不进入可持续协同执行状态 |
| 执行结果 | 资源锁关系恢复一致，关键路径恢复可用，受影响任务完成重新分配，群体未执行状态下降 |
| 时间信息 | T |

这条履历把原本分散在 MES、WCS、执行主体、资源和许可系统中的状态，关联到同一次协同入口判定中。

其中，入口级 `A-D` 与群控协同层的“群体停滞成立 / 资源竞争型”作为两类不同分析结果保存，并共同连接控制仲裁、控制处理和执行结果。

后续形成新的目标状态入口时，由对应 PCN 建立新的状态迁移判定履历。

## 案例总结

本次示例开始时，任务存在，执行主体在线，工位有需求，部分路径可以使用，单体设备也没有重大报警。

与此同时，多个任务持续未执行，多个主体持续等待，整体协同执行受阻。

以“进入可持续协同执行状态”为目标状态入口重新组织这些状态以后，可以确认资源锁状态在系统之间不同步，因此入口级形成 `A-D`。

同时，群体运行数据表明群体停滞已经成立，停滞结构属于资源竞争型。

控制仲裁据此优先处理资源锁状态不一致，并同时执行路径协调和任务重新分配。处理后，资源锁关系恢复一致，关键路径恢复可用，群体未执行状态下降。

### 本次判定中明确的工程信息

| 原有现场能够确认 | 本次判定进一步明确 |
|---|---|
| 任务已经生成 | 当前判定对象明确为“进入可持续协同执行状态”这一目标状态入口 |
| 执行主体在线 | 主体在线只是协同执行链中的相关状态之一 |
| 多个主体持续等待 | 群体未执行状态已经达到停滞识别条件 |
| 资源锁存在状态不一致 | 当前资源锁属于 A，并形成 `A-D` |
| 单体设备没有重大报警 | 协同问题仍可能存在于任务、许可、共享资源、路径和执行链关系中 |
| 多条路径和资源存在竞争 | 群控协同分析进一步识别为资源竞争型 |
| 现场看到整体协同受阻 | 可以区分入口级 `A-D` 与群控协同层的资源竞争型停滞 |
| 工程师需要跨系统协调处理 | 控制方向明确为资源释放、路径协调和任务重新分配 |
| 处理以后只能重新观察系统状态 | 可以继续比较资源锁、任务、路径和群体未执行状态的变化 |
| 不同系统分别保存状态和日志 | 判定、分型、控制和执行结果可以关联到同一次 PCN Trace |

本次案例展示了群控协同场景中的两类分析关系：目标状态入口层通过 CAE-SDB 定位具体许可状态的动态问题，群控协同层通过群体指标判断停滞是否成立及其结构类型。两类结果共同进入控制仲裁，并继续连接控制处理、执行结果和状态迁移判定履历。
