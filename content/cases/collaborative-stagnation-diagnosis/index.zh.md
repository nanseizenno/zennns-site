## 1. 现场问题

MES 可以记录任务、设备、工位、物料、报警、产量和生产实绩。

WCS 可以记录搬送任务、车辆状态、路径状态、资源占用和调度结果。

设备系统可以记录运行、等待、报警和互锁状态。

HMI 也可以显示 Ready、Waiting、Blocked、Pending 等运行状态。

但在多设备、多任务和多系统协同场景中，仍可能出现：

- 任务已经生成，但执行持续无法推进；
- 车辆在线，工位存在需求，但补料仍未形成连续执行；
- 单体设备没有明显故障，系统整体吞吐却持续下降；
- MES、WCS、PLC、车辆和工位均有状态记录，但难以快速定位协同停滞发生的位置；
- 订单变化、资源竞争、许可等待、下游阻塞、人工确认和能源补给等因素相互叠加，最终仍需人工跨系统核对日志和状态。

因此，问题已经不再是“系统是否有数据”。

更需要回答的是：

> **当前系统为什么无法进入可持续协同执行状态？**

在 TPCA / PCN 中，这一问题被处理为一个明确的目标状态入口问题。

PCN 围绕“可持续协同执行状态”这一目标，汇总与本次状态迁移有关的多源状态，并将其组织为：

- C：任务、物料、站点、路径和现场条件是否成立；
- A：调度许可、资源锁、区域许可、安全许可和人工许可是否成立；
- E：主体、路径、缓存、下游、能源补给和结果回写是否能够继续接续。

随后进一步进行 S / D / B 判定，并结合群体状态完成停滞识别、结构分析、控制仲裁和多路径控制。

因此，系统输出不再局限于：

```text
Waiting
Blocked
Pending
```

而是进一步形成：

```text
当前协同状态
→ 停滞识别
→ 结构化判定
→ 控制仲裁
→ 多路径控制
→ PCN Trace
```

## 2. 模块定位与 PCN 位置

本案例对象为：

> **MES / WCS 协同停滞诊断模块。**

该模块位于制造现场协同层，可连接 MES、WCS、搬送系统、设备单元、站点、缓存、路径资源、许可系统和现场执行对象。

AGV / AMR 群控搬送可以作为代表场景，但模块本身不限定于 AGV。

典型适用对象还包括：

- 无人叉车和自动搬运系统；
- 多设备协同生产；
- 线边补料与缓存调度；
- 工位等待与站点承接；
- 路径资源竞争；
- 区域许可和资源锁协调；
- 临时订单和优先级切换；
- 能源补给集中导致的群体执行能力下降。

![MES / WCS 协同停滞诊断模块示意图](/images/tpca/08-mes-wcs-collaborative-stagnation-module.png)

图：MES / WCS 协同停滞诊断模块位于制造现场协同层，汇总 MES、WCS、AGV / AMR、缓存区、加工设备、路径资源、自动门、电梯、充电区、安全许可系统和监控系统等多源状态。

本案例中的当前协同状态可以表现为：

```text
任务存在
车辆在线
工位有需求
系统持续 Waiting / Blocked / Pending
局部拥堵或执行断续
整体吞吐下降
```

Target State：

```text
可持续协同执行状态
```

该目标状态表示：

> **任务、主体、路径、资源、站点、下游和结果回写已经形成可持续接续的执行结构。**

因此，可以将 PCN 设置在“可持续协同执行状态”这一目标状态入口前：

```text
当前协同状态
        ↓
      PCN
        ↓
可持续协同执行状态
```

PCN 在目标协同执行状态进入之前完成多源状态汇总、结构化判定、停滞识别和控制路径选择。

如果系统后续再次形成与历史正常运行阶段相似的协同状态内容，在 TPCA 中仍然属于新的状态实例，而不是回到原来的状态实例。

## 3. 多源状态信号与 C / A / E 状态映射

协同停滞不是单一设备状态，而是多个任务、主体、资源和执行对象之间的组合状态。

PCN 需要读取与当前协同执行直接相关的多源状态。

| 信号来源 | 代表性信号 |
|---|---|
| MES | 工单、任务、优先级、物料需求、工位需求、计划变更、人工确认、异常记录 |
| WCS / 调度系统 | 任务队列、任务分配结果、任务状态、派单结果、资源锁、路径分配、站点占用、缓存状态 |
| AGV / AMR / 无人叉车 | 在线状态、自动模式、位置、空载 / 负载、电量、任务执行、等待、移动、报警状态 |
| 设备 / 工位 | 可接收状态、运行状态、等待状态、缺料状态、完成状态、报警状态 |
| 路径与设施资源 | 窄通道、交叉口、自动门、电梯、区域通行权、缓存区、装卸点占用状态 |
| 安全与许可系统 | 区域许可、安全许可、上位放行、人工放行、锁定状态 |
| 下游与回写链路 | 下游可承接状态、结果回写状态、异常处理状态 |

这些状态进入 PCN 后，根据“可持续协同执行状态”这一目标进行 C / A / E 映射。

| 变量域 | 判定对象 | 本案例中的代表项 |
|---|---|---|
| C：Condition | 进入目标协同执行状态前的事实条件是否成立 | 任务是否存在；物料是否匹配；目标工位是否存在需求；站点是否有效；主体是否属于可调度对象；目标路径是否存在 |
| A：Authority | 系统是否允许当前任务、主体或资源继续进入协同执行 | 调度许可；资源锁释放；区域许可；安全许可；人工确认；上位放行 |
| E：Execution Chain | 进入目标协同执行状态后，执行链是否能够持续接续 | 主体是否可执行；路径是否可通行；站点是否可承接；缓存是否可接收；下游是否可继续；能源补给是否影响执行能力；结果是否能够回写 |

因此，需要区分以下关系：

```text
任务存在
≠
目标协同执行状态成立

车辆在线
≠
执行链成立

单体 Ready
≠
群体执行链能够持续接续
```

例如：

- 任务存在，但资源锁尚未释放，A 不成立；
- 主体在线，但目标站点无法承接，E 不成立；
- 大量主体集中进行能源补给，可执行主体比例下降，E 的群体执行能力受到影响；
- 任务、主体和路径记录均存在，但下游长期无法承接，目标协同执行状态仍不能成立。

## 4. S / D / B 判定与群体状态

C / A / E 用于说明当前问题涉及的状态变量域。

S / D / B 用于进一步判断这些状态的结构完整性、动态时序有效性和控制边界。

| 判定性质 | 判定对象 | 本案例中的代表项 |
|---|---|---|
| S：Structure | 所需信号、接口、映射关系、许可来源、资源关系和执行链边界是否已经定义、接入并可观测 | MES 与 WCS 的任务映射；资源锁来源；站点承接状态；路径资源；能源补给状态；结果回写状态 |
| D：Dynamics | 当前任务、主体、站点、许可、路径和执行状态是否仍然有效、同步、未超时且未冲突 | 工单变更未同步；主体位置延迟；站点状态未刷新；许可撤销；路径占用冲突；执行反馈超时 |
| B：Boundary | 当前协同状态是否已经进入预先定义的控制边界 | 等待时间；资源占用时间；站点容量；群体未执行比例；能源补给比例；重试次数；限流条件；改派条件；恢复条件 |

单体状态之外，还需要观察群体层面的运行特征。

代表性群体状态或指标可以包括：

- 群体未执行比例；
- 群体辅助执行比例；
- 群体能源补给比例；
- 群体许可未成立比例；
- 路径资源占用状态；
- 站点承接状态；
- 关键任务持续未执行状态。

这些群体状态用于判断：

> **当前问题是否已经由局部等待发展为群体协同层面的持续停滞。**

![协同停滞识别与多路径控制流程图](/images/tpca/09-collaborative-stagnation-control-flow.png)

图：模块从多源状态汇总开始，依次完成 C / A / E 状态映射、S / D / B 判定、群体状态计算、停滞识别、结构分析、控制仲裁、多路径控制和履历记录。

## 5. 停滞识别与结构分析

协同停滞诊断首先需要确认系统是否已经进入持续停滞状态，而不是直接对单一 Waiting 或 Blocked 状态进行分类。

例如：

```text
存在有效任务
        +
多个自动运行主体持续未进入有效执行
        +
群体未执行状态持续达到判定条件
        ↓
群体协同停滞
```

在确认群体协同停滞后，再结合群体状态以及相关 C / A / E 信息分析停滞结构。

代表性结构包括：

### 分配约束

典型表现包括：

- 存在有效任务；
- 多个主体长期未进入执行；
- 任务分配、许可或资源释放未形成有效执行关系。

### 资源竞争

典型表现包括：

- 主体仍在移动、绕行、等待或争用共享资源；
- 路径、交叉口、自动门、电梯、站点或其他共享资源形成竞争；
- 群体存在较多辅助执行，但有效任务推进不足。

### 能源偏在

典型表现包括：

- 较多主体集中进入充电或其他能源补给状态；
- 可用于实际任务执行的主体比例下降；
- 能源补给分布对整体协同执行形成明显影响。

### 未确定状态

当现有状态和群体指标不足以形成可靠结构判断时，保留为未确定状态，并进入增强记录或人工复核。

在具体 MES / WCS 产品实现中，还可以进一步显示许可、站点承接、路径阻塞等诊断信息，但这些信息应与群体停滞识别和结构分析保持一致。

## 6. CAE-SDB 判定结果、时间信息 T、控制仲裁与多路径控制

PCN 对 C / A / E 状态进行 S / D / B 判定后，可以形成一个或多个 CAE-SDB Result，并保留与本次状态和判定对应的时间信息 T。

时间信息 T 可用于：

- 判断群体状态持续时间；
- 判断相关状态是否超时或未刷新；
- 判断状态先后关系；
- 形成 PCN Trace。

代表性结果如下。

| 判定结果 | 本案例中的代表性问题 |
|---|---|
| C-S | 任务、对象、站点或路径的必要映射关系缺失 |
| C-D | 工单变更未同步；任务状态未刷新；需求已经过期 |
| C-B | 任务等待、积压或持续未执行达到控制边界 |
| A-S | 调度许可、资源锁、区域许可或人工确认来源未定义或不可观测 |
| A-D | 许可未刷新、反复撤销或资源锁状态不同步 |
| A-B | 许可等待或资源占用达到控制边界 |
| E-S | 路径、站点、缓存、下游、能源补给或回写链路结构缺失 |
| E-D | 路径状态冲突；站点状态未刷新；主体执行反馈超时；执行链持续阻塞 |
| E-B | 路径等待、站点容量、能源补给或下游等待达到控制边界 |

同一次协同停滞中可以同时存在多个判定结果。

这些判定结果与群体停滞状态共同进入控制仲裁，形成最终多路径控制。

代表性控制路径可以包括：

- 正常继续执行；
- 等待；
- 任务重新分配；
- 资源释放；
- 路径或通行权协调；
- 限流；
- 缓存分流；
- 下游协调；
- 能源补给策略调整；
- 降级执行；
- 人工确认；
- 禁止进入；
- 异常隔离；
- 增强记录。

这些控制路径表示系统从当前协同状态进入不同的后续目标状态或目标执行路径。

即使后续再次形成与历史正常运行阶段相同的协同状态内容，在 TPCA 中仍然属于新的状态实例。

因此，现场看到的结果不再局限于：

```text
Waiting
Blocked
Pending
```

而可以进一步形成：

```text
当前协同状态
→ 停滞识别
→ CAE-SDB Result + T
→ 控制仲裁
→ 多路径控制
```

## 7. PCN Trace 与协同停滞复盘

PCN 在形成判定和控制结果的同时，可以生成相应的 PCN Trace。

代表性记录内容包括：

- 当前协同状态；
- 目标协同执行状态；
- 相关主体和任务；
- 关键输入状态；
- 时间信息 T；
- C / A / E 状态映射；
- S / D / B 判定；
- CAE-SDB Result；
- 群体状态或指标；
- 停滞识别结果；
- 控制仲裁结果；
- 多路径控制结果；
- 执行结果；
- Trace ID。

这些记录可以用于：

- 高频停滞入口识别；
- 群体停滞结构比较；
- 许可和资源锁问题复盘；
- 路径与站点协同问题分析；
- 能源补给分布分析；
- 控制路径效果比较；
- MES / WCS 诊断页面；
- 后续工程改善。

PCN Trace 记录的不是简单的停机日志，而是：

> **为什么系统在某一次协同状态迁移中未能进入可持续协同执行状态，以及最终采用了什么控制路径。**

时间信息 T 还可以用于区分工程状态内容相同、但发生在不同时间位置的协同状态实例。

## 8. 模块价值与公开边界

MES / WCS 协同停滞诊断模块的核心作用，不是增加日志数量，而是将原本分散在任务、调度、资源、路径、站点、许可、主体和下游系统中的状态，组织为可用于协同停滞判定和控制的工程结构。

它使现场处理过程可以从：

```text
系统停滞
→ 查日志
→ 查调度
→ 查设备
→ 跨系统确认
```

进一步转化为：

```text
协同状态异常
→ PCN 判定
→ 停滞识别
→ 结构分析
→ CAE-SDB Result + T
→ 控制仲裁
→ 多路径控制
→ PCN Trace
```

对于 MES / WCS 产品，这意味着系统不仅可以记录：

> **发生了什么。**

还可以进一步说明：

> **为什么当前协同执行无法继续，以及后续应进入哪一条控制路径。**

本文为公开案例，仅说明：

- 模块定位；
- 多源状态；
- C / A / E 状态映射；
- S / D / B 判定；
- 群体状态与指标；
- 停滞识别；
- 结构分析；
- CAE-SDB Result；
- 时间信息 T；
- 控制仲裁；
