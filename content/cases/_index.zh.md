这里整理 TPCA / PCN 在不同工程对象中的公开案例，并通过案例对照说明：在原有系统已经具备状态数据的基础上，TPCA / PCN 还能进一步明确什么工程信息。

三个案例分别对应自动化执行单元、群控协同和制造 DX 跨系统状态迁移。它们使用同一套九步工程分析顺序，但各自保留与具体工程对象相对应的专业分析内容。

### [自动化执行单元前置判定案例](/zh/cases/automation-execution-unit-pre-control/)

以视觉识别输送线机器人单元为代表例，围绕“进入抓取阶段”这一目标状态入口，组织视觉、机器人、安全、输送和下游承接状态。

### [MES / WCS 协同停滞诊断模块案例](/zh/cases/collaborative-stagnation-diagnosis/)

以制造现场协同停滞为对象，围绕“进入可持续协同执行状态”这一目标状态入口，组织 MES、WCS、搬送主体、站点、资源、许可和下游状态，并保留群体停滞识别与停滞结构分型。

### [制造 DX 状态迁移条件设计与履历分析案例](/zh/cases/production-dx-state-transition/)

以“自动加工完成 → 人工作业单元组装开始”为代表状态迁移，将自动加工设备、MES、质量系统、部件供给、作业人员资格、单元设备、治具工具和后续处理状态组织到同一个目标状态入口。

# 三个案例体现的工程价值

| 案例 | 原有现场能够确认 | 通过案例进一步明确 | 主要工程价值 |
|---|---|---|---|
| 自动化执行单元 | 机器人已经就绪，但抓取没有开始 | 明确“进入抓取阶段”这一目标状态入口，并定位为 `C-D：视觉结果已失去动态时序有效性` | 将“设备就绪但不动作”进一步定位到具体入口判定问题，并连接后续控制路径 |
| MES / WCS 协同停滞 | 任务存在、主体在线，但多个主体持续等待 | 明确 `A-D：资源锁状态不同步`，同时识别群体停滞成立及资源竞争型结构 | 将分散状态与群体现象进一步转化为入口判定、停滞结构和协调控制方向 |
| 制造 DX 跨系统状态迁移 | 自动加工完成、质量合格、设备就绪，但组装未开始 | 明确 `A-B：当前作业人员资格已超过有效期` | 将跨设备、系统、人员和许可的信息组织到同一次入口判定，并识别关键许可约束 |

# 九步工程分析顺序

以下九个步骤来自 [TPCA / PCN 状态迁移前置控制架构｜白皮书](/zh/whitepaper/)，作为公开案例的统一工程展开顺序。

| 步骤 | 简要说明 |
|---|---|
| **1. 当前状态** | 明确本次状态迁移从什么状态或阶段开始。 |
| **2. 目标状态 / 目标状态入口** | 明确准备进入什么目标状态，以及需要进行前置判定的目标状态入口。 |
| **3. PCN：相关状态获取 + C / A / E 状态映射** | 获取与本次状态迁移直接相关的多源状态，并按照条件状态、许可状态、执行链状态进行映射。 |
| **4. CAE-SDB 矩阵 + S / D / B 判定** | 将 C / A / E 与 S / D / B 组合为 9 个判定坐标，对当前入口相关状态进行判定，形成 CAE-SDB 结果，并保留时间信息 T。 |
| **5. 控制仲裁** | 处理多个判定结果、关键许可和控制约束之间的优先关系。 |
| **6. 多路径控制** | 输出经控制仲裁确定的多路径控制。 |
| **7. 当前入口控制结果** | 明确本次目标状态入口的控制结果，例如允许进入、暂不进入、禁止进入或转入已确定的后续控制路径。 |
| **8. 选定控制路径与执行结果** | 由相应执行主体执行已确定的控制路径，并记录实际执行结果；如果形成新的目标状态入口，则进入新的前置判定。 |
| **9. 状态迁移判定履历** | 将本次状态、判定、控制和执行结果关联记录为状态迁移判定履历。 |

不同应用可以在九步主链内部加入本领域需要的分析。例如，制造现场协同停滞案例在第 4 步进一步加入群体指标、群体停滞识别和停滞结构分型，但整体工程顺序保持一致。
