## 一句话定义

TPCA 是面向明确状态迁移入口的前置控制架构。

PCN 是部署在目标状态、目标执行路径或目标物理执行阶段进入之前的前置控制节点。PCN 围绕一次明确的状态迁移，组织多源状态信号，进行 C / A / E 状态映射与 S / D / B 判定，形成 CAE-SDB 判定结果，经控制仲裁输出多路径控制，并通过 PCN Trace 记录本次判定与执行履历。

多个 PCN 按实际状态迁移关系连接后，可以进一步形成 PCN 网络。

它关注的核心问题是：

- 为什么不能进入下一状态；
- 问题来自条件、许可还是执行链；
- 问题属于结构缺失、动态异常还是控制边界；
- 多个判定结果同时存在时如何形成最终控制结论；
- 下一步应进入哪一条控制路径；
- 本次判定、控制和执行结果如何记录与追溯。

## 执行摘要

制造现场已经具备 Ready、Interlock、Handshake、报警、状态码、MES 记录和 WCS 日志。

这些机制能够支撑设备运行，也能够记录大量状态。

真正困难的是：

> **当系统不能进入目标状态时，现场仍然需要判断问题来自哪里，以及下一步应进入哪一条控制路径。**

这些具体问题已经在 [工程问题](/zh/questions/) 中展开。

本文关注它们背后的共同结构：

> **一次明确的目标状态迁移，需要被作为独立的工程判定对象。**

![复杂工程系统中的共通状态迁移问题](/images/tpca/01-common-state-transition-problem.png)

图1：多个现场问题往往集中发生在系统准备进入目标状态之前。

TPCA 定义总体前置控制架构。

PCN 设置在明确的状态迁移入口前，接收多源状态信号，完成 C / A / E 状态映射、S / D / B 判定、CAE-SDB 判定结果生成和控制仲裁，再输出对应的多路径控制，并记录 PCN Trace。

因此，TPCA / PCN 不是为了增加更多报警或状态分类，而是把目标状态进入前原本分散的判断组织为：

```text
当前状态
→ 目标状态
→ PCN
→ 多源状态信号
→ C/A/E 状态映射
→ S/D/B 判定
→ CAE-SDB 判定结果
→ 控制仲裁
→ 多路径控制
→ PCN Trace
```

# 第 1 章 工程问题

制造现场通常已经具备多种控制和记录机制。

PLC 有顺序控制、互锁和状态位。

机器人有 Ready、自动模式、报警和动作完成反馈。

视觉系统有 OK / NG、置信度、位置和姿态。

安全系统有安全门、光栅、急停和安全回路。

MES / WCS 有任务、工单、派单、执行状态和日志。

HMI / SCADA 有报警画面、设备状态和趋势记录。

这些机制能够支撑基础运行，但在系统不能进入下一状态时，结果经常被压缩成：

```text
OK / NG
Ready / Not Ready
True / False
允许 / 不允许
报警 / 正常
Waiting / Pending / Blocked
```

这些结果能够阻止错误动作，却不一定能够直接说明：

- 问题来自对象条件、许可状态还是执行链接续；
- 当前状态是结构缺失、动态失效还是进入控制边界；
- Ready 是否只代表本机就绪；
- 任务是否真正具备进入目标执行路径的条件；
- 某个报警是源头问题还是后续结果；
- 下一步应等待、重识别、回流、协调、降级、禁止，还是人工确认。

# 第 2 章 TPCA / PCN 的基本架构

## 2.1 TPCA 的定位

TPCA，Transition Pre-Control Architecture，即状态迁移前置控制架构。

TPCA 面向系统进入目标状态、目标执行路径或目标物理执行阶段之前的前置判定与多路径控制。

目标状态可以是：

- 自动化执行单元的下一物理执行阶段；
- 机器人单元的抓取、放置、回流或异常分流阶段；
- 压装、检测、搬送交接等工艺阶段；
- AGV / AMR 群控系统恢复到可持续协同执行状态；
- MES / WCS 中的目标执行路径；
- 生产 DX 中人员、设备、系统和流程之间的关键状态切换；
- 数字调用系统中的目标执行路径。

TPCA 关注：

- 进入目标状态前，条件是否成立；
- 许可是否成立；
- 进入以后执行链是否能够接续；
- 当前判定结构是否完整；
- 当前状态是否仍然有效；
- 是否进入控制边界；
- 多个判定结果如何形成最终控制路径。

## 2.2 PCN 与 CAE-SDB 的层级关系

PCN，Pre-Control Node，即前置控制节点。

PCN 是 TPCA 的最小工程节点。

它部署在一个明确的状态迁移入口前，围绕本次目标状态进入组织输入、判定、仲裁、控制和履历。

CAE-SDB 是 PCN 内部的结构化判定逻辑。

C / A / E 表示状态变量域：

- C = Condition，条件状态；
- A = Authority，许可状态；
- E = Execution Chain，执行链状态。

S / D / B 表示判定性质：

- S = Structure，结构完整性；
- D = Dynamics，动态时序有效性；
- B = Boundary，控制边界。

因此，当前层级关系为：

```text
TPCA
→ PCN
→ CAE-SDB
→ 控制仲裁
→ 多路径控制
→ PCN Trace
```

TPCA 定义架构。

PCN 承载一次具体状态迁移前置控制。

CAE-SDB 完成结构化判定。

控制仲裁处理多个判定结果和控制约束。

多路径控制形成最终工程输出。

PCN Trace 记录本次状态迁移的判定与执行履历。

## 2.3 基本工程链条

TPCA / PCN 的基本工程链条如下：

```text
当前状态 / 当前阶段
→ 目标状态 / 目标阶段
→ PCN
→ 多源状态信号
→ C/A/E 状态映射
→ S/D/B 判定
→ CAE-SDB 判定结果
→ 控制仲裁
→ 多路径控制
→ PCN Trace
→ 复盘、改善与再部署
```

![TPCA 的基本处理链条](/images/tpca/02-tpca-process-chain.png)

图2：TPCA 从当前状态、目标状态和多源状态出发，经 PCN 完成结构化判定、控制仲裁、多路径控制和判定履历记录。

在这条链中，False、NG、Not Ready、Pending 不再作为终点。

系统继续判断：

- 问题属于哪个变量域；
- 属于哪种判定性质；
- 多个结果之间如何形成最终控制结论；
- 最终进入哪一条控制路径；
- 本次状态迁移如何形成可追溯履历。

# 第 3 章 PCN：状态迁移前置控制的最小工程节点

## 3.1 PCN 的定义

PCN 是部署在明确状态迁移入口之前的前置控制节点。

一个 PCN 对应一个明确的状态迁移入口。

它至少承担以下内容：

- 获取当前状态和目标状态；
- 读取与本次状态迁移相关的多源状态信号；
- 对状态进行必要的标准化整理；
- 完成 C / A / E 状态映射；
- 完成 S / D / B 判定；
- 形成一个或多个 CAE-SDB 判定结果；
- 对多个判定结果进行控制仲裁；
- 输出最终多路径控制；
- 记录 PCN Trace。

PCN 把 TPCA 从总体架构转化为可以被配置、部署、显示、记录和复盘的工程节点。

相关阅读：

[为什么 PCN 是 TPCA 的最小工程节点？](/zh/notes/pcn-minimum-engineering-unit/)

## 3.2 PCN 设置在什么位置

PCN 设置在：

```text
当前状态
→ PCN
→ 目标状态
```

![PCN 前置控制节点的位置与工作方式](/images/tpca/04-pcn-node-position.png)

图3：PCN 位于当前状态与目标状态之间，在进入目标状态之前完成状态组织、结构化判定、控制仲裁和控制路径输出。

在自动化执行单元中，PCN 可以设置在：

- 等待阶段 → 抓取阶段之前；
- 放置完成 → 压装阶段之前；
- 待检测 → 检测执行之前；
- 搬送待机 → 交接阶段之前；
- 正常路径、回流路径、异常分流路径切换之前。

在 MES / WCS 协同系统中，PCN 可以设置在：

- 任务进入执行路径之前；
- 区域放行之前；
- 站点承接之前；
- 主体进入有效执行状态之前；
- 群控系统恢复可持续协同执行状态之前。

在生产 DX 中，PCN 可以设置在人员、设备、系统和流程之间的关键状态切换入口。

PCN 的部署位置由目标状态入口决定，而不是由设备名称决定。

## 3.3 PCN 的基本分析模板

一个 PCN 至少需要明确以下项目。

| 分析项 | 内容 |
|---|---|
| 当前状态 / 当前阶段 | 系统当前处于什么状态 |
| 目标状态 / 目标阶段 | 系统准备进入什么状态 |
| PCN 设置位置 | 前置控制节点位于哪个状态迁移入口 |
| 触发时机 | 什么时候启动本次前置判定 |
| 多源状态信号 | 本次迁移需要读取哪些状态 |
| C 条件状态 | 哪些状态用于判断进入条件 |
| A 许可状态 | 哪些状态用于判断是否允许进入 |
| E 执行链状态 | 哪些状态用于判断进入以后是否能够接续 |
| S 结构判定 | 所需信号、接口、映射、许可来源和执行链边界是否完整 |
| D 动态判定 | 当前状态是否有效、同步、未超时、可信 |
| B 控制边界 | 当前状态是否进入预设控制边界 |
| CAE-SDB 判定结果 | 本次判定形成了哪些结构化结果 |
| 控制仲裁 | 多个结果如何形成最终控制结论 |
| 多路径控制 | 最终进入哪一条控制路径 |
| PCN Trace | 记录本次输入、判定、控制和执行结果 |

不同现场的设备、信号和接口可以不同，但一个 PCN 的基本工程结构保持一致。

PCN 不需要接收所有现场数据。

进入 PCN 的状态，应与本次目标状态进入直接相关，并能够参与 C / A / E 映射、S / D / B 判定或最终控制路径选择。

关于适用对象和工程边界，可参见：

[TPCA / PCN 适用场景分析](/zh/notes/tpca-pcn-applicable-scenarios/)

## 3.4 PCN 节点示例

以机器人由等待阶段进入抓取阶段为例。

当前阶段：机器人等待，主输送带输送工件，视觉系统完成识别。

目标阶段：机器人进入抓取阶段。

PCN 设置位置：抓取动作真正启动之前。

相关状态可以来自视觉系统、机器人控制器、安全系统、输送系统、下游投放位、返回路径、异常分流路径和上位系统。

C 条件状态可以包括：

- 工件是否存在；
- 位置是否合格；
- 姿态是否合格；
- 视觉结果是否有效。

A 许可状态可以包括：

- 安全许可；
- 区域许可；
- 上位生产许可；
- 本次动作许可；
- 必要人工确认。

E 执行链状态可以包括：

- 机器人路径是否可达；
- 夹爪是否可用；
- 正常投放位是否可承接；
- 返回路径是否可用；
- 异常分流路径是否可用；
- 结果是否能够回写。

随后由 S / D / B 对这些状态进行判定，形成 CAE-SDB 判定结果，经控制仲裁后生成最终多路径控制。

## 3.5 多个 PCN 形成 PCN 网络

单个 PCN 对应一个状态迁移入口。

复杂工程系统通常包含多个连续、并行或相互依赖的状态迁移入口。

多个 PCN 按实际状态迁移关系连接以后，可以形成 PCN 网络。

例如，在自动化执行单元中，可以存在：

```text
等待 → 抓取
抓取完成 → 搬送
搬送完成 → 投放
投放完成 → 后续处理
```

每一个关键入口都可以形成独立 PCN。

在 MES / WCS 协同系统中，也可以围绕任务执行、区域进入、站点承接、资源释放、下游接续和结果回写等状态迁移入口形成多个 PCN。

PCN 网络使工程师能够进一步观察：

- 哪些状态迁移入口频繁出现问题；
- 哪些许可长期成为阻断点；
- 哪些执行链反复无法接续；
- 哪些控制路径经常触发；
- 哪些工程修改以后状态迁移表现发生变化。

相关阅读：

[多个 PCN 如何形成状态迁移前置控制网络？](/zh/notes/pcn-network-structure/)

## 3.6 PCN 的部署方式

PCN 不要求一次性重构既有控制系统。

实际部署可以逐步推进。

### 旁路诊断

读取历史日志、准实时状态或导出数据，形成结构化判定和履历，用于验证分析价值。

### 结构化显示

将 PCN 判定结果用于 HMI、MES / WCS 页面、事件报告和复盘记录。

### 建议性控制

根据判定结果和控制仲裁，向工程师或上位系统输出建议控制路径。

### 工程嵌入

在符合安全、控制规范和验证要求的前提下，将部分 PCN 前置判定与控制逻辑嵌入 PLC / HMI、WCS、边缘控制器或软件平台。

不同部署方式可以对应不同项目阶段。

PCN 与既有 PLC、SFC、Interlock、安全系统、MES 和 WCS 形成工程分工，不替代这些成熟机制。

# 第 4 章 C / A / E 状态映射与 S / D / B 判定

## 4.1 C = Condition，条件状态

C 表示进入目标状态前，与目标状态进入相关的事实条件是否成立。

在自动化执行单元中，可以包括：

- 工件是否存在；
- 位置是否合格；
- 姿态是否合格；
- 视觉结果是否有效；
- 识别置信度是否满足；
- 前序动作是否完成；
- 工艺参数是否完整。

在 MES / WCS 协同系统中，可以包括：

- 任务是否存在；
- 任务目标是否明确；
- 物料需求是否有效；
- 目标站点是否定义；
- 缓存区是否可用；
- 订单、工艺和现场条件是否满足。

## 4.2 A = Authority，许可状态

A 表示系统是否允许进入目标状态。

可以包括：

- 安全许可；
- 区域许可；
- 上位系统放行；
- 人工确认；
- 资源锁；
- 任务分配许可；
- 对方设备接收许可；
- 权限或授权状态；
- 调度系统放行；
- 质量或工艺放行。

关键 A 可以构成独立必要约束。

关键许可不成立时，即使 C 和 E 均成立，也不得进入目标状态。

## 4.3 E = Execution Chain，执行链状态

E 表示进入目标状态以后，整个执行链是否能够继续接续。

E 的范围大于单体 Ready。

在自动化执行单元中，可以包括：

- 机器人路径是否可达；
- 夹爪、真空或治具是否可用；
- 下游放置位是否可承接；
- 返回路径是否可用；
- 异常分流路径是否可用；
- 回退路径是否存在；
- 结果上传或回写是否可继续。

在 AGV / AMR 群控系统中，可以包括：

- 主体是否能够执行任务；
- 路径是否可通行；
- 站点是否可承接；
- 共享资源是否可用；
- 能源补给是否影响执行能力；
- 下游是否能够继续承接；
- 结果状态是否能够回写。

E 关注的是目标状态进入以后执行链是否接得住。

## 4.4 S = Structure，结构完整性

S 判断目标状态进入所需要的结构是否已经定义、接入并可观测。

典型内容包括：

- 所需信号；
- 接口；
- 映射关系；
- 许可来源；
- 路径；
- 角色；
- 执行链边界。

例如：

- 视觉结果已经存在，但时间信息没有接入；
- 下游状态存在，但没有纳入目标状态进入判定；
- 资源锁存在，但来源和释放状态不可观测；
- 异常分流路径存在，但没有进入执行链定义。

## 4.5 D = Dynamics，动态时序有效性

D 判断当前状态在本次状态迁移中是否仍然有效。

典型问题包括：

- 超时；
- 未刷新；
- 抖动；
- 冲突；
- 延迟；
- 不同步；
- 低置信度；
- 许可撤销；
- 状态切换。

例如：

- 视觉结果曾经成立，但已经超过有效时间；
- 下游 Ready 长时间未刷新；
- 上位许可在多个周期内反复成立和撤销；
- WCS 显示任务已经派发，但主体状态仍未进入执行。

## 4.6 B = Boundary，控制边界

B 判断 C / A / E 状态处于未完全确定或边界状态时，应进入什么样的控制边界处理。

用于边界判定的工程参数可以包括：

- 时间窗口；
- 重试上限；
- 信号有效时间；
- 识别置信度范围；
- 位置和姿态偏差范围；
- 容量边界；
- 资源占用边界；
- 其他与目标状态进入相关的边界参数。

B 的具体内容由目标状态、风险等级、设备特性、工艺条件和控制策略决定。

## 4.7 状态随时间变化

PCN 的判定对象不是静止不变的。

进入目标状态之前，多源状态会持续刷新。

例如：

| 时间点 | C 条件状态 | A 许可状态 | E 执行链状态 | 说明 |
|---|---|---|---|---|
| t0 | C(t0) | A(t0) | E(t0) | 当前采样 |
| t1 | C(t1) | A(t1) | E(t1) | 状态继续刷新 |
| t2 | C(t2) | A(t2) | E(t2) | 状态可能稳定、撤销、冲突或失效 |
| tn | C(tn) | A(tn) | E(tn) | 进入目标状态前的最终判定依据 |

现场经常出现：

- 视觉结果在 t0 有效，后续已经失效；
- 安全许可在 t0 成立，t1 被撤销；
- 下游 Ready 在 t0 成立，后续长期未刷新；
- 任务存在，但资源锁未释放；
- 主体处于自动模式，但有效执行能力持续下降。

因此，PCN 不只读取当前逻辑值，还需要判断这些状态在本次迁移中的有效性。

## 4.8 CAE-SDB 的组合关系

C / A / E 表示状态变量域。

S / D / B 表示判定性质。

二者组合形成 CAE-SDB 判定结构。

| 判定性质 / 状态变量域 | C 条件 | A 许可 | E 执行链 |
|---|---|---|---|
| S 结构完整性 | 条件状态所需信号、接口和映射是否完整 | 许可来源、接口和关系是否完整 | 下游、回退、异常路径和回写链路是否完整 |
| D 动态时序有效性 | 条件状态是否超时、抖动、冲突、未刷新 | 许可是否延迟、撤销、冲突、未同步 | 执行链是否阻塞、反馈超时、状态未刷新或切换中 |
| B 控制边界 | 条件状态是否进入预设边界 | 许可状态是否进入预设边界 | 执行链状态是否进入预设边界 |

![CAE-SDB 正交判定结构](/images/tpca/03-cae-sdb-matrix.png)

图4：C / A / E 表示状态变量域，S / D / B 表示判定性质，组合后形成 CAE-SDB 判定结果。

CAE-SDB 判定结果不是最终控制动作。

同一次状态迁移可以形成多个判定结果。

这些结果进入控制仲裁以后，再形成最终多路径控制。

# 第 5 章 CAE-SDB 判定结果、控制仲裁与多路径控制

## 5.1 从判定结果到控制路径

PCN 内部形成的控制链为：

```text
CAE-SDB 判定结果
→ 控制仲裁
→ 多路径控制
→ 执行结果
→ PCN Trace
```

CAE-SDB 判定结果说明：

> 问题位于哪个状态变量域，以及属于什么判定性质。

控制仲裁处理：

> 多个判定结果、关键许可和控制约束同时存在时，最终应形成什么控制结论。

多路径控制则把控制结论转化为实际工程路径。

代表性路径包括：

- 允许进入；
- 等待；
- 重识别；
- 重采样；
- 重定位；
- 回流；
- 异常分流；
- 下游协调；
- 资源释放；
- 任务重新分配；
- 降级执行；
- 备用路径；
- 禁止进入；
- 安全锁定；
- 人工确认；
- 异常隔离；
- 增强记录。

## 5.2 CAE-SDB 判定结果

代表性判定结果包括：

| 判定结果 | 含义 |
|---|---|
| C-S | 条件域存在结构完整性问题 |
| C-D | 条件域存在动态时序有效性问题 |
| C-B | 条件域进入控制边界 |
| A-S | 许可域存在结构完整性问题 |
| A-D | 许可域存在动态时序有效性问题 |
| A-B | 许可域进入控制边界 |
| E-S | 执行链域存在结构完整性问题 |
| E-D | 执行链域存在动态时序有效性问题 |
| E-B | 执行链域进入控制边界 |

同一次状态迁移中可以同时存在多个判定结果。

## 5.3 控制仲裁的基本原则

公开白皮书只说明控制仲裁的基本原则。

关键 A 可以构成独立必要约束。

关键许可不成立时，不允许进入目标状态。

关键结构缺失时，不能默认相关状态已经成立。

关键动态状态失效时，不能继续把已经超时、未刷新、冲突或不同步的状态作为放行依据。

当多个 CAE-SDB 判定结果同时存在时，需要经过控制仲裁，再生成最终多路径控制。

只有必要条件、关键许可和执行链接续均满足，并且不存在更高优先级的限制结果时，才允许进入目标状态。

完整仲裁规则、内部运行生命周期、配置结构和具体控制参数不属于本公开白皮书范围。

## 5.4 PCN Trace

PCN 在完成判定和控制的同时，可以形成 PCN Trace。

建议公开层面至少理解以下内容：

| 记录内容 | 作用 |
|---|---|
| 当前状态 / 当前阶段 | 明确系统当时处于什么状态 |
| 目标状态 / 目标阶段 | 明确系统准备进入哪里 |
| 关键输入状态 | 记录与本次迁移直接相关的状态 |
| C / A / E 状态映射 | 记录状态变量域 |
| S / D / B 判定 | 记录判定性质 |
| CAE-SDB 判定结果 | 记录结构化判定结果 |
| 控制仲裁结果 | 记录最终控制结论的形成结果 |
| 多路径控制 | 记录最终控制路径 |
| 执行结果 | 记录控制以后实际发生了什么 |
| Trace ID | 关联同一次状态迁移判定履历 |

PCN Trace 的价值不在于增加更多日志，而在于把一次状态迁移判定作为完整的工程数据对象记录下来。

相关阅读：

[为什么 PCN Trace 是一种新的工程数据？](/zh/notes/why-pcn-trace-is-engineering-data/)

## 5.5 复盘与改善

PCN Trace 可以进一步用于观察：

- 哪些状态迁移入口频繁出现问题；
- 哪些条件状态长期失效；
- 哪些许可经常阻断；
- 哪些执行链经常不能接续；
- 哪些动态问题长期反复；
- 哪些控制边界经常进入；
- 哪些控制路径经常触发；
- 某次工程修改以后，状态迁移表现发生了什么变化。

因此，TPCA / PCN 不只服务于当前一次状态迁移控制，也可以为后续设计改善、设备复用、工程培训、项目交接和生产 DX 提供结构化履历。

AI 可以基于 PCN Trace 进行履历比较、模式分析、候选改善方向整理和报告生成。

AI 不直接绕过 PCN 或既有现场控制逻辑控制设备。

自动化执行单元包括：

- 机器人抓取；
- 压装；

- 搬送交接；
- 视觉识别输送线；

## 6.2 MES / WCS 协同停滞

在 AGV / AMR、多设备协同、WCS、MES、缓存区、站点、共享资源和下游工位之间，单体设备正常并不代表群体能够持续执行。

典型问题包括：

- 任务存在，但主体没有有效执行；
- 多个主体长期处于 Waiting、Blocked、Idle、Pending；
- 主体集中等待共享资源；
- 资源锁未释放；
- 区域许可未成立；
- 下游站点不能承接；
- 能源补给集中导致可执行主体比例下降；
- MES / WCS 有记录，但现场仍需人工跨系统查日志。

群控协同层 PCN 汇总多源状态，进行 C / A / E 映射、S / D / B 判定，并结合群体指标进行停滞识别和结构分析。

- 分配约束；
- 资源竞争；
- 能源偏在；
- 未确定状态；
- 等待；
- 任务重新分配；
- 资源释放；
- 路径或通行权协调；
- 限流；
- 下游协调；
- 人工确认；
- 增强记录。

## 6.3 生产 DX

生产 DX 经常从数据采集、可视化、报表和看板开始。

TPCA / PCN 进一步关注：

> **这些数据如何参与一个明确状态迁移入口的工程判定。**

例如：

- 人工确认完成后是否允许自动恢复；
- 工单切换后是否允许进入目标生产状态；
- 保全解除后是否允许重新投入；
- 质量放行后是否允许进入下一处理路径；
- 多系统状态是否已经形成可接续执行链。

PCN 可以把原本分散在设备、系统、人员和流程中的状态迁移条件显式化，并形成判定、控制和履历。

## 6.4 数字调用治理扩展

TPCA / PCN 也可以扩展到数字调用治理场景。

例如：

- AI 推理调用；
- 工具调用；
- 企业知识库访问；
- API 调用；
- 外部服务调用；
- 智能体调用链；
- 高成本模型调用。

请求已经生成，并不代表目标执行路径已经成立。

仍然需要判断：

- 请求条件是否满足；
- 权限、预算、租户授权或工具调用许可是否成立；
- 模型、工具链、接口服务或队列资源是否可执行；
- 最终应进入高成本路径、澄清路径、降级路径、等待路径还是阻断路径。

这一方向属于 TPCA / PCN 的扩展应用。

制造系统中的主要应用仍然是自动化执行单元前置控制和 MES / WCS 协同停滞诊断。

# 结语

制造系统的问题，不只是设备多、信号多和日志多。

状态迁移入口也越来越多。

TPCA 定义状态迁移前置控制的总体架构。

PCN 设置在明确的目标状态入口之前，把与本次状态迁移相关的多源状态组织为 C / A / E 状态变量，通过 S / D / B 进行判定，形成 CAE-SDB 判定结果，再经过控制仲裁输出最终多路径控制，并通过 PCN Trace 记录本次状态迁移履历。

因此，当前体系的核心关系可以概括为：

```text
TPCA = 状态迁移前置控制架构

PCN = 前置控制节点

CAE-SDB = PCN 内部结构化判定逻辑

控制仲裁 = 多判定结果的控制结论形成过程

多路径控制 = 最终工程输出

PCN Trace = 状态迁移判定履历
```

TPCA / PCN 不替代 PLC、SFC、Interlock、安全系统、MES 或 WCS。

它补充的是：

> **一次明确目标状态进入之前，如何把分散状态组织成可判定、可控制和可追溯的工程结构。**

单个 PCN 可以独立设计、部署和复盘。

多个 PCN 按实际状态迁移关系连接以后，可以进一步形成 PCN 网络。
