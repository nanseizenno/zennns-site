## 装置はすでに Ready なのに、なぜシステムは次へ進まないのか？

製造現場や複雑なオートメーションシステムでは、次のような状況が頻繁に見られる。

- 装置はすでに Ready なのに、動作が開始されない。
- タスクは生成されているのに、実際の実行が始まらない。
- MES / WCS、PLC、ロボット、下流設備にそれぞれ状態情報はあるものの、なぜ停止しているのかを直接説明できない。
- 個々のシステムには明確な異常がないのに、工程全体が先へ進まない。
- 次工程を開始できるかどうかを、結局はエンジニアが複数システムを横断して確認しなければならない。

これらは一見すると別々の問題に見えるが、多くの場合、同じエンジニアリング上の位置で発生している。

> **システムが Current State から、明確な Target State へ入ろうとする直前である。**

本当に確認すべきなのは、次の問いである。

> **今回の Target State Entry は、なぜ許可されるのか。あるいは、なぜまだ許可されないのか。**

## TPCA / PCN の中核命題

> **明確な Target State Entry は、それ自体を独立して設計・判定・制御・記録できるエンジニアリング対象として扱うべきである。**

**TPCA（Transition Pre-Control Architecture）** は、状態遷移前制御アーキテクチャである。  
**PCN（Pre-Control Node）** は、Target State Entry の前に配置される前制御ノードである。

> **TPCA は全体アーキテクチャであり、PCN は個々の状態遷移入口に配置されるエンジニアリングノードである。**

TPCA / PCN は、PLC、ステートマシン、SFC、Interlock、安全制御、MES / WCS などを置き換えるものではない。

複数の既存メカニズムが共同で 1 回の状態遷移を決定する場面において、TPCA / PCN は、同一の Target State Entry を中心に、事前判定・制御出力・判定履歴をどのように構造化するかを定める。
