## 設備はすでに Ready なのに、なぜシステムは次の段階へ進まないのか？

製造現場、自動化実行ユニット、PLC / HMI、ロボットシステム、MES / WCS、AGV / AMR 群制御システム、生産 DX のプロセスでは、表面的には条件が成立しているように見えても、システムが次の状態へ進めないという問題がしばしば発生する。

代表的な場面には、次のようなものがある。

- 設備はすでに Ready だが、システムは次の段階へ進まない；
- PLC の条件は成立しているが、アクチュエータが動作しない；
- 画像認識システムは OK を出力し、ロボットも Ready を示しているが、ロボットがピックアップ動作へ入らない；
- MES / WCS に Waiting、Pending、Blocked と表示されているが、停滞理由を説明できない；
- アラームによって対象設備は特定できても、状態遷移が成立しない理由までは説明できない；
- タスクはすでに生成されているが、目標実行経路が成立していない；
- 複数のシステムに多くの状態が記録されているが、それらを協調判定につなげられない；
- MES、品質、設備、人、下流システムにそれぞれデータが存在していても、現在の生産プロセスが次の段階へ進めるかどうかを最終的に人が確認しなければならない。

これらの問題は、多くの場合、同じ位置で発生する。

**システムが Target State、目標実行経路、または目標物理実行段階へ入る前である。**

本サイトでは、このような状態遷移前のエンジニアリング判定問題を中心に整理している。

## 本サイトが扱う問題

複雑な工学システムが次の状態へ進む前に確認すべきことは、ある設備が Ready であるかどうかだけではない。

さらに、次のような事項を判定する必要がある。

- 条件が成立しているか；
- 許可が成立しているか；
- 実行チェーンが継続可能か；
- 判定構造が完全か；
- 現在状態が有効か；
- 事前に定義された制御境界が発火しているか；
- 複数の判定結果が同時に存在する場合、最終的にどの制御経路を出力すべきか；
- 今回の状態遷移が、なぜ許可、待機、Hold、阻断、または分流されたのか；
- これらの判定結果を追跡可能な状態遷移履歴として残し、後続の振り返りやエンジニアリング改善に利用できるか。

本サイトでは、このような問題を TPCA / PCN 状態遷移前制御体系 として整理している。

内訳は次の通りである。

- **TPCA**：Transition Pre-Control Architecture、状態遷移前制御アーキテクチャ；
- **PCN**：Pre-Control Node、Target State へ入る前に配置する前制御ノード；
- **CAE-SDB**：PCN 内部で、条件・許可・実行チェーンと、構造・動態・境界判定を整理するための構造化判定ロジック；
- **PCN Trace**：1 回の Target State 進入前判定を中心に形成される状態遷移判定履歴。

目的は、従来 PLC プログラム、HMI 画面、ロボットコントローラ、MES / WCS ログ、品質許可、安全許可、人の権限、スケジューリング状態、エンジニアの経験などに分散していた状態遷移判定を、記述・確認・記録・再利用可能なエンジニアリング構造として整理することである。
