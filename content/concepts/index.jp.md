## 中核用語クイックリファレンス

TPCA / PCN 状態遷移前制御体系で使用する主な用語を以下に示す。

| 用語 | 日本語名称 | 基本的な役割 |
|---|---|---|
| TPCA | 状態遷移前制御アーキテクチャ | Target State へ入る前の前置判定と制御を扱う全体アーキテクチャ |
| PCN | 前制御ノード | 個別の状態遷移入口の前に配置する最小のエンジニアリング実装単位 |
| Current State | 現在状態 | システムが現在位置している状態、工程段階、または経路位置 |
| Target State | 目標状態 | システムが次に入ろうとしている状態、目標実行経路、または目標物理実行段階 |
| C | Condition / 条件状態 | Target State へ入るために必要な対象、データ、タスク、パラメータなどの条件が成立しているかを判定する |
| A | Authority / 許可状態 | 安全、権限、資源、上位システム、または人による許可が Target State への移行を認めているかを判定する |
| E | Execution Chain / 実行チェーン状態 | Target State へ入った後に、後続の実行チェーンが継続できるかを判定する |
| S | Structure / 構造完全性 | 必要な信号、インターフェース、マッピング関係、許可元、実行チェーン境界が定義・接続されているかを判定する |
| D | Dynamics / 動的時系列有効性 | 関連状態が現在も有効で、同期・安定しており、タイムアウト、取消、旧バージョン化などが発生していないかを判定する |
| B | Boundary / 制御境界 | 関連状態が事前に定義された制御境界に到達しているかを判定する |
| CAE-SDB | 構造化判定ロジック | C / A / E の状態変数領域と S / D / B の判定性質を組み合わせて分析する |
| CAE-SDB Result | CAE-SDB 判定結果 | 1 回の前置判定で得られた 1 つまたは複数の構造化判定座標とその組合せ結果 |
| Arbitration | 制御優先度調停 | 完全な判定結果と事前定義された制御制約に基づいて最終的な制御方向を決定する |
| Multipath Control | 複数経路制御 | 調停結果を、許可、待機、回流、縮退、禁止、手動確認などの実際の制御経路へ変換する |
| PCN Trace | PCN 状態遷移判定履歴 | 1 回の Target State Entry における入力状態、判定過程、制御出力、実行結果を記録する |
| PCN Runtime | PCN ランタイム | PCN のオンライン判定、調停、制御出力、履歴生成を実行するランタイム部分 |
| PCN Network | PCN ネットワーク | 複数の PCN を状態遷移関係に基づいて接続した前制御構造 |

これらの用語は、次のようなエンジニアリング上の流れでつながっている。

```text
Current State
→ Target State
→ PCN
→ C / A / E Mapping
→ S / D / B Evaluation
→ CAE-SDB Result
→ Arbitration
→ Multipath Control
→ PCN Trace
```

この一連の処理を実際に実行する部分が PCN Runtime であり、複数の PCN を状態遷移入口の関係に沿って接続すると PCN Network になる。

以下、各用語の具体的な意味を順に説明する。

---

## Current State / Target State

Current State は、システムが実行前に現在位置している状態、工程段階、または経路位置を示す。

Target State は、システムが次に入ろうとしている状態、目標実行経路、または目標物理実行段階を示す。

TPCA が扱うのは、この Current State から Target State へ入る前に発生する問題である。

たとえば次のような遷移が該当する。

- 待機段階 → ピックアップ段階；
- 配置完了 → 圧入段階；
- 検査待ち → 検査実行段階；
- タスク存在 → タスク割当経路；
- AGV 到着 → ステーション受入；
- 現在リクエスト → 目標呼出経路。

Target State は、工程上の次の正常段階だけを指すわけではない。　手直しや回流、回退、異常分流、再投入、代替経路など、あらためて進入判定が必要になる状態も Target State として扱える。

---

## 前制御

前制御とは、システムが Target State、目標実行経路、または目標物理実行段階へ入る前に、関連する複数ソース状態を構造化して判定し、その結果に基づいて進入可否と進入すべき実行経路を制御するという考え方である。対象になるのはあくまで Target State へ入る前の問題であり、動作が失敗した後の事後診断や、単純なアラーム分類とは性質が異なる。

前制御で確認する事項は、少なくとも次の通りである。

- 条件が成立しているか；
- 許可が成立しているか；
- 実行チェーンが継続可能か；
- 必要な構造が完全か；
- 現在状態に動的時系列有効性があるか；
- 事前定義された制御境界に入っているか；
- 複数の判定結果が同時に存在する場合、どの結果を優先するか；
- 最終的にどの制御経路を出力するか。

---

## TPCA

英語：Transition Pre-Control Architecture

状態遷移前制御アーキテクチャ。

TPCA は、Target State、目標実行経路、または目標物理実行段階へ入る前の構造化判定と複数経路制御を扱うアーキテクチャであり、
基本的なエンジニアリングチェーンは次のとおりである。

> Current State  
> → Target State  
> → PCN  
> → C / A / E Mapping  
> → S / D / B Evaluation  
> → CAE-SDB Result  
> → Arbitration  
> → Multipath Control  
> → PCN Trace

{{< pcn-animation >}}

TPCA の目的は、新しいアラーム層を積み増すことではない。従来はプログラムや装置、インターフェース、運用判断などに分散していた判定を、Target State へ入る前の段階で明確なエンジニアリング構造として整理し直すことにある。

---

## PCN

英語：Pre-Control Node

前制御ノード。

PCN は、Target State へ入る前に配置される TPCA の最小エンジニアリング実装単位である。1 つの PCN は 1 つの明確な状態遷移入口に対応し、次のような処理を担う。

- Current State と Target State の確認；
- 複数ソース状態の取得と整理；
- C / A / E 状態マッピング；
- S / D / B 判定；
- CAE-SDB Result の生成；
- 制御優先度の Arbitration；
- Multipath Control の出力；
- 状態記録とトレース。

1 つの PCN は、1 つの明確な状態遷移入口に対応する。

自動化実行ユニットでは、PLC ファンクションブロックやエッジコントローラモジュール、あるいはソフトウェア判定ノードとして PCN を実装でき、HMI などの画面に判定結果や制御結果を表示することもできる。

MES / WCS、AGV / AMR 群制御、生産 DX、デジタル呼出ガバナンスといった場面では、タスク割当前、資源許可前、ステーション受入前、協調実行再開前、目標呼出経路への進入前などに PCN を配置できる。

---

## PCN Runtime

英語：PCN Runtime

PCN ランタイム。

PCN Runtime は、PCN が実システム上で前置判定と制御処理を実行する、いわば実行部分である。具体的な Target State Entry が発生すると、対象 PCN について次の処理を担当する。

- 状態取得と整理；
- C / A / E Mapping；
- S / D / B Evaluation；
- CAE-SDB Result の生成；
- Arbitration；
- Multipath Control の出力；
- PCN Trace の生成。

PCN Runtime はあくまで PCN の実行上の役割を示すものであり、特定のソフトウェアや PLC、産業用エッジコントローラ、MES / WCS プラグインなど、実装方式を限定するものではない。システムごとに実装方法は異なっても、PCN が処理する基本的な状態遷移前制御の関係そのものは共通している。

なお、具体的な Runtime アーキテクチャや設定方式、Rule Pack、完全な Arbitration ロジック、制御優先度、主要パラメータ、インターフェース、配置方式などは、本サイトの一般公開範囲には含めていない。

---

## PCN Network

英語：PCN Network

PCN ネットワーク。

PCN Network は、複数の PCN を状態遷移関係に基づいて接続した前制御構造である。単一の PCN が 1 つの Target State Entry に対応するのに対し、複数の PCN は装置ユニットや生産ライン、MES / WCS、AGV / AMR 群制御層、生産 DX システム、デジタル呼出システムなどに分散配置できる。ここで扱うのは状態遷移入口同士の関係であって、装置間の物理的な接続関係そのものではない点に注意したい。

```text
State A
→ PCN-1
→ State B
→ PCN-2
→ State C
```

システムが手直しや回流、異常分流といった別の実行経路へ移る場合も、それぞれに状態遷移入口を設定し、対応する PCN を配置できる。

PCN Network を俯瞰すると、次のような点を確認しやすくなる。

- どの位置に PCN を配置すべきか；
- どの状態遷移入口が頻繁に成立しないか；
- どの重要許可を独立制約として扱うべきか；
- どの実行チェーンが頻繁に継続できないか；
- どの状態遷移条件を明示化すべきか；
- どの PCN Trace を複数ノード横断の振り返りと改善に利用できるか。

---

## 複数ソース状態信号

複数ソース状態信号とは、Target State への進入判定に関わる入力情報全般を指す。信号源には PLC、ロボットコントローラ、画像認識システム、安全システム、HMI / SCADA、MES、WCS、AGV / AMR スケジューラ、現場センサ、上位システム、人による確認、デジタルシステムインターフェースなどが含まれる。

PCN はこれらの信号を取得元でそのまま分類するのではなく、その状態遷移入口において信号がどのようなエンジニアリング上の役割を果たすかに基づいて C / A / E へマッピングする。同じ信号でも、Target State が変われば役割も変わりうる。たとえば同じ品質結果であっても、「次の正常工程へ進む」前では C の条件状態として働く一方、「手直し工程へ進む」前では手直し経路の成立に必要な C 条件として働く、といった具合である。したがって複数ソース状態信号は、Current State と Target State を組み合わせて初めて正しく解釈できる。

また、ある状態が「現在も有効かどうか」を判断できるだけのエンジニアリング情報も必要になる。システムに応じて、タイムスタンプ、更新時刻、状態バージョン、シーケンス情報、ロット番号、オブジェクト ID、イベント ID、更新状態、その他その Target State Entry に関係するトレース情報などを利用できる。

---

## CAE-SDB

CAE-SDB は、PCN の内部で用いる構造化判定ロジックであり、基本構造は次のように表せる。

> {C, A, E} × {S, D, B}

C / A / E が状態変数領域を表し、S / D / B はそれらを評価する際の判定性質を表す。両者を組み合わせると、次の 9 つの判定座標が形成される。

|  | S | D | B |
|---|---|---|---|
| C | C-S | C-D | C-B |
| A | A-S | A-D | A-B |
| E | E-S | E-D | E-B |

1 回の前置判定では、1 つまたは複数の有効な判定座標が得られることがある。これらをまとめたものが CAE-SDB Result であり、複数の結果が同時に存在する場合はさらに Arbitration が必要になる。

> CAE-SDB Result　→ Arbitration → Multipath Control　

CAE-SDB の価値は、静的な 3 × 3 の分類表を作ること自体にあるのではない。false や NG、not ready、waiting、pending、blocked といった、Target State へ入る前に圧縮されがちな状態を、判定・調停・制御・記録が可能なエンジニアリング構造として展開し直せる点にある。

---

## C

英語：Condition（条件状態）

C は、Target State へ入る前に必要となる現場条件、対象条件、認識条件、データ条件、タスク条件、パラメータ条件などが成立しているかを表す。

- ワークが存在する；
- 位置が許容範囲内である；
- 認識結果が有効である；
- タスクが存在する；
- パラメータが揃っている；
- 前工程が完了している；
- 製品またはロット情報が正しい；
- 現在対象と関連結果の対応関係が正しい。

C が確認するのは、

> **この Target State に入るために必要な事実条件が成立しているか。**

という点である。

---

## A

英語：Authority（許可状態）

A は、システムが Target State への進入を許可しているかどうかを表す。

- 安全許可；
- 上位許可；
- エリア許可；
- 人による確認；
- 権限；
- 認可；
- 資源ロック；
- 相手機器の許可。

重要な A は、独立した必要制約として扱うことができる。安全許可や認可、資源ロック、エリア許可などが成立していなければ、C 条件と E 実行チェーンがどれだけ揃っていても Target State への進入は許可されない。A を単なる Condition の一項目として扱うべきではない理由もここにある。

A が確認するのは、

> **条件が揃っていても、システムとして現在この Target State へ入ることが許可されているか。**

という点である。

---

## E

英語：Execution Chain（実行チェーン状態）

E は、Target State へ入った後に実行チェーンが継続できるかを表す。単一装置が Ready であることと同義ではない。実行チェーンには、次のような要素が含まれうる。

- 本体装置；
- エンドエフェクタ；
- 下流受入；
- 正常実行経路；
- 代替経路；
- 回退経路；
- 異常排出経路；
- 結果アップロードまたは書戻し経路；
- 相手機器の受入状態。

たとえばロボットが Ready であることは、局所的な状態の一つにすぎない。ピック後に下流が受け入れ可能か、異常品を排出できるか、回流経路が使えるか、結果を書き戻せるか――こうした項目もすべて E の判定対象になる。

E が確認するのは、

> **Target State へ入った後、後続の実行チェーンが受け止められるか。**

という点である。

---

## S

英語：Structure（構造完全性）

S は、C / A / E の状態変数を評価する際に使う判定性質の一つで、Target State へ入る前に必要な信号、インターフェース、マッピング関係、許可元、経路、役割、実行チェーン境界が、定義・接続され、観測可能になっているかを判定する。

- 必要信号が未定義；
- インターフェースが未接続；
- マッピング関係が未設定；
- 許可元が不明確；
- 実行チェーン境界が欠落；
- 必要状態を観測できない；
- 対象と状態の関連付けが未定義。

S が確認するのは、

> **この状態遷移判定に必要なエンジニアリング構造が成立しているか。**

という点である。

---

## D

英語：Dynamics（動的時系列有効性）

D も S と同じく C / A / E を評価する判定性質の一つで、運転中の関連状態が現在も有効で、同期・安定し、信頼できる状態にあるかを判定する。

- 信号タイムアウト；
- 未更新；
- 状態の期限切れ；
- チャタリング；
- 競合；
- 遅延；
- 非同期；
- バージョン不一致；
- シーケンス関係異常；
- 低信頼度；
- 許可取消；
- 状態切替中。

ここで押さえておきたいのは、

> **状態値が成立していることと、その状態が現在も有効であることは同じではない。**

という点である。たとえば「下流受入可能 = True」という値があっても、それが長時間更新されていなかったり、下流側の状態切替前に生成された古い値だったりする場合、現在値だけを見て E 実行チェーンが有効だと判断することはできない。

D が確認するのは、

> **この状態を、今回の Target State Entry の有効な判定根拠として現在も使用できるか。**

という点である。

---

## B

英語：Boundary（制御境界）

B も同じく判定性質の一つで、C・A・E のいずれかの状態が事前定義された制御境界に到達しているか、また関連する境界条件が発動しているかを判定する。境界判定に用いるエンジニアリングパラメータには、たとえば次のようなものがある。

- 許容範囲；
- 時間ウィンドウ；
- リトライ上限；
- 信頼度範囲；
- 位置偏差範囲；
- 手動確認の有効期限；
- バッファ容量；
- 縮退条件；
- 進入禁止条件；
- その他、Target State への進入に関係する境界条件。

B 自体は最終的な制御経路を決めるものではない。たとえばリトライ上限に達した後、最終出力を待機・回流・手動確認・進入禁止のどれにするかは、完全な CAE-SDB Result をもとに Arbitration を行ったうえで決まる。

B が確認するのは、

> **現在状態が、制御方法を切り替える必要のある境界に到達しているか。**

という点である。

---

## CAE-SDB Result

英語：CAE-SDB Result

CAE-SDB Result は、PCN が Target State へ入る前の C / A / E 状態変数を、S / D / B の判定性質から評価して得られる構造化判定結果である。

たとえば「C-D」は C 条件領域に動的時系列有効性の問題があることを、「E-S」は E 実行チェーン領域に構造完全性の問題があることを示す。1 回の状態遷移前置判定で複数の座標結果が同時に得られることもあり、「C-D + E-D」であれば条件領域と実行チェーン領域の両方に動的時系列有効性の問題があることになる。

CAE-SDB Result が示すのは、

> **どの状態変数領域で問題が発生しており、それがどの判定性質に属するか。**

という点であり、これ自体が最終制御指令になるわけではない。この後、Arbitration が必要になる。

---

## Arbitration

英語：Arbitration（制御優先度調停）

1 つの状態遷移入口で複数の CAE-SDB Result が同時に成立した場合、事前定義された制御制約と優先関係に基づいて最終的な制御方向を決める必要がある。たとえば C 条件に動的異常があると同時に重要な A 許可も成立していない、というケースでは、1 つの判定座標だけを見て最終動作を決めることはできない。

Arbitration の役割は、

> **完全な CAE-SDB Result に基づいて、複数の判定結果間の制御優先関係を処理し、最終的な制御方向を決定すること。**

であり、その結果は Multipath Control へ渡される。なお、本サイトで公開するのは Arbitration の位置付けと基本的な役割までとし、具体的な制御優先度やショートサーキット機構、ルール設定、調停の実装には立ち入らない。

---

## Multipath Control

英語：Multipath Control（複数経路制御）

Multipath Control は、CAE-SDB Result 全体に対して Arbitration を行った後に生成される、最終的なエンジニアリング制御出力である。代表的な制御経路には次のようなものがある。

- 進入許可；
- 待機；
- 再認識；
- 再サンプリング；
- 再位置決め；
- 回流；
- 異常分流；
- 下流調整；
- 資源解放；
- 縮退実行；
- 代替経路；
- 進入禁止；
- 安全ロック；
- 手動確認；
- 異常隔離；
- 強化記録。

正常な実行条件が成立していればシステムは Target State へ進入できるし、そうでなければ待機や再試行、回流、調整、縮退、手動確認、進入禁止など、あらかじめ定義された経路のいずれかが選ばれる。整理すると、

> **CAE-SDB Result は問題の発生領域と性質を示し、Arbitration は制御優先関係を決定し、Multipath Control が最終的なエンジニアリング出力となる。**

という関係になる。

## PCN Trace / 状態遷移判定履歴

英語：PCN Trace

PCN Trace は、1 回の状態遷移前置判定プロセスとその制御結果を構造化して記録する履歴である。単なる装置状態の履歴ではなく、

> **1 回の状態遷移が、なぜ許可、待機、阻止、回流、縮退、分流されたのかを記録する判定履歴**

だといえる。記録される内容には、Current State、Target State、判定に使った複数ソース状態、時刻やバージョン・シーケンス・対象情報、C / A / E Mapping、S / D / B Evaluation、CAE-SDB Result、Arbitration Result、Multipath Control、実行結果、Trace ID などが含まれる。

PCN Trace は現場振り返りや問題追跡、状態遷移設計レビュー、プロジェクト引継ぎ、長期履歴比較、エンジニアリング改善といった用途に使える。製品化する場合は、MES / WCS、HMI、SCADA、後続のデータ分析モジュールなどに向けた構造化データソースとしても利用できるだろう。

PCN Trace が目指すのは、単純にログ項目を増やすことではない。

```text
どの Target State へ入ろうとしていたか
→ その時点でどの状態を根拠にしたか
→ なぜその判定になったか
→ 最終的にどの制御経路を選択したか
→ 実際に状態遷移が完了したか
```

という一連の流れを、1 回の状態遷移判定履歴としてまとめることにある。なお、具体的な PCN Trace のデータ構造は、本サイトの一般公開範囲には含めていない。

## 中核用語の関係

TPCA / PCN の中核用語の関係は次のように整理できる。

```text
TPCA
│
├─ PCN
│   │
│   ├─ PCN Runtime
│   │   │
│   │   ├─ C / A / E Mapping
│   │   ├─ S / D / B Evaluation
│   │   ├─ CAE-SDB Result
│   │   ├─ Arbitration
│   │   ├─ Multipath Control
│   │   └─ PCN Trace
│   │
│   └─ 1 つの明確な Target State Entry に対応
│
└─ 複数の PCN
    ↓
   PCN Network
```

それぞれの位置付けをあらためて整理すると、TPCA が全体アーキテクチャ、PCN が個別の状態遷移入口に配置するエンジニアリングノード、PCN Runtime が PCN をオンラインで動かす実行部分にあたる。C / A / E は状態変数領域、S / D / B はそれを評価する判定性質であり、両者から得られるのが CAE-SDB Result である。複数の結果が競合すれば Arbitration によって優先順位が決まり、最終的な出力として Multipath Control が実行される。この一連のプロセスは PCN Trace として記録され、複数の PCN をつなげたものが PCN Network となる。
