本ページでは、TPCA / PCN 状態遷移前制御体系で使用する中核用語を整理する。

これらの用語は、公開説明、適用事例、協業時の説明、今後の技術文書における共通用語として使用する。

TPCA / PCN の中核となる考え方は、次の通りである。

> **明確な Target State Entry は、それ自体を独立して設計・判定・制御・記録できるエンジニアリング対象として扱うべきである。**

TPCA / PCN と既存の産業オートメーション方法や制御メカニズムとの関係については、以下を参照。

[TPCA / CAE-SDB と既存の産業オートメーション理論との関係](/ja/notes/tpca-existing-theories/)

## 中核用語クイックリファレンス

| 用語 | 日本語名称 | 基本的な役割 |
|---|---|---|
| TPCA | 状態遷移前制御アーキテクチャ | 明確な Target State Entry を対象とする全体的な前置判定・制御アーキテクチャ |
| PCN | 前制御ノード | 個別の Target State Entry の前に配置するエンジニアリングノード |
| Current State | 現在状態 | システムが現在位置している状態、工程段階、または経路位置 |
| Target State | 目標状態 | システムが次に入ろうとしている状態、目標実行経路、または目標物理実行段階 |
| Target State Entry | 目標状態入口 | Current State から Target State へ入る際に前置判定を行うエンジニアリング上の位置 |
| C | Condition / 条件状態 | Target State へ入るために必要な対象、データ、タスク、パラメータなどの事実条件が成立しているかを判定する |
| A | Authority / 許可状態 | 安全、権限、資源、上位システム、または人による許可が Target State への進入を認めているかを判定する |
| E | Execution Chain / 実行チェーン状態 | Target State へ入った後に、後続の実行チェーンが継続できるかを判定する |
| S | Structure / 構造完全性 | 必要な信号、インターフェース、マッピング関係、許可元、経路、役割、実行チェーン境界が定義・接続され、観測可能であるかを判定する |
| D | Dynamics / 動的時系列有効性 | 関連状態が現在も有効で、同期・安定し、タイムアウト、取消、競合などが発生していないかを判定する |
| B | Boundary / 制御境界 | 関連状態が事前に定義された制御境界に到達しているかを判定する |
| CAE-SDB | 構造化判定ロジック | C / A / E の状態変数領域と S / D / B の判定性質を組み合わせて分析する |
| CAE-SDB Result | CAE-SDB 判定結果 | 1 回の前置判定によって形成される 1 つまたは複数の構造化判定結果 |
| T | 時間情報 | 状態および判定とともに保持する時間情報。状態の前後関係、動的判定、PCN Trace に使用する |
| Arbitration | 制御優先度調停 | 完全な判定結果と事前定義された制御制約に基づき、制御上の優先関係を決定する |
| Multipath Control | 複数経路制御 | Arbitration の結果に基づいて、次の Target State または目標実行経路を決定する |
| PCN Trace | PCN 状態遷移判定履歴 | 1 回の Target State Entry における入力、判定、時間情報、制御出力、実行結果を記録する |
| PCN Runtime | PCN ランタイム | PCN のオンライン判定、Arbitration、制御出力、履歴生成を実行するランタイム部分 |
| PCN Network | PCN ネットワーク | 複数の PCN を実際の状態遷移関係および必要な依存関係に基づいて接続した前制御構造 |

TPCA / PCN の基本的なエンジニアリング関係は、次のように表せる。

```text
Current State
→ Target State
→ PCN
→ C / A / E Mapping
→ S / D / B Evaluation
→ CAE-SDB Result + T
→ Arbitration
→ Multipath Control
→ PCN Trace
````

この一連の処理を実際に実行する部分が PCN Runtime である。

複数の PCN を、それぞれの Target State Entry と実際の状態遷移関係に沿って接続すると、PCN Network が形成される。

## Current State、Target State、Target State Entry

**Current State（現在状態）** は、状態遷移前にシステムが現在位置している状態、工程段階、または経路位置を示す。

**Target State（目標状態）** は、システムが次に入ろうとしている状態、目標実行経路、または目標物理実行段階を示す。

**Target State Entry（目標状態入口）** は、システムが Current State から Target State へ入ろうとする際に、前置判定を行うエンジニアリング上の位置である。

TPCA / PCN が対象とする問題は、Target State へ実際に入る前に発生する。

たとえば次のような遷移が該当する。

* 待機段階 → ピックアップ段階；
* 配置完了 → 圧入段階；
* 検査待ち → 検査実行段階；
* タスク存在 → タスク実行；
* AGV 到着 → ステーション受入；
* 現在リクエスト → 目標呼出経路。

Target State は、工程上の次の正常段階だけを意味するものではない。

手直し、回流、回退、異常分流、再投入、代替経路など、あらためて進入判定が必要になる状態も Target State として扱うことができる。

TPCA の実行上の視点では、これらはすべて次のように表される。

```text
Current State
→ New Target State
```

新しい Target State が過去の状態と同一または類似したエンジニアリング内容を持っていたとしても、それは新しい状態インスタンスである。

Current State、Target State、Target State Entry が明確でなければ、PCN は安定したエンジニアリング対象を持つことができない。

## 前制御

前制御とは、システムが Target State、目標実行経路、または目標物理実行段階へ入る前に、関連する複数ソース状態を構造化して判定し、その完全な判定結果に基づいて、進入可否と進入すべき経路を決定する考え方である。

対象になるのは Target State へ入る前のエンジニアリング判断であり、動作失敗後の事後診断や、単純なアラーム分類とは異なる。

前制御では、少なくとも次の事項を扱う。

* 条件が成立しているか；
* 許可が成立しているか；
* 実行チェーンが継続可能か；
* 判定に必要な構造が完全か；
* 現在状態に動的時系列有効性があるか；
* 事前定義された制御境界に入っているか；
* 複数の判定結果が同時に存在する場合、どのように制御上の優先関係を処理するか；
* 最終的にどの Target State または目標実行経路へ進むか。

## TPCA

英語：Transition Pre-Control Architecture

日本語：状態遷移前制御アーキテクチャ。

TPCA は、明確な Target State Entry を中心として構築する全体的な前制御アーキテクチャである。

従来、装置、制御プログラム、MES / WCS、安全システム、人による確認、その他のエンジニアリングインターフェースに分散していた関連状態を、判定・制御・記録が可能な状態遷移前制御構造として整理する。

基本的なエンジニアリングチェーンは次の通りである。

```text
Current State
→ Target State
→ PCN
→ C / A / E Mapping
→ S / D / B Evaluation
→ CAE-SDB Result + T
→ Arbitration
→ Multipath Control
→ PCN Trace
```

{{< pcn-animation >}}

TPCA は、PLC、ステートマシン、SFC、Interlock、安全制御、MES / WCS などを置き換えるものではない。

TPCA が扱うのは、複数の既存メカニズムが同じ状態遷移を共同で決定している場合に、それらを同一の Target State Entry を中心として、明確な前置判定、制御出力、判定履歴として構造化することである。

TPCA では、状態と判定に関する時間情報も保持する。

実システムにおける状態遷移は常に時間方向へ進む。

後続状態が過去の状態と同じエンジニアリング内容を持っていたとしても、それは新しい状態インスタンスである。

## PCN

英語：Pre-Control Node

日本語：前制御ノード。

PCN は、明確な Target State Entry の前に配置される、TPCA の具体的な状態遷移入口におけるエンジニアリングノードである。

1 つの PCN は 1 つの明確な Target State Entry に対応し、その入口を中心として次の処理を行う。

* Current State と Target State の確認；
* 複数ソース状態の取得と整理；
* C / A / E 状態マッピング；
* S / D / B 判定；
* CAE-SDB Result の生成；
* 時間情報 T の保持；
* Arbitration；
* Multipath Control の出力；
* PCN Trace の生成。

PCN の具体的な実装形式は固定されない。

自動化実行ユニットでは、PLC ファンクションブロック、エッジコントローラモジュール、ソフトウェア判定ノードなどとして実装できる。

MES / WCS、AGV / AMR 群制御、生産 DX、デジタルシステムなどでは、タスク実行、資源許可、ステーション受入、状態復帰、目標呼出経路などの Target State Entry の前に配置することができる。

---

## PCN Runtime

英語：PCN Runtime

日本語：PCN ランタイム。

PCN Runtime は、PCN が実システム上でオンライン状態処理、判定、制御出力、履歴生成を実行するランタイム部分である。

具体的な Target State Entry が発生した場合、PCN Runtime は対象 PCN に対して次の処理を行う。

* 状態取得と整理；
* C / A / E Mapping；
* S / D / B Evaluation；
* CAE-SDB Result の生成；
* 時間情報の記録；
* Arbitration；
* Multipath Control の出力；
* PCN Trace の生成。

PCN Runtime は PCN の実行上の役割を表すものであり、特定のソフトウェア、PLC、産業用エッジコントローラ、MES / WCS プラグイン、その他のプラットフォーム実装を限定するものではない。

具体的な Runtime アーキテクチャ、設定方式、Rule Pack、完全な Arbitration、制御優先度、主要パラメータ、インターフェース、配置方式などは、本サイトの一般公開範囲には含めていない。

---

## PCN Network

英語：PCN Network

日本語：PCN ネットワーク。

PCN Network は、複数の PCN を、実際の状態遷移関係および必要な許可・資源・実行依存関係に基づいて接続した前制御構造である。

単一の PCN が 1 つの明確な Target State Entry に対応するのに対し、複数の PCN は装置ユニット、生産ライン、MES / WCS、AGV / AMR 群制御層、生産 DX システム、デジタルシステムなどに分散配置することができる。

PCN Network が扱うのは、Target State Entry 同士のエンジニアリング上の関係であり、装置間の物理的な接続関係そのものではない。

たとえば、

```text
State A
→ PCN-1
→ State B
→ PCN-2
→ State C
```

という関係を持つことができる。

システムが手直し、回流、異常分流、再投入、その他の実行経路へ進む場合も、新しい Target State Entry とそれに対応する PCN を設定することができる。

PCN Network の状態タイプ上の関係は循環を形成することがある。

しかし、実際の運転で生成される状態インスタンスは、常に時間方向へ進み続ける。

PCN Network では、複数の Target State Entry 間に存在する次のような関係を確認できる。

* 状態進行；
* 許可依存；
* 資源依存；
* 実行チェーンの接続；
* 状態書戻し；
* 判定履歴間の関係。

## 複数ソース状態信号

複数ソース状態信号とは、1 回の Target State Entry に関係する入力情報を指す。

信号源には、次のようなものが含まれる。

* PLC；
* ロボットコントローラ；
* 画像認識システム；
* 安全システム；
* HMI / SCADA；
* MES；
* WCS；
* AGV / AMR スケジューリングシステム；
* 現場センサ；
* 上位システム；
* 人による確認；
* デジタルシステムインターフェース。

PCN は、信号を取得元によって直接分類するのではない。

具体的な Target State Entry において、その状態がどのようなエンジニアリング上の役割を持つかに基づいて C / A / E へマッピングする。

同じ状態でも、Target State Entry が変われば異なる役割を持つ場合がある。

したがって、複数ソース状態は Current State、Target State、Target State Entry と組み合わせて理解する必要がある。

システムに応じて、状態情報には次のような情報を含めることもできる。

* タイムスタンプ；
* 更新時刻；
* 状態バージョン；
* シーケンス情報；
* ロット番号；
* オブジェクト ID；
* イベント ID；
* その他、本状態遷移に関係するトレース情報。

## CAE-SDB

CAE-SDB は、PCN 内部で使用する構造化判定ロジックである。

基本構造は次のように表せる。

```text
{C, A, E} × {S, D, B}
```

ここで、

* C / A / E は状態変数領域；
* S / D / B は、それらの状態変数を分析する際に使用する判定性質；

を表す。

両者を組み合わせると、9 つの判定座標が形成される。

|   | S   | D   | B   |
| - | --- | --- | --- |
| C | C-S | C-D | C-B |
| A | A-S | A-D | A-B |
| E | E-S | E-D | E-B |

1 回の前置判定では、1 つまたは複数の CAE-SDB Result が形成される場合がある。

各判定では、対応する時間情報 T も同時に保持する。

複数の判定結果が同時に存在する場合は、さらに次の処理へ進む。

```text
CAE-SDB Result + T　→ Arbitration　→ Multipath Control
```

CAE-SDB の目的は、静的な 3 × 3 の分類表を作ることではない。

Target State へ入る前に false、NG、not ready、waiting、pending、blocked などとして圧縮されがちな状態を、状態変数領域と判定性質を持つ構造化されたエンジニアリング結果として展開することにある。

## C：Condition

日本語：条件状態。

C は、Target State へ入る前に、本状態遷移に必要な事実条件が成立しているかを表す。

代表的な内容には、次のようなものがある。

* ワークが存在する；
* 位置が要求条件を満たしている；
* 認識結果が有効である；
* タスクが存在する；
* パラメータが揃っている；
* 前工程が完了している；
* 製品またはロット情報が正しい；
* 対象と関連結果が正しく対応している。

C が確認するのは、

> **この Target State に入るために必要な事実条件が成立しているか。**

という点である。

---

## A：Authority

日本語：許可状態。

A は、システムとして Target State への進入が許可されているかを表す。

代表的な内容には、次のようなものがある。

* 安全許可；
* 上位許可；
* エリア許可；
* 人による確認；
* 権限または認可；
* 資源ロック；
* 相手機器の許可。

重要な A は、独立した必要制約となる。

安全許可、認可、資源ロック、エリア許可などの重要な許可が成立していない場合、C と E がともに成立していても Target State へ進入してはならない。

A が確認するのは、

> **条件が揃っていても、システムとして現在この Target State へ入ることが許可されているか。**

という点である。

---

## E：Execution Chain

日本語：実行チェーン状態。

E は、Target State へ入った後に、後続の実行チェーンが継続できるかを表す。

E は、単一装置の Ready と同義ではない。

実行チェーンには、次のような要素が含まれる。

* 本体装置；
* エンドエフェクタ；
* 下流受入；
* 正常実行経路；
* 代替経路；
* 回流経路；
* 回退経路；
* 異常排出経路；
* 結果アップロードまたは書戻し経路；
* 相手機器の受入状態。

たとえば、ロボットが Ready であることは、ロボット本体が局所的に運転可能な状態であることを示すにすぎない。

ピック後に下流が受け入れ可能か、異常品を排出できるか、回流経路が使用可能か、結果を書き戻せるかといった事項も、E の判定対象になる。

E が確認するのは、

> **Target State へ入った後、後続の実行チェーンが継続できるか。**

という点である。

---

## S：Structure

日本語：構造完全性。

S は、C / A / E の状態変数を分析する際に使用する判定性質である。

S は、Target State へ入るために必要な信号、インターフェース、マッピング関係、許可元、経路、役割、実行チェーン境界が、定義・接続され、観測可能になっているかを判定する。

代表的な問題には、次のようなものがある。

* 必要信号が未定義；
* インターフェースが未接続；
* マッピング関係が未設定；
* 許可元が不明確；
* 実行チェーン境界が欠落；
* 必要状態を観測できない；
* 対象と状態の関連付けが未定義。

S が確認するのは、

> **この状態遷移判定に必要なエンジニアリング構造が完全であるか。**

という点である。

---

## D：Dynamics

日本語：動的時系列有効性。

D は、C / A / E の状態変数を分析する際に使用する判定性質である。

D は、運転中の関連状態が現在も有効で、同期・安定し、信頼できる状態にあるかを判定する。

代表的な問題には、次のようなものがある。

* 信号タイムアウト；
* 未更新；
* 状態の期限切れ；
* チャタリング；
* 競合；
* 遅延；
* 非同期；
* バージョン不一致；
* シーケンス関係異常；
* 低信頼度；
* 許可取消；
* 状態切替中。

重要なのは、

> **状態値が成立していることと、その状態が現在も有効であることは同じではない。**

という点である。

たとえば、

```text
下流受入可能 = TRUE
```

という値が存在していても、その状態が長時間更新されていなかったり、下流側の状態切替前に生成された値であったりする場合、現在値だけを見て E 実行チェーンが現在も有効であると判断することはできない。

D の判定には、タイムスタンプ、更新時刻、シーケンス、バージョン、対象との関連情報などを利用することができる。

D が確認するのは、

> **この状態を、今回の Target State Entry に対する有効な判定根拠として現在も使用できるか。**

という点である。

---

## B：Boundary

日本語：制御境界。

B は、C / A / E の状態変数を分析する際に使用する判定性質である。

B は、関連状態が事前に定義された制御境界に到達しているかを判定する。

境界判定に使用するエンジニアリングパラメータには、たとえば次のようなものがある。

* 許容範囲；
* 時間ウィンドウ；
* リトライ上限；
* 信頼度範囲；
* 位置偏差範囲；
* 手動確認の有効期限；
* バッファ容量；
* 縮退条件；
* 進入禁止条件；
* その他、Target State への進入に関係する境界条件。

B 自体は、最終的な制御経路ではない。

ある境界に到達した後、待機、回流、手動確認、進入禁止、その他のどの経路を選択するかは、完全な CAE-SDB Result に基づいて Arbitration を行った後に決定される。

B が確認するのは、

> **現在状態が、制御方法を変更する必要のある事前定義された境界に到達しているか。**

という点である。

---

## CAE-SDB Result

日本語：CAE-SDB 判定結果。

CAE-SDB Result は、PCN が C / A / E の状態変数に対して S / D / B の判定を行った結果として形成される構造化判定結果である。

たとえば、

```text
C-D
```

は、C 条件領域に動的時系列有効性の問題が存在することを示す。

```text
E-S
```

は、E 実行チェーン領域に構造完全性の問題が存在することを示す。

1 回の状態遷移前置判定で、複数の結果が同時に形成されることもある。

たとえば、

```text
C-D + E-D
```

であれば、条件領域と実行チェーン領域の両方に動的時系列有効性の問題が存在することを意味する。

CAE-SDB Result が示すのは、

> **どの状態変数領域で問題が発生し、それがどの判定性質に属するか。**

という点である。

各判定では、対応する時間情報 T も同時に保持する。

CAE-SDB Result 自体は最終的な制御指令ではなく、この後に Arbitration が必要になる。

---

## 時間情報 T

T は、状態および CAE-SDB Result とともに保持する時間情報を表す。

システムに応じて、次のような情報を利用することができる。

* Timestamp；
* 更新時刻；
* イベント時刻；
* シーケンス時刻；
* ロット時刻；
* その他、状態の前後関係を特定できる時間情報。

T は主に次の目的で使用する。

* 状態および判定が発生した時間位置を特定する；
* 複数状態間の前後関係を判定する；
* 動的時系列有効性の判定を支援する；
* PCN Trace を形成する。

TPCA の実行上の視点では、後続状態が過去の状態と同じエンジニアリング内容を持っていたとしても、発生時間が異なれば、それは異なる状態インスタンスである。

---

## Arbitration

英語：Arbitration

日本語：制御優先度調停。

Arbitration は、1 つまたは複数の CAE-SDB Result、重要な許可、制御制約の間にある優先関係を処理し、最終的な制御方向を決定する。

1 つの Target State Entry において複数の判定結果が同時に存在する場合、1 つの判定座標だけから最終的な動作を直接決定することはできない。

Arbitration の位置は次の通りである。

```text
CAE-SDB Result + T　→ Arbitration　→ Multipath Control
```

本サイトで公開するのは、Arbitration のエンジニアリング上の位置と基本的な役割までとする。

具体的な制御優先度、ショートサーキット機構、ルール設定、調停ロジックの実装などは、一般公開範囲には含めていない。

---

## Multipath Control

英語：Multipath Control

日本語：複数経路制御。

Multipath Control は、完全な CAE-SDB Result に対して Arbitration を行った後に形成される最終的なエンジニアリング制御出力である。

代表的な制御経路には、次のようなものがある。

* 進入許可；
* 待機；
* 再認識；
* 再サンプリング；
* 再位置決め；
* 回流；
* 戻り；
* 回退；
* 異常分流；
* 下流調整；
* 資源解放；
* 縮退実行；
* 代替経路；
* 進入禁止；
* 安全ロック；
* 手動確認；
* 異常隔離；
* 強化記録。

これらは、それぞれ異なるエンジニアリング処理経路を表す。

TPCA の状態遷移視点から見ると、最終的には、

> **Current State の次に、どの Target State または目標実行経路へ進むべきか。**

を決定している。

したがって、

> **CAE-SDB Result は構造化判定結果を示し、Arbitration は制御上の優先関係を処理し、Multipath Control が次の Target State または目標実行経路を形成する。**

という関係になる。

---

## PCN Trace

日本語：PCN 状態遷移判定履歴。

PCN Trace は、1 回の状態遷移前置判定と、その制御結果を構造化して記録する履歴である。

単なる装置状態の履歴ではなく、

> **1 回の状態遷移が、なぜ許可、待機、阻止、回流、縮退、分流されたのかを記録する判定履歴**

である。

代表的な記録内容には、次のようなものがある。

* Current State；
* Target State；
* 本判定に使用した複数ソース状態；
* 時間情報 T；
* 状態に関係するバージョン、シーケンス、対象情報；
* C / A / E Mapping；
* S / D / B Evaluation；
* CAE-SDB Result；
* Arbitration Result；
* Multipath Control；
* 実行結果；
* Trace ID。

PCN Trace は、現場振り返り、問題追跡、状態遷移設計レビュー、プロジェクト引継ぎ、長期履歴比較、エンジニアリング改善などに利用することができる。

PCN Trace の目的は、単純にログ項目を増やすことではない。

```text
どの Target State へ入ろうとしていたか
→ その時点でどの状態を根拠にしたか
→ なぜその判定になったか
→ 最終的にどの制御結果が形成されたか
→ 実際にどの状態または経路へ進んだか
```

という一連の流れを、1 回の状態遷移判定履歴として構造化することにある。

時間情報を保持することで、PCN Trace は、同じ状態内容であっても異なる時間位置で発生した状態インスタンスを区別することができる。

具体的な PCN Trace のデータ構造は、本サイトの一般公開範囲には含めていない。

## 中核用語の関係

TPCA / PCN の中核用語の関係は、次のように整理できる。

```text
TPCA
│
├─ PCN
│   │
│   ├─ PCN Runtime
│   │   │
│   │   ├─ C / A / E Mapping
│   │   ├─ S / D / B Evaluation
│   │   ├─ CAE-SDB Result + T
│   │   ├─ Arbitration
│   │   ├─ Multipath Control
│   │   └─ PCN Trace
│   │
│   └─ 1 つの明確な Target State Entry に対応
│
└─ 複数の PCN
    ↓
    PCN Network
```

それぞれの位置付けは、次の通りである。

* **TPCA**：全体アーキテクチャ；
* **PCN**：個別の Target State Entry に配置するエンジニアリングノード；
* **PCN Runtime**：PCN のオンライン前置判定と制御を実行するランタイム部分；
* **C / A / E**：状態変数領域；
* **S / D / B**：判定性質；
* **CAE-SDB Result**：構造化判定結果；
* **T**：状態および判定とともに保持する時間情報；
* **Arbitration**：制御優先度調停；
* **Multipath Control**：次の Target State または目標実行経路；
* **PCN Trace**：1 回の状態遷移判定履歴；
* **PCN Network**：複数の PCN によって形成される状態遷移前制御ネットワーク。
