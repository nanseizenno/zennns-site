本页用于说明 TPCA / PCN 相关技术交流、PoC 和初步合作方向。

合作不需要从完整系统开发开始。

更适合的方式是：

> **先选择一个明确的状态迁移入口，把问题范围、PCN 位置、必要状态和 PoC 输出定义清楚，再判断是否进入下一阶段。**

---

## 1. 主要合作入口

### 自动化执行单元前置判定

适合自动化系统集成商、机器人工作站厂商、PLC / HMI 相关企业和制造企业生产技术部门。

典型问题包括：

- 设备 Ready，但不能进入下一阶段；
- PLC 中存在大量 Ready / Interlock / Handshake，现场仍需要查程序定位原因；
- 机器人、视觉、安全和下游状态相互关联，异常处理高度依赖工程师经验。

初步合作可围绕：

- Current State / Target State；
- PCN 候选位置；
- 代表性多源状态；
- C / A / E 映射；
- S / D / B 判定范围；
- 多路径控制和 HMI / Web 展示范围。

相关案例：[自动化执行单元前置判定案例](/zh/cases/automation-execution-unit-pre-control/)

---

### MES / WCS 协同停滞诊断

适合 MES / WCS 企业、AGV / AMR 系统商、制造业 DX 方案商及存在多设备协同停滞问题的制造企业。

典型问题包括：

- 任务存在，但群体有效执行比例下降；
- 系统显示 Waiting、Pending、Blocked，却不能解释为什么停；
- 单体设备没有明显故障，但整体吞吐下降；
- 停滞原因仍依赖人工查多个系统日志。

初步合作可围绕：

- 最小可观测状态；
- 群体停滞事件识别；
- 代表性群体指标；
- 基础结构分型；
- MES / WCS 页面、事件报告和增强记录范围。

相关案例：[MES / WCS 协同停滞诊断模块案例](/zh/cases/collaborative-stagnation-diagnosis/)

---

### 生产 DX 状态迁移条件设计

适合制造企业 DX、生产技术、质量、设备、保全部门，以及 MES / QMS / 制造数据平台相关企业。

典型问题包括：

- MES、质量、设备和人员系统都有数据，但下一阶段是否可以开始仍依赖人工确认；
- 质量放行、保全解除、工单切换后的状态迁移条件没有统一表达；
- Waiting、Hold、Manual Confirm 反复发生，却缺少可复盘的状态迁移履历。

初步合作可围绕：

- Current State / Target State；
- 跨系统 PCN 位置；
- C / A / E 状态迁移条件；
- S / D / B 判定范围；
- 多路径输出；
- PCN Trace 与后续履历分析。

相关案例：[生产 DX 状态迁移条件设计与履历分析案例](/zh/cases/production-dx-state-transition/)

---

### 其他扩展方向

也可讨论生成式 AI、工具调用、企业知识库访问和 API 调用等数字请求的前置控制问题。

该方向主要关注请求进入目标执行路径之前的条件、授权、执行链状态及多路径分流。

## 2. 初次沟通

首次联系时，不需要提供完整程序、数据库、接口资料或企业机密。

建议简要说明：

- 所属行业或系统对象；
- 当前最希望解决的问题；
- 当前状态和目标状态（如果已经能够明确）；
- 涉及哪些设备、系统或角色；
- 希望讨论技术交流、PoC、产品合作还是其他方式。

首轮沟通主要判断：

> **这个问题是否适合使用 TPCA / PCN，以及是否值得进一步做 PoC。**

如果现有系统已经能够很好地解决，也没有必要为了使用方法而强行导入。

## 3. 合作与公开边界

本站公开内容主要用于说明工程问题、总体架构、基本概念、公开案例和应用方向。

以下内容不属于网站公开范围：

- PCN Runtime；
- Config / Rule Pack；
- 完整 Arbitration 规则；
- 控制优先级和具体参数；
- Trace 详细结构；
- 接口与部署实现；
- 未公开实施方案。

如合作需要进入上述内容，可根据项目阶段和资料范围另行确认保密要求，并在必要时签署 NDA。

涉及专利授权、权利归属、许可模式等法律事项，应以专利代理人或律师意见为准。
