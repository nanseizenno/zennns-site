# 关于作者

**全野南政 / Nansei Zenno**

长期从事制造现场自动化、生产技术、PLC / HMI、电气控制、生产数据采集、IoT 和制造系统改善相关工作。

工程经历涉及工业控制器开发、电气设计、自动化生产线建设、生产系统导入、多设备协同、新工厂建设、海外制造现场及生产 DX 项目，并长期参与设备控制、系统联动、状态记录和现场改善。

这些工程实践中反复遇到一类问题：

> **设备、任务、许可和运行状态都已经存在，但系统为什么仍然不能进入下一状态，往往需要工程师跨程序、设备和系统重新确认。**

TPCA / PCN 是在持续整理这类工程问题的过程中逐步形成的。

## 问题来源

在制造现场中，经常可以观察到：

- 设备已经 Ready，动作仍未开始；
- 系统长期停留在 Waiting、Pending 或 Blocked；
- 单体设备没有明显故障，整体流程仍持续停滞；
- MES / WCS 已经保存任务和状态，停滞原因仍需要跨系统确认；
- 质量、许可、设备、人员和下游状态分别存在，但下一阶段是否可以进入仍缺少统一判断。

这些现象虽然出现在不同系统中，但都涉及同一个工程位置：

> **系统从当前状态准备进入一个明确目标状态之前。**

需要明确的是本次目标状态入口使用哪些状态进行判定、为什么允许或暂不允许进入，以及随后形成什么控制结果和判定履历。

TPCA / PCN 围绕这一工程对象展开。

## 当前方向

当前主要围绕状态迁移前置控制在制造系统中的工程应用进行整理和验证。

公开方向包括：

- **自动化执行单元**：机器人、检测、压装、搬送交接等物理执行阶段进入前的判定与多路径控制；
- **MES / WCS 协同停滞**：多设备、AGV / AMR 和制造现场协同过程中的停滞识别、结构分析与控制处理；
- **制造 DX 状态迁移**：MES、质量、设备、人员、保全和下游系统之间的目标状态入口设计与 PCN Trace；
- **工程方法与数据**：状态迁移判定结构、运行履历、PCN Network 及长期工程分析。
