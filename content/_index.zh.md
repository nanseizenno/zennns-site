## 装置はすでに Ready なのに、なぜシステムは次へ進まないのか？

製造現場や複雑なオートメーションシステムでは、次のような状況がしばしば発生する。

- 装置はすでに Ready なのに、動作が開始されない；
- タスクは生成されているのに、実際の実行が始まらない；
- MES / WCS、PLC、ロボット、下流設備にそれぞれ状態情報があるにもかかわらず、なぜ停止しているのかを直接説明できない；
- 個々のシステムには明確な異常がないのに、全体の工程が継続できない；
- 次工程を開始できるかどうかを、依然としてエンジニアが複数システムを横断して確認しなければならない。

これらは一見すると異なる問題に見えるが、多くの場合、同じエンジニアリング上の位置で発生している。

> **システムが Current State から、明確な Target State へ入ろうとする直前である。**

本当に確認すべきなのは、次の問いである。

> **今回の Target State Entry は、なぜ進入できるのか。あるいは、なぜまだ進入できないのか。**

## TPCA / PCN の中核命題

> **明確な Target State Entry は、それ自体を独立して設計・判定・制御・記録できるエンジニアリング対象として扱うべきである。**

**TPCA（Transition Pre-Control Architecture）** は、状態遷移前制御アーキテクチャである。  
**PCN（Pre-Control Node）** は、Target State Entry の前に配置される前制御ノードである。

> **TPCA は全体アーキテクチャであり、PCN は個別の状態遷移入口に配置されるエンジニアリングノードである。**

TPCA / PCN は、PLC、ステートマシン、SFC、Interlock、安全制御、MES / WCS などを置き換えるものではない。

複数の既存メカニズムが共同で 1 回の状態遷移を決定する場合に、TPCA / PCN は、同一の Target State Entry を中心として、前置判定、制御出力、判定履歴をどのように構造化するかを扱う。
