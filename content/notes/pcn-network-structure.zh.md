# 从单个 PCN 到 PCN 网络

TPCA / PCN 的核心命题是：

> **一次明确的目标状态入口，应当成为可以被独立设计、判定、控制和记录的工程对象。**

一个 PCN 对应一个明确的目标状态入口。

复杂工程系统通常包含多个连续、并行、分支或相互依赖的目标状态入口。

多个 PCN 按实际状态迁移关系以及必要的许可、资源、执行和状态回写依赖形成连接后，可以进一步形成 **PCN 网络（PCN Network）**。

PCN 网络用于描述：

> **复杂工程系统中的关键目标状态入口，以及这些目标状态入口之间的状态迁移和工程依赖关系。**

## 1. PCN 网络的节点对象

PCN 网络以需要独立设计和管理的目标状态入口作为节点对象。

设备、控制器、工位和上位系统可以向 PCN 提供状态，但这些物理设备或软件系统本身不直接等同于 PCN 节点。

例如：

| 状态迁移 | 对应 PCN |
|---|---|
| 机器人等待 → 进入抓取阶段 | 抓取前 PCN |
| 放置完成 → 进入压装阶段 | 压装前 PCN |
| 待检测 → 进入检测阶段 | 检测前 PCN |
| 任务已生成 → 进入执行状态 | 任务执行前 PCN |
| AGV 到站 → 进入站点承接状态 | 站点承接前 PCN |
| 保全解除 → 恢复自动运行 | 自动复归前 PCN |

因此：

- 一台复杂设备内部可以设置多个 PCN；
- 一条生产线可以围绕多个关键目标状态入口设置 PCN；
- MES / WCS 与现场设备之间可以形成跨系统 PCN；
- 人工确认、质量放行、设备复归等过程，只要存在明确目标状态入口，也可以纳入 PCN 网络。

PCN 网络可以表示为：

> **由多个目标状态入口及其工程关系构成的状态迁移前置控制结构。**

---

## 2. “这里需要增加一个 PCN 点”的工程含义

在自动化系统、生产线、物流系统或 MES / WCS 联动设计中，某些目标状态入口可能具有以下特征：

- 进入下一状态需要多个相关状态共同参与判定；
- 存在关键许可、资源约束或跨系统依赖；
- 进入目标状态后还需要确认执行链能否继续接续；
- 判定结果可能进入不同控制路径；
- 本次判定具有记录和追溯价值。

这类位置可以在工程讨论中表述为：

> **这里需要增加一个 PCN 点。**

“PCN 点”表示一个需要独立设计的目标状态入口。

该入口需要明确：

```text
当前状态
→ 目标状态
→ 与本次迁移相关的多源状态
→ C / A / E 状态映射
→ S / D / B 状态判定
→ CAE-SDB 判定结果
→ 控制仲裁
→ 多路径控制
→ PCN Trace
```

因此，“增加一个 PCN 点”的工程含义是：

> **将该目标状态入口作为独立的前置判定、控制和记录对象进行设计。**

## 3. 哪些目标状态入口适合设置 PCN

PCN 不要求覆盖系统中的每一个局部动作。

判断一个目标状态入口是否适合作为独立 PCN，可以检查以下条件：

1. 当前状态和目标状态是否明确；
2. 进入目标状态前是否需要多个相关状态共同参与判定；
3. 是否存在关键许可、资源、执行链或跨系统依赖；
4. 判定结果是否会影响实际状态迁移或控制路径；
5. 本次判定是否具有形成 PCN Trace 的工程价值。

当上述条件成立时，该目标状态入口具有较高的独立 PCN 设置价值。

例如，系统准备进入包装阶段时，可能需要同时确认：

- 待包装对象状态；
- 包装材料状态；
- 必要许可；
- 包装设备状态；
- 下游承接能力；
- 异常处理路径。

此时，“进入包装阶段”可以作为独立 PCN 的目标状态入口。

关于适用边界，可参见：

[TPCA / PCN 适用场景分析](/zh/notes/tpca-pcn-applicable-scenarios/)

## 4. 多个 PCN 之间的工程关系

多个 PCN 之间的连接来源于实际状态迁移及工程依赖。

代表性关系包括：

```text
状态推进关系
许可依赖关系
资源依赖关系
执行依赖关系
状态回写依赖关系
```

### 4.1 状态推进关系

状态推进关系表示一个目标状态成立后，系统进入新的当前状态，并可能进一步进入后续 PCN。

例如：

```text
等待抓取
→ 抓取前 PCN
→ 抓取完成

抓取完成
→ 投放前 PCN
→ 投放完成

投放完成
→ 后续阶段 PCN
→ 后续执行
```

每个 PCN 对应自己的目标状态入口。

前一次状态迁移完成后形成新的当前状态，后续 PCN 基于新的状态事实进行下一次前置判定。

### 4.2 许可依赖关系

一个 PCN 所需的许可状态可以来源于其他设备、系统、人员流程或前序状态迁移结果。

例如：

- 质量放行影响下一工序入口；
- 区域许可影响设备或车辆进入目标区域；
- 上位系统放行影响任务执行入口；
- 对方设备接收许可影响交接入口。

许可依赖进入相应 PCN 的 A 许可状态判定。

### 4.3 资源依赖关系

多个 PCN 可以共同依赖共享资源。

例如：

- 共享路径；
- 缓存区；
- 自动门；
- 电梯；
- 工装；
- 站点；
- 共享执行机构；
- 其他受限资源。

共享资源的状态可能同时影响多个目标状态入口。

### 4.4 执行依赖关系

某个目标状态进入后是否能够继续执行，可能依赖其他设备、路径或下游系统。

例如：

- 下游设备是否可以承接；
- 返回路径是否可用；
- 异常分流路径是否可用；
- 结果上传链路是否可用；
- 后续工艺阶段是否具备接续条件。

这些关系进入相关 PCN 的 E 执行链状态判定。

### 4.5 状态回写依赖关系

一个状态迁移完成后，其执行结果可能需要回写到 PLC、MES、WCS、质量系统、任务系统或其他上位系统。

回写后的状态可能成为后续目标状态入口的输入。

例如：

```text
工序完成
→ 完成状态回写
→ 下一任务状态更新
→ 后续 PCN 获取新的状态
```

状态回写依赖属于 PCN 网络中的工程依赖关系之一。

它描述后续目标状态入口所需要的状态来源和更新关系。

## 5. 状态类型循环与状态实例连续生成

PCN 网络可以包含回流、返工、恢复、补偿、重新投入等路径。

这些路径在状态类型关系上可能形成循环。

例如：

```text
A → B → C → A
```

在实际运行中，第二次进入 A 时，系统已经处于新的时间位置。

因此，可进一步表示为：

```text
状态 A / 实例 A₁
→ PCN-1
→ 状态 B / 实例 B₁
→ PCN-2
→ 状态 C / 实例 C₁
→ PCN-3
→ 状态 A / 实例 A₂
```

其中：

```text
A₁ ≠ A₂
```

两者属于相同状态类型，但属于不同状态实例。

因此：

> **状态类型关系可以形成循环，实际运行中的状态实例沿时间方向继续生成。**

返工、回流、恢复、补偿和重新投入等过程，应作为新的状态迁移事实继续进入相应 PCN。

这一关系可以概括为：

```text
当前状态
→ 新目标状态
→ 新状态实例
→ 后续 PCN
```

PCN 网络中的循环描述状态类型和工艺路径关系，不表示运行事实返回或覆盖历史状态实例。

## 6. PCN 网络的控制与部署边界

PCN 网络描述目标状态入口之间的状态迁移和工程依赖关系，对底层控制架构不作集中式或分布式限定。

例如：

```text
PCN A
→ 状态迁移
→ PCN B
→ 状态迁移
→ PCN C
```

系统也可以存在：

- 并行 PCN；
- 分支 PCN；
- 回流 PCN；
- 相互依赖的 PCN；
- 跨设备 PCN；
- 跨系统 PCN。

PCN 可以部署在：

- PLC / HMI；
- 工业边缘控制器；
- WCS；
- MES；
- 软件服务；
- 其他适合的确定性控制或计算平台。

不同 PCN 可以采用不同部署位置。

PCN 网络也不要求建立一个“全工厂唯一总状态”。

实际工程可以按照以下责任边界组织：

```text
设备
单元
任务
站点
生产区域
其他明确工程责任域
```

各责任域内部维护与其状态迁移相关的状态关系，并通过明确的许可、资源、执行和状态回写依赖与其他 PCN 建立联系。

具体 PCN Runtime 生命周期、PCN 间协议、同步机制、完整接口、完整控制优先级和部署参数属于内部工程实现范围，不在本公开札记中展开。

## 7. PCN 网络与 PCN Trace

单个 PCN 围绕一次目标状态进入形成 PCN Trace。

PCN Trace 记录与本次状态迁移相关的状态、判定、控制和执行履历。

多个 PCN 持续运行后，可以基于 PCN Trace 形成系统级状态迁移判定履历视图。

该履历视图可以用于观察：

- 哪些目标状态入口频繁无法成立；
- 哪些节点经常受到关键许可阻断；
- 哪些执行链接续问题反复出现；
- 哪些目标状态入口长期处于等待；
- 哪些控制路径经常被触发；
- 哪些 PCN 之间反复出现许可、资源或执行依赖问题；
- 哪些状态回写关系反复出现异常；
- 某项工程修改后，相关状态迁移表现是否发生变化。

PCN Trace 在这里承担履历和追溯作用。

许可、资源、执行和状态回写依赖描述 PCN 网络运行中的工程关系。

两者结合后，可以从单次目标状态入口的判定履历进一步观察多个目标状态入口之间的长期运行关系。

关于 PCN Trace，可参见：

[为什么 PCN Trace 是一种新的工程数据？](/zh/notes/why-pcn-trace-is-engineering-data/)

## 8. 三类典型 PCN 网络形态

### 8.1 自动化执行单元

例如：

```text
等待
→ 抓取前 PCN
→ 抓取

抓取完成
→ 投放前 PCN
→ 投放

投放完成
→ 后续阶段 PCN
→ 后续执行
```

一个自动化执行单元内部可以存在多个关键 PCN。

节点之间主要体现状态推进、许可依赖和执行链接续关系。

### 8.2 MES / WCS 与多设备协同

例如：

```text
任务生成
→ 任务执行前 PCN
→ 执行

到达站点
→ 站点承接前 PCN
→ 交接

执行完成
→ 结果回写前 PCN
→ 完成
```

这一层的 PCN 可以跨越任务、资源、路径、站点、执行主体和下游系统。

不同 PCN 之间可以存在调度许可、共享资源、执行链和状态回写依赖。

### 8.3 生产 DX 与跨系统状态迁移

例如：

```text
质量确认
→ 下一工序前 PCN
→ 工序进入

保全解除
→ 自动复归前 PCN
→ 恢复运行

异常处理完成
→ 再投入前 PCN
→ 重新执行
```

这些 PCN 可以跨越设备、人员、MES、质量系统和保全系统。

其共同工程特征是存在明确且具有独立管理价值的目标状态入口。

## 工程结论

单个 PCN 对应一个明确的目标状态入口。

多个 PCN 按实际状态迁移关系以及必要的许可、资源、执行和状态回写依赖形成连接后，可以进一步形成 PCN 网络。

PCN 网络描述：

> **关键目标状态入口及其状态迁移和工程依赖关系。**

在 PCN 网络中：

```text
一个 PCN
= 一个明确目标状态入口的前置控制节点

多个 PCN
= 多个目标状态入口之间的状态迁移与依赖结构
```

状态类型关系可以形成循环，实际运行中的状态实例沿时间方向继续生成。

因此，“这里需要增加一个 PCN 点”可以作为复杂工程系统设计中的简化工程语言，其含义为：

> **这里存在一个需要独立设计、判定、控制和记录的目标状态入口。**

当多个这样的目标状态入口按照实际工程关系持续组织和连接后，TPCA 可以由单个 PCN 扩展为系统级状态迁移前置控制结构。
