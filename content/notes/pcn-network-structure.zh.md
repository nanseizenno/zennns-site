## 多个 PCN 如何形成状态迁移前置控制网络？

一个 PCN（Pre-Control Node / 前置控制节点）对应一个明确的目标状态入口。

复杂工程系统中通常同时存在多个目标状态入口，这些入口可以连续、并行、分支或循环存在。

单个 PCN 负责一个目标状态入口上的局部前置判定与控制。当前入口的控制路径实际执行后，会形成执行结果，并进一步造成实际工程状态变化。

如果这些状态变化形成新的工程状态事实，并成为其他目标状态入口的相关输入，实际改变其判定环境，多个 PCN 之间就形成工程依赖关系。

由这些目标状态入口、对应 PCN 和实际状态迁移依赖关系构成的结构，称为 **PCN Network**。

PCN Network 定义为：

> **由多个目标状态入口及其对应 PCN，通过执行结果形成的实际状态更新，以及这些状态更新对其他目标状态入口判定环境产生的影响关系连接而成的状态迁移前置控制网络。**

PCN Network 中真正传播的是实际工程状态变化及其形成的状态事实。前一个 PCN 已经形成的 CAE-SDB 判定标签保留在本节点，不直接传递给下一个 PCN。

PCN Network 的基本运行关系可以概括为：

```text
PCN-A
→ Execution Result
→ State Update
→ 更新工程状态事实
→ 影响其他 Target State Entry 的判定环境
→ PCN-B 重新执行自己的映射和判定
```

这里保留箭头，是因为它表示实际状态从一个 PCN 的执行结果传播到另一个目标状态入口的过程。

## 1. PCN Network 的节点与基本对象

PCN Network 的节点对象，是具有独立设计、判定、控制和记录价值的目标状态入口及其对应 PCN。

例如：

| 状态迁移 | 对应 PCN |
|---|---|
| 机器人等待 → 抓取阶段 | 抓取前 PCN |
| 放置完成 → 压装阶段 | 压装前 PCN |
| 待检测 → 检测阶段 | 检测前 PCN |
| 任务已生成 → 执行状态 | 任务执行前 PCN |
| AGV 到站 → 站点接收状态 | 站点接收前 PCN |
| 保全解除 → 自动运行恢复 | 自动运行恢复前 PCN |

设备、PLC、机器人控制器、MES、WCS、质量系统以及其他工程系统，可以为各 PCN 提供目标状态入口判定所需要的状态信息。

PCN 的设置单位由目标状态入口决定，与设备数量、控制器数量或系统名称没有固定对应关系。

因此，一台复杂设备内部可以存在多个 PCN；不同设备之间也可以通过实际状态迁移形成 PCN 依赖；跨 MES / WCS、设备、质量、保全和人工操作的状态迁移，也可以分别设置对应 PCN。

多个 PCN 只有在目标状态入口之间存在实际状态迁移影响关系时，才形成相应的 Network 关系。

## 2. 状态事实保持稳定，迁移语义绑定具体目标状态入口

PCN Network 中传播和共享的基础，是实际工程状态事实。

设备、控制器和上位系统优先提供自身能够确认的客观运行状态，例如：

```text
PROCESS_COMPLETE
RUN_READY
STATUS_VALID
质量放行状态
资源占用状态
区域许可状态
下游接收状态
任务状态
```

这些状态事实本身不预先固定为 C、A 或 E。

C / A / E 表示某一状态相对于当前目标状态入口所承担的状态迁移功能角色。各 PCN 在设计或配置阶段，根据自己的目标状态入口预先定义相关状态的 C / A / E 映射关系。

例如，某个下游设备的接收状态，在上游设备准备进入搬送阶段时，可以作为与 E：Execution Chain 有关的状态，用于判断进入目标阶段后执行链能否继续接续。

同一个状态事实进入另一个目标状态入口后，如果工程作用不同，可以在另一个 PCN 中承担不同的预定义角色。

如果某个状态表示明确的进入许可，则可以在相应目标状态入口中作为 A：Authority。

因此：

> **状态事实的基础语义保持稳定，C / A / E 角色由具体目标状态入口决定。**

不同 PCN 可以引用同一个状态对象，但分别调用各自已经定义的状态映射关系。

运行时根据当前受影响的目标状态入口读取最新状态，再执行该 PCN 适用的 S / D / B 判定。

## 3. PCN 工程依赖如何形成

PCN Network 中的连接，不根据设备物理连接、通信连接、流程先后关系或系统归属自动建立。

一个直接 PCN 工程依赖关系，需要满足以下过程：

1. PCN-A 执行已经选定的控制路径；
2. 执行结果形成实际 State Update；
3. State Update 形成或更新某项工程状态事实；
4. 该状态事实成为 PCN-B 对应 Target State Entry 的相关输入；
5. 该变化实际改变 PCN-B 的判定环境。

满足这些条件后，PCN-A 与 PCN-B 之间形成直接工程依赖关系。

本文中的 **状态更新（State Update）**，是已选控制路径执行后形成的实际工程状态变化。

因此：

> **PCN Network 的连接基础是实际状态影响关系。**

设备物理连接、通信连接、流程上的前后顺序、属于同一设备或生产线、共享某个资源，以及统计上经常同时发生，都不足以单独建立 PCN 工程依赖。

State Update 的具体内容由实际工程对象决定，可以涉及：

- 状态推进；
- 许可状态变化；
- 资源状态变化；
- 执行链状态变化；
- 任务状态变化；
- 对象 / 周期状态变化；
- 其他工程状态变化。

这些变化首先表现为实际工程状态更新，再根据是否影响其他目标状态入口决定是否形成 PCN Dependency。

例如，抓取执行完成以后形成“抓取完成”这一新的工程状态事实。如果它成为“进入放置阶段”的相关输入，放置前 PCN 就根据自己的目标状态入口读取当前状态并重新判定。

区域许可、质量放行、资源占用、Buffer 容量、下游接收、结果回写等状态发生实际变化以后，如果更新后的状态事实进入其他目标状态入口的判定环境，也可以形成相应的 PCN Dependency。

替代路径、回流路径或异常处理路径如果对应新的目标状态，应在新的 Target State Entry 下独立进行前置判定。

## 4. 各 PCN 保持局部判定语义，并通过 Trace 形成系统级关联

PCN Network 中，各 PCN 保持自己的局部判定语义。

例如，PCN-A 中形成 `A-D`，表示某个许可状态在 PCN-A 对应的目标状态入口中存在动态时序有效性问题。

如果 PCN-A 后续执行形成新的实际状态变化，并影响 PCN-B，PCN-B 不继承 `A-D` 这一标签。

PCN-B 读取更新后的工程状态事实，调用自己的 C / A / E 状态映射关系，再基于当前状态执行适用的 S / D / B 判定，形成自己的 CAE-SDB Result。

原因是：

> **C / A / E 是状态相对于具体 Target State Entry 的局部迁移功能角色。**

因此，PCN Network 跨节点传播的是实际状态事实及其必要上下文。

单个 PCN 会形成一次目标状态入口对应的 PCN Trace，代表性内容包括：

- 当前状态；
- 目标状态；
- 目标状态入口；
- 相关状态；
- C / A / E 状态映射关系；
- S / D / B 判定；
- CAE-SDB 判定结果；
- 控制仲裁结果；
- 多路径控制结果；
- 执行结果；
- 时间信息；
- Trace ID。

单个 PCN Trace 用于说明：

> **这一目标状态入口为什么形成当前判定和控制结果。**

将多个 PCN Trace 与实际状态迁移依赖对应以后，可以继续追踪：

- 某个状态事实由哪个上游执行结果产生；
- 该状态影响了哪个目标状态入口；
- 下游 PCN 形成了什么新的判定结果；
- 后续又形成了什么新的状态变化。

PCN Network 的实际结构可以连续、并行、分支、循环或跨系统。

同一个 State Update 如果实际影响多个目标状态入口，可以形成多个工程依赖关系。

状态类型也可以形成循环，例如：

```text
A → B → C → A
```

但实际运行中的状态实例仍沿时间方向继续生成：

```text
A₁ → B₁ → C₁ → A₂
```

A₁ 与 A₂ 属于同一状态类型，但属于不同运行实例。

返工、回流、恢复、重新投入等工艺路径可以形成状态类型上的循环，运行履历仍保持时间方向上的连续性。

## 5. PCN Network 的工程形态与边界

PCN Network 可以存在于不同工程层级。

### 自动化执行单元

一个自动化执行单元内部可以设置多个主要目标状态入口，例如抓取、放置和后续执行阶段。

前一个阶段执行完成后形成新的工程状态事实，这些状态事实如果进入后续 Target State Entry 的判定环境，就形成相应的 PCN 工程依赖。

### MES / WCS 与多设备协同

MES / WCS 与多设备协同时，目标状态入口往往分布在不同设备和系统中。

任务生成、任务执行、站点接收、交接等过程都可以形成明确的目标状态入口。

任务、资源、路径、站点、许可和执行链等状态只有发生实际更新，并进一步影响其他目标状态入口时，才形成 PCN Network 中的直接依赖关系。

### 制造 DX 与跨系统状态迁移

设备、人员、MES、质量系统和保全系统之间也存在大量明确的状态迁移入口，例如：

- 质量状态更新后进入下一工序；
- 保全状态更新后恢复自动运行；
- 工单或配方状态更新后进入新的生产状态。

PCN Network 不要求把这些系统统一成一个新的中央状态系统。

各 PCN 仍围绕自己的 Target State Entry 读取相关状态、执行判定并形成控制结果。

不同 PCN 可以部署在 PLC / HMI、工业控制器、边缘控制器、WCS、MES 或软件服务等不同位置，也不要求所有 PCN 由一个中央控制器统一执行。

PCN Network 的工程对象是目标状态入口之间的实际状态影响关系，不是设备拓扑、通信拓扑或普通生产流程图。

判断是否形成直接工程依赖，需要确认四个问题：

1. PCN-A 的执行结果是否形成实际 State Update；
2. 该 State Update 是否形成或改变工程状态事实；
3. 该状态事实是否成为 PCN-B 的相关输入；
4. 是否实际改变 PCN-B 对应 Target State Entry 的判定环境。

只有这些关系成立时，才建立直接 PCN Dependency。

PCN Network 不追求节点和连接数量最大化。

更合理的目标是：

> **用尽可能简洁的关系结构，保留真实系统中对状态迁移判定、控制、传播和追溯具有工程意义的依赖关系。**

具体运行生命周期、节点间通信协议、同步方式、State Update 数据结构、完整接口定义、完整控制仲裁规则以及其他内部实现机制，属于工程实现内容，本公开札记不展开。

## 总结

一个 PCN 对应一个明确的目标状态入口。

多个 PCN 之间只有在执行结果形成实际状态更新，并进一步改变其他目标状态入口的判定环境时，才形成直接工程依赖关系。

跨节点传播的是更新后的工程状态事实。C / A / E 和 CAE-SDB 等局部迁移语义始终绑定具体 Target State Entry，由各 PCN 按自己的预定义关系重新执行映射和判定。

上游 PCN 的 CAE-SDB 判定结果保留在自身 PCN Trace 中，不直接成为下游 PCN 的判定结果。

多个目标状态入口及其工程依赖关系持续连接以后，形成 PCN Network。

因此，PCN Network 可以概括为：

> **以多个目标状态入口及其对应 PCN 为节点，以执行结果形成的实际状态更新对其他目标状态入口产生的真实影响关系为连接基础，用于组织、追溯和分析连续状态迁移关系的工程网络。**
