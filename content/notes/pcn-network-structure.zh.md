单个 PCN 对应一个明确的目标状态入口。

多个 PCN 按状态迁移关系连接起来，就形成状态迁移前置控制网络。

PCN控制网络关注的是：

> **复杂制造系统中，哪些关键状态迁移入口需要独立的前置判定。**

![多个 PCN 如何形成状态迁移前置控制网络](/images/tpca/10-pcn-network-structure.zh.png)

图：多个 PCN 围绕目标状态入口形成状态迁移前置控制网络。

工程师讨论产线、自动化单元、物流路径或 MES / WCS 联动时，如果某个位置存在明确的：

```text
Current State
→ Target State
```

而进入 Target State 之前需要综合多个条件、许可和执行链状态进行判断，就可以说：

> **这里需要增加一个 PCN 点。**

这句话的含义不是“再加一个传感器”或“再加一个 Interlock”。

而是：

> **这里需要把一次关键状态迁移作为独立工程对象进行判定、控制和记录。**

---

## 1. PCN 网络按状态迁移入口组织

PCN 网络的节点是关键状态迁移入口。

例如：

| 状态迁移入口 | PCN 点 |
|---|---|
| 机器人等待 → 抓取 | 抓取前 PCN |
| 放置完成 → 压装 | 压装前 PCN |
| 待检测 → 检测执行 | 检测前 PCN |
| 任务存在 → 任务进入执行 | 任务执行前 PCN |
| AGV 到站 → 站点承接 | 站点承接前 PCN |
| 包装待机 → 包装执行 | 包装前 PCN |
| 包装完成 → 码垛 | 码垛前 PCN |
| 码垛完成 → 入库 / 交接 | 入库 / 交接前 PCN |

因此：

- 一台复杂设备内部可以存在多个 PCN；
- 一条产线可以在不同工序入口设置多个 PCN；
- MES / WCS 与现场设备之间也可以存在 PCN；
- 人工确认、质量放行或设备复归，只要形成明确状态迁移入口，也可以成为 PCN 的组成部分。

PCN 网络应理解为：

> **状态迁移入口之间的工程关系网络。**

而不是设备之间的物理连接图。

---

## 2. 哪里需要增加 PCN 点

并不是每一个动作、每一个信号都需要单独设置 PCN。

一个位置是否值得设置 PCN，可以先问几个问题：

1. 是否存在明确的 Current State 和 Target State？
2. 进入 Target State 前，是否需要多个状态共同判断？
3. 是否存在关键安全许可、上位许可、资源锁、区域许可或人工确认？
4. 进入 Target State 后，是否需要确认下游或后续执行链能够接续？
5. 是否存在等待、重识别、回流、异常分流、降级、人工确认、禁止进入等不同处理路径？
6. 本次判定是否有必要留下 Trace，用于后续复盘或改善？

如果大多数答案为“是”，这里就具有较强的 PCN 设置价值。

例如包装前，系统可能不仅需要判断：

```text
Packaging Machine Ready
```

还需要判断：

- 待包装品是否成立；
- 包装材料是否满足；
- 质量许可是否成立；
- 下游码垛是否能够承接；
- 异常路径是否可用；
- 结果是否能够正常回写。

同样，码垛前可能需要同时判断：

- 包装是否完成；
- 托盘是否存在；
- 码垛规则是否有效；
- 安全区域是否许可；
- 入库 / 交接路径是否可用。

这些位置都比普通局部动作更适合设置 PCN。

## 3. PCN 之间如何连接

PCN 网络中的连接是遵循“状态迁移关系”。

### 3.1 状态推进关系

前一个 PCN 成功进入目标状态后，可以形成后一个 PCN 的 Current State 或前置条件。

例如：

```text
抓取完成
→ 投放前 PCN
→ 投放完成
→ 下一阶段 PCN
```

或者：

```text
包装完成
→ 码垛前 PCN
→ 码垛完成
→ 入库 / 交接前 PCN
```

这种连接表达的是系统状态如何逐步推进。

---

### 3.2 许可依赖关系

一个节点的状态也可能成为另一个节点的 A 域许可输入。

例如：

- 资源锁未释放，后续任务不得进入；
- 站点接收许可未成立，AGV 不得进入交接阶段；
- 质量放行未完成，下一工序不得进入；
- 入库许可未成立，物料不得进入仓储路径。

A 域中的关键许可可以构成独立必要约束。

因此，一个 PCN 的输出或状态变化，可能改变另一个 PCN 的许可条件。

---

### 3.3 执行链接续关系

一个 PCN 在进入 Target State 前，还需要考虑进入以后是否接得住。

例如：

- 抓取前确认正常投放位、回流路径和异常分流路径；
- 包装前确认码垛承接；
- 码垛前确认入库或交接路径；
- 检测前确认质量结果回写和后续分流链路；
- AGV 进入站点前确认站点、缓存和后续交接是否可承接。

这也是 E = Execution Chain 与单体 Ready 的区别。

一个设备 Ready，只说明局部可运行。

E 关注的是：

> **进入目标状态以后，后续执行链是否能够继续。**

---

## 4. 网络中的判定仍然发生在各个 PCN

PCN 形成网络以后，并不意味着所有判定都集中到一个“大中央节点”。

每个 PCN 仍然围绕自己的 Target State 完成局部前置判定：

```text
Current State
→ Target State
→ Multi-source State Signals
→ C/A/E Mapping
→ S/D/B Evaluation
→ CAE-SDB Result
→ Arbitration
→ Multipath Control
→ PCN Trace
```

其中：

- C/A/E 用于整理本次状态迁移相关的状态变量；
- S/D/B 用于判断结构完整性、动态有效性和控制边界；
- CAE-SDB Result 是本次前置判定结果；
- Arbitration 处理多个判定结果之间的优先关系；
- Multipath Control 形成最终控制路径；
- PCN Trace 保存本次判定履历。

---

## 5. PCN 网络的工程价值

PCN 网络首先提供了一种统一的工程讨论语言。

过去在产线方案讨论中，经常会听到：

> 这里加一个传感器。  
> 这里加一个 Interlock。  
> 这里加一个报警。  
> 这里让 HMI 显示一下。  
> 这里等 MES 放行。

这些做法本身没有问题，但关注点往往停留在局部信号或局部功能。

如果把问题放到 PCN 层面，讨论会变成：

> 这里是不是一个关键 Target State Entry？

> 进入以前需要哪些 C？

> 哪些 A 必须成立？

> E 能不能继续接续？

> 这里有哪些边界状态？

> 多个结果冲突时怎么仲裁？

> 最终允许走哪些控制路径？

> 这次判定要不要留下 Trace？

因此：

> **“这里需要增加一个 PCN 点”**

实际上是在说：

> **这里需要把一个重要状态迁移入口显式化。**

这比单纯补一个局部信号更接近系统设计问题。

---

## 6. 多个 PCN 可以形成状态迁移履历

单个 PCN 保存的是一次状态迁移判定。

多个 PCN 长期运行以后，可以形成系统级状态迁移履历。

每一次 PCN Trace 可以关联：

- PCN；
- Current State；
- Target State；
- 关键输入状态；
- C/A/E 映射；
- S/D/B 判定；
- CAE-SDB Result；
- Arbitration Result；
- Multipath Control；
- Execution Result；
- Timestamp；
- Trace ID。

这些 Trace 聚合以后，可以进一步观察：

- 哪些状态迁移入口最容易失败；
- 哪些 PCN 长期 Waiting；
- 哪些节点频繁出现许可问题；
- 哪些执行链经常无法接续；
- 哪些状态反复出现动态失效；
- 哪些边界经常被触发；
- 哪些控制路径经常执行但恢复效果有限；
- 哪些节点经过改善以后问题明显下降。

因此 PCN Network 的长期价值不仅是运行时控制。

它还可以逐步形成：

> **状态迁移设计的运行履历。**

这为后续的复盘、比较、工程改善和再部署提供统一的数据基础。

---

## 7. 典型应用位置

PCN Network 可以跨越不同层级，但共同点始终是存在明确 Target State Entry。

### 自动化执行单元

例如：

- 等待 → 抓取；
- 抓取完成 → 投放；
- 放置完成 → 压装；
- 待检测 → 检测；
- 检测完成 → 正常 / 异常分流；
- 异常停止 → 复归；
- 手动调整 → 自动恢复。

### MES / WCS 与搬送系统

例如：

- 任务存在 → 任务进入执行；
- 资源可用 → 任务获得执行许可；
- AGV 到站 → 站点承接；
- 缓存占用 → 缓存释放；
- 下游需求产生 → 补料任务进入执行；
- 执行完成 → 结果回写。

### 生产 DX 和人机协同

例如：

- 人工确认完成 → 自动放行；
- 质量判定完成 → 下一工序进入；
- 保全解除 → 自动复归；
- 异常处理完成 → 再投入；
- 工单切换完成 → 新生产状态进入。

这些位置并不是因为使用了某种设备或软件才成为 PCN。

而是因为它们具有相同结构：

```text
Current State
→ Target State
→ 前置判定
→ 控制路径
→ Trace
```

---

## 小结

单个 PCN 对应一个明确的目标状态入口。

多个 PCN 按状态迁移关系连接，就形成状态迁移前置控制网络。

这个网络不是设备连接图，也不是把所有控制逻辑集中到一个系统里。

它做的是：

> **把复杂制造系统中的关键状态迁移入口逐个显式化。**

工程师可以据此判断：

- 哪里需要独立前置判定；
- 哪里存在关键许可约束；
- 哪里需要确认执行链接续；
- 哪里存在多个控制路径；
- 哪里需要保留完整判定履历；
- 哪些节点值得优先改善。

因此：

> **“这里需要增加一个 PCN 点”**

可以成为一种面向复杂自动化和制造系统设计的工程语言。

它表达的不是：

> “这里再加一个信号。”

而是：

> **“这里存在一个重要状态迁移入口，需要被独立设计、判定、控制和记录。”**
