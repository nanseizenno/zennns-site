## 多个 PCN 如何形成状态迁移前置控制网络？

一个 PCN（Pre-Control Node / 前置控制节点）对应一个明确的目标状态入口。

复杂工程系统中通常同时存在多个目标状态入口。这些入口可能连续、并行、分支、循环，也可能通过许可、资源、执行链或状态更新形成相互依赖。

将这些目标状态入口及其对应 PCN 按实际状态迁移关系和工程依赖关系组织起来，就形成 **PCN Network**。

PCN Network 可以定义为：

> **由多个目标状态入口、对应 PCN，以及它们之间的状态推进、许可、资源、执行链和状态更新等工程依赖关系构成的关系结构。**

下图给出 PCN Network 的整体结构示意。

多个目标状态入口分别形成对应的 PCN，并通过状态推进、许可、资源、执行链和状态更新等工程关系连接。不同设备、MES / WCS、AGV / AMR 群控等系统可以为各 PCN 提供相关状态信息；PCN Trace 进一步为跨节点的履历比较和系统级分析提供基础。

## 1. PCN Network 的节点是目标状态入口 / PCN

PCN Network 的节点对象，是具有独立设计、判定、控制和记录价值的目标状态入口及其对应 PCN。

例如：

| 状态迁移 | 对应 PCN |
|---|---|
| 机器人等待 → 抓取阶段 | 抓取前 PCN |
| 放置完成 → 压装阶段 | 压装前 PCN |
| 待检测 → 检测阶段 | 检测前 PCN |
| 任务已生成 → 执行状态 | 任务执行前 PCN |
| AGV 到站 → 站点接收状态 | 站点接收前 PCN |
| 保全解除 → 自动运行恢复 | 自动运行恢复前 PCN |

设备、PLC、机器人控制器、MES、WCS、质量系统等为各 PCN 提供判定所需的状态信息。

PCN 的设置单位由目标状态入口决定。一台复杂设备内部可以有多个 PCN，一条生产线也可以围绕多个关键入口配置 PCN。

跨 MES / WCS 与现场设备的状态迁移，以及包含人工确认、质量放行等条件的状态迁移，只要存在明确的目标状态入口，都可以纳入 PCN Network。

---

## 2. 同一状态对象在不同 PCN 中可以承担不同的 C / A / E 角色

PCN Network 中的状态对象不具有全局固定的 C / A / E 属性。

C / A / E 表示某一状态相对于当前目标状态入口所承担的状态迁移功能角色。

例如，某个下游设备的接收状态，在上游设备准备进入搬送阶段时，可以作为 E：Execution Chain，用于判断进入目标阶段后执行链是否能够继续接续。

当系统进入另一个目标状态入口后，同一状态事实如果成为下一阶段进入前必须满足的前提条件，则可以在该 PCN 中作为 C：Condition 使用。

如果某一状态表达的是明确的进入许可，则可以在相应目标状态入口中作为 A：Authority 使用。

其基本关系可以表示为：

```text
状态对象
    ×
目标状态入口
    ↓
本次 PCN 中的 C / A / E 状态映射
```

因此，不同 PCN 可以引用同一个状态对象，并根据各自目标状态入口的迁移关系形成不同的 C / A / E 角色。

PCN Network 为这些状态角色提供明确的状态迁移上下文。

## 3. PCN 之间通过哪些工程关系连接

PCN Network 中的连接来自实际状态迁移和工程依赖。

主要关系包括：

```text
状态推进
许可依赖
资源依赖
执行链依赖
状态更新依赖
```

### 3.1 状态推进关系

一个状态迁移完成后，系统形成新的当前状态，并由该状态继续进入后续目标状态入口。

例如：

```text
等待抓取
→ 抓取前 PCN
→ 抓取完成

抓取完成
→ 放置前 PCN
→ 放置完成

放置完成
→ 后续阶段 PCN
→ 后续执行
```

前一个迁移产生新的状态事实，后一个 PCN 再基于新的当前状态及相关状态进行判定。

### 3.2 许可依赖关系

某个 PCN 使用的许可状态，可以来自其他设备、上位系统、人员操作或前序状态迁移结果。

例如：

- 安全许可；
- 区域进入许可；
- 上位系统执行许可；
- 质量确认；
- 对方设备许可；
- 人工确认。

当这些状态在当前目标状态入口中承担进入许可作用时，对应 A：Authority。

### 3.3 资源依赖关系

多个 PCN 可能同时依赖同一个共享资源，例如：

- 共享路径；
- 缓存区；
- 自动门；
- 电梯；
- 工装；
- 站点；
- 共享执行机构。

共享资源可能同时影响多个目标状态入口，因此需要从 PCN Network 层面表示不同入口之间的资源依赖关系。

具体资源状态在各 PCN 中属于 C、A 还是 E，由该状态在对应目标状态入口中的功能角色决定。

### 3.4 执行链依赖关系

进入目标状态后，执行链能否继续，可能依赖其他设备、路径或下游系统。

例如：

- 下游设备是否能够接收；
- 当前目标状态对应的后续路径是否可用；
- 结果发送或回写链路是否正常；
- 后续设备是否能够接续；
- 目标阶段所需的执行机构是否可用。

这些状态可以作为相应 PCN 中与 E：Execution Chain 有关的状态。

替代路径、回流路径或异常处理路径如果形成新的候选状态迁移，应在其对应目标状态入口下重新判定。

### 3.5 状态更新依赖关系

某个 PCN 的执行结果或状态变化，可能需要写回 PLC、MES、WCS、质量系统或其他上位系统。

更新后的状态又可能成为后续 PCN 的输入。

例如：

```text
工序完成
→ MES / PLC / WCS 状态更新
→ 后续 PCN 获取更新后的状态
→ 判定下一个目标状态入口
```

状态更新依赖描述后续 PCN 使用状态的来源和更新关系，是 PCN Network 中的重要连接关系。

## 4. PCN Network 可以形成不同结构

PCN Network 的结构取决于实际状态迁移和工程依赖，可以形成连续、并行、分支、循环或跨系统结构。

连续关系例如：

```text
PCN-A
→ 状态迁移
→ PCN-B
→ 状态迁移
→ PCN-C
```

并行或分支关系例如：

```text
        → PCN-B
PCN-A
        → PCN-C
```

状态类型也可以形成循环，例如：

```text
A → B → C → A
```

实际运行中的状态实例始终沿时间方向继续生成。

再次进入状态类型 A 时，可以表示为：

```text
A₁ → B₁ → C₁ → A₂
```

A₁ 与 A₂ 属于同一状态类型，但属于不同的运行实例。

返工、回流、恢复、重新投入等工艺路径可以形成状态类型上的循环，运行履历仍然保持时间方向上的连续性。

关于这一点，可参见：

- [TPCA 的状态迁移单向性——为什么真实工程系统不存在状态回退？](/zh/notes/tpca-unidirectional-state-transition/)

PCN Network 也可以跨越 PLC、机器人、MES、WCS、质量系统等不同系统层级。

其关注对象始终是系统中的目标状态入口，以及这些入口之间的状态迁移和工程依赖关系。

## 5. PCN Network 与单个 PCN 的在线运行

每个 PCN 负责一个目标状态入口上的局部前置判定与控制。

单个 PCN 获取与当前入口有关的状态，进行 C / A / E 状态映射和 S / D / B 判定，并形成相应的判定结果、控制结果和状态迁移判定履历。

PCN Network 从系统关系层面描述多个 PCN 之间的状态推进、许可、资源、执行链和状态更新依赖。

不同 PCN 可以部署在 PLC / HMI、工业控制器、边缘控制器、WCS、MES 或软件服务等不同位置。

PCN Network 不要求所有 PCN 由同一个上层控制器集中执行。只要节点之间的工程关系能够被明确，就可以构成相应的 Network 关系结构。

具体运行生命周期、节点间通信协议、同步方式、完整接口定义和完整控制仲裁规则属于工程实现内容，本公开札记不展开。

## 6. PCN Network 与 PCN Trace

单个 PCN 会形成一次目标状态入口对应的 PCN Trace。

其中可以记录：

- 本次迁移使用的状态；
- C / A / E 状态映射；
- S / D / B 判定；
- CAE-SDB 判定结果；
- 控制仲裁结果；
- 多路径控制结果；
- 执行结果；
- 相关时间信息。

当多个 PCN 的 Trace 与 Network 中已经定义的依赖关系对应起来后，可以进一步分析单个目标状态入口之外的系统级问题。

例如：

```text
PCN-A
许可更新延迟
    ↓
PCN-B
等待时间延长
```

也可能出现：

```text
PCN-C
占用共享资源
    ↓
PCN-D / PCN-E
在目标状态入口等待
```

结合 PCN Network 中已经定义的依赖关系，可以进一步分析等待与前序许可更新、共享资源占用、执行链依赖或状态更新延迟之间的关系。

长期积累后，可以分析：

- 哪些目标状态入口问题频发；
- 哪些 PCN 之间反复出现许可依赖；
- 哪些共享资源持续影响多个入口；
- 哪些状态更新关系经常出现延迟；
- 同一状态对象在不同 PCN 中承担哪些迁移角色；
- 工程修改以后相关 PCN 的判定和执行结果发生了什么变化。

PCN Network 为 PCN Trace 补充节点之间的关系信息，使履历分析能够从单个目标状态入口扩展到系统级依赖关系。

PCN Trace 的详细说明参见：

- [为什么 PCN Trace 是一种新的工程数据？](/zh/notes/why-pcn-trace-is-engineering-data/)

## 7. 三种代表性的 PCN Network 形态

### 7.1 自动化执行单元

一个自动化执行单元内部可以有多个主要目标状态入口。

例如：

```text
等待
→ 抓取前 PCN
→ 抓取

抓取完成
→ 放置前 PCN
→ 放置

放置完成
→ 后续阶段 PCN
→ 后续执行
```

这类 Network 中，PCN 之间主要体现状态推进、许可和执行链依赖。

同一个设备状态或下游状态也可以被不同 PCN 引用，并根据各自目标状态入口承担不同的 C / A / E 角色。

### 7.2 MES / WCS 与多设备协同

MES / WCS 与多设备协同时，目标状态入口往往跨系统存在。

例如：

```text
任务生成
→ 任务执行前 PCN
→ 执行

到达站点
→ 站点接收前 PCN
→ 交接

执行完成
→ 状态更新
→ 后续 PCN
```

任务、资源、路径、站点、许可、执行链和状态更新之间的关系，都可以在 PCN Network 中进行整理。

同一个站点状态、任务状态或资源状态，可以根据不同目标状态入口，在不同 PCN 中承担不同的迁移功能角色。

### 7.3 制造 DX 与跨系统状态迁移

设备、人员、MES、质量系统和保全系统之间也存在大量明确的状态迁移入口。

例如：

```text
质量确认
→ 下一工序前 PCN
→ 工序进入

保全解除
→ 自动运行恢复前 PCN
→ 运行恢复

作业指示切换
→ 目标生产状态前 PCN
→ 新生产状态
```

这类场景的状态和许可来源分散在多个系统，但每次状态迁移仍然可以围绕明确的目标状态入口进行组织。

PCN Network 将这些不同系统中的目标状态入口及其状态、许可、资源、执行链和状态更新关系连接起来。

---

## 总结

一个 PCN 对应一个明确的目标状态入口。

多个 PCN 按实际状态迁移关系以及许可、资源、执行链和状态更新等工程依赖连接后，形成 PCN Network。

PCN Network 主要描述：

```text
状态推进
许可依赖
资源依赖
执行链依赖
状态更新依赖
```

同一个状态对象在不同 PCN 中可以承担不同的 C / A / E 角色，其角色由对应目标状态入口决定。

```text
状态对象
    ×
目标状态入口
    ↓
C / A / E 状态映射
```

单个 PCN 负责一个目标状态入口上的局部前置判定与控制，PCN Network 描述多个目标状态入口之间的状态迁移和工程依赖关系。

当 PCN Trace 与 Network 关系结合后，可以进一步分析多个入口之间的问题传递、共享资源影响、许可依赖、执行链依赖和状态更新影响。

因此，PCN Network 可以概括为：

> **将多个目标状态入口分别定义为 PCN，并按实际状态迁移和工程依赖关系连接起来，用于系统级设计、确认和分析的关系结构。**
