# 从单个 PCN 到 PCN Network

TPCA / PCN 的核心命题是：

> **一次明确的目标状态入口，应当成为可以被独立设计、判定、控制和记录的工程对象。**

一个 PCN 对应一个明确的目标状态入口。

复杂工程系统中通常存在多个这样的入口。

当多个 PCN 按照实际状态迁移关系以及必要的许可、资源和执行依赖关系连接起来时，可以进一步形成 **PCN Network**。

PCN Network 关注的是：

> **复杂工程系统中，哪些关键目标状态入口需要被独立设计，以及这些入口之间存在怎样的工程关系。**

## 1. PCN Network 的节点不是设备，而是目标状态入口

在传统设备结构图中，节点通常表示：

- PLC；
- 机器人；
- 输送机；
- 工位；
- AGV；
- MES / WCS；
- 其他设备或系统。

PCN Network 的节点不是这些设备或系统本身。

其基本节点是：

> **需要被独立设计和管理的关键目标状态入口。**

例如：

| 状态迁移 | 对应 PCN |
|---|---|
| 机器人等待 → 进入抓取阶段 | 抓取前 PCN |
| 放置完成 → 进入压装阶段 | 压装前 PCN |
| 待检测 → 进入检测阶段 | 检测前 PCN |
| 任务已生成 → 进入执行状态 | 任务执行前 PCN |
| AGV 到站 → 进入站点承接状态 | 站点承接前 PCN |
| 保全解除 → 恢复自动运行 | 自动复归前 PCN |

因此：

- 一台复杂设备内部可以存在多个 PCN；
- 一条产线可以围绕多个关键目标状态入口设置 PCN；
- MES / WCS 与现场设备之间也可以形成 PCN；
- 人工确认、质量放行或设备复归，只要形成明确的目标状态入口，也可以纳入 PCN Network。

因此，PCN Network 应理解为：

> **目标状态入口及其相互关系构成的工程网络。**

它不是设备连接图，也不是通信拓扑图。

---

## 2. “这里需要增加一个 PCN 点”是什么意思？

在复杂自动化、产线、物流路径或 MES / WCS 联动设计中，某些位置可能具有以下特征：

- 不能由单一 Ready 决定是否进入下一状态；
- 需要多个系统状态共同参与判断；
- 存在关键许可或资源约束；
- 进入目标状态以后还需要确认后续执行链能否接续；
- 不能进入时可能存在多种处理路径；
- 判定过程具有后续追溯价值。

这类位置可以在工程讨论中表述为：

> **这里需要增加一个 PCN 点。**

这里的“PCN 点”并不是指增加一个传感器、一个状态位或一个 Interlock。

它表达的是：

> **这里存在一个重要的目标状态入口，需要被独立设计、判定、控制和记录。**

因此，“PCN 点”可以作为一种简化的工程讨论语言。

它将讨论对象从：

> “这里是否还缺一个信号？”

提升为：

> **“这一次目标状态进入是否已经被完整设计？”**

---

## 3. 哪些位置值得设置 PCN？

并不是每一个动作、每一个步骤都需要单独设置 PCN。

判断某个目标状态入口是否具有较高的 PCN 设置价值，可以先考虑以下四个问题：

1. 当前状态和目标状态是否明确？
2. 进入目标状态前，是否需要多个相关状态共同参与判断？
3. 判定结果是否会直接影响实际状态迁移或控制路径？
4. 本次判定是否具有形成可追溯履历的工程价值？

如果上述条件大部分成立，则该目标状态入口具有较强的 PCN 设置必要性。

例如，在进入包装阶段之前，如果系统不仅需要确认包装设备 Ready，还需要同时判断：

- 待包装对象是否满足要求；
- 包装材料是否齐备；
- 必要许可是否成立；
- 下游是否能够承接；
- 异常处理路径是否可用；

那么“进入包装阶段”就比某一个局部动作更适合作为独立 PCN 的工程对象。

关于更完整的适用边界，可参见：

[TPCA / PCN 适用场景分析](/zh/notes/tpca-pcn-applicable-scenarios/)

## 4. 多个 PCN 之间如何形成工程关系

多个 PCN 之间的连接，应来源于实际状态迁移关系，而不是为了形成网络而人为建立连接。

例如：

```text
等待抓取
→ 抓取前 PCN
→ 抓取完成

抓取完成
→ 投放前 PCN
→ 投放完成

投放完成
→ 下一阶段 PCN
→ 后续执行
```

这里，每一个 PCN 都对应自己的目标状态入口。

前一个状态迁移完成以后，系统进入新的状态，并可能进一步进入后续 PCN。

因此，PCN Network 中最基本的连接关系是：

> **状态推进关系。**

除此之外，不同 PCN 之间还可能存在其他工程依赖。

### 许可依赖

一个 PCN 的状态或输出，可能成为另一个 PCN 的许可输入。

例如：

- 质量放行结果影响下一工序入口；
- 资源释放结果影响后续任务执行入口；
- 区域许可影响设备或车辆进入目标区域。

### 资源依赖

不同 PCN 可能共同依赖：

- 共享路径；
- 缓存区；
- 自动门；
- 电梯；
- 工装；
- 站点；
- 其他共享资源。

### 执行链接续关系

前一个 PCN 的目标状态完成以后，可能直接改变后一个 PCN 的执行链接续条件。

### 状态回写关系

某个 PCN 的执行结果或 Trace，也可能影响后续系统状态更新和下一次目标状态进入。

无论关系类型如何，最终都应回到同一个判断原则：

> **这一关系是否影响另一个目标状态入口的判定、控制或履历。**

## 5. PCN Network 不规定集中式或分布式控制架构

多个 PCN 形成网络以后，并不意味着所有判定都必须集中到一个中央控制器。

每个 PCN 仍然围绕自己的目标状态入口完成前置判定。

例如：

```text
PCN A → 状态迁移 → PCN B → 状态迁移 → PCN C
```

系统也可以存在并行、分支、回流或相互依赖的 PCN。

因此：

> **PCN Network 描述的是状态迁移及其工程依赖关系，不规定底层系统必须采用集中式或分布式控制架构。**

实际工程中，PCN 可以部署在：

- PLC / HMI；
- 边缘控制器；
- WCS；
- MES；
- 软件服务；
- 其他适合的控制或计算平台。

不同 PCN 的实际部署位置可以不同。

TPCA / PCN 关注的是工程责任边界和状态迁移关系，而不是强制统一具体技术平台。

具体 PCN Runtime、接口、同步、配置和部署机制不属于本公开札记范围。

## 6. PCN Network 与 PCN Trace

单个 PCN 可以围绕一次目标状态进入形成 PCN Trace。

多个 PCN 长期运行以后，可以进一步形成系统级的状态迁移判定履历。

这使工程师能够观察：

- 哪些目标状态入口频繁无法成立；
- 哪些节点经常受到关键许可阻断；
- 哪些执行链接续问题反复出现；
- 哪些状态迁移长期处于 Waiting；
- 哪些控制路径经常被触发；
- 哪些节点之间反复出现资源或许可依赖问题；
- 某项工程修改以后，相关状态迁移表现是否发生变化。

因此，PCN Network 的长期价值不仅体现在运行时控制。

它还可以形成：

> **以关键目标状态入口及其关系为中心的系统级运行结构和履历视图。**

这种履历视图不同于单纯设备报警、任务日志或系统事件列表。

它关注的是：

> **哪些目标状态入口被成功进入、等待、阻断或分流，以及这些状态迁移之间存在怎样的工程关系。**

关于 PCN Trace，可参见：

[为什么 PCN Trace 是一种新的工程数据？](/zh/notes/why-pcn-trace-is-engineering-data/)

## 7. 三类典型 PCN Network 形态

PCN Network 可以存在于不同工程层级。

### 自动化执行单元

例如：

```text
等待 → 抓取前 PCN → 抓取

抓取完成 → 投放前 PCN → 投放

投放完成 → 后续阶段 PCN 
```

一个自动化执行单元内部即可形成多个关键 PCN。

这些节点之间主要体现连续状态推进、许可依赖和执行链接续关系。

---

### MES / WCS 与多设备协同

例如：

```text
任务生成 → 任务执行前 PCN → 执行

到达站点 → 站点承接前 PCN → 交接

执行完成 → 结果回写前 PCN → 完成
```

这一层的 PCN 可以跨越任务、资源、路径、站点、执行主体和下游状态。

节点之间还可能存在共享资源、调度许可和群体执行关系。

---

### 生产 DX 与跨系统状态迁移

例如：

```text
质量确认 → 下一工序前 PCN → 工序进入

保全解除 → 自动复归前 PCN → 恢复运行

异常处理完成 → 再投入前 PCN → 重新执行
```

这些 PCN 可以跨越设备、人员、MES、质量和保全系统。

不同场景的共同点并不是系统类型相同，而是：

> **都存在明确且具有独立工程管理价值的目标状态入口。**

---

## 工程结论

单个 PCN 对应一个明确的目标状态入口。

多个 PCN 按照实际状态迁移关系以及必要的许可、资源和执行依赖关系连接以后，可以进一步形成 PCN Network。

PCN Network 不是设备连接图，也不是中央控制系统。

它表达的是：

> **复杂工程系统中，关键目标状态入口及其相互依赖关系构成的工程网络。**

因此：

> **“这里需要增加一个 PCN 点”**

可以作为复杂工程系统设计中的一种简化工程语言。

它实际表达的是：

> **“这里存在一个重要的目标状态入口，需要被独立设计、判定、控制和记录。”**

当多个这样的目标状态入口被持续识别、设计并按照实际工程关系连接以后，TPCA 才从单个 PCN 进一步扩展为系统级状态迁移前置控制架构。
