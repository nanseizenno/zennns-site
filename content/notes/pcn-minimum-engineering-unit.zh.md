TPCA 是状态迁移前置控制架构。

PCN（Pre-Control Node）是部署在明确状态迁移入口前的前置控制节点。

CAE-SDB 是 PCN 内部的结构化判定逻辑。

一个 PCN 围绕一次明确的目标状态进入，把本次状态迁移所需要的输入、判定、仲裁、控制和履历组织在同一个工程节点中。

其基本结构为：

```text
当前状态
→ 目标状态
→ PCN
    ├─ 多源状态信号
    ├─ C/A/E 状态映射
    ├─ S/D/B 判定
    ├─ CAE-SDB 判定结果
    ├─ 控制仲裁
    ├─ 多路径控制
    └─ PCN Trace
```

因此，PCN 是 TPCA 从架构进入具体工程系统时的最小工程节点。

## 1. PCN 位于明确的状态迁移入口前

TPCA 面向的是目标状态、目标执行路径或目标物理执行阶段进入之前的前置判定与控制。

因此，在设置 PCN 之前，需要先明确：

```text
当前状态
→ 目标状态
```

PCN 设置在这一次状态迁移真正发生之前。

例如：

```text
机器人等待
→ PCN
→ 进入抓取阶段
```

PCN 在机器人进入抓取阶段之前完成前置判定。

再例如：

```text
检测完成
→ PCN
→ 正常分流 / 异常分流 / 其他处理路径
```

PCN 在系统进入目标处理路径之前完成判定和控制分流。

因此：

> **一个 PCN 对应一个明确的状态迁移入口。**

同一台复杂设备可以存在多个状态迁移入口，也可以设置多个 PCN。

跨设备、跨控制器、跨上位系统或包含人工确认的状态迁移，同样可以设置 PCN。

## 2. 一个 PCN 的基本工程结构

一个 PCN 至少围绕以下对象展开：

| 对象 | 工程含义 |
|---|---|
| 当前状态 | 系统当前所处的状态、阶段或执行位置 |
| 目标状态 | 系统准备进入的目标状态、目标路径或目标阶段 |
| PCN 位置 | 前置判定设置在哪一个状态迁移入口 |
| 多源状态信号 | 本次状态迁移需要读取哪些状态 |
| C/A/E 状态映射 | 将相关状态映射到条件、许可和执行链三个变量域 |
| S/D/B 判定 | 从结构完整性、动态时序有效性和控制边界进行判定 |
| CAE-SDB 判定结果 | 形成一个或多个结构化判定结果 |
| 控制仲裁 | 处理多个判定结果及控制约束之间的优先关系 |
| 多路径控制 | 输出最终控制路径 |
| PCN Trace | 记录本次判定、控制和执行履历 |

这些对象共同构成一次目标状态进入前的完整前置控制闭环。

---

## 3. 为什么称为“最小工程节点”

PCN 的“最小”，指的是：

> **一个完整的状态迁移前置控制闭环，最终必须落实到一个明确的状态迁移入口。**

再向下拆分，可以得到：

- 单个现场信号；
- 单个 Ready；
- 单个许可；
- 单个 Interlock；
- 单个 S/D/B 判定；
- 单个 CAE-SDB 判定结果；
- 单个控制动作。

这些都可以作为 PCN 内部的一部分，但不能单独代表一次完整的状态迁移前置控制。

PCN 则围绕一个明确入口，把这些对象组织为：

```text
状态迁移入口
→ 多源状态信号
→ C/A/E 状态映射
→ S/D/B 判定
→ CAE-SDB 判定结果
→ 控制仲裁
→ 多路径控制
→ PCN Trace
```

因此，PCN 是 TPCA 中能够保持完整工程意义的最小节点。

## 4. PCN 如何组织分散的现场状态

复杂工程系统中的状态通常分散在不同设备和系统中。

例如机器人准备进入抓取阶段时，相关状态可能来自：

- 视觉系统；
- 机器人控制器；
- PLC；
- 安全系统；
- 主输送系统；
- 正常投放位；
- 返回路径；
- 异常分流路径；
- 上位系统。

PCN 围绕“进入抓取阶段”这一目标状态，对这些状态重新进行工程语义组织。

### C：Condition

表示进入目标状态前的条件是否成立，例如：

- 工件存在；
- 视觉结果有效；
- 工件位置满足要求；
- 姿态满足要求。

### A：Authority

表示系统是否允许进入目标状态，例如：

- 安全许可；
- 区域许可；
- 上位系统许可；
- 本次动作许可；
- 必要人工确认。

关键 A 可以构成独立必要约束。

### E：Execution Chain

表示进入目标状态以后，整个执行链是否能够继续接续，例如：

- 机器人路径可达；
- 夹爪可用；
- 正常投放位可承接；
- 返回路径可用；
- 异常分流路径可用；
- 结果回写链路可接续。

随后，PCN 对 C / A / E 从 S / D / B 三类性质进行判定：

```text
C/A/E 状态映射
→ S/D/B 判定
→ CAE-SDB 判定结果
```

同一次状态迁移可以形成多个 CAE-SDB 判定结果。

这些结果经过控制仲裁，最终形成多路径控制。

例如：

- 正常抓取；
- 等待；
- 重识别；
- 重定位；
- 回流；
- 异常分流；
- 人工确认；
- 禁止进入；
- 安全相关控制路径。

[自动化执行单元前置判定案例](/zh/cases/automation-execution-unit-pre-control/)

## 5. PCN 可以部署在不同工程层级

PCN 不是某一种固定硬件或软件形式。

它的工程形态取决于目标状态迁移发生在哪一个系统层级。

### 自动化执行单元

PCN 可以设置在：

- 机器人抓取前；
- 压装执行前；
- 检测执行前；
- 搬送交接前；
- 正常分流或异常分流前。

工程实现可以结合：

- PLC；
- 工业控制器；
- 边缘控制器；
- HMI；
- 自动化平台软件。

### MES / WCS 与群控协同

PCN 可以围绕以下状态迁移入口设置：

- 任务进入执行前；
- 资源使用前；
- 站点承接前；
- 区域进入前；
- 关键协同状态恢复前。

### 生产 DX

PCN 可以围绕以下状态迁移入口设置：

- 质量放行前；
- 工单切换后的目标生产状态进入前；
- 保全解除后的再投入前；
- 人工确认后的自动恢复前；
- 下游生产状态进入前。

不同场景中的输入和控制路径不同，但 PCN 的基本结构保持一致：

```text
当前状态
→ 目标状态
→ 多源状态信号
→ C/A/E 状态映射
→ S/D/B 判定
→ CAE-SDB 判定结果
→ 控制仲裁
→ 多路径控制
→ PCN Trace
```

## 6. PCN Trace 记录一次状态迁移判定

PCN 在完成当前控制的同时，可以形成对应的 PCN Trace。

一条 PCN Trace 围绕一次具体状态迁移，可以关联：

- PCN；
- 当前状态；
- 目标状态；
- 关键输入状态；
- 时间、版本和对象信息；
- C/A/E 状态映射；
- S/D/B 判定；
- CAE-SDB 判定结果；
- 控制仲裁结果；
- 多路径控制结果；
- 执行结果；
- Trace ID。

这些记录使工程师能够进一步观察：

- 哪些状态迁移入口频繁出现问题；
- 哪些 C / A / E 变量长期不成立；
- 哪些 S / D / B 判定反复出现；
- 哪些控制路径频繁触发；
- 某次工程改善以后，判定结果和执行结果发生了什么变化。

这样，分析对象不再只是零散报警或设备状态，而是一次完整的状态迁移判定履历。

---

## 7. 从单个 PCN 到 PCN 网络

单个 PCN 对应一个明确的状态迁移入口。

复杂工程系统通常包含多个连续、并行或相互依赖的状态迁移入口。

例如：

```text
PCN-01
等待 → 抓取

        ↓

PCN-02
抓取完成 → 搬送

        ↓

PCN-03
搬送完成 → 投放

        ↓

PCN-04
投放完成 → 后续处理
```

这些 PCN 按实际状态迁移关系连接以后，可以形成 PCN 网络。

单个 PCN 负责一个明确的状态迁移入口。

多个 PCN 的连接关系则构成更高层级的状态迁移前置控制结构。

## 小结

TPCA 是状态迁移前置控制架构。

PCN 是部署在明确状态迁移入口之前的前置控制节点。

CAE-SDB 是 PCN 内部的结构化判定逻辑。

一个 PCN 围绕一次明确的状态迁移，形成：

```text
当前状态
→ 目标状态
→ PCN
    ├─ 多源状态信号
    ├─ C/A/E 状态映射
    ├─ S/D/B 判定
    ├─ CAE-SDB 判定结果
    ├─ 控制仲裁
    ├─ 多路径控制
    └─ PCN Trace
```

因此：

> **PCN 是 TPCA 中能够保持完整状态迁移前置控制闭环的最小工程节点。**

从单个 PCN 开始，TPCA 可以进一步扩展到多个状态迁移入口，并形成 PCN 网络。
