TPCA 是状态迁移前置控制架构。

PCN（Pre-Control Node）是部署在明确目标状态入口前的前置控制节点。

CAE-SDB 是 PCN 内部的结构化判定逻辑。

一个 PCN 围绕一次明确的目标状态进入，将与本次状态迁移有关的输入、判定、仲裁、控制和履历组织到同一个工程节点中。

其基本结构为：

```text
当前状态
→ 目标状态
→ PCN
    ├─ 多源状态信号
    ├─ C / A / E 状态映射
    ├─ S / D / B 判定
    ├─ CAE-SDB Result
    ├─ 控制仲裁
    ├─ 多路径控制
    └─ PCN Trace
```

因此，PCN 是 TPCA 从总体架构落实到具体工程系统时，能够完整保持一次状态迁移前置控制闭环的最小工程节点。

## 1. PCN 位于明确的目标状态入口前

TPCA 面向的是目标状态、目标执行路径或目标物理执行阶段进入之前的前置判定与控制。

因此，在设置 PCN 之前，需要先明确：

```text
当前状态
→ 目标状态
```

PCN 设置在本次状态迁移真正发生之前。

例如：

```text
机器人等待
→ PCN
→ 进入抓取阶段
```

PCN 在机器人真正进入抓取阶段之前完成前置判定。

再例如：

```text
检测完成
→ PCN
→ 正常分流 / 异常分流 / 其他处理路径
```

PCN 在系统进入目标处理路径之前完成判定和控制分流。

因此：

> **一个 PCN 对应一个明确的目标状态入口。**

同一台复杂设备可以存在多个目标状态入口，也可以设置多个 PCN。

跨设备、跨控制器、跨上位系统，或者包含人工确认的状态迁移，只要存在明确的目标状态入口，同样可以设置相应 PCN。

## 2. 一个 PCN 的基本工程构成

一个 PCN 至少围绕以下对象展开：

| 对象 | 工程含义 |
|---|---|
| 当前状态 | 系统当前所处的状态、阶段或执行位置 |
| 目标状态 | 系统准备进入的目标状态、目标路径或目标阶段 |
| PCN 位置 | 前置判定设置在哪一个目标状态入口 |
| 多源状态信号 | 本次状态迁移需要读取哪些相关状态 |
| C / A / E 状态映射 | 将相关状态映射到条件、许可和执行链三个状态变量域 |
| S / D / B 判定 | 从结构完整性、动态时序有效性和控制边界进行判定 |
| CAE-SDB Result | 形成一个或多个结构化判定结果 |
| 控制仲裁 | 处理多个判定结果及控制约束之间的优先关系 |
| 多路径控制 | 形成最终工程控制路径 |
| PCN Trace | 记录本次判定、控制和执行履历 |

这些对象共同构成一次目标状态进入前的完整前置控制闭环。

这里的“完整”并不表示所有 PCN 必须具有完全相同的输入数量、判定规则或控制路径。

不同工程对象可以具有不同实现规模。

需要保持一致的是：

> **PCN 始终围绕一个明确的目标状态入口，完成从状态输入到判定、控制和履历的完整工程关系。**

## 3. 为什么称为“最小工程节点”

PCN 的“最小”不是指：

- 最少的信号数量；
- 最小的软件模块；
- 最小的 PLC 功能块；
- 最少的判定规则。

这里的“最小”指的是：

> **在 TPCA 中，能够完整保持一次目标状态入口前置判定、控制输出和判定履历关系的最小工程组织单元。**

如果继续向下拆分，可以得到：

- 单个现场信号；
- 单个 Ready；
- 单项许可；
- 单个 Interlock；
- 单项 S / D / B 判定；
- 单个 CAE-SDB Result；
- 单个控制动作。

这些对象都可以成为 PCN 的组成部分，但任意一个对象单独存在时，都不能完整代表一次状态迁移前置控制。

PCN 则围绕一个明确的目标状态入口，将这些对象组织为：

```text
目标状态入口
→ 多源状态信号
→ C / A / E 状态映射
→ S / D / B 判定
→ CAE-SDB Result
→ 控制仲裁
→ 多路径控制
→ PCN Trace
```

因此：

> **PCN 是 TPCA 中能够保持完整工程语义和控制闭环的最小工程节点。**

## 4. PCN 如何组织分散的现场状态

复杂工程系统中的状态通常分散在不同设备和系统中。

例如，机器人准备进入抓取阶段时，相关状态可能来自：

- 视觉系统；
- 机器人控制器；
- PLC；
- 安全系统；
- 主输送系统；
- 正常投放位；
- 返回路径；
- 异常分流路径；
- 上位系统。

PCN 围绕“进入抓取阶段”这一明确目标状态入口，对这些状态重新组织其工程含义。

### C：Condition

表示进入目标状态前的事实条件是否成立，例如：

- 工件存在；
- 视觉结果有效；
- 工件位置满足要求；
- 姿态满足要求。

### A：Authority

表示系统当前是否被允许进入目标状态，例如：

- 安全许可；
- 区域许可；
- 上位系统许可；
- 本次动作许可；
- 必要人工确认。

关键 A 可以构成独立必要约束。

### E：Execution Chain

表示进入目标状态以后，整个执行链是否能够继续接续，例如：

- 机器人路径可达；
- 夹爪可用；
- 正常投放位可承接；
- 返回路径可用；
- 异常分流路径可用；
- 结果回写链路可接续。

完成 C / A / E 状态映射后，PCN 进一步按照 S / D / B 三类判定性质进行分析：

```text
C / A / E 状态映射
→ S / D / B 判定
→ CAE-SDB Result
```

同一次状态迁移可以同时形成多个 CAE-SDB Result。

这些结果经过控制仲裁以后，再形成最终多路径控制。

代表性控制路径可以包括：

- 正常进入；
- 等待；
- 重识别；
- 重定位；
- 回流；
- 异常分流；
- 人工确认；
- 禁止进入；
- 安全相关控制路径。

[自动化执行单元前置判定案例](/zh/cases/automation-execution-unit-pre-control/)

## 5. PCN 可以部署在不同工程层级

PCN 不是某一种固定硬件或软件形式。

它的工程实现取决于目标状态入口位于哪一个系统层级。

### 自动化执行单元

PCN 可以设置在：

- 机器人抓取前；
- 压装执行前；
- 检测执行前；
- 搬送交接前；
- 正常分流或异常分流前。

具体实现可以结合：

- PLC；
- 工业控制器；
- 边缘控制器；
- HMI；
- 自动化平台软件。

### MES / WCS 与群控协同

PCN 可以围绕以下目标状态入口设置：

- 任务进入执行前；
- 资源使用前；
- 站点承接前；
- 区域进入前；
- 关键协同状态恢复前。

### 生产 DX

PCN 可以围绕以下目标状态入口设置：

- 质量放行前；
- 工单切换后的目标生产状态进入前；
- 保全解除后的再投入前；
- 人工确认后的自动恢复前；
- 下游生产状态进入前。

不同场景中的输入、判定规则和控制路径可以不同，但 PCN 的基本工程关系保持一致：

```text
当前状态
→ 目标状态
→ PCN
→ 多源状态信号
→ C / A / E 状态映射
→ S / D / B 判定
→ CAE-SDB Result
→ 控制仲裁
→ 多路径控制
→ PCN Trace
```

因此，PCN 的统一性不在于采用同一种软件实现，而在于：

> **不同系统都围绕明确目标状态入口形成相同层级的前置判定、控制和履历结构。**

## 6. PCN Trace 记录一次状态迁移判定

PCN 在完成本次前置判定和控制输出的同时，可以形成对应的 PCN Trace。

一条 PCN Trace 围绕一次具体目标状态进入，可以关联：

- PCN；
- 当前状态；
- 目标状态；
- 关键输入状态；
- 时间、版本和对象信息；
- C / A / E 状态映射；
- S / D / B 判定；
- CAE-SDB Result；
- 控制仲裁结果；
- 多路径控制结果；
- 执行结果；
- Trace ID。

这些记录使工程分析对象由零散报警或单个设备状态，进一步转变为一次完整的状态迁移判定履历。

长期积累以后，可以进一步观察：

- 哪些目标状态入口频繁不能成立；
- 哪些 C / A / E 状态变量长期存在问题；
- 哪些 S / D / B 判定反复出现；
- 哪些控制路径被高频触发；
- 工程修改以后，判定结果和执行结果发生了什么变化。

因此，PCN Trace 不是 PCN 的附加日志。

它是 PCN 完成一次状态迁移判定闭环后形成的工程履历对象。

## 7. 从单个 PCN 到 PCN Network

单个 PCN 对应一个明确的目标状态入口。

复杂工程系统通常包含多个连续、并行或相互依赖的状态迁移入口。

例如：

```text
PCN-01
等待 → 抓取

        ↓

PCN-02
抓取完成 → 搬送

        ↓

PCN-03
搬送完成 → 投放

        ↓

PCN-04
投放完成 → 后续处理
```

这些 PCN 按实际状态迁移关系连接以后，可以形成 PCN Network。

单个 PCN 负责一个明确的目标状态入口。

多个 PCN 之间的状态迁移关系，则构成更高层级的状态迁移前置控制结构。

因此，PCN Network 不是简单的设备连接图，也不是把所有控制逻辑集中到一个中央节点。

它表达的是：

> **多个明确目标状态入口之间的工程关系。**

## 小结

TPCA 是状态迁移前置控制架构。

PCN 是部署在明确目标状态入口前的前置控制节点。

CAE-SDB 是 PCN 内部的结构化判定逻辑。

一个 PCN 围绕一次明确的目标状态进入，形成：

```text
当前状态
→ 目标状态
→ PCN
    ├─ 多源状态信号
    ├─ C / A / E 状态映射
    ├─ S / D / B 判定
    ├─ CAE-SDB Result
    ├─ 控制仲裁
    ├─ 多路径控制
    └─ PCN Trace
```

因此：

> **PCN 是 TPCA 中能够完整保持一次目标状态入口前置判定、控制输出和判定履历闭环的最小工程节点。**

从单个 PCN 开始，TPCA 可以进一步扩展到多个目标状态入口，并通过这些节点之间的状态迁移关系形成 PCN Network。
