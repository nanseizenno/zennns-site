机器视觉、优化算法、预测模型和强化学习正在不断提高自动化系统的识别、预测和决策能力。

视觉系统可以识别工件的位置和姿态，优化算法可以计算路径和资源配置，预测模型可以识别异常趋势，强化学习可以根据长期结果学习策略。

当这些算法的输出进入物理系统时，问题会变得更加具体。例如：

- 机器人是否开始抓取；
- 工件是否放行；
- AGV 是否进入某一区域；
- 设备是否恢复自动运行；
- 下一工序是否开始。

这些动作都对应一次实际的状态迁移。

控制系统最终需要在具体入口上形成明确的工程结果，例如允许进入、保持当前状态、切换路径或禁止执行。

本文所说的“确定性判定”，是指在一个明确的状态迁移入口上，根据当前可用状态和既定控制约束，形成可执行、可复核的控制结果。

上游的识别、预测、估计和优化仍然可以采用概率模型、统计模型或学习算法。进入物理执行之前，则需要把算法输出放回当前实际状态迁移中进行工程判定。

---

## 1. 算法输出与执行许可是两类工程结果

智能算法通常输出识别结果、预测值、风险概率、候选路径、优化结果或策略建议。

例如：

```text
视觉识别结果：对象位置与姿态
路径优化结果：路径 B
故障预测结果：未来一定时间内风险上升
```

这些结果可以直接参与后续控制，但不能单独决定物理动作是否执行。

机器人开始抓取之前，控制系统还要确认当前工件是否仍在有效抓取区域、视觉结果是否仍属于当前对象、安全许可是否成立、机器人是否处于正确模式、末端执行机构是否可用、下游是否能够承接，以及当前任务是否仍然有效。

进入物理执行前需要确认：

> **当前这一组工程状态，是否足以支持本次状态迁移？**

物理执行还会直接改变现实状态。

机器人开始动作后，工件位置和设备状态会发生变化；输送线放行后，工件进入下一区域；AGV 进入共享路径后，相关资源占用状态随之变化；设备恢复自动运行后，新的执行链开始形成。

所以，状态迁移入口需要具有明确的控制责任边界。

控制系统使用的状态本身也具有时间属性。

`Robot Ready = TRUE` 只说明某一时点取得了 Ready 状态。真正准备进入下一阶段时，还要确认这个状态是否仍然有效，是否发生超时、未刷新、不同步、许可撤销或状态切换。

物理执行前至少需要明确两个问题：

- 当前需要观察哪些状态；
- 这些状态现在是否仍能够支持本次状态迁移。

## 2. 从推荐结果到执行控制

假设路径优化算法计算得到路径 B 的综合代价最低。

对于优化算法，这一结果已经完成当前计算任务。

进入实际调度和执行以后，系统还要确认路径 B 当前是否开放、共享资源是否被占用、区域许可是否成立、目标站点是否可接收、车辆当前状态是否允许进入，以及进入以后后续路径是否能够继续。

这里涉及两个不同的工程对象：

| 对象 | 主要内容 |
|---|---|
| 算法输出 | 哪一种识别、预测、路径或策略更符合当前优化目标 |
| 执行控制 | 当前是否允许实际进入对应的目标状态或执行路径 |

生产系统中的启动、进入、放行、转移、接收、恢复和切换等动作，都可以看作离散事件。

离散事件系统研究由事件驱动的状态变化。监督控制进一步研究如何依据控制规范，对可控事件进行约束，使系统行为满足预定要求。

从这个角度看，“下一步是否允许发生”本身就是一个正式的控制问题。

复杂自动化系统还需要把这个控制问题落实到具体工程对象上：本次状态迁移涉及哪些状态，这些状态为什么需要参与当前判断，它们在这次迁移中承担什么作用。

---

## 3. 状态表示决定后续能够判断什么

算法能够处理什么，首先取决于系统提供了什么状态表示。

假设视觉与机器人系统已经提供视觉结果、置信度和 Robot Ready。如果系统没有同时表示安全许可、生产许可、下游承接状态、视觉结果的时序有效性、位置边界和相关执行链状态，那么后续算法能够处理的工程关系已经受到输入表示的限制。

强化学习研究同样重视状态表示。复杂或高维观测通常需要转换成能够支持后续决策的状态表示。状态表示会影响学习效率、泛化能力和最终策略表现。

制造系统中的问题更加具体。

现场可能有数千个设备 Tag、多个任务系统、资源状态、安全许可和人工状态。对于“机器人是否可以进入抓取阶段”，与该入口直接相关的只是一部分状态；对于“AGV 是否可以进入某个站点”，所需观察的状态集合又会变化。

所以，状态组织至少需要同时考虑两个信息：

- 状态对象本身是什么；
- 当前准备发生哪一次状态迁移。

同一个状态对象进入不同 Target State Entry 时，其工程作用也可能不同。

对于状态迁移控制，工程顺序可以概括为：

> **先确定观察对象和相关状态，再明确这些状态如何判定，最后选择适合的控制或分析方法。**

如果状态迁移对象和状态表示尚未明确，后续规则、优化算法、机器学习或大语言模型只能在已有表示范围内工作。

TPCA / PCN 将一次明确的状态迁移入口定义为 Target State Entry（目标状态入口），并以此作为状态组织和前置判定的工程对象。

---

## 4. TPCA / PCN 如何组织目标状态入口前的判定

TPCA / PCN 将明确的 Target State Entry 作为可以独立设计、判定、控制和记录的工程对象。

一个 PCN 对应一个明确的 Target State Entry，并部署在该入口之前。

PCN 首先取得与本次状态迁移直接相关的状态，再按照这些状态在当前入口中的工程作用进行 C / A / E Mapping：

- **C = Condition**：进入目标状态所需条件是否成立；
- **A = Authority**：当前是否获得进入目标状态的许可；
- **E = Execution Chain**：进入目标状态以后，相关执行链是否能够继续接续。

例如，机器人准备进入抓取阶段时，工件位置可以属于 C，区域许可属于 A，下游接收状态和机器人执行链相关状态可以属于 E。

同一个状态对象进入另一个 Target State Entry 后，可以承担不同的工程角色。

完成 C / A / E Mapping 后，再按照当前入口已经定义的规则执行 S / D / B Evaluation：

- **S = Structure**：判定所需的信号、接口、映射、许可来源、路径和执行链边界是否已经定义、接入并可观测；
- **D = Dynamics**：相关状态在当前时点是否仍然有效，包括超时、未刷新、延迟、不同步、许可撤销和状态切换等；
- **B = Boundary**：相关状态是否仍处于预先定义的允许范围或控制边界内，包括阈值、容差、容量、时间窗口、次数和置信度等。

C / A / E 与 S / D / B 组合后形成 CAE-SDB Result。

同一次 Target State Entry 中可以同时出现多个判定结果。控制仲裁根据完整判定结果、关键许可和预先定义的控制约束确定控制方向，再形成对应的 Multipath Control。

实际控制路径可以包括允许进入、等待、重新识别、重新定位、回流、替代路径、人工确认、禁止进入或安全锁定等。

控制路径执行后，系统取得实际执行结果。本次使用的状态、CAE-SDB Result、控制仲裁结果、多路径控制、执行结果和时间信息进一步形成 PCN Trace。

这样，一次状态迁移就具有了完整的工程上下文：

- 准备进入什么目标状态；
- 使用了哪些相关状态；
- 这些状态分别承担什么工程作用；
- 执行了什么判定；
- 为什么形成当前控制结果；
- 实际执行以后发生了什么。

TPCA / PCN 在这里承担的是状态迁移工程结构的组织工作。确定性控制、优化算法和学习算法可以在这一结构中分别承担适合自己的功能。

---

## 5. 从单个 Target State Entry 到 PCN Network

在单个自动化执行单元中，可以围绕抓取、放置、检测、压装、恢复等不同 Target State Entry 分别设置 PCN。

系统扩展到 AGV / AMR 群控、MES / WCS 协同和多设备自动化以后，会同时存在更多目标状态入口，例如任务进入执行、车辆进入区域、资源进入占用、站点进入接收以及设备恢复运行等。

不同 PCN 之间的工程关系，由实际状态变化形成。

当 PCN-A 的控制路径执行后，Execution Result 形成 State Update；如果该更新形成或改变某项工程状态事实，并成为 PCN-B 对应 Target State Entry 的相关输入，实际改变其判定环境，那么 PCN-A 与 PCN-B 之间形成直接 PCN Dependency。

PCN-B 随后读取更新后的状态事实，调用自身已经定义的 C / A / E Mapping，并重新执行适用的 S / D / B 判定。

跨节点传播的是实际工程状态事实。上游 PCN 已经形成的 CAE-SDB Result 保留在自身 PCN Trace 中，不直接作为下游 PCN 的判定结果。

例如，AGV-A 改道后，如果共享路径占用状态发生变化，并进一步成为 AGV-B 或 Station-C 对应 Target State Entry 的相关输入，就会改变后续 PCN 的判定环境。

多个 PCN 及其之间成立的 PCN Dependency 共同构成 PCN Network。

这样，单个状态迁移入口上的前置判定可以继续扩展到多主体、多设备和跨系统的状态迁移关系，同时保持各 PCN 自己的局部判定语义。

## 总结

智能算法可以提供识别、预测、优化和策略结果。

当这些结果进入物理系统时，控制系统还要面对一次具体的状态迁移：当前有哪些状态与这次进入有关，这些状态是否有效，必要许可是否成立，执行链能否接续，以及最终应选择哪一条控制路径。

TPCA / PCN 将这一过程组织在明确的 Target State Entry 上。

Target State Entry 确定本次状态迁移对象；C / A / E 描述相关状态在当前迁移中的工程作用；S / D / B 对这些状态执行结构、动态和边界判定；CAE-SDB Result 进入控制仲裁并形成多路径控制；执行后的实际结果和时间信息继续形成 PCN Trace。

当执行结果进一步改变其他 Target State Entry 的判定环境时，多个 PCN 之间形成 PCN Dependency，并扩展为 PCN Network。

状态迁移前置控制关注的，是智能算法输出进入实际工程执行之前，相关状态如何围绕一次明确的目标状态进入被组织、判定、控制和记录。
