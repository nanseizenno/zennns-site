## なぜ PCN は TPCA の最小エンジニアリングノードなのか？

TPCA は、システムが目標状態へ移行する直前の判定と制御を、明確な**目標状態入口**ごとに設計するための状態遷移前制御アーキテクチャである。

PCN（Pre-Control Node / 前制御ノード）は、その考え方を具体的な状態遷移へ適用するための基本単位である。

一つの PCN は、一つの明確な目標状態入口を担当する。

その入口に対して必要となる状態を収集し、C / A / E へ整理し、S / D / B の観点から判定し、その結果を制御へつなげ、実行結果まで含めて PCN Trace として記録する。

基本的な流れは次のとおりである。

```text
現在状態
    ↓
PCN
    ↓
目標状態入口
    ↓
目標状態
```

PCN 内部では、対象となる状態遷移に対して、次の処理が行われる。

```text
関連状態
→ C / A / E Mapping
→ S / D / B Evaluation
→ CAE-SDB Result + T
→ 制御優先度調停
→ 複数経路制御
→ 実行結果
→ PCN Trace
```

ここで、

```text
C = Condition         条件状態
A = Authority         許可状態
E = Execution Chain   実行チェーン状態

S = Structure         構造完全性
D = Dynamics          動的時系列有効性
B = Boundary          制御境界
```

を表す。

PCN を「最小」と呼ぶ理由は、信号数やソフトウェア規模が小さいからではない。

一つの状態遷移について、

- 何を根拠に判定したか
- どのような判定結果になったか
- どの制御経路を選択したか
- 実際に何が起きたか
- その結果をどのように記録したか

という一連の関係を、分断せずに扱える最小単位だからである。

## 1. PCN は一つの目標状態入口を担当する

PCN を設計する際には、最初に現在状態、目標状態、そしてその間にある目標状態入口を明確にする。

たとえば、ロボットが待機状態から把持段階へ移行する場合は、次のように整理できる。

```text
ロボット待機
    ↓
PCN
    ↓
目標状態入口
    ↓
把持段階
```

PCN は、ロボットが実際に把持段階へ入る前に、必要な状態を確認し、その遷移を許可できるかを判定する。

複雑な設備や生産システムでは、状態遷移入口は一つとは限らない。

同じロボットであっても、

- 待機から把持
- 把持から搬送
- 搬送から配置
- 異常発生時の退避
- 再投入
- 回流

といった複数の状態遷移が存在する。

それぞれで必要な条件、許可、実行チェーンは異なるため、必要に応じて個別の PCN を設定する。

PCN の境界は、設備台数や PLC 台数で決まるものではない。

**独立して判定・制御・記録すべき状態遷移入口がどこにあるか**

によって決まる。

目標状態入口は、状態遷移そのものの入口であり、PCN はその入口の直前で前制御を担当する。

この二つは密接に対応するが、同じものではない。

---

## 2. PCN が一つの単位として扱う情報

一つの PCN が扱う範囲は、単なる判定ロジックにとどまらない。

目標状態入口を基準として、その遷移に必要な情報と結果を一つの単位として扱う。

| 対象 | 役割 |
|---|---|
| 目標状態入口 | PCN が担当する状態遷移を定める |
| 関連状態 | 状態遷移に必要な状態を各システムから取得する |
| CAE-SDB | 関連状態を構造化して判定する |
| 制御優先度調停 / 複数経路制御 | 判定結果から実際の制御経路を決定する |
| 実行結果 | 制御後に現実に発生した結果を確認する |
| PCN Trace | 判定から実行結果までを一つの履歴として残す |

ここで重要なのは、これらがすべて同じ状態遷移に紐付いていることである。

状態情報が PLC、ロボット、安全システム、MES、WCS、画像認識システムなどに分散していても、それらが同じ目標状態入口に関係するのであれば、一つの状態遷移コンテキストとして扱う。

PCN ごとに入力信号数や判定規則、制御経路が異なっていても問題はない。

PCN として共通しているのは、

**一つの状態遷移について、入力・判定・制御・結果・履歴を連続して扱うこと**

である。

---

## 3. 「最小」の意味は状態遷移の責任境界にある

PCN の最小性は、物理的な大きさやプログラム規模ではなく、状態遷移に対する責任範囲から決まる。

一つの信号は、一つの局所状態しか示さない。

`Robot Ready = TRUE` であっても、それだけでは把持を開始してよいかどうかは分からない。

安全許可が成立していても、下流が受入不能であれば、その状態遷移は成立しない可能性がある。

逆に、ある CAE-SDB 判定結果が得られても、それだけでは最終的にどの制御経路を選ぶかは決まらない。

したがって、単一信号、単一判定、単一制御出力だけでは、一回の状態遷移を説明するには不十分である。

必要なのは、

> **今回の状態遷移について、何を見て、どう判定し、どの制御を選び、その結果どうなったか**

を一続きで扱える単位である。

PCN は、その最小単位に相当する。

```text
目標状態入口
        ↑
       PCN
        │
        ├─ 関連状態
        ├─ CAE-SDB
        ├─ 制御優先度調停
        ├─ 複数経路制御
        ├─ 実行結果
        └─ PCN Trace
```

複数の目標状態入口を一つの PCN にまとめ過ぎると、どの判定がどの状態遷移に対するものかが曖昧になる。

一方、単一信号や単一判定まで細分化すると、状態遷移全体を一貫して扱えなくなる。

そのため PCN は、

> **一つの目標状態入口について、入力から判定、制御、実行結果、履歴までを一貫して扱える最小のエンジニアリングノード**

として位置付けられる。

---

## 4. 分散した状態を一つの状態遷移へ結び付ける

複雑な自動化システムでは、一回の状態遷移に必要な情報が複数の装置やシステムに分散している。

ロボットが把持段階へ入る場面を考えると、必要な情報は例えば次のように分散している。

- 画像認識システム：ワーク位置、姿勢、認識結果
- ロボットコントローラ：Ready、動作可能状態
- PLC：工程状態、搬送状態
- 安全システム：安全許可
- 搬送設備：ワーク位置、搬送状態
- 下流設備：受入可能状態
- 上位システム：生産許可、タスク状態

これらを一か所へ集約して保存すること自体が目的ではない。

重要なのは、

**今回の把持入口に対して、どの状態が必要なのか**

をあらかじめ定義しておくことである。

PCN は、その定義に従って必要な状態を取得し、本状態遷移に対する判定を行う。

```text
画像認識システム
ロボットコントローラ
PLC
安全システム
搬送設備
下流設備
上位システム
      ↓
関連状態
      ↓
PCN
      ↓
C / A / E Mapping
      ↓
S / D / B Evaluation
      ↓
CAE-SDB Result
```

この構成により、

**状態がどこに保存されているか**

と、

**その状態を今回の遷移でどのような意味で使うか**

を分けて設計できる。

PCN は、すべての現場データを集中管理するための中央ノードではない。

対象となる状態遷移に必要な情報だけを扱い、その判定と制御の責任範囲を明確にする。

関連する具体例については、以下を参照できる。

- [自動化実行ユニット前判定事例](/jp/cases/automation-execution-unit-pre-control/)

## 5. PCN は論理的な責任単位であり、実装形式を限定しない

PCN は、特定のハードウェアやソフトウェア製品を意味するものではない。

状態遷移前制御における**論理的な責任単位**である。

そのため、実装形態は対象システムによって異なる。

たとえば、

- PLC の標準機能ブロック
- 産業用コントローラ
- エッジ制御モジュール
- MES / WCS 上のソフトウェア機能
- AI ゲートウェイの前制御機能

などとして実装できる。

また、ロボット、安全システム、画像認識システム、下流設備、上位システムと必要な情報をやり取りする構成も取り得る。

実装形態が異なっても、PCN の基本構造は変わらない。

```text
現在状態
    ↓
PCN
    ↓
目標状態入口
    ↓
目標状態
```

対象となる状態遷移について必要な状態を取得し、前制御判定を行い、制御経路を決定し、実行結果を取得し、その一連の結果を PCN Trace として残す。

PCN の本質は、どこに実装されているかではなく、

**一つの状態遷移をどこまで一貫して担当するか**

にある。

## まとめ

PCN（Pre-Control Node / 前制御ノード）は、TPCA を具体的な状態遷移へ適用するための基本単位である。

一つの PCN は、一つの明確な目標状態入口を担当する。

その中では、

```text
関連状態
→ CAE-SDB
→ 制御優先度調停
→ 複数経路制御
→ 実行結果
→ PCN Trace
```

という一連の関係が維持される。

PCN における「最小」とは、信号数が最少であることや、プログラムが小さいことを意味しない。

> **一つの目標状態入口について、状態入力、構造化判定、制御選択、実行結果、運転履歴までを一貫して扱える最小のエンジニアリングノードである。**

PCN をこの単位で設計することで、TPCA の状態遷移前制御を、設備、自動化実行ユニット、MES / WCS、その他のシステム階層に存在する具体的な状態遷移入口へ展開できる。
