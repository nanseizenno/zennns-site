TPCA は、状態遷移前制御アーキテクチャである。

PCN（Pre-Control Node / 前制御ノード）は、明確な目標状態入口の前に配置するエンジニアリングノードである。

CAE-SDB は、PCN 内部で使用する構造化判定ロジックである。

1 つの PCN は、1 回の明確な目標状態入口に関係する入力状態、判定、制御優先度調停、複数経路制御、PCN 状態遷移判定履歴を、一つのエンジニアリング対象として整理する。

基本的な構成は次の通りである。

```text
現在状態
→ 目標状態
→ PCN
    ├─ 複数系統の状態
    ├─ C / A / E 状態マッピング
    ├─ S / D / B 判定
    ├─ CAE-SDB 判定結果 + T
    ├─ 制御優先度調停
    ├─ 複数経路制御
    └─ PCN 状態遷移判定履歴
```

PCN は、TPCA の全体アーキテクチャを具体的な目標状態入口へ展開する際の最小エンジニアリングノードである。

## 1. PCN は明確な目標状態入口の前に配置する

TPCA は、目標状態、目標実行経路、または目標物理実行段階へ入る前の判定と制御を対象とする。

PCN を設定する際は、まず次の状態遷移を明確にする。

```text
現在状態 → 目標状態
```

その上で、PCN を目標状態入口の前に配置する。

例えば、

```text
ロボット待機
→ PCN
→ ピックアップ段階
```

という構成では、PCN がピックアップ段階への進入に関係する状態を取得し、進入前に判定と制御を行う。

分流工程では、例えば「正常分流への進入」を明確な目標状態入口として PCN を配置できる。

```text
検査完了
→ PCN
→ 正常分流
```

今回の目標状態入口に対する判定結果に応じて、複数経路制御では待機、再確認、異常分流など、事前に定義された別の処理経路を選択できる。

1 つの PCN は、1 つの明確な目標状態入口に対応する。

複雑な設備には複数の目標状態入口が存在するため、1 台の設備内に複数の PCN を配置できる。

設備間、コントローラ間、上位システム間、または手動確認を含む状態遷移についても、目標状態入口を明確に定義できる場合は、その入口に対応する PCN を構成できる。

---

## 2. 1 つの PCN を構成する基本要素

1 つの PCN は、少なくとも次の対象を整理する。

| 対象 | エンジニアリング上の役割 |
|---|---|
| 現在状態 | システムが現在位置している状態、工程段階、または実行位置 |
| 目標状態 | システムが次に入ろうとしている状態、目標実行経路、または目標物理実行段階 |
| PCN の配置位置 | 今回の目標状態入口をどこに設定するか |
| 複数系統の状態 | 今回の状態遷移に関係する入力状態 |
| C / A / E 状態マッピング | 関連状態を C：条件状態、A：許可状態、E：実行チェーン状態へ整理する |
| S / D / B 判定 | 関連状態に対して S：構造完全性、D：動的時系列有効性、B：制御境界の判定を行う |
| CAE-SDB 判定結果 | 1 回の前判定によって形成される 1 つまたは複数の構造化判定結果 |
| 時間情報 T | 状態および判定とともに保持し、状態の前後関係、D の判定、PCN 状態遷移判定履歴に使用する |
| 制御優先度調停 | CAE-SDB 判定結果と事前定義された制御制約に基づき、制御上の優先関係を処理する |
| 複数経路制御 | 制御優先度調停の結果に基づいて、今回の目標状態入口に対する制御経路を形成する |
| PCN 状態遷移判定履歴 | 今回の目標状態入口における入力、判定、時間情報、制御出力、実行結果を記録する |

これらの要素によって、1 回の目標状態入口に対する状態入力、判定、制御、履歴を一つのエンジニアリング単位として扱うことができる。

各 PCN の入力数、判定ルール、制御経路、実装規模は、対象設備やシステムに応じて設定する。

PCN の基本構成は、次の関係で統一される。

> **1 つの明確な目標状態入口を中心として、状態入力、構造化判定、制御優先度調停、複数経路制御、PCN 状態遷移判定履歴を一連の関係として構成する。**

---

## 3. 「最小エンジニアリングノード」の意味

TPCA における「最小エンジニアリングノード」は、

> **1 回の明確な目標状態入口に対する状態遷移前判定、制御出力、状態遷移判定履歴を一つの関係として保持できる最小のエンジニアリング組織単位**

を示す。

信号数、ソフトウェアサイズ、PLC ファンクションブロックの大きさ、判定ルール数などの実装規模は、対象システムごとに異なる。

PCN を構成要素へ分解すると、例えば次のような対象になる。

- 1 つの現場信号
- 1 つの Ready 状態
- 1 つの許可状態
- 1 つの Interlock
- 1 つの S / D / B 判定
- 1 つの CAE-SDB 判定結果
- 1 つの制御出力

これらの要素を今回の目標状態入口に対応付け、PCN として次の関係にまとめる。

```text
目標状態入口
→ 複数系統の状態
→ C / A / E 状態マッピング
→ S / D / B 判定
→ CAE-SDB 判定結果 + T
→ 制御優先度調停
→ 複数経路制御
→ PCN 状態遷移判定履歴
```

この単位で、目標状態入口に対する判定根拠、構造化判定結果、制御結果、履歴を同じエンジニアリング文脈で扱うことができる。

そのため、PCN は TPCA を具体的なシステムへ展開する際の最小エンジニアリングノードとなる。

## 4. PCN は分散した現場状態を目標状態入口に対応付ける

複雑なシステムでは、1 回の目標状態入口に必要な状態が複数の設備やシステムに分散している。

例えば、ロボットがピックアップ段階へ入る場合、関連状態は次のような情報源から取得されることがある。

- 画像認識システム
- ロボットコントローラ
- PLC
- 安全システム
- メインコンベヤ
- 正常配置先
- 上位システム

PCN は、目標状態入口に関係する複数系統の状態を、今回の状態遷移での役割に応じて C / A / E へ整理する。

### C：Condition

C は、目標状態へ入るために必要な事実条件に関係する状態変数領域である。

例えば、

- ワーク存在状態
- 画像認識結果
- ワーク位置
- ワーク姿勢

などが該当する。

### A：Authority

A は、目標状態への進入を許可する状態に関係する状態変数領域である。

例えば、

- 安全許可
- エリア許可
- 上位システム許可
- 今回の動作に必要な許可
- 手動確認

などが該当する。

重要な A は、目標状態入口に対する独立した必要制約として扱う。

### E：Execution Chain

E は、目標状態へ入った後に必要となる実行チェーンに関係する状態変数領域である。

例えば、

- ロボット経路状態
- グリッパ状態
- 正常配置先の受入状態
- 下流受入状態
- 結果書戻し状態

などが該当する。

C / A / E 状態マッピングの後、PCN は関連状態に対して必要な S / D / B 判定を行う。

```text
C / A / E 状態マッピング
→ S / D / B 判定
→ CAE-SDB 判定結果 + T
```

1 回の目標状態入口で複数の CAE-SDB 判定結果が形成された場合は、制御優先度調停で制御上の優先関係を処理する。

その結果に基づいて複数経路制御を形成する。

代表的な制御経路には、例えば次のものがある。

- 進入許可
- 待機
- 再認識
- 再位置決め
- 回流
- 異常分流
- 手動確認
- 進入禁止
- 安全関連の制御経路

関連事例：

[自動化実行ユニット前判定事例](/jp/cases/automation-execution-unit-pre-control/)

## 5. PCN は異なるエンジニアリング階層に配置できる

PCN の実装形式は、目標状態入口が存在するシステム階層に応じて決定する。

### 自動化実行ユニット

PCN は、例えば次の目標状態入口に配置できる。

- ロボットがピックアップ段階へ入る前
- 圧入段階へ入る前
- 検査実行段階へ入る前
- 搬送引渡しへ入る前
- 正常分流または異常分流へ入る前

実装には、例えば次の構成を使用できる。

- PLC ファンクションブロック
- 産業用コントローラ
- エッジコントローラ
- ソフトウェア判定モジュール
- HMI と連携する制御モジュール

### MES / WCS・群制御協調

PCN は、例えば次の目標状態入口に配置できる。

- タスク実行へ入る前
- 資源使用へ入る前
- ステーション受入へ入る前
- エリア進入へ入る前
- 協調実行状態へ移行する前

### 生産 DX

PCN は、例えば次の目標状態入口に配置できる。

- 品質放行後の次工程進入前
- 作業指示切替後の目標生産状態への進入前
- 保全完了後の再投入前
- 手動確認後の自動運転再開前
- 下流生産状態への進入前

各適用先では、入力状態、判定ルール、複数経路制御の候補、PCN Runtime の実装方法を個別に設定する。

基本的なエンジニアリング関係は、次の通りである。

```text
現在状態
→ 目標状態
→ PCN
→ 複数系統の状態
→ C / A / E 状態マッピング
→ S / D / B 判定
→ CAE-SDB 判定結果 + T
→ 制御優先度調停
→ 複数経路制御
→ PCN 状態遷移判定履歴
```

PCN は、明確な目標状態入口に対して、この階層関係で状態遷移前判定、制御、履歴を構成する。実装するハードウェアやソフトウェアは、対象システムに応じて選択する。

## 6. PCN 状態遷移判定履歴は 1 回の目標状態入口に対する判定履歴である

PCN は、今回の目標状態入口に対する判定、制御優先度調停、複数経路制御、実行結果を PCN 状態遷移判定履歴として記録する。

1 つの PCN 状態遷移判定履歴には、例えば次の情報を関連付ける。

- PCN
- 現在状態
- 目標状態
- 主要な入力状態
- 時間情報 T
- 状態に関係するバージョン、シーケンス、対象情報
- C / A / E 状態マッピング
- S / D / B 判定
- CAE-SDB 判定結果
- 制御優先度調停結果
- 複数経路制御
- 実行結果
- Trace ID

この履歴により、1 回の目標状態入口に対する状態遷移判定全体を追跡できる。

継続して蓄積すると、例えば次の内容を確認できる。

- どの目標状態入口で特定の CAE-SDB 判定結果が頻発しているか。
- C / A / E のどの状態変数領域で反復的な問題が発生しているか。
- S / D / B のどの判定性質に関係する結果が多いか。
- どの複数経路制御が高頻度で選択されているか。
- エンジニアリング変更後に CAE-SDB 判定結果、制御優先度調停結果、実行結果がどのように変化したか。

PCN 状態遷移判定履歴は、現場確認、設計レビュー、改善比較に使用できる。

## 7. 単一 PCN から PCN Network へ展開する

1 つの PCN は、1 つの明確な目標状態入口に対応する。

複雑なシステムでは、連続、並列、または依存関係を持つ複数の目標状態入口が存在する。

例えば、

```text
PCN-01
待機 → ピックアップ

        ↓

PCN-02
ピックアップ完了 → 搬送

        ↓

PCN-03
搬送完了 → 配置

        ↓

PCN-04
配置完了 → 後続処理
```

という関係を構成できる。

複数の PCN を、実際の状態遷移関係、および必要な許可、資源、実行チェーンの依存関係に基づいて接続すると、PCN Network を形成できる。

単一 PCN は、個別の目標状態入口に対する判定と制御を担当する。

PCN Network は、複数の目標状態入口間に存在する状態進行、許可依存、資源依存、実行チェーン接続、履歴関係などを扱う。

PCN Network が表す対象は、

> **複数の目標状態入口間に存在するエンジニアリング上の関係**

である。

[複数の PCN はどのように状態遷移前制御ネットワークを形成するのか？](/jp/notes/pcn-network-structure/)

## まとめ

TPCA は、状態遷移前制御アーキテクチャである。

PCN は、明確な目標状態入口の前に配置する前制御ノードである。

CAE-SDB は、PCN 内部で使用する構造化判定ロジックである。

1 つの PCN は、1 回の明確な目標状態入口に対して、次の関係を構成する。

```text
現在状態
→ 目標状態
→ PCN
    ├─ 複数系統の状態
    ├─ C / A / E 状態マッピング
    ├─ S / D / B 判定
    ├─ CAE-SDB 判定結果 + T
    ├─ 制御優先度調停
    ├─ 複数経路制御
    └─ PCN 状態遷移判定履歴
```

この単位によって、目標状態入口に関係する状態入力、構造化判定、時間情報、制御上の優先関係、制御出力、状態遷移判定履歴を同じエンジニアリング文脈で扱うことができる。

そのため、PCN は TPCA の全体アーキテクチャを具体的なシステムへ展開する際の最小エンジニアリングノードとなる。

単一 PCN を起点として、複数の目標状態入口と PCN を実際の状態遷移関係に沿って接続することで、PCN Network へ展開できる。
