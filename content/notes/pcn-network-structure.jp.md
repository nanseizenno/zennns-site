# 単一 PCN から PCN Network へ

TPCA / PCN の中核となる考え方は、次の通りである。

> **明確な Target State Entry は、それ自体を独立して設計・判定・制御・記録できるエンジニアリング対象として扱うべきである。**

1 つの PCN は、1 つの明確な Target State Entry に対応する。

複雑なエンジニアリングシステムには、連続、並列、分岐、または相互依存する複数の Target State Entry が存在する。

複数の PCN を、実際の状態遷移関係、および必要な許可、資源、実行、状態書戻しの依存関係に基づいて接続すると、**PCN Network** を形成できる。

PCN Network は、次の関係を表す。

> **複雑なエンジニアリングシステムにおける主要な Target State Entry と、それらの間に存在する状態遷移およびエンジニアリング上の依存関係。**

![複数の PCN が状態遷移前制御ネットワークを形成する関係](/images/tpca/10-pcn-network-structure.zh.png)

図：複数の PCN が主要な Target State Entry を中心として状態遷移前制御ネットワークを形成する。

## 1. PCN Network のノード対象

PCN Network では、独立して設計・管理する必要がある Target State Entry をノード対象とする。

設備、コントローラ、ステーション、上位システムなどは PCN に状態を提供できるが、それらの物理設備やソフトウェアシステム自体が、そのまま PCN ノードになるわけではない。

例えば、次のように整理できる。

| 状態遷移 | 対応する PCN |
|---|---|
| ロボット待機 → ピックアップ段階 | ピックアップ前 PCN |
| 配置完了 → 圧入段階 | 圧入前 PCN |
| 検査待ち → 検査段階 | 検査前 PCN |
| タスク生成済み → 実行状態 | タスク実行前 PCN |
| AGV 到着 → ステーション受入状態 | ステーション受入前 PCN |
| 保全解除 → 自動運転再開 | 自動運転再開前 PCN |

したがって、

- 1 台の複雑設備内に複数の PCN を設定できる。
- 1 本の生産ラインに複数の主要な Target State Entry を設定し、それぞれに PCN を配置できる。
- MES / WCS と現場設備の間に、システムをまたぐ PCN を設定できる。
- 手動確認、品質放行、設備復帰なども、明確な Target State Entry を持つ場合は PCN Network に含めることができる。

PCN Network は、

> **複数の Target State Entry と、それらの間に存在するエンジニアリング上の関係によって構成される状態遷移前制御構造**

として扱う。

---

## 2. 「ここに PCN を設定する必要がある」という表現の意味

自動化システム、生産ライン、物流システム、MES / WCS 連携を設計する際、Target State Entry に次のような特徴がある場合がある。

- 次の状態へ進む前に、複数の関連状態を用いて判定する必要がある。
- 重要な許可、資源制約、またはシステム間依存が存在する。
- Target State へ入った後の Execution Chain に関係する状態を確認する必要がある。
- 判定結果によって複数の制御経路に分岐する可能性がある。
- 今回の判定を記録し、後から追跡する必要がある。

このような位置について、エンジニアリング上の議論では、

> **ここに PCN を設定する必要がある。**

と表現できる。

これは、その Target State Entry を独立したエンジニアリング対象として扱うことを意味する。

設定時には、少なくとも次の関係を明確にする。

```text
Current State
→ Target State
→ 今回の状態遷移に関係する複数ソース状態
→ C / A / E Mapping
→ S / D / B Evaluation
→ CAE-SDB Result + T
→ Arbitration
→ Multipath Control
→ PCN Trace
```

したがって、「ここに PCN を設定する」という表現は、

> **その Target State Entry を、独立した前判定、制御、記録の対象として設計する**

ことを示す。

---

## 3. PCN の設定に適した Target State Entry

PCN は、システム内のすべての局所動作やステップに設定するものではない。

Target State Entry を独立した PCN として設定するかを判断する際は、次の条件を確認できる。

1. Current State と Target State が明確であるか。
2. Target State へ入る前に、複数の関連状態を用いた判定が必要であるか。
3. 重要な許可、資源、Execution Chain、またはシステム間依存が存在するか。
4. 判定結果が実際の状態遷移または Multipath Control に影響するか。
5. 今回の判定を PCN Trace として記録するエンジニアリング上の価値があるか。

これらの条件を満たす Target State Entry は、独立した PCN として設定する対象になりやすい。

例えば、システムが包装段階へ入る前に、次の状態を確認する必要がある場合を考える。

- 包装対象の状態
- 包装材料の状態
- 必要な許可
- 包装設備の状態
- 下流受入状態
- 異常処理経路の状態

この場合、「包装段階へ入る」という Target State Entry を、独立した PCN の対象として設定できる。

適用境界については、以下を参照。

[TPCA / PCN の適用場面分析](/jp/notes/tpca-pcn-applicable-scenarios/)

## 4. 複数 PCN 間のエンジニアリング関係

複数の PCN 間の接続は、実際の状態遷移およびエンジニアリング上の依存関係に基づいて設定する。

代表的な関係は次の通りである。

```text
状態進行関係

許可依存関係

資源依存関係

実行依存関係

状態書戻し依存関係
```

### 4.1 状態進行関係

状態進行関係は、1 回の状態遷移が完了した後、その結果として形成された新しい Current State から、後続の Target State Entry へ進む関係を表す。

例えば、

```text
ピックアップ待ち
→ ピックアップ前 PCN
→ ピックアップ完了

ピックアップ完了
→ 配置前 PCN
→ 配置完了

配置完了
→ 後続段階 PCN
→ 後続実行
```

のように構成できる。

各 PCN は、それぞれ異なる Target State Entry に対応する。

前の状態遷移が完了すると新しい Current State が形成され、後続 PCN はその新しい状態事実に基づいて次の前判定を行う。

### 4.2 許可依存関係

ある PCN で使用する許可状態は、他の設備、システム、人による処理、または前段の状態遷移結果から取得される場合がある。

例えば、

- 品質放行状態が次工程の Target State Entry に影響する。
- エリア許可が設備または車両の対象エリアへの進入に影響する。
- 上位システムの許可がタスク実行の Target State Entry に影響する。
- 相手機器の受入許可が引渡しの Target State Entry に影響する。

これらの許可状態は、該当する PCN における A：Authority の状態として扱う。

### 4.3 資源依存関係

複数の PCN が、同じ共有資源に依存する場合がある。

例えば、

- 共有経路
- バッファ
- 自動扉
- エレベータ
- 治具
- ステーション
- 共有アクチュエータ
- その他の制約付き資源

などである。

共有資源の状態は、複数の Target State Entry に同時に影響する場合がある。

### 4.4 実行依存関係

ある Target State へ入った後の実行が、他の設備、経路、下流システムの状態に依存する場合がある。

例えば、

- 下流設備が受入可能であるか。
- 回流経路が使用可能であるか。
- 異常分流経路が使用可能であるか。
- 結果送信経路が使用可能であるか。
- 後続工程が今回の実行チェーンに必要な状態となっているか。

これらは、該当する PCN における E：Execution Chain に関係する状態として扱う。

### 4.5 状態書戻し依存関係

1 回の状態遷移が完了した後、その実行結果を PLC、MES、WCS、品質システム、タスクシステム、その他の上位システムへ書き戻す場合がある。

書き戻された状態は、後続の Target State Entry における入力状態になる場合がある。

例えば、

```text
工程完了
→ 完了状態を書戻し
→ 次タスクの状態更新
→ 後続 PCN が新しい状態を取得
```

という関係である。

状態書戻し依存関係は、PCN Network におけるエンジニアリング上の依存関係の一つである。

これは、後続の Target State Entry が使用する状態の取得元と更新関係を表す。

## 5. 状態タイプの循環と状態インスタンスの継続生成

PCN Network には、回流、手直し、復帰、補償、再投入などの経路を含めることができる。

これらの経路は、状態タイプの関係として循環を形成する場合がある。

例えば、

```text
A → B → C → A
```

という関係である。

実際の運転では、2 回目に A の状態タイプへ入った時点で、システムは新しい時間位置にある。

したがって、状態インスタンスとしては次のように表すことができる。

```text
状態 A / インスタンス A₁

→ PCN-1

→ 状態 B / インスタンス B₁

→ PCN-2

→ 状態 C / インスタンス C₁

→ PCN-3

→ 状態 A / インスタンス A₂
```

ここで、

```text
A₁ ≠ A₂
```

である。

A₁ と A₂ は同じ状態タイプに属するが、異なる状態インスタンスである。

したがって、

> **状態タイプの関係には循環を含めることができるが、実運転中の状態インスタンスは時間方向へ継続して生成される。**

手直し、回流、復帰、補償、再投入などが発生した場合も、新しい状態遷移事実として、その時点の Target State Entry と PCN に接続する。

この関係は、次のように整理できる。

```text
Current State
→ New Target State
→ 新しい状態インスタンス
→ 後続 PCN
```

PCN Network における循環は、状態タイプおよび工程経路の関係を表すものであり、過去の状態インスタンスを上書きするものではない。

## 6. PCN Network の制御・配置境界

PCN Network は、Target State Entry 間の状態遷移とエンジニアリング上の依存関係を表す。

基盤となる制御アーキテクチャを、集中制御または分散制御のいずれかに限定するものではない。

例えば、

```text
PCN A

→ 状態遷移

→ PCN B

→ 状態遷移

→ PCN C
```

という構成のほか、

- 並列 PCN
- 分岐 PCN
- 回流 PCN
- 相互依存する PCN
- 設備をまたぐ PCN
- システムをまたぐ PCN

などを構成できる。

PCN は、Target State Entry の位置とシステム構成に応じて、例えば次の場所に配置できる。

- PLC / HMI
- 産業用エッジコントローラ
- WCS
- MES
- ソフトウェアサービス
- その他の適切な確定的制御または計算プラットフォーム

複数の PCN を、異なる実装位置へ配置することもできる。

PCN Network では、工場全体を 1 つの総合状態として管理することを前提としない。

実際のエンジニアリングでは、例えば次のような責任範囲に分けて状態関係を管理できる。

```text
設備

ユニット

タスク

ステーション

生産エリア

その他の明確なエンジニアリング責任範囲
```

各責任範囲では、その範囲に関係する状態遷移を管理し、明確な許可、資源、実行、状態書戻しの依存関係を介して、他の PCN と接続する。

具体的な PCN Runtime のライフサイクル、PCN 間プロトコル、同期機構、完全なインターフェース、完全な Arbitration の優先関係、配置パラメータなどは、内部のエンジニアリング実装に属するため、本公開ノートでは扱わない。

## 7. PCN Network と PCN Trace

単一 PCN は、1 回の Target State Entry に対して PCN Trace を形成する。

PCN Trace は、今回の状態遷移に関係する状態、判定、制御、実行の履歴を記録する。

複数の PCN が継続して動作すると、それぞれの PCN Trace を基に、システムレベルで状態遷移判定履歴を確認できる。

例えば、次の内容を確認できる。

- どの Target State Entry で進入不能が頻発しているか。
- どの PCN で重要な許可による制約が繰り返し発生しているか。
- どの Execution Chain に関係する問題が反復しているか。
- どの Target State Entry で待機が長期化しているか。
- どの Multipath Control が高頻度で選択されているか。
- どの PCN 間で許可、資源、実行依存に関係する問題が繰り返し発生しているか。
- どの状態書戻し関係で異常が繰り返し発生しているか。
- エンジニアリング変更後に、関連する状態遷移の結果がどのように変化したか。

PCN Trace は、各 Target State Entry における判定履歴と追跡情報を提供する。

許可、資源、実行、状態書戻しの依存関係は、PCN Network 内のエンジニアリング関係を表す。

両者を組み合わせることで、単一 Target State Entry の履歴だけでなく、複数の Target State Entry 間に存在する長期的な運転関係も確認できる。

PCN Trace については、以下を参照。

[なぜ PCN Trace は新しいエンジニアリングデータなのか？](/jp/notes/why-pcn-trace-is-engineering-data/)

## 8. 3 つの代表的な PCN Network 形態

### 8.1 自動化実行ユニット

例えば、

```text
待機

→ ピックアップ前 PCN

→ ピックアップ

ピックアップ完了

→ 配置前 PCN

→ 配置

配置完了

→ 後続段階 PCN

→ 後続実行
```

という構成がある。

1 つの自動化実行ユニット内に、複数の主要 PCN を設定できる。

PCN 間では、主として状態進行、許可依存、Execution Chain に関係する依存関係を扱う。

### 8.2 MES / WCS と複数設備協調

例えば、

```text
タスク生成

→ タスク実行前 PCN

→ 実行

ステーション到着

→ ステーション受入前 PCN

→ 引渡し

実行完了

→ 結果書戻し前 PCN

→ 完了
```

という構成がある。

この階層の PCN は、タスク、資源、経路、ステーション、実行主体、下流システムにまたがって配置できる。

PCN 間には、スケジューリング許可、共有資源、Execution Chain、状態書戻しなどの依存関係が存在する場合がある。

### 8.3 生産 DX とシステム間状態遷移

例えば、

```text
品質確認

→ 次工程前 PCN

→ 工程進入

保全解除

→ 自動運転再開前 PCN

→ 運転再開

異常処理完了

→ 再投入前 PCN

→ 再実行
```

という構成がある。

これらの PCN は、設備、人、MES、品質システム、保全システムなどをまたいで配置できる。

共通するエンジニアリング上の特徴は、独立して管理する価値のある明確な Target State Entry が存在することである。

## エンジニアリング上の結論

1 つの PCN は、1 つの明確な Target State Entry に対応する。

複数の PCN を、実際の状態遷移関係、および必要な許可、資源、実行、状態書戻しの依存関係に基づいて接続すると、PCN Network を形成できる。

PCN Network が表すのは、

> **主要な Target State Entry と、それらの間に存在する状態遷移およびエンジニアリング上の依存関係**

である。

PCN Network では、次のように整理できる。

```text
1 つの PCN

= 1 つの明確な Target State Entry に対応する前制御ノード

複数の PCN

= 複数の Target State Entry 間に存在する状態遷移と依存関係の構造
```

状態タイプの関係には循環を含めることができるが、実運転中の状態インスタンスは時間方向へ継続して生成される。

したがって、複雑なシステムの設計時に、

> **ここに PCN を設定する必要がある。**

という表現を使用する場合、その意味は、

> **ここに、独立して設計・判定・制御・記録する必要がある Target State Entry が存在する。**

ということである。

このような Target State Entry を実際のエンジニアリング関係に沿って接続することで、TPCA は単一 PCN からシステムレベルの状態遷移前制御構造へ展開できる。
