## 为什么是 CAE-SDB？

**CAE-SDB 是 TPCA / PCN 中用于目标状态入口前复杂状态判定的核心结构化分析方法。**

在制造和自动化系统中，一次状态迁移往往同时受到设备状态、安全许可、视觉结果、任务状态、下游承接和上位系统状态等多个因素影响。

这些状态来自不同设备和系统，但在一次明确的状态迁移中，需要回答两个不同的问题：

```text
第一轴：这个状态在本次状态迁移中承担什么作用？

第二轴：应从什么性质判定这个状态？
```

CAE-SDB 将这两个问题分别整理为：

```text
C / A / E：状态迁移功能角色

S / D / B：状态判定性质
```

其中：

```text
C = Condition         条件状态
A = Authority         许可状态
E = Execution Chain   执行链状态

S = Structure         结构完整性
D = Dynamics          动态时序有效性
B = Boundary          控制边界
```

通过 **C / A / E × S / D / B** 的双轴结构，可以明确表示：

> **哪个状态变量域，出现了哪一种判定结果。**

这些结构化结果进一步进入控制仲裁、多路径控制和 PCN Trace，形成从状态分析到控制与履历的工程闭环。

---

## 1. 为什么需要两条轴

TPCA / PCN 将系统从当前状态准备进入目标状态的工程入口定义为目标状态入口（Target State Entry）。

以机器人进入抓取阶段为例，现场可能同时存在：

```text
视觉识别结果 = 成立
安全许可 = 成立
机器人准备状态 = 成立
下游接收状态 = 可接收
```

这些状态都与当前目标状态入口有关，但承担的工程作用不同。

- 视觉识别结果与进入抓取阶段所需条件有关；
- 安全许可决定当前是否允许进入；
- 机器人准备状态与下游接收状态参与判断进入抓取阶段以后，执行链是否能够继续。

另一方面，一个状态即使已经成立，也仍然需要确认：

- 相关信号和接口是否已经正确建立；
- 状态是否仍属于当前对象和当前周期；
- 状态是否仍在有效时间内；
- 相关数值是否仍处于允许范围。

因此：

```text
状态在本次迁移中的作用

        ×

状态当前应接受什么性质的判定
```

是两个相互独立的问题。

CAE-SDB 将前者整理为 C / A / E，将后者整理为 S / D / B。

---

## 2. C / A / E：状态迁移功能角色

C / A / E 用于根据状态在当前目标状态入口中承担的工程作用进行整理。

```text
C：进入目标状态所需的条件

A：是否允许进入目标状态

E：进入目标状态以后执行链能否继续
```

可以将其理解为一次状态迁移中的三个不同功能位置：

```text
进入前                目标状态入口                进入后

  │                       │                       │

  C                       A                       E

条件状态                许可状态              执行链状态
```

C、A、E 均在进入目标状态之前由 PCN 获取和判定。

C / A / E 对应一次明确状态迁移相对于目标状态入口的三个功能位置：进入前所需条件、入口处的进入许可，以及进入后的执行链接续。

对于一次具有明确方向的状态迁移，这三个位置构成对迁移成立性相关状态功能角色的结构性分解。

当前状态、目标状态、时间信息、状态标识、判定结果和控制结果具有各自独立的工程作用，不属于状态迁移功能角色。

### 2.1 C：Condition｜条件状态

C 表示进入目标状态之前需要成立的条件状态。

典型内容包括：

- 工件是否存在；
- 对象、位置、姿态是否满足要求；
- 视觉或检测结果是否已经取得；
- 前序工序是否完成；
- 请求参数是否完整；
- 必要数据是否存在。

C 回答：

> **当前是否具备进入这个目标状态的条件？**

### 2.2 A：Authority｜许可状态

A 表示系统当前是否允许进入目标状态。

典型内容包括：

- 安全许可；
- 区域许可；
- 上位系统许可；
- 对方设备许可；
- 资源锁；
- 用户权限；
- 人工确认。

关键 A 可以构成独立必要约束。

当关键许可未成立时，即使 C 与 E 已经满足，本次目标状态入口仍不得放行。

A 回答：

> **当前是否允许进入这个目标状态？**

### 2.3 E：Execution Chain｜执行链状态

E 表示进入目标状态后，当前目标阶段所需要的执行链是否能够继续接续。

例如机器人进入抓取阶段时，相关状态可能包括：

- 机器人运行准备状态；
- 机器人路径可达状态；
- 夹爪或末端执行机构状态；
- 下游接收状态；
- 对方设备承接状态；
- 结果上传或回写链路状态。

一个单体设备的 Ready 可以作为 E 的输入之一，E 关注的是整个目标执行链接续性。

E 回答：

> **进入当前目标状态后，这一执行链是否能够继续？**

E 必须绑定当前目标状态入口。

替代路径、回流路径、异常路径等如果形成新的候选状态迁移，应在对应目标状态入口下重新进行判定。

## 3. S / D / B：状态判定性质

完成 C / A / E 状态映射后，PCN 根据当前目标状态入口已定义的判定规则，对相关状态执行 S / D / B 判定。

S / D / B 分别对应工程状态验证中的三个基本问题：判定所依赖的结构是否已经建立、状态是否仍然有效，以及有效状态是否仍处于预先定义的允许边界内。

结构建立、运行时有效性和允许边界是工程系统中长期存在的基本验证问题。TPCA / PCN 将这三类判定性质统一收拢到目标状态入口的状态判定语境中，并使其能够一致作用于 C / A / E 三类状态变量域。

```text
S：结构是否建立完整？

D：当前状态是否仍然有效？

B：当前状态是否仍在界内？
```

### 3.1 S：Structure｜结构完整性

S 用于确认本次状态迁移判定所需要的工程结构是否已经建立。

典型检查内容包括：

- 必要信号是否定义；
- 接口是否接入；
- 对象与状态之间的映射关系是否明确；
- 许可来源是否确定；
- 相关路径是否定义；
- 执行链边界是否明确；
- 必要状态是否可观测。

S 回答：

> **本次判定所依赖的结构是否已经定义、接入并可观测？**

### 3.2 D：Dynamics｜动态时序有效性

D 用于确认已经存在的状态，是否仍能够作为本次目标状态入口的有效判定依据。

典型问题包括：

- 超时；
- 未刷新；
- 抖动；
- 冲突；
- 延迟；
- 不同步；
- 低置信度；
- 许可撤销；
- 状态切换。

例如：

```text
视觉识别结果 = 成立
```

如果该结果对应上一件工件，则不能继续用于当前抓取入口。

状态值虽然存在，但已经失去当前状态迁移的动态有效性。

D 回答：

> **这个状态还能否作为本次目标状态入口的有效判定依据？**

### 3.3 B：Boundary｜控制边界

B 用于确认相关状态是否处于预先定义的允许范围、阈值或控制边界以内。

代表性项目包括：

- 最小值 / 最大值；
- 阈值；
- 容差；
- 允许范围；
- 时间窗口；
- 上限量；
- 容量；
- 频率上限；
- 重试次数上限。

例如尺寸允许范围为：

```text
19.90 mm ～ 20.10 mm
```

则：

```text
20.06 mm → 范围内
20.18 mm → 范围外
```

B 回答：

> **状态是否处于这个目标状态入口预先定义的控制边界内？**

D 与 B 分别处理两个不同的问题：

```text
D：这个状态现在是否仍然有效？

B：这个有效状态现在是否仍然在允许范围内？
```

例如：

```text
视觉结果属于上一件工件
→ D

视觉结果属于当前工件，但位置偏差超出允许范围
→ B
```

## 4. C / A / E 与 S / D / B 如何组合

两条轴组合后形成 CAE-SDB 双轴判定结构。

| 状态变量域 | S：结构完整性 | D：动态时序有效性 | B：控制边界 |
|---|---|---|---|
| C：条件状态 | C-S | C-D | C-B |
| A：许可状态 | A-S | A-D | A-B |
| E：执行链状态 | E-S | E-D | E-B |

这些坐标表示：

```text
哪个状态变量域

×

出现了哪一种判定结果
```

例如：

```text
C-D：条件状态存在动态时序有效性问题
A-D：许可状态存在动态时序有效性问题
E-B：执行链状态超出预先定义的控制边界
C-S：条件状态所需结构尚未完整建立
```

同一个状态变量域可以接受多种判定。

例如视觉识别结果映射到 C 后，可以分别检查：

```text
C-S
识别结果接口和对象映射是否已经建立

C-D
识别结果是否仍属于当前工件并处于有效时间内

C-B
置信度、位置偏差等是否处于允许范围
```

同一种判定性质也可以作用于不同变量域：

```text
C-D：视觉结果过期

A-D：许可已经撤销

E-D：下游状态长时间未刷新
```

CAE-SDB 判定结果只能在相应规则已经定义、输入具备判定依据，并完成实际判定后形成。

时间信息 T 与相关状态和判定结果一起保留。

## 5. CAE-SDB 判定结果的位置

CAE-SDB 的职责，是将与目标状态入口有关的状态按照 C / A / E 与 S / D / B 两条轴进行结构化，并形成判定结果。

基本关系如下：

```text
当前状态
    ↓
目标状态
    ↓
目标状态入口 / PCN
    ↓
C / A / E 状态映射
    ↓
S / D / B 判定
    ↓
CAE-SDB 判定结果 + 时间信息
    ↓
控制仲裁
    ↓
多路径控制
    ↓
PCN Trace
```

一次目标状态入口中，可以同时形成 C-D、A-B、E-D 等多个 CAE-SDB 判定结果。

CAE-SDB 将这些结果结构化后交给后续处理。控制优先级、具体控制路径和执行结果记录分别由控制仲裁、多路径控制和 PCN Trace 处理。

CAE-SDB 判定结果与具体控制动作之间不采用固定的一一对应关系。

## 6. 结构基础、适用范围与后续课题

CAE-SDB 的两条轴分别具有明确的结构基础和工程基础。

### 6.1 C / A / E 的结构基础

C / A / E 表示一次明确目标状态入口中，与状态迁移成立性直接相关的三类功能角色。

```text
进入前
进入目标状态所需条件是否成立
        ↓
C = 条件状态

目标状态入口
是否允许进入目标状态
        ↓
A = 许可状态

进入后
目标状态所需执行链是否能够继续
        ↓
E = 执行链状态
```

对于一次具有明确方向的状态迁移，与迁移成立性直接相关的状态功能位置可以整理为进入前、入口处和进入后三部分。

C / A / E 即以目标状态入口为基准，对这三个功能位置进行结构化。

当某一信息无法直接归入 C / A / E 时，应判断其是否属于当前状态、目标状态、时间信息、状态标识、元数据、判定性质、控制结果或履历信息，并确定其在整体工程结构中的位置。

### 6.2 S / D / B 的工程基础

S / D / B 表示对 C / A / E 状态进行工程验证时使用的三类基本判定性质。

```text
S = 结构完整性
判定所需结构是否已经定义、接入并可观测。

D = 动态时序有效性
状态是否仍可作为本次状态迁移的判定依据。

B = 控制边界
有效状态是否处于预先定义的允许范围、
阈值或控制边界内。
```

它们分别对应三个基本问题：

```text
结构建立了吗？

状态有效吗？

状态在界内吗？
```

结构建立、运行时有效性和允许边界等问题长期存在于工业控制、过程系统、工业通信、数据质量、软件接口等工程领域。

TPCA / PCN 将这三类判定性质统一置于目标状态入口的状态迁移判定中，并作用于 C / A / E 三类状态变量域。

```text
状态迁移功能角色
C / A / E

        ×

状态判定性质
S / D / B

        ↓

CAE-SDB 判定结果
```

这构成 CAE-SDB 的基本分析结构。

### 6.3 适用范围

CAE-SDB 的直接适用对象，是具有明确状态迁移关系的工程系统。

应用时至少需要明确：

- 当前状态 / 当前阶段；
- 目标状态 / 目标阶段；
- 目标状态入口；
- 与本次状态迁移直接相关的状态；
- 条件、许可、执行链三类功能角色；
- 必要的结构、动态时序有效性和控制边界判定依据。

设备类型、控制平台、行业和信号名称可以不同，只要对象能够被表示为一次明确的状态迁移入口，就可以采用同一分析结构。

### 6.4 后续课题

CAE-SDB 的后续研究通过不同设备、系统和行业的实际应用继续展开。

主要包括行业状态映射、S / D / B 判定规则、CAE-SDB 判定结果评价、控制仲裁与多路径控制设计，以及基于 PCN Trace 的比较分析。
