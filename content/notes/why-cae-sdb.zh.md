## 为什么是 CAE-SDB？

**CAE-SDB 是 TPCA / PCN 中用于目标状态入口前复杂状态判定的核心结构化分析方法。**

在制造和自动化系统中，一次状态迁移往往同时受到设备状态、安全许可、视觉结果、任务状态、下游承接和上位系统状态等多个因素影响。

这些状态来自不同设备和系统，但在一次明确的状态迁移中，需要回答两个不同的问题：

```text
第一轴：这个状态在本次状态迁移中承担什么作用？
第二轴：应从什么性质判定这个状态？
```

CAE-SDB 将这两个问题分别整理为：

```text
C / A / E：状态迁移功能角色
S / D / B：状态判定性质
```

其中：

```text
C = Condition         条件状态
A = Authority         许可状态
E = Execution Chain   执行链状态

S = Structure         结构完整性
D = Dynamics          动态时序有效性
B = Boundary          控制边界
```

通过 **C / A / E × S / D / B** 的双轴结构，可以明确表示：

> **哪个状态变量域，出现了哪一种判定结果。**

这些结构化结果进一步进入控制仲裁、多路径控制、执行结果和 PCN Trace，形成从状态分析到控制、执行与履历的工程闭环。

---

## 1. 为什么需要两条轴

TPCA / PCN 将系统从当前状态准备进入目标状态的工程入口定义为目标状态入口（Target State Entry）。

以机器人进入抓取阶段为例，现场可能同时存在：

```text
视觉识别结果 = 成立
安全许可 = 成立
机器人准备状态 = 成立
下游接收状态 = 可接收
```

这些状态都与当前目标状态入口有关，但承担的工程作用不同。

- 视觉识别结果与进入抓取阶段所需条件有关；
- 安全许可决定当前是否允许进入；
- 机器人准备状态与下游接收状态参与判断进入抓取阶段以后，执行链是否能够继续。

另一方面，一个状态即使已经成立，也仍然需要确认：

- 相关信号和接口是否已经正确建立；
- 状态是否仍属于当前对象和当前周期；
- 状态是否仍在有效时间内；
- 相关数值是否仍处于允许范围。

因此：

```text
状态在本次迁移中的作用
        ×
状态当前应接受什么性质的判定
```

是两个相互独立的问题。

CAE-SDB 将前者整理为 C / A / E，将后者整理为 S / D / B。

---

## 2. C / A / E：状态迁移功能角色

C / A / E 用于根据状态在当前目标状态入口中承担的工程作用进行整理。

```text
C：进入目标状态所需的条件

A：是否允许进入目标状态

E：进入目标状态以后执行链能否继续
```

可以将其理解为一次状态迁移中的三个不同功能位置：

```text
进入前                目标状态入口                进入后

  │                       │                       │

  C                       A                       E

条件状态                许可状态              执行链状态
```

C、A、E 均在进入目标状态之前由 PCN 获取和判定。

C / A / E 对应一次明确状态迁移相对于目标状态入口的三个功能位置：进入前所需条件、入口处的进入许可，以及进入后的执行链接续。

对于一次具有明确方向的状态迁移，这三个位置构成对迁移成立性相关状态功能角色的结构性分解。

当前状态、目标状态、时间信息、状态标识、判定结果和控制结果具有各自独立的工程作用，不属于状态迁移功能角色。

### 2.1 C：Condition｜条件状态

C 表示进入目标状态之前需要成立的条件状态。

在自动化执行单元中，工件是否存在、对象的位置与姿态是否满足要求、视觉或检测结果是否已经取得，以及前序工序是否完成，都可能构成当前目标状态入口的条件状态。对于数字系统，请求参数和必要数据是否完整，也属于同一类问题。

C 所回答的是：

> **当前是否具备进入这个目标状态的条件？**

### 2.2 A：Authority｜许可状态

A 表示系统当前是否允许进入目标状态。

安全许可、区域许可、上位系统许可、对方设备许可、资源锁、用户权限和人工确认等，都可能构成一次状态迁移中的许可状态。它们关注的是系统当前有没有进入目标状态的权限，而不仅仅是进入条件是否已经具备。

关键 A 可以构成独立必要约束。当关键许可未成立时，即使 C 与 E 已经满足，本次目标状态入口仍不得放行。

A 所回答的是：

> **当前是否允许进入这个目标状态？**

### 2.3 E：Execution Chain｜执行链状态

E 表示进入目标状态后，当前目标阶段所需要的执行链是否能够继续接续。

例如机器人准备进入抓取阶段时，仅确认机器人本体 Ready 并不足以描述整个执行链。机器人路径是否可达、夹爪或末端执行机构是否可用、下游是否能够承接、对方设备是否具备接续条件，以及结果上传或回写链路是否正常，都可能影响进入目标状态以后能否继续执行。

因此，一个单体设备的 Ready 可以作为 E 的输入之一，E 关注的是当前目标状态所对应的整个执行链接续性。

E 所回答的是：

> **进入当前目标状态后，这一执行链是否能够继续？**

## 3. S / D / B：状态判定性质

完成 C / A / E 状态映射后，PCN 根据当前目标状态入口已定义的判定规则，对相关状态执行 S / D / B 判定。

S / D / B 分别对应工程状态验证中的三个基本问题：判定所依赖的结构是否已经建立、状态是否仍然有效，以及有效状态是否仍处于预先定义的允许边界内。

结构建立、运行时有效性和允许边界是工程系统中长期存在的基本验证问题。TPCA / PCN 将这三类判定性质统一收拢到目标状态入口的状态判定语境中，并使其能够一致作用于 C / A / E 三类状态变量域。

```text
S：结构是否建立完整？
D：当前状态是否仍然有效？
B：当前状态是否仍在界内？
```

### 3.1 S：Structure｜结构完整性

S 用于确认本次状态迁移判定所依赖的工程结构是否已经建立。

这里的结构既包括必要信号和接口，也包括对象与状态之间的映射关系、许可来源、相关路径、执行链边界以及必要状态的可观测性。一个状态即使在现场真实存在，如果判定系统没有定义相应信号、没有接入接口，或者无法确认它与当前对象和目标状态入口之间的关系，本次判定所需要的结构仍然不完整。

S 所回答的是：

> **本次判定所依赖的结构是否已经定义、接入并可观测？**

### 3.2 D：Dynamics｜动态时序有效性

D 用于确认已经存在的状态，是否仍能够作为本次目标状态入口的有效判定依据。

工程系统中的状态具有时间属性。一个已经取得的状态，可能因为超时、未刷新、通信延迟、系统间不同步或状态切换而失去当前判定价值；许可也可能在判定过程中被撤销，识别结果的置信度也可能随着对象或环境变化而失去原有意义。

例如：

```text
视觉识别结果 = 成立
```

如果这个结果对应的是上一件工件，那么状态值虽然仍然存在，却已经不能用于当前抓取入口。

D 所回答的是：

> **这个状态还能否作为本次目标状态入口的有效判定依据？**

### 3.3 B：Boundary｜控制边界

B 用于确认相关状态是否仍处于当前目标状态入口预先定义的允许范围或控制边界以内。

工程判定中的边界可以表现为数值范围、阈值、容差、容量，也可以表现为时间窗口、次数上限等约束。例如某一尺寸的允许范围为：

```text
19.90 mm ～ 20.10 mm
```

那么 20.06 mm 仍在允许范围内，而 20.18 mm 已经超出当前控制边界。

B 所回答的是：

> **状态是否处于这个目标状态入口预先定义的控制边界内？**

D 与 B 处理的是两个不同层面的问题：

```text
D：这个状态现在是否仍然有效？

B：这个有效状态现在是否仍然在允许范围内？
```

例如，视觉结果属于上一件工件，属于动态时序有效性问题；视觉结果属于当前工件，但位置偏差已经超出允许范围，则属于控制边界问题。

## 4. C / A / E 与 S / D / B 如何组合

两条轴组合后形成 CAE-SDB 双轴判定结构。

| 状态变量域 | S：结构完整性 | D：动态时序有效性 | B：控制边界 |
|---|---|---|---|
| C：条件状态 | C-S | C-D | C-B |
| A：许可状态 | A-S | A-D | A-B |
| E：执行链状态 | E-S | E-D | E-B |

这些坐标表示：

```text
哪个状态变量域
  ×
出现了哪一种判定结果
```

例如：

```text
C-D：条件状态存在动态时序有效性问题
A-D：许可状态存在动态时序有效性问题
E-B：执行链状态超出预先定义的控制边界
C-S：条件状态所需结构尚未完整建立
```

同一个状态变量域可以接受多种判定。

例如视觉识别结果映射到 C 后，可以分别检查：

```text
C-S
识别结果接口和对象映射是否已经建立

C-D
识别结果是否仍属于当前工件并处于有效时间内

C-B
置信度、位置偏差等是否处于允许范围
```

同一种判定性质也可以作用于不同变量域：

```text
C-D：视觉结果过期

A-D：许可已经撤销

E-D：下游状态长时间未刷新
```

CAE-SDB 判定结果只能在相应规则已经定义、输入具备判定依据，并完成实际判定后形成。

时间信息 T 与相关状态和判定结果一起保留。

---

## 5. CAE-SDB 判定结果的位置

CAE-SDB 的职责，是将与目标状态入口有关的状态按照 C / A / E 与 S / D / B 两条轴进行结构化，并形成判定结果。

基本关系如下：

```text
当前状态
    ↓
目标状态
    ↓
目标状态入口 / PCN
    ↓
C / A / E 状态映射
    ↓
S / D / B 判定
    ↓
CAE-SDB 判定结果 + 时间信息 T
    ↓
控制仲裁
    ↓
多路径控制
    ↓
执行结果
    ↓
PCN Trace
```

一次目标状态入口中，可以同时形成 C-D、A-B、E-D 等多个 CAE-SDB 判定结果。

CAE-SDB 将这些结果结构化后交给后续处理。控制优先级、具体控制路径和执行结果记录分别由控制仲裁、多路径控制和 PCN Trace 处理。

CAE-SDB 判定结果与具体控制动作之间不采用固定的一一对应关系。

---

## 6. 适用范围与工程边界

CAE-SDB 的直接适用对象，是具有明确状态迁移关系的工程系统。

实际应用时，首先需要明确系统当前处于什么状态或阶段，准备进入什么目标状态或阶段，以及目标状态入口位于哪里。随后再确定与这次迁移直接相关的状态，根据它们在当前迁移中的工程作用进行 C / A / E 映射，并依据实际工程要求进行必要的 S / D / B 判定。

设备类型、控制平台、行业和具体信号名称可以不同，状态映射、判定规则和控制边界则需要结合实际工程对象确定。CAE-SDB 提供的是围绕目标状态入口组织状态迁移判定的双轴分析结构。
