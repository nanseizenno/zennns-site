## なぜ CAE-SDB なのか？

**CAE-SDB は、TPCA / PCN において、目標状態入口前の複雑な状態を構造化して判定するための中核分析法である。**

製造・自動化システムでは、一回の状態遷移が、設備状態、安全許可、画像認識結果、タスク状態、下流受入状態、上位システム状態など、複数の要素に同時に依存する。

これらの状態は異なる設備やシステムから取得されるが、一つの状態遷移について判定する際には、少なくとも二つの異なる観点を分けて扱う必要がある。

第一は、その状態が今回の状態遷移においてどのような役割を担っているかという観点である。第二は、その状態を現在どのような性質から評価すべきかという観点である。

CAE-SDB では、この二つをそれぞれ次の軸として整理する。

```text
C / A / E：状態遷移における機能役割
S / D / B：状態に対する判定性質
```

各要素の意味は次のとおりである。

```text
C = Condition         条件状態
A = Authority         許可状態
E = Execution Chain   実行チェーン状態

S = Structure         構造完全性
D = Dynamics          動的時系列有効性
B = Boundary          制御境界
```

この **C / A / E × S / D / B** の二軸構造により、「どの状態遷移機能役割に、どのような判定結果が生じているか」を明示できる。

形成された判定結果は、その後の制御優先度調停、複数経路制御、実行結果、PCN Trace へ接続される。これにより、状態の取得から判定、制御、実行、履歴までを、一つの状態遷移を基準として連続的に扱うことができる。

---

## 1. なぜ二つの軸が必要なのか

TPCA / PCN では、システムが現在状態から目標状態へ進入する直前の工程位置を**目標状態入口**として扱う。

たとえば、ロボットが把持段階へ進入しようとしている場合、現場には画像認識結果、安全許可、ロボット準備状態、下流受入状態などが同時に存在する。

```text
画像認識結果 = 成立
安全許可 = 成立
ロボット準備状態 = 成立
下流受入状態 = 受入可能
```

いずれも今回の状態遷移に関係する状態であるが、工程上の役割は同じではない。

画像認識結果は、把持段階へ進入するための条件に関係する。安全許可は、現在その遷移を許可してよいかに関係する。ロボット準備状態や下流受入状態は、目標状態へ進入した後に実行チェーンを継続できるかに関係する。

一方、ある状態が成立していたとしても、その値をそのまま現在の判定に利用できるとは限らない。

たとえば、必要な信号やインターフェースが正しく定義・接続されているか、その状態が現在の対象物や現在の周期に対応しているか、状態が有効時間内にあるか、位置や信頼度などの値が許容範囲内にあるか、といった点を別途確認する必要がある。

つまり、

```text
今回の状態遷移で何の役割を持つか
        ×
現在その状態をどの性質から確認するか
```

は、異なる問題である。

CAE-SDB では、前者を C / A / E、後者を S / D / B として分離する。

---

## 2. C / A / E：状態遷移における機能役割

C / A / E は、各状態が現在の目標状態入口に対して、どのような工程上の役割を持つかを整理する軸である。

概念的には、次の三つに分けられる。

```text
C：目標状態へ進入するための条件
A：目標状態への進入許可
E：目標状態へ進入した後の実行チェーン継続性
```

状態遷移との位置関係は、次のように表せる。

```text
進入前                目標状態入口                進入後

  │                       │                       │

  C                       A                       E

条件状態                許可状態              実行チェーン状態
```

C、A、E は、いずれも実際に目標状態へ進入する前に PCN が取得・判定する。

三者は、一つの方向性を持つ状態遷移に対して、進入前に必要な条件、入口を通過するための許可、進入後に継続すべき実行チェーンという三つの異なる機能位置を表している。

現在状態、目標状態、時間情報、状態識別子、判定結果、制御結果などは、それぞれ別の工程上の意味を持つため、C / A / E には含めない。

### 2.1 C：Condition｜条件状態

C は、目標状態へ進入するために必要な条件が成立しているかを表す。

自動化実行ユニットでは、ワークが存在しているか、対象物の位置や姿勢が要求を満たしているか、画像認識や検査結果が取得済みか、前工程が完了しているかといった状態が C に該当する。

デジタルシステムでは、要求パラメータや必要情報が十分にそろっているかという問題も同じ観点で扱うことができる。

C が答える問いは、

> **この目標状態へ進入するための条件が、現在そろっているか。**

である。

### 2.2 A：Authority｜許可状態

A は、システムが現在その目標状態へ進入することを許可されているかを表す。

安全許可、区域進入許可、上位システム許可、相手機器からの許可、資源ロック、ユーザー権限、人工確認などが代表例である。

A が扱うのは、単に「条件が成立しているか」という問題ではない。その状態遷移を現在実行してよいかという許可の問題である。

重要な A は、独立した必要条件として扱う。したがって、重要許可が成立していない場合、C と E が成立していても、対象となる目標状態への進入は許可しない。

A が答える問いは、

> **現在、この目標状態への進入を許可してよいか。**

である。

### 2.3 E：Execution Chain｜実行チェーン状態

E は、目標状態へ進入した後、その状態に必要な実行チェーンを継続できるかを表す。

たとえば、ロボットが把持段階へ進入する場合、ロボット本体が Ready であることだけでは、実行チェーン全体を表したことにはならない。

ロボット経路が到達可能か、ハンドや末端実行機構が使用可能か、下流設備が受入可能か、相手機器が後続動作へ接続できるか、代替経路や回退経路が利用可能か、結果の送信や書戻しが可能かといった状態も、目標状態によっては実行チェーンの一部となる。

したがって、単一設備の Ready は E の入力の一つにはなり得るが、E 全体を代表するものではない。

E が答える問いは、

> **この目標状態へ進入した後、必要な実行チェーンを継続できるか。**

である。

---

## 3. S / D / B：状態に対する判定性質

C / A / E の整理が完了した後、PCN は現在の目標状態入口に対して定義された判定規則に基づき、関連状態を S / D / B の観点から評価する。

S / D / B は、工程状態を検証する際の三つの基本的な問いに対応する。

```text
S：必要な構造は正しく成立しているか
D：現在の状態は、まだ有効な判定根拠か
B：その状態は、定義された許容範囲内にあるか
```

構造、時間的有効性、許容境界は、いずれも既存の工学システムで継続的に扱われてきた基本的な検証課題である。

TPCA / PCN では、これらを目標状態入口における状態判定性質として整理し、C / A / E の各機能役割に対して共通に適用する。

### 3.1 S：Structure｜構造完全性

S は、本状態遷移の判定に必要な工程構造が成立しているかを確認する。

ここでいう構造には、必要な信号が定義されているか、インターフェースが接続されているか、状態と対象物の対応関係が定義されているか、許可元が明確か、必要な経路や実行チェーンの範囲が定義されているか、必要な状態を観測できるか、といった要素が含まれる。

ある状態が現場では実際に存在していても、判定側でその信号や関連関係が定義されていなければ、今回の状態遷移に必要な判定構造は成立していない。

S が答える問いは、

> **本状態遷移の判定に必要な構造が、定義・接続され、観測可能な状態になっているか。**

である。

### 3.2 D：Dynamics｜動的時系列有効性

D は、すでに取得されている状態が、現在の目標状態入口に対する有効な判定根拠として利用できるかを確認する。

工程状態には時間的性質がある。

一度取得した状態であっても、タイムアウト、未更新、通信遅延、システム間の非同期、チャタリング、状態切替、許可撤回、対象物の変化、信頼度低下などによって、現在の判定には利用できなくなる場合がある。

たとえば、

```text
画像認識結果 = 成立
```

という状態が残っていても、その結果が前のワークに対するものであれば、現在の把持入口には使用できない。

状態値が存在していることと、その状態を現在の状態遷移に使用できることは、別の問題である。

D が答える問いは、

> **この状態は、現在の目標状態入口に対する判定根拠としてまだ有効か。**

である。

### 3.3 B：Boundary｜制御境界

B は、関連状態が現在の目標状態入口に対して定義された許容範囲または制御境界内にあるかを確認する。

工程上の境界は、数値範囲、閾値、公差、容量、時間窓、回数上限、信頼度、位置偏差などとして定義される。

たとえば、ある寸法の許容範囲が、

```text
19.90 mm ～ 20.10 mm
```

と定義されている場合、20.06 mm は許容範囲内であり、20.18 mm は制御境界を超えている。

B が答える問いは、

> **この状態は、現在の目標状態入口に対して定義された制御境界内にあるか。**

である。

D と B は、明確に異なる性質を扱う。

```text
D：この状態は、現在の判定にまだ使えるか
B：有効な状態が、現在の許容範囲内にあるか
```

たとえば、画像認識結果が前のワークに対応している場合は D の問題であり、現在ワークの認識結果ではあるが位置偏差が許容値を超えている場合は B の問題である。

## 4. C / A / E と S / D / B の組合せ

二つの軸を組み合わせることで、CAE-SDB の構造化判定が形成される。

| 状態遷移機能役割 | S：構造完全性 | D：動的時系列有効性 | B：制御境界 |
|---|---|---|---|
| C：条件状態 | C-S | C-D | C-B |
| A：許可状態 | A-S | A-D | A-B |
| E：実行チェーン状態 | E-S | E-D | E-B |

各座標は、

```text
どの機能役割に
    ×
どのような判定結果が生じたか
```

を表す。

たとえば、C-D は条件状態に動的時系列上の問題があること、A-D は許可状態に動的時系列上の問題があること、E-B は実行チェーン状態が定義された制御境界を超えていること、C-S は条件状態の判定に必要な構造が成立していないことを示す。

一つの状態遷移機能役割に対して、複数の判定性質を適用できる。

たとえば、画像認識結果を C として扱う場合、C-S では画像認識結果のインターフェースや対象物との対応関係が正しく定義されているかを確認し、C-D ではその結果が現在のワークに対応し有効時間内にあるかを確認し、C-B では信頼度や位置偏差が許容範囲内にあるかを確認する。

同じ判定性質を、異なる機能役割へ適用することもできる。

たとえば、画像認識結果のタイムアウトは C-D、判定途中での許可撤回は A-D、下流状態の長時間未更新は E-D として整理できる。

CAE-SDB の判定結果は、対応する判定規則が定義され、必要な入力が存在し、実際の判定処理が行われた場合に形成される。

時間情報 T は、関連状態および判定結果とともに保持される。

---

## 5. CAE-SDB 判定結果の工程上の位置

CAE-SDB の役割は、目標状態入口に関連する状態を C / A / E と S / D / B の二軸で整理し、構造化された判定結果を形成することである。

基本的な処理関係は次のとおりである。

```text
現在状態
    ↓
目標状態
    ↓
目標状態入口 / PCN
    ↓
C / A / E Mapping
    ↓
S / D / B Evaluation
    ↓
CAE-SDB Result + T
    ↓
制御優先度調停
    ↓
複数経路制御
    ↓
実行結果
    ↓
PCN Trace
```

一つの目標状態入口に対して、C-D、A-B、E-D など複数の CAE-SDB 判定結果が同時に形成される場合もある。

CAE-SDB は、それらを構造化したうえで後段の制御処理へ渡す。

具体的な制御優先度は制御優先度調停で決定し、制御経路は複数経路制御で選択する。実行後の結果は PCN Trace に記録する。

したがって、CAE-SDB の判定結果と具体的な制御動作は、一対一で固定的に対応するものではない。

---

## 6. 適用範囲と工程上の前提

CAE-SDB の直接的な適用対象は、明確な状態遷移関係を持つ工程システムである。

適用時には、まず現在どの状態または段階にあるか、次にどの状態または段階へ進もうとしているか、その間にある目標状態入口はどこかを明確にする。

そのうえで、今回の状態遷移に直接関係する状態を選定し、それぞれを工程上の役割に応じて C / A / E に整理する。さらに、実際の工程要求に基づいて必要な S / D / B 判定を適用する。

対象設備、制御プラットフォーム、業種、信号名称が異なっても、この二軸構造自体は共通して利用できる。

一方、具体的な状態マッピング、判定規則、時間条件、許容範囲、制御境界は、対象となる工程システムに応じて定義する必要がある。

CAE-SDB は、**目標状態入口を基準として状態遷移判定を構造化するための二軸分析法**である。
