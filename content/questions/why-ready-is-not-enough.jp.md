自動化ラインがピックアップ動作の直前で停止している。

ロボットは Ready を表示し、PLC にも明確な異常はないが、ピックアップ動作が開始されない。

確認を進めると、例えば次のような状態が見つかることがある。

- ワーク条件が成立していない。
- 必要な許可が成立していない。
- 下流が受入可能な状態にない。
- 関連状態が長時間更新されていない。

現場で確認したいのは、

> **今回の目標状態入口に対して、Ready を含む関連状態がどのような関係にあるか。**

という点である。

Ready は、設備、機構、モジュールなどの局所的な運転可能状態を表す。

状態遷移前判定では、Ready を含む関連状態を同じ目標状態入口に対応付けて整理する。

---

## 1. Ready が表す状態

自動化システムでは、Ready によって次のような状態を表すことがある。

- 設備が自動モードにある。
- サーボが運転可能な状態にある。
- 主要なアラームが発生していない。
- プログラムが実行可能な状態にある。
- 機構が待機位置にある。
- 相手機器から Ready が返されている。
- 通信対象がオンラインである。

これらは、対象設備やモジュールの現在状態を確認するための情報である。

例えば、ロボットがピックアップ段階へ進む場合、Robot Ready と合わせて次の状態が関係することがある。

- ワークが存在するか。
- 位置・姿勢が要求条件を満たしているか。
- 安全許可やエリア許可が成立しているか。
- 今回の目標状態へ進入した後に必要な実行チェーンが継続できるか。
- 判定に使用する状態が現在も有効か。

Ready は、このような関連状態の一つとして目標状態入口の判定に使用する。

---

## 2. Ready は目標状態入口に対応付けて確認する

同じ Ready 信号でも、対象となる目標状態が変われば、判定に使用する関連状態も変わる。

例えば、

```text
Robot Ready = TRUE
```

という状態があっても、次の目標状態によって確認内容は異なる。

```text
現在状態 → ピックアップ段階
現在状態 → 原点復帰
現在状態 → 異常時退避
```

そのため、まず次の関係を明確にする。

```text
現在状態
→ 目標状態
```

その上で、

> **今回の目標状態入口に、どの状態が関係するか。**

を整理する。

目標状態入口を明確にすると、Ready が今回の判定でどの役割を持つか、どの状態と組み合わせて確認するかを整理しやすくなる。

---

## 3. 目標状態入口に関係する状態を C / A / E に整理する

TPCA / PCN では、目標状態入口に関係する状態を C / A / E の状態変数領域に整理する。

### C：Condition / 条件状態

目標状態へ進むための前提条件に関係する状態である。

例えば、

- ワーク存在状態
- 対象状態
- 必要データの取得状態
- 前段階の完了状態

などが該当する。

### A：Authority / 許可状態

目標状態への進入許可に関係する状態である。

例えば、

- 安全許可
- エリア許可
- 上位システム許可
- 資源ロック
- 相手機器からの許可

などが該当する。

重要な A は、目標状態入口に対する独立した必要制約として扱う。

### E：Execution Chain / 実行チェーン状態

目標状態へ進入した後、その段階を継続・完了するために必要な実行チェーンに関係する状態である。

例えば、ピックアップ段階では、

- ロボット本体の運転状態
- ロボット経路状態
- グリッパ状態
- 今回の目標状態に対して必要と定義された下流受入状態
- 結果送信・書戻し状態

などが該当する。

Ready は、対象となる目標状態入口で担う役割に応じて、関連する状態変数領域へ整理する。

---

## 4. Ready の現在有効性も確認する

状態値が正常でも、今回の目標状態入口に対する判定時点では確認が必要な場合がある。

例えば、

- 検査結果が長時間更新されていない。
- 下流 Ready が以前の値を保持している。
- 許可が動作開始前に取り消されている。
- 上流と下流で状態更新時刻が大きくずれている。
- システムが状態切替中である。

TPCA / PCN では、C / A / E に整理した状態に対して、必要な S / D / B 判定を行う。

Ready のタイムアウト、未更新、取消、非同期、競合、切替中などは、D：Dynamics / 動的時系列有効性の判定対象となる。

これにより、

```text
Ready = TRUE
```

という現在値と、

```text
今回の目標状態入口に対して使用できる状態か
```

を同じ判定の中で確認できる。

C / A / E の状態変数領域と S / D / B の判定特性を組み合わせる考え方については、以下を参照。

[なぜ CAE-SDB なのか？― 状態遷移における機能役割と状態検証の二軸構造](/jp/notes/why-cae-sdb/)

## 5. Ready を状態遷移前判定へ組み込む

PCN では、Ready、インターロック、ハンドシェイク、許可、下流状態などを、今回の目標状態入口に関係する状態として整理する。

基本的な処理関係は次の通りである。

```text
現在状態
→ 目標状態
→ PCN
→ 複数系統の状態
→ C / A / E 状態マッピング
→ S / D / B 判定
→ CAE-SDB 判定結果 + 時間情報 T
→ 制御優先度調停
→ 複数経路制御
→ PCN 状態遷移判定履歴
```

この構成により、次の事項を同じ目標状態入口に対応付けて確認できる。

- 現在状態
- 目標状態
- Ready を含む関連状態
- C / A / E の状態変数領域
- 必要な S / D / B 判定
- CAE-SDB 判定結果
- 制御優先度調停の結果
- 複数経路制御
- PCN 状態遷移判定履歴

## エンジニアリング上の結論

Ready は、設備、機構、モジュールなどの局所的な運転可能状態を示す重要な情報である。

状態遷移前判定では、Ready を今回の目標状態入口に対応付け、条件状態、許可状態、実行チェーン状態、および必要な S / D / B 判定と合わせて確認する。

TPCA / PCN では、

> **現在状態から目標状態へ進む前に、今回の目標状態入口に必要な状態関係を整理し、判定結果を制御優先度調停と複数経路制御へ接続する。**

Ready は、その判定に使用する状態の一つとして扱う。
