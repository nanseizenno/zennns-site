MES 里已经有任务，WCS 里也有搬送任务，但现场一直没有真正执行。

继续往下查，可能发现：

- 目标工位还没有放行；
- 资源锁没有释放；
- 区域许可没有成立；
- 下游缓存已经满载；
- 可用主体不足；
- 结果回写链路没有准备好。

任务确实存在。

但目标执行路径并没有成立。

这类问题在 MES / WCS 和自动化系统中很常见：

> **“有任务”只说明系统存在一个待执行对象，并不等于这个任务现在已经具备执行条件。**

---

## 1. 任务存在，只说明“有事情需要做”

任务存在通常可以表示：

- MES 已经生成工单或生产任务；
- WCS 已经生成搬送任务；
- PLC 已经收到启动请求；
- 某个设备已经收到执行要求；
- 某个工位已经产生处理需求。

这些信息都很重要。

但它们主要回答的是：

> **有没有事情需要执行？**

真正进入目标执行路径之前，还需要继续判断：

- 进入条件是否成立；
- 系统是否允许执行；
- 执行以后整个链路是否能够继续接续。

因此：

```text
任务存在
≠
目标执行路径已经成立
```

---

## 2. 任务存在以后，还可能卡在 C / A / E

对于一个明确的目标执行入口，可以把相关状态进一步整理为 C / A / E。

### C：Condition

判断任务本身和现场条件是否完整。

例如：

- 任务目标是否明确；
- 工单数据是否完整；
- 物料状态是否满足；
- 目标工位是否有效；
- 前序工序是否完成；
- 必要参数是否齐全。

任务存在本身通常只是 C 中的一部分。

### A：Authority

判断系统是否允许任务进入目标执行路径。

例如：

- 上位系统是否放行；
- 调度许可是否成立；
- 资源锁是否释放；
- 区域许可是否成立；
- 人工确认是否完成；
- 对方设备是否允许接收。

关键许可不成立时，即使任务已经存在，也不能进入目标执行路径。

### E：Execution Chain

判断任务一旦进入执行，整个执行链是否能够继续接续。

例如：

- 是否有可执行主体；
- 路径是否可通行；
- 下游是否能够承接；
- 缓存是否可用；
- 回退路径是否存在；
- 结果是否能够正确回写。

因此：

> **任务存在不能覆盖许可，也不能覆盖执行链接续性。**

---

## 3. Pending、Waiting 不能作为解释终点

如果系统最后只显示：

```text
TASK EXISTS
PENDING
WAITING
```

现场仍然需要继续问：

> **为什么没有进入执行？**

同样一个 Pending，背后可能是：

- 任务条件尚未完整；
- 关键许可没有成立；
- 资源锁仍被占用；
- 下游无法承接；
- 路径暂时不可用；
- 状态已经超时或未刷新。

所以，Pending 和 Waiting 只是当前运行状态。

真正需要说明的是：

> **本次任务为什么没有进入目标执行路径。**

PCN 把任务重新放回明确的状态迁移入口中：

```text
当前状态
→ 目标执行状态
→ PCN
→ C/A/E 状态映射
→ S/D/B 判定
→ CAE-SDB 判定结果
→ 控制仲裁
→ 多路径控制
→ PCN Trace
```

---

## 4. 状态成立，也要确认它现在仍然有效

任务执行问题还经常出现在状态时序上。

例如：

- 任务已经存在，但目标工位状态长时间没有刷新；
- 资源锁曾经释放，但当前已经被重新占用；
- 区域许可刚刚被撤销；
- 下游 Ready 已经超时；
- 任务参数在等待过程中发生变更；
- WCS 与现场状态出现不同步。

因此，PCN 不只判断“有没有任务”和“有没有许可”。

还需要继续判断：

- 所需结构是否完整；
- 当前状态是否仍然有效；
- 是否已经进入控制边界。

也就是对 C / A / E 进一步进行 S / D / B 判定。

这样才能区分：

```text
任务真的不能执行
```

和：

```text
任务原本可以执行，但当前判定依据已经失效
```

---

## 5. 任务不能执行以后，还需要决定下一步怎么办

“不能执行”不是最终工程结论。

真正还需要确定的是：

> **接下来进入哪一条控制路径？**

例如：

- 继续等待；
- 请求许可刷新；
- 释放资源；
- 调整任务分配；
- 改派其他主体；
- 协调下游；
- 进入备用路径；
- 人工确认；
- 禁止进入；
- 增强记录。

因此，一个完整的任务执行判断，不只是：

```text
Task Exists = TRUE
```

而是：

```text
任务存在
→ 状态迁移前置判定
→ 控制仲裁
→ 多路径控制
→ 执行结果
→ PCN Trace
```

这使系统能够记录：

> **任务为什么没有执行，以及后来是如何恢复或转入其他路径的。**

---

## 工程结论

任务存在很重要。

但任务存在不代表任务可以执行。

真正进入目标执行路径之前，还需要确认：

- C：任务和现场条件是否成立；
- A：关键许可是否成立；
- E：执行链是否能够继续接续；
- S / D / B：相关状态是否结构完整、动态有效，并处于可接受控制边界。

因此：

> **“Task Exists” 是执行判断的起点，不是执行许可本身。**

TPCA / PCN 关注的，就是把任务放回明确的目标执行入口，判断这一次状态迁移为什么能够成立，或者为什么没有成立。

这样，现场才能从：

> **“任务已经有了，为什么还不执行？”**

进一步走到：

> **“到底缺的是条件、许可还是执行链接续，以及下一步应该进入什么控制路径。”**
