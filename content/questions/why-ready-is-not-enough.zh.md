一条自动化产线停止在抓取前。

机器人显示 Ready，PLC 没有明显异常，但抓取动作没有开始。

继续检查后，可能发现工件条件尚未成立，某项必要许可还没有满足，下游当前无法承接，或者某个看起来正常的状态已经长时间没有更新。

于是现场会遇到一个很常见的问题：

> **设备已经 Ready，为什么系统仍然不能进入下一步？**

Ready 本身没有异常。它说明的是某个局部对象当前具备一定的运行能力，而一次实际动作能否开始，还取决于这次状态迁移所涉及的其他状态。

---

## 1. Ready 描述的是局部运行状态

在自动化系统中，Ready 是非常重要的运行状态。它通常用于表示设备处于自动模式、伺服已经上电、没有主要报警、机构位于等待位置，或者对方设备已经返回可运行状态。

这些信息能够快速说明某个设备、机构或模块当前具备一定的运行能力。

但机器人 Ready，并不能同时说明工件条件已经成立、当前动作已经获得必要许可、目标区域允许进入、下游能够继续承接，以及当前读取到的相关状态仍然有效。

因此，看到：

```text
Robot Ready = TRUE
```

能够确认机器人当前处于某种可运行状态，但还不能仅凭这一项状态判断系统是否可以进入下一阶段。

---

## 2. Ready 必须放到具体的状态迁移中理解

同一个 Ready，在不同状态迁移中可能具有不同的工程含义。

例如：

```text
Robot Ready = TRUE
```

如果系统准备进入抓取阶段，它是与本次抓取有关的状态之一；如果系统准备进入回原点、异常退避或其他执行阶段，同一个 Ready 所处的判断关系也会发生变化。

因此，状态迁移判断首先需要明确：

> **系统当前处于什么状态，准备进入什么目标状态？**

目标状态不同，与本次进入直接相关的条件、许可和执行链接续关系也会不同。

这也是复杂自动化系统中一个容易被忽略的问题：状态本身通常已经存在，但这些状态需要放回一次明确的状态迁移中，才能判断它们对于“现在能不能进入下一步”究竟意味着什么。

---

## 3. 为什么多个正常状态仍然可能不够

假设现场同时看到：

```text
Robot Ready = TRUE
工件检测 = TRUE
安全许可 = TRUE
Downstream Ready = TRUE
```

从单个状态看，似乎都没有问题。

但如果 Downstream Ready 是较早以前保留下来的旧状态，或者安全许可已经在当前周期发生变化，那么这些 TRUE 仍然不能直接支持当前状态迁移。

一次目标状态进入，需要同时考虑进入所需的条件、当前是否获得许可、进入以后执行链能否继续，以及这些状态现在是否仍然能够作为本次判断的有效依据。

随着 PLC、机器人、安全系统、视觉系统、MES / WCS 和下游设备共同参与一次状态迁移，这些关系越来越难由单一 Ready 信号完整表达。

因此，真正需要确认的问题逐渐从：

> Ready 是否成立？

转变为：

> **系统现在准备进入哪个目标状态，以及哪些状态能够支持这一次进入？**

这也是目标状态入口（Target State Entry）需要被明确出来的原因。

---

## 工程结论

Ready 能够有效表示设备或模块的局部运行状态。

当一次动作同时受到工件条件、安全许可、上位系统、下游承接和状态时序等因素影响时，还需要进一步明确：

> **系统现在准备进入哪个目标状态，以及哪些状态能够支持这一次进入。**

TPCA / PCN 将这一明确的目标状态入口作为工程对象，进一步组织与本次状态迁移相关的状态、前置判定和后续控制。
