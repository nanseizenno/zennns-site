MES、WCS、PLC、搬送設備、ステーションなどが連携するシステムでは、各システムに状態情報があり、タスクも生成されているにもかかわらず、協調処理が進まないことがある。

例えば、

```text
MES：タスクあり
WCS：Pending
AGV：Online
PLC：Auto
Station：Available
```

と表示されていても、実際の搬送や引渡しが開始されない場合がある。

このとき現場で確認したいのは、

> **各システムが現在どの状態を持っているか。**

に加えて、

> **今回、どの状態からどの状態へ進もうとしており、その移行に関係する状態がどこで止まっているか。**

という点である。

---

## 1. 各システムは、それぞれの役割に応じた状態を持つ

複数システム連携では、各システムが異なる対象を管理している。

例えば、

- MES は、作業指示、タスク、生産実績などを管理する。
- WCS は、搬送タスク、経路、資源、ステーション状態などを管理する。
- PLC は、設備状態、動作条件、インターロックなどを管理する。
- AGV / AMR は、位置、運転状態、タスク実行状態などを持つ。
- ステーションは、受入状態、処理状態、完了状態などを持つ。

これらの状態は、それぞれのシステム内部では必要な情報である。

一方、1 回の協調処理が複数システムにまたがる場合、その処理に必要な状態は複数の場所へ分散する。

例えば搬送開始では、タスク、実行主体、経路、資源、ステーション、許可などが同時に関係することがある。

---

## 2. タスクが存在していても、実行開始には別の確認が必要になる

タスクは、システムに実行すべき対象が存在することを示す。

例えば、

```text
MES：搬送要求あり
WCS：搬送タスク生成済み
```

という状態である。

その後、実際に搬送を開始するまでには、現場側の状態が変化することがある。

例えば、

- 目標ステーションが他の処理を実行中となる。
- 共有資源が他のタスクに使用される。
- 実行主体が別の処理へ割り当てられる。
- 必要な許可が成立していない。
- 下流の受入状態が変化する。
- タスク生成時とは現場条件が変わる。

このため、タスク生成後も、実行開始時点の状態を確認する必要がある。

---

## 3. 協調停滞では、確認対象がシステム間にまたがる

複数システム連携で処理が進まない場合、単一の設備や単一の状態だけでは、なぜ今回の状態遷移が成立していないのかを確認しにくいことがある。

例えば、

```text
Task = Pending
Vehicle = Waiting
Path = Available
Station = Online
```

という状態でも、別の許可、資源、下流状態、更新時刻などが今回の移行判定に関係している場合がある。

現場では、

```text
MES を確認
→ WCS を確認
→ 車両状態を確認
→ 経路・資源を確認
→ ステーションを確認
→ PLC を確認
→ 時刻を照合
```

という形で、複数システムの情報を確認することになる。

確認範囲が広いほど、

> **今回の協調処理で、どの状態遷移を確認しているのか。**

を明確にすることが重要になる。

---

## 4. まず Current State と Target State を明確にする

複数システム連携の問題を整理するときは、まず今回の状態遷移を明確にする。

例えば、

```text
Current State：タスク割当済み
Target State：搬送開始
```

または、

```text
Current State：搬送完了
Target State：ステーション受入
```

という関係である。

その上で、

- 今回の目標状態入口はどこか。
- どのシステムの状態が今回の移行に関係するか。
- どの状態が現在の移行判定に影響しているか。
- 関連状態は現在の判定に使用できる状態か。
- 次の処理へ進んだ後も、必要な処理が継続できるか。

を確認する。

TPCA / PCN では、今回の状態遷移に対する目標状態入口を明確にし、複数システムに分散する状態を、その入口に関係する状態として整理する。

---

## エンジニアリング上の結論

複数システム連携では、MES、WCS、PLC、搬送設備、ステーションなどに状態情報が存在していても、協調処理が進まない場合がある。

まず、**現在どの状態からどの状態へ進もうとしているのかを明確にする。**


その上で、今回の目標状態入口に関係する状態を、システムをまたいで確認する。

これにより、個別のタスク状態や Waiting、Pending、Blocked などの表示を、今回の協調処理における状態遷移と対応付けて整理できる。
